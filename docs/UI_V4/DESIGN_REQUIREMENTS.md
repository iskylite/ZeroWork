# SVG 设计要求

## 目录边界

- `docs/UI_V4/` 仅允许可编辑 `.svg` 设计稿及 `.md` 说明、规范、风格指南。
- 根目录 `design/` 只保存可编辑 `.svg` 设计稿。配套 Markdown 说明归入文档目录。
- 禁止存放任何栅格图片，包括预览图、截图、对比图、验证图片、图标位图和参考照片。
- 禁止存放脚本、JSON、日志、测试报告、缓存或临时文件。
- 生成／验证工具放在 `tools/ui_v4/`；导出图、原生截图、像素采样、测量报告写入 `/tmp` 或根目录 `artifacts/ui-v4/`，不得生成到 `docs` 后再清理。
- SVG 不得通过 `<image>` 嵌入截图或整页位图，不以 base64 图片规避目录规则。真实产品必须使用的矢量图标可内嵌 symbol/path；嵌入字体不是图片。

## 设计稿要求

- 明确 width、height、viewBox 和逻辑单位。宽窗与窄窗单独设计，不整体缩放宽窗冒充响应式。
- 保留可编辑 text/tspan、语义化分组和唯一 ID。普通控件不统一转曲，不用单张图片或一个大路径代替整页。
- 画布只包含真实 UI 元素与产品文案；尺寸线、备注、版本标签、解释、验收结果放在 Markdown 或非渲染 metadata 中。
- 区分组件实际边界、透明视口、文字边界和点击区；阴影不作为布局尺寸。
- 对齐、尺寸、内外边距、字体、颜色、圆角与投影必须有明确来源；不得凭截图印象反复修改数字。
- 状态变化不得意外移动工作区。明确固定、填充、内容适配、压缩、溢出和滚动归属。
- 已有功能、会话归属、快捷键、关闭入口及 AI 浮条交互遵守现有契约；视觉修订不擅自增加标签、按钮或说明文字。

## 已落地界面的通用约束

- 同类选择器复用现有组件和反馈规则；卡片、标题和浮层检查默认、悬停、按下及键盘焦点状态。
- 折叠只改变显示，开关才改变功能启用状态。列表使用有界滚动，固定行和操作区不得被压缩或遮挡。
- 浮层相对实际触发控件定位，并限制在所属窗口可用区域；空间不足时翻转或滚动。具体边距和尺寸以对应原生组件为准。
- 取消待确认步骤时保留原有草稿，且不提交该步骤；已受理或已派发的操作按实际回执处理，取消后续步骤不撤销已发生的结果。审批、广播和异步结果绑定原目标，不随当前激活会话改变归属。
- 新建连接入口复用连接向导，并加载相应协议的编辑器；AI 附件可在发送前预览，发送由用户主动触发。
- 演示数据和模拟结果不能作为真实接口、系统能力或原生功能已验证的依据。

设计稿以可编辑 SVG 保存。需要 HTML/CSS 辅助测量时，在临时目录读取实际布局与计算样式，完成后清理临时文件。明确的局部修复可复用现有参考。原生界面使用 Zenit 控件及真实状态。

## SVG 到原生的验收

1. 以当前 SVG 的实际渲染画面为基准，读取源参数及浏览器实际边界。
2. 对齐逻辑视口、主题、缩放和交互状态，再比较真实原生窗口。正文数据不同须明确，不用整页像素得分掩盖状态差异。
3. 先检查外层布局和几何，再检查轮廓、颜色、字体及投影。编译通过不代表视觉完成。
4. 模糊、透明、颜色合成等效果按最终视觉校准。SVG 高斯模糊与原生 SDF 的同名数值不要求相等；详见风格指南。
5. 必须查看原生截图，确认阴影没有被父级裁剪、没有把相邻组件连成一片，白色表面保持清晰。
6. 只做与改动相称的交互检查，必要时检查宽窄状态；不重复无关全量测试。
7. 在说明中区分已验证和未验证事项。截图与机器报告只保留在设计目录外。

`tools/ui_v4/verify_mist.py` 在几何检查前执行目录白名单检查；发现任何非 SVG／Markdown 文件即失败。

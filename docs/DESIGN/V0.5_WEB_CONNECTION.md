# V0.5 网页连接插件

> 初稿：2026-10-26；本轮审计：2026-11-01。源码基线为 `0.2.7` 工作树（HEAD `615dafc`，包含尚未提交的现有改动），Zig `0.17.0`、`vendor/zenit`、Apple Silicon/macOS 14+。本文是待实施设计：仅完成源码/公开头文件静态核对，未运行平台实验、构建、HTML 原型或原生验收。先通过 v0.5.1 平台阻断验证，再实施插件与非 UI 契约，最后进入 v0.5.2 UI；版本顺序见[路线](README.md)。不升级构建版本、不创建标签。

## 1. 目标与范围

新增随应用静态链接的网页连接插件。用户在标准新建连接入口选择“网页”，保存可选网站 URL 和有序 SSH 跳板引用，打开后在独立内容页中浏览和操作内网站点；未填写 URL 则显示空白浏览页，由用户手动输入网址。浏览器运行在本机，跳板只转发 TCP，不安装浏览器、不需要远程桌面。

本版交付 HTTP/HTTPS、单级/多级 SSH 路由、原始域名与路径、常见表单登录、重定向、Cookie、JavaScript、Fetch/XHR、WS/WSS，以及页内导航、隔离浏览数据、会话内网页下载和网页文件选择上传。网站兼容性以明确场景验收，不承诺与完整 Safari 的所有能力等价。

仅支持 macOS Apple Silicon，使用系统 WebKit。业务逻辑与插件契约使用 Zig；平台 ABI 桥接沿用项目现有方式，可使用最小 Objective-C/C bridge，不为“全部源文件必须为 Zig”引入额外 runtime/Block ABI 实现。没有 Node/Python/Playwright、Chromium 分发、无头浏览器、画面推流或 WebView 替代应用外壳。

不包含浏览器扩展、开发者工具产品入口、书签/同步/通用浏览历史、自动填密码、网页 AI 自动化、集群操作、目录上传、文件拖放/剪贴板上传、跨会话后台下载和断点续传、摄像头/麦克风/屏幕共享、WebRTC、客户端证书管理和跨平台适配。上述功能不通过空按钮或虚假能力声明占位。V0.4 的助手与集群能力不能隐式授予网页 DOM、Cookie 或点击执行权限。

## 2. 标准插件接入

遵循 [V0.2 插件宿主](V0.2_PLUGIN_HOST.md)：复用配置，每个新会话独立建立运行连接，插件自主决定配置与流程。

| 注册贡献 | 本版约定 |
| --- | --- |
| id / origin | `web` / bundled；内部 ID 在实施时校验无冲突后冻结 |
| connection | 标准 ConnectionContribution，保存与临时创建、payload 校验/codec/migrate、专属 editor；不套用 SSH 资产字段解释网页 |
| session_factory | 每次 create 建立独立网页 controller；实现 cancel/close/release_stale |
| workspace_kind / content_renderer | `web`；标准 mount/update/focus/unmount，页面局部工具栏由 renderer 绘制 |
| dependencies / required_services | dependencies 声明宿主 API 依赖；required_services 只列本插件必须发布的会话服务。具体清单见 §14，不把宿主能力填入 required_services |
| icons / integration | 提供协议、资产、页签图标及标准标题/状态/关闭能力投影；不自行绘制全局 UI |
| tools / settings_section | 本版无新增 AI 工具；没有实际插件级偏好则不注册空设置分区，下载位置复用每次保存对话框 |

协议选择器、侧栏资产、页签、状态栏、设置身份卡和关闭入口都消费注册贡献。公共消费者禁止 `if plugin_id == web`，禁止新增业务闭枚举或按 ID 选择工厂。生产注册缺少 WebView/代理能力时应给出标准不可用原因，不发布可创建但必然失败的半成品入口。

新增文件集中于插件目录，静态组合处一次注册。平台桥接、公共宿主能力及构建链接属于明确列出的基础设施增量，不能伪装为现有 API 已覆盖；也不能借此重构无关消费者。

## 3. 复用与最小增量

| 已有基础 | 复用方式与边界 |
| --- | --- |
| plugin_registry / plugin_ui_contract / session_host | 沿用清单、editor、renderer、owner、operation、generation、会话状态与关闭回执 |
| connection_config_resolver | 冻结保存 SSH 配置和凭据引用，沿用重复、循环、删除和 revision 校验 |
| transport_factory | 由当前网页 owner 建立独立无 shell transport；只消费公共 facade，不借用活跃终端的 session/channel/fd |
| socks5_listener / relay / forward_service 底层 | 复用 SOCKS5 协议、非阻塞转发和清理机制；现有 forward_service 绑定原 SSH 会话身份，不能直接冒充网页会话复用 |
| challenge / credential / host key 服务 | 沿用逐跳认证与信任交互；网站 TLS 与 SSH 主机密钥分别处理 |
| 内容槽、窗口和布局 | 沿用宿主页签/窗口生命周期，增加通用平台内容 surface 服务 |

增量按所属版本分开，不能把尚未实现的前序设计当作当前源码能力：

| 归属 | V0.5 的使用方式 |
| --- | --- |
| 当前 0.2.7 已有 | API 2 清单/open/retry、typed binding、frame sink、owned transport 与 SSH 认证/主机密钥；只复用其真实边界 |
| [V0.3 通用补齐](V0.3_BMC_IKVM.md) | 最先交付 `SessionServiceAccess`、通用 probe factory/host 和无 Tab 的受管理真实 SessionHandle scope；V0.5 只注册网页 probe 与使用服务访问，不重复定义一套身份/接口 |
| [V0.4 兼容演进](V0.4_AI_AGENT_CLUSTER.md) | 拟采用 API 3 并兼容 API 2；网页继续声明 API 2，经同一兼容层接入，新增宿主能力仍单独声明 `host.*@1` |
| V0.5 新增 | 网页插件、owned proxy、WebView/native surface、排他 site data、通用下载 producer/目的地、文件选择和异步关闭风险协调；按 §13–§23 的边界实现 |

前序通用契约未交付时，应先补齐其原定交付项并验收，不在网页目录复制私有替代。现有 `HostContext.trust` 仅有 SSH 主机密钥，`credentials.resolve` 返回 SSH Auth；二者不是网站 TLS 信任或 HTTP 密码存储。网站 TLS 由 WebKit/测试客户端的系统校验处理，HTTP 认证用一次性受控挑战。网页插件不得直接 import SSH 插件内部 controller、libssh2 或平台 WebKit 对象。

## 4. 配置与编辑流程

连接 Envelope 继续保存宿主身份、协议 ID、payload_version 和插件 payload；以下为逻辑字段，不预设未经实现确认的 Zig 类型。

| 字段 | 约定 |
| --- | --- |
| 名称 | 复用宿主连接名称与校验 |
| URL | 可留空；填写时为绝对 HTTP/HTTPS URL；保留域名、端口、路径与查询；禁止 userinfo、控制字符和非 HTTP(S) 顶层协议 |
| 跳板链 | 有序保存连接 ID 引用，至少一个 SSH 节点；上限沿用当前 resolver，不另设冲突限制 |
| 浏览数据 | 默认每会话临时隔离；可选本连接记住登录，具体隔离见 §8 |

本版只覆盖经 SSH 的网页连接，不增加直连模式、手填本机转发端口和全局系统代理设置。目标 URL 不充当 SSH 节点，不要求网站提供 SSH。保存连接只校验和持久化，不联网；打开与测试才建立运行资源。

editor 挂载在标准创建/编辑槽，复用连接选择器、跳板摘要与受控挑战组件。用户流程：名称/可选网站 → 选择跳板 → 测试或保存并打开。URL 留空时进入浏览空白页，由用户在地址栏手动输入。可用同一表单组织，不强制增加全局向导步骤。凭据只引用 SSH 配置，不复制到网页 payload；URL 可能含敏感查询，诊断不记录完整查询和 fragment，提示用户避免保存临时令牌。

重复打开同一资产创建独立 owner、独立 transport、独立代理及 WebView，不依赖任何 SSH 终端是否打开。运行中编辑资产不替换当前快照；重试保留原 Envelope 快照、重新冻结 SSH 引用；使用最新网页配置须显式重新打开，见 §18。引用被删除或失效时给出具体节点错误，不隐式换其他同名连接。

## 5. 网络与代理契约

```text
WKWebView（原始 https://console.internal/path）
  → 本会话独立 WebsiteDataStore 的 SOCKS5 配置
  → 127.0.0.1:系统分配端口
  → 本会话 owned SSH transport → 有序跳板链
  → 最终跳板发起目标域名:端口 TCP 连接
```

采用保留原始 URL 的代理模式，默认不提供 localhost URL 改写路线。这样保留 HTTP Host、TLS SNI、证书域名、Origin 和 Cookie 域语义；不解密 HTTPS，不重签证书，不修改页面响应或注入代理脚本。

代理配置在首次 load 之前设置并完成确认。所有该数据仓相关的 HTTP/HTTPS、子资源、重定向、Fetch/XHR、WS/WSS 均须走代理；SOCKS5 传递域名并由最终 SSH 出口解析。不得主动在本机预解析内网域名。域名解析、代理覆盖和无直连回退均是实测门槛，不能仅凭 API 存在宣布满足。

监听仅绑定 loopback，由系统分配空闲端口；不暴露到 LAN，不在公共“转发列表”伪造用户手动转发任务。监听器与 transport 均由网页 owner 持有。采用有界并发、背压与超时，复用当前 transport 的流数量上限，不把现有上限无理由放大；超限应排队至有界期限或明确失败。

代理不可用、SSH 断开或代理重建时禁止自动直连、系统代理回退、临时清空代理或把外链交系统浏览器。保持失败的旧端点配置，按 §18.3 保留拒绝连接的旧监听端点和 retirement 记录，避免 teardown 窗口泄漏或端口复用串代。重连创建新 generation 的 transport/代理/页面实例，原地切换数据仓代理不能作为默认恢复方式。

只支持 TCP 网页功能，不允许绕过代理的 UDP/QUIC/WebRTC。须核实并约束引擎对应行为；拒绝摄像头/麦克风不阻止 WebRTC data channel、ICE/STUN/TURN 探测。页面任意脚本可发起的绕行路径，不能仅以“产品不支持 WebRTC”排除验证。若无法用公开 API 限制且无法证明无绕行，则阻断整个网页插件发布并重新评估平台方案，不能静默降低隔离要求。

## 6. 公共能力契约

以下为拟新增逻辑接口，并非声明仓库已有同名 API。实施前对照实际服务 ID/版本，尽量扩展已有 facade。

### 6.1 会话代理端点

输入：SessionHandle、OperationKey、冻结路由、取消令牌、继承的网络资源限制。输出：不透明端点 lease、loopback 地址/端口、阶段与清理回执。

提供 start、snapshot、stop/release；配置解析和凭据获取在其规定线程进行，SSH 工作线程唯一持有 native IO。插件只能取得 lease 和脱敏状态。禁止网页 UI 持有 Session、channel 或直接轮询 libssh2。端点不共享到其他会话；关闭回执保留 released/awaiting/unknown 语义，unknown 进入现有保留清理机制。

### 6.2 WebView 内容 surface

宿主分配受限 surface token，绑定 WindowId、SessionHandle、renderer scope 和 generation。插件可提交创建配置、load/back/forward/reload/stop、焦点及销毁请求，订阅标题/URL/加载进度/导航结果/挑战/进程终止事件。

平台层拥有 WKWebView、delegates、WebsiteDataStore 和 NSView，不把 NSWindow/App/原生指针交插件。宿主更新逻辑坐标、裁剪、像素比例、可见性和输入激活；仅在主线程创建、布局、聚焦和释放 WebKit 对象。网络线程通过带 generation 的队列返回结果；过期事件丢弃但资源仍按原 owner 释放。

新增服务是可被其他插件使用的通用能力，不把网页 URL、SSH 跳板配置或 web 插件 ID 写进窗口宿主。renderer 初始不宣称 supports_window_transfer；跨窗口迁移仅在明确实现释放/重挂与输入恢复后开放。

## 7. 生命周期与状态

连接状态：idle → resolving → connecting_route → starting_proxy → creating_view → loading → ready。旁路为 challenge、failed、disconnected、closing → closed/cleanup_unknown。网络就绪与页面加载状态分别记录：代理可用不等于网页加载成功；子资源失败不等于整个 SSH 会话失败。

- create：冻结配置与路由，建立独立传输，启动代理，配置隔离数据仓和 WebView，填写 URL 时自动导航，留空时进入浏览空白页；自动打开规则见 §15。
- cancel：覆盖解析、认证、代理启动与加载阶段；关闭其已取得资源，取消后不再提交导航。
- test：受管理临时 scope 建链；URL 非空时经同代理验证 DNS/TCP/TLS 与 HEAD 响应，URL 为空时只验证跳板/代理并明确未验证网站。401/403 表示网站可达但需认证，3xx 不代表已登录成功。测试不复用默认 Cookie、不提交登录表单，结束释放全部资源；具体接口见 §15、§22。
- 页面失败：显示真实导航错误，保留返回/重载；HTTP 状态、TLS、代理、认证和 WebContent 进程终止分别分类。
- 隧道断开：停止导航并撤销页面交互，展示宿主可见的断线状态；不自动重放表单、POST 或未知完成的操作。由用户显式重连后重新打开配置首页；未配置首页则回到空白页。
- 标签页切换：隐藏并停用 surface 输入，保持本页会话；返回时恢复几何与焦点，不重新建链。
- close：先撤销输入/新工作、完成或取消 pending handlers，再释放 WebView 等对象，停止 transport 并保留旧端点拒绝连接；是否能释放 retirement 和数据仓排他 lease 由 §18 的关闭屏障判定。应用回执不等于 WebKit 已确认全部网络进程终止，清理不确定保留 unknown。
- 应用恢复：恢复连接配置与页签元数据，重新创建会话；不持久化运行端口/lease/fd，不自动重放网页操作。

## 8. 登录数据、导航与安全边界

默认使用每会话独立 non-persistent WebsiteDataStore，关闭后不承诺保留登录。选择“本连接记住登录”时采用持久化、独立数据仓：以 connection ID + 独立浏览实例 ID 分配，重复打开不并发共享数据仓；重新打开可复用空闲实例，实例占用时新建隔离实例。实例映射持久化但不包含 Cookie 明文。禁止并发会话共享同一数据仓，否则代理配置会互相覆盖。

关闭持久会话保留其网站数据；提供本连接清除登录数据动作，使用标准影响确认，先关闭相关页面再删除数据仓。删除资产同时清理其仓库映射并协调活动会话关闭；失败保留待清理状态。临时连接不能选择持久登录。SSH 凭据仍由现有凭据服务管理，网站登录由网页自身处理，不在插件配置中保存密码。

HTTP Basic 等网站认证用受控挑战；本版不通过 challenge 主动保存网站凭据（网页自身设置的 Cookie 服从所选数据仓模式）。HTTPS 使用系统信任与域名校验；自签名证书须按现有系统信任部署，本版不提供“忽略所有证书错误”。SSH 主机密钥批准不等于批准网站证书。

用户主动的普通链接默认当前页导航；可确认的普通 GET 链接 `target=_blank` 可保留原请求转为同页导航，具体政策见 §17.4。程序弹窗、POST 新窗口及依赖独立 opener 的认证站点暂不承诺兼容，不改写为 GET、不静默创建共享数据的全局浏览窗口。顶层非 HTTP(S) 导航默认拒绝并解释原因；允许的页内 blob/data 资源不得升级为宿主命令入口。

页面不安装宿主 JS 消息桥，不获得终端/文件/AI 服务。网页文件选择上传按 §23 处理，设备权限请求明确拒绝并展示原因；网页下载按 §19 处理。外部浏览器打开不作为自动降级，避免 URL 绕过 SSH。网页可在隧道内访问重定向和子资源域名，本版不引入域名白名单产品；该范围应在连接说明中明确。

诊断只记录 owner、operation、阶段、跳板身份和脱敏 origin/错误，禁止 Cookie、密码、Authorization、表单内容及完整敏感 URL。静态可信插件不提供进程内恶意代码隔离承诺；loopback 端点也不是对同机其他进程的强安全边界。

## 9. 内容页与界面契约

应用外壳、侧栏、Tab、设置与挑战仍使用 Zenit。只有实际远端网页使用 WKWebView；不将应用表单或工具栏改为 HTML WebView。

内容页由本插件 renderer 提供紧凑导航栏与浏览区域：返回、前进、重载/停止、当前地址与连接详情入口。连接资产名作为稳定页签主标题，网页标题作辅助信息；空白页当前地址为空，地址栏提供“输入网址”提示；有当前地址时可复制，编辑后仅允许 HTTP(S) 并保持同一代理。暂不新增地址自动补全/浏览历史产品。

复用现有连接进度、逐跳详情、认证和错误组件。必须覆盖：初始连接、认证、加载、正常、页面失败、TLS 失败、隧道断开、重连、关闭中和清理未知。按钮可用性由真实历史/加载状态驱动。

宿主 Modal/Sheet/Popover/AI 面板不得被 NSView 覆盖。surface 由宿主统一处理裁剪、隐藏/显示和命中：遮挡区域不能继续收输入；如需在模态期间隐藏整个网页，可暂以快照保持背景，但交互仍必须是实际 WKWebView。若需要部分遮挡，必须实现匹配的裁剪/布局方案，不以截图宣称网页可交互。

键盘归属明确：网页聚焦时文本输入、选择、复制和 IME 进入 WebView；宿主关闭页签、切换页签等保留快捷键按统一规则仲裁。切到 AI/认证/弹窗后网页立即失焦；关闭浮层后恢复有效输入目标。

v0.5.2 前按 zenit-html-ui 制作最小可编辑 HTML/CSS 原型，复用 UI_V3 的组件、tokens 和布局。原型只表达工具栏、创建流程与状态布局，样例网页为占位且不证明实际站点兼容。记录 DOM bounds、computed styles、视口、缩放、字体；用同内容区尺寸的真实应用截图核验。本文不预先编造像素值，不将文档完成等同视觉已确认。

## 10. 平台依据与实施阻断项

### 10.1 本轮已证实与仍未证实

`build.zig` 的主 target 明确为 aarch64/macOS 14.0，`build.zig.zon` 为 0.2.7/Zig 0.17.0；本轮依据实际源码，未沿用 skill 的旧 Zig 示例版本。项目已有 `src/platform/macos_*.m` 与构建链接，可新增最小远端网页 bridge；应用外壳继续使用 zenit。

本机 SDK 根目录为 `/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk`。已核对 `WebKit.framework/Headers/WKWebsiteDataStore.h` 和 `Network.framework/Headers/proxy_config.h`：

| 能力 | 静态核对结果 | 尚需实验的结论 |
| --- | --- | --- |
| `proxyConfigurations` | macOS 14.0 可用，绑定 data store | 每种请求是否覆盖、localhost/IPv6/解析是否旁路 |
| `nw_proxy_config_create_socksv5` / `set_failover_allowed` | 均 macOS 14.0；failover 默认 false，仍显式设 false | WebKit 各网络路径是否实际遵循；不能由默认值推断无泄漏 |

| `runOpenPanel…` / `WKOpenPanelParameters` | macOS 14 基线可用，有多选/目录参数 | 文档失效时结果不会交新文档；签名/sandbox 下实际授权 |
| `WKFrameInfo` | 瞬时信息对象，不提供跨回调稳定 frame/document ID | iframe 移除/导航与 picker 的安全关联，见 §23.3 |
| zenit `ui` / `zenit_app` | `ui.zig` 无 native surface API；runtime 拥有窗口，`MultiWindowApp.window(id)` 可按 ID 查找受管 App | 需明确受控窗口承载扩展，不能将内部 `win.window_ptr` 当既有插件 API |

### 10.2 G0：实施插件前先做最小平台实验

G0 是 v0.5.1 的首项、阻断项；只用最小临时承载/bridge、可控代理和夹具证明可行性，不先投入完整 controller、editor 或产品 UI。至少覆盖最低支持系统与一个当前支持系统，记录实际版本；若无法取得最低系统，仅记录待验收，不宣称全版本支持。

1. 证明受管 WindowId 到承载 NSView 的显式注册、附着/移除、遮挡/输入门控路径；最小 zenit 实验验证双窗口定位、一个浮层、焦点和中文 IME，不把关键混合承载风险拖至 v0.5.2。
2. 对 §10.3 每个网络夹具独立留出口证据，确认首次 load 前代理生效、拒绝回退、数据仓隔离，以及下载/上传同出口。
3. 验证旧 view 释放、长连接/worker/download 停止、旧端点 retirement、持久仓重新 acquire/删除，以及 §17.4、§23.3 的 pending handler/document 竞态。

任一必需路径不能证明无绕行、持久仓安全串行复用或原生窗口受控承载，G0 不通过，记录具体可复现阻塞并停止产品实施。不得自动换 Chromium、改系统代理、注入拦截脚本或降低 TLS 校验。少数站点自身要求 opener 等明确排除的兼容性问题须记录，不能拿来豁免所有页面都能触发的网络旁路。

### 10.3 网络实验必须可复现

准备本机直接出口、最终跳板出口和可控 DNS/HTTP(S)/WS 服务三处观察。每用例使用唯一无敏感值请求 ID、新域名/冷数据仓以避缓存，记录 SOCKS ATYP/目标、服务器看到的源地址与请求次数，以及本机物理接口和 loopback 上 DNS/TCP/UDP 观测。先用刻意直连的对照请求验证观察设备能发现直连，再运行待测请求；“网站打不开”或“只看见代理连接”不等于无泄漏证明。捕获仅限专用夹具流量，不采集用户 Cookie/正文。

| 独立夹具 | 操作与通过条件 |
| --- | --- |
| 内网 DNS/预取 | 本机不可解析、跳板可解析域名；普通导航、dns-prefetch/preconnect 分开触发。域名以 ATYP domain 到最终出口，本机无对应解析/直连；优化未执行记录为未触发，不能冒充已覆盖 |
| localhost/地址族 | `localhost`、`127.0.0.1`、`[::1]` 和可控 IPv6 literal 分开测试；成功访问必须是跳板侧目标，本机同端口陷阱服务器无请求；不允许隐式 bypass |
| 普通网络 | HTTP、HTTPS、不同 origin 子资源、Fetch/XHR、跨 origin/协议重定向各自关联请求 ID；保留 Host/SNI/Origin 和 TLS 失败语义 |
| 长连接/后台上下文 | WS/WSS、dedicated worker、service worker（可注册的持久仓）分别发请求；切 Tab、导航离开、断线/销毁后观察；不支持注册的系统如实记录，不能漏掉可用系统 |
| UDP 路径 | 提供 HTTP/3 Alt-Svc、WebRTC data channel/ICE/STUN/TURN 夹具，摄麦权限拒绝状态下重测；无未授权 UDP/直接 TCP，无法限制即 G0 失败 |
| 下载 | Cookie/认证链接、下载重定向、唯一计数 POST 导出、页面 blob 分别触发；出口相同、POST 只一次、blob 不从字符串重建 |
| 上传 | 单/多文件 form POST、Fetch/XHR、分片、重定向分别验证服务端内容与出口；断线不直连、不自动重发 |
| 故障与代际 | 在握手、TLS、WS、下载、上传各阶段断 SSH/停代理；保持直接网络可达以暴露回退；另测 WebContent 终止、view 关闭、旧 callback 到达、新 owner 建链，不串端点/仓库 |
| 资源上限 | 16 active、16 pending、2 opener 用可阻塞服务分别压满；观测第 17 条的明确失败/有界等待、超时/取消后槽位恢复，无主线程阻塞与无界线程/fd/缓冲 |

每个证据包含夹具版本/命令、SDK/OS、网络拓扑、请求 ID、时间范围、预期/实测和原始脱敏日志位置。负面用例必须覆盖“代理坏但直连可用”；页面 GET 通过不能替代 WS、worker、下载或上传。未取得证据的行保持 pending，不能用一次成功演示批量签通过。

## 12. 论证结论与现有接口审计

本节以下是模块级实施契约；现有符号按本次工作树核实，新符号均标为“拟新增”。代码块为接口设计，不表示已经编译或落地。若前述概述不够精确，按本节以下的具体语义实施。

### 12.1 为什么选择此架构

| 决策 | 依据、收益与代价 |
| --- | --- |
| WKWebView 原生嵌入 | 系统提供 HTML/CSS/JS、输入法、登录和下载；避免分发浏览器及画面编码。代价是 NSView 与 Zenit Metal 内容的层级必须由宿主协调 |
| 原始 URL + SOCKS5 | TCP 字节透传，不改写 Host/SNI/Origin；相较 localhost 端口 URL，更适合 HTTPS、多域子资源和登录跳转。代价是所有所需请求类型必须验证代理覆盖 |
| 每会话独立 transport | 与 V0.2 配置复用/运行连接独立原则一致；关终端不影响网页。代价是重复打开会重复认证/建立 SSH，不能未经设计改成共享活动会话 |
| 独立 WebsiteDataStore | 代理配置按 data store 生效；共享会导致会话互改出口。Cookie 隔离不等于浏览器进程隔离，不通过 WKProcessPool 承诺独立进程 |
| WebKit 执行下载 | 保留 Cookie、认证、重定向、POST 响应及 blob 上下文；另起 curl/URLSession 会丢失上下文或绕行。代价是管理器需对接外部下载任务，而非套 SFTP 引擎 |
| 宿主 facade + 插件 controller | 宿主管平台资源和通用能力，插件管网站业务；避免 web ID 特判与 native 指针外泄。代价是需要一次明确的公共能力补齐 |

`WKURLSchemeHandler` 不作为 HTTP(S) 代理替代：不能靠接管自定义 scheme 获得原始 HTTPS 的完整浏览器语义。导航 delegate 也不等同所有子资源的网络拦截器。脚本替换 fetch、HTML 响应改写和系统全局代理均不采用。

### 12.2 已核实的具体事实

| 实际接口/位置 | 事实与设计影响 |
| --- | --- |
| `PluginManifest.dependencies/provides`、`PluginHost.apis` | 依赖 API ID/major；当前默认宿主 API 只有 `host@2`，新增宿主能力要在组合时发布 API 定义 |
| `services/required_services`、Registry 校验 | required 必须被本 manifest 的 services 覆盖，readyPlugin 还会验证绑定；不能用它声明 HostContext 输入能力 |
| `SessionCreateSpec.plugin: Envelope` | 网页沿已有开放分支创建；不增加 `.web` union 分支、LegacyPluginId 或 ServiceKind |
| `SessionFactory.poll` | 可在主线程安全点推进异步 controller，再调用 SessionHost；factory.create 不可重入调用 SessionHost |
| `readyPlugin(handle,key,bindings)` | 一次接受，发布 typed bindings；queryTypedService 只对 ready/attached 可用。必须先发布可呈现会话，再 mount/加载页面 |
| `ContentMount` | 现有 slot、content_context、frame_sink，没有 SessionHost 或 typed query。不能假定 renderer 已能按 owner 查询新服务 |
| `HostContext` | 现有 resolver、owned transport、SSH credentials/trust、挑战、通知、presentation；没有通用 TLS trust/secret/probe/service_access 或网页代理/网站数据/下载/surface facade |
| `transport_factory.openTcpStream` | 有 16 路上限，返回 socketpair 一侧；内部等待完成，不能在 UI 线程或代理主 poll 循环同步调用 |
| `socks5_listener` | 当前实现依赖 SSH native IO；不能把 OwnedTransport 的 socket fd 当 LIBSSH2_SESSION 传入；应复用协议解析/relay 原理，通过 stream adapter 接入 |
| `SessionHost.retry` | 失败且清理 released 才允许；提升 generation，但保留原 spec。不能声称它自动读取最新网页 Envelope |
| CloseStep | pause_transfers → stop_ai → release_forwards → close_protocol → release_content；网页专属代理不能提前挂在 release_forwards 被销毁 |
| `content.Context.route` | 现有输入是应用事件到 consumer 的转发；NSView 原生输入不会天然经过此函数，需要独立 native surface lease 闸门 |
| `file_transfer_host` | 面向 SFTP runtime/Mux，不是现成通用浏览器下载服务；只能复用可证明通用的管理器展示/目的地协调部分 |


## 15. URL 配置、自动打开与编辑器接口

### 15.1 PayloadV1

```json
{
  "url": "https://console.internal.example:8443/dashboard?view=nodes",
  "ssh_assets": [101, 205],
  "site_data": "ephemeral"
}
```

`site_data` 仅允许 ephemeral/persistent，临时 Envelope（id=0）只能 ephemeral。payload 不重复保存名称/分组/协议，不保存运行端口、当前导航地址、下载路径、凭据、Cookie 或 data store UUID。ID 使用合法正整数并按 ConnectionId 边界检查；有序数组长度 1..resolver.max_jumps，拒绝重复和非 SSH 引用。

URL 可缺省/null/空字符串，解析后统一为 null；输入仅有空白时按留空处理。非空 URL 必须由可靠解析器解析，保留 percent-encoding、路径、查询和 fragment 的语义；禁止仅按字符串拼接重建请求。scheme 仅 HTTP/HTTPS，host 非空，端口 1..65535，拒绝 userinfo/NUL/CRLF/无效 UTF-8；IDN 转 ASCII 与 IPv6 方括号由标准 URL 层验证。空路径可规范化为 `/`，不默认将 HTTP 改 HTTPS，不擅自去掉查询。语法校验不得联网或请求凭据。

model 入口拟定为 `parse(a,payload)!OwnedConfig`、`validatePayload(payload)!void`、`validateReferences(config,resolver)!void`、`safeOrigin(a,url)![]u8`。codec 签名与现有 ConnectionContribution 完全一致：encode/decode 先验证 protocol_id、payload_version 和 Envelope，再 clone；migrate 只接受已实现的目标版本，未来版本报错，不能默认覆盖。

### 15.2 自动打开的唯一触发点

**URL 是可选首页，无额外“自动打开”开关。** 打开已保存连接或临时连接时，renderer/surface 绑定完成、代理已配置后，若 config.url 非空，由 controller 自动且仅一次 `load(config.url)`（如已有用户显式输入，优先该地址，见 §22）；若为空，则展示宿主提供的纯原生空白状态并聚焦地址栏，不发送远端请求。手动输入后才导航，不要求用户预先配置 URL。空白状态不能带外部脚本/图片/探测请求。

每个 runtime 使用 `initial_navigation_decided`（首页已导航或已决定留空）和 WebView generation 防重复；resize、主题变化、Tab 切换、renderer update 不触发重新加载。renderer 重挂在同一个仍存活 WebView 上不重复首页导航。显式关闭后重新打开、失败重试的新 runtime 和应用恢复新会话，均重新加载非空配置首页，否则回到空白页。

区分三种 URL：资产 `configured_url`、当前地址 `current_url`、本次 pending 导航地址。地址栏输入和页面跳转只改后两者。只有标准编辑连接并保存才能改变首页；编辑期间已打开页面继续使用其冻结配置。填写 URL 时默认首页请求为 GET，不保存 POST 作为自动打开动作。首页若直接返回下载则按 §19 弹出保存位置，页面显示下载提示，不无限重试首页。

### 15.3 编辑器与测试接入

复用真实 `EditorFactory.mount(?*anyopaque, EditorMount)!EditorInstance`、snapshot、clear_secrets、unmount 和 EditorEvents.submit。editor 快照只生成 Envelope；保存执行引用离线校验，宿主事务成功后才更新侧栏。测试与保存互不代替，测试失败仍可保存合法配置。

当前 ConnectionContribution 没有通用 probe factory，`SubmitIntent.probe` 也不代表执行路径已实现。通用 `EditorHost` probe facade、可选 `ConnectionContribution.probe_factory` 和受管理无 Tab scope 由 V0.3 首先交付；V0.5 只实现网页 probe contribution。沿用 token、真实 scope OperationKey、Envelope、draft_revision 与受限 ProbeContext，结果在主线程 poll 发布，不直接访问 editor node；完整身份前置见 §22.2。

网页 probe 使用通用 ProbeContext 的 resolver、SSH 认证/信任、取消/审计，以及 V0.5 增加的受限 owned_proxy/网站探测能力，不含页面 surface、下载或默认网站数据仓。网站探测客户端需显式走该 SOCKS 端点并使用系统 TLS 校验，不能把现有 SSH trust 当 TLS verifier。没有 probe_factory 的插件隐藏测试入口或显示未支持，保持现有路径。公共 editor 的 probe 分派复用 V0.3 交付，不新增 web 专用分支。snapshot draft_revision 不一致则测试结果标为旧草稿；关闭编辑器取消 probe 并交清理回执，不保留失效 editor 指针。

URL 留空时网页 probe 仅验证 SSH 路由与 SOCKS 监听，明确网站未验证；URL 非空时经代理验证目标 DNS/TCP/TLS 和 HTTP 响应；HTTP 默认 HEAD，405/501 报“连通但不支持 HEAD”，不自动 GET 任意路径，不执行脚本、不保存 Cookie、不跟随无限重定向。TLS 失败不可写成“测试通过”。测试不保证网站业务登录成功、所有子资源正常或页面加载无副作用。

## 16. 代理工厂、stream adapter 与网络线程

### 16.1 拟新增公共签名

```zig
pub const ProxyToken = struct { owner: SessionHandle, id: u64, generation: u64 };
pub const Factory = struct {
    context: *anyopaque,
    owner: SessionHandle,
    prepare: *const fn (*anyopaque, OperationKey, *const FrozenRoute)
        anyerror!ProxyToken,
    start: *const fn (*anyopaque, ProxyToken) anyerror!void,
    snapshot: *const fn (*anyopaque, ProxyToken) anyerror!ProxySnapshot,
    endpoint: *const fn (*anyopaque, ProxyToken) anyerror!EndpointLease,
    stop: *const fn (*anyopaque, ProxyToken) CloseReceipt,
};
```

prepare 在配置 owning thread 复制路由并调用已有 prepareOwned，不联网；start 只入 worker 队列，不在 UI 调用 OwnedTransport.start/openTcpStream。endpoint 仅在 listening 时可得，含 owner、proxy token、IPv4 loopback、actual_port 和 lease revision；WebView 工厂接收 lease，由宿主校验，renderer 不接触代理凭据/fd。

ProxySnapshot 是固定大小或有界拷贝数据，包含阶段、端口、活动/等待连接数、流量、safe_failure 与 receipt。stop 即刻撤销新 endpoint acquire、拒绝新 SOCKS CONNECT，并排空/取消流。transport 的 released 与 endpoint 的可回收是两个条件：旧 WebKit context 未证实失活时，监听端口继续绑定为拒绝连接的 tombstone，不交新 owner、不改到新 transport；retirement 的回执按 §18.3 处理。重复 stop 不产生新 worker。

### 16.2 具体数据流

SOCKS accept/poll worker 做增量握手解析。只允许 SOCKS5 CONNECT；BIND/UDP ASSOCIATE 返回不支持；ATYP domain 原样交 `Destination.host`，不本机 DNS。每个 accepted socket 先受握手超时、连接数、缓冲大小限制，再进入有界开流队列。

已有 openTcpStream 是同步等待，因此使用固定小型 opener worker 池（上限不超过 transport.max_streams）消费开流请求，不能一条连接无限创建一个线程。开流成功取得 OwnedStream/socketpair，由代理 poll worker 双向 relay；握手成功响应只能在实际 TCP 通道建立后发送。失败按 SOCKS reply 分类，不提前回复成功。

默认 active streams 上限 16（沿用 max_streams），pending CONNECT 上限 16，opener workers 上限 2；两个 opening 请求计入 pending，成功时原子移入 active，不能形成 16+16+2 的额外预算。未完成 SOCKS 握手的 accepted sockets 也受独立不大于 16 的上限；日志明确统计口径，取消/超时必须归还全部计数。超出返回可解释的代理失败，不无限排队。握手复用当前 10s 守护，建链/开流沿用 Factory.timeout_ms（当前默认 15s）；每连接双向缓冲有界，建议各 64KiB，实际值以复用 relay 的既有限制为准并记录。worker 停止通过取消/唤醒和 transport close 结束等待，主线程不能阻塞 join 未完成线程。

OwnedStream.close 只提交槽位关闭，socketpair fd 不由插件随意 close；所有 fd/stream/transport 遵循其唯一所有者。代理 host 负责 final close/deinit 或 adoptFailedOpen，controller 仅持 token。底层 adapter 的通道开关、取消和 native IO 顺序继续由 OwnedTransport worker 负责。

### 17.1 拟新增两层接口

WebView Session 管网络上下文和导航，Surface 只管放进哪个内容槽；避免 controller 需要 renderer 的 UI node 才能创建会话。

controller 是唯一 drain 消费者；renderer 通过 PageSnapshot 观察，不再读取平台队列。事件队列必须有界，进度/标题可合并，挑战/下载/终态不可丢；容量不足时停止接受新任务并转明确失败/取消，不能漏掉一次性 completion handler。

### 17.2 创建、挂载与 native 输入

create 主线程配置数据仓代理，明确 `nw_proxy_config_set_failover_allowed(config,false)`，不设置绕过域名；构建 WKWebViewConfiguration 后创建视图。proxy 设置的同步完成只证明配置已赋值，不是网络覆盖已确认；支持性仍由 G0 证据判定。在 WindowHost 的安全点完成 attach；未绑定可见内容槽不发送首页导航，避免隐藏创建时弹下载/认证对话框。

当前 `ui` 未提供嵌入 NSView 的公开入口。实现先在应用创建/销毁受管窗口时建立 `WindowId → NativeWindowLease` registry，宿主平台 adapter 通过明确的 zenit_app/runtime 扩展注册承载容器与失效回调；原生指针只保留在这两个受信层内。若需要依赖侧改动，限定为该承载接口并单独验收；不是允许插件读取 `App.win`。禁止遍历 NSApp.windows、猜 keyWindow 或按焦点寻找窗口，双窗口与关闭/重建必须证明不会错挂。容器未就绪/已失效时 attach 明确失败，不退回任意主窗口。

AnchorToken 由宿主根据 renderer 在 slot 内创建的节点注册，带 WindowId、owner、scope 实例和 generation；插件不能指定窗口任意坐标。布局完成后 native_surface_host 从节点实际 global rect 计算内容区、裁剪及 flipped NSView 坐标，处理逻辑 points 与 backing scale，窗口缩放或侧栏尺寸变化统一刷新。

native surface 引入受控 human-focus lease：点击原生区域前校验当前窗口/owner、授权和宿主遮挡状态；只有有效 lease 才允许成为 first responder。失焦/撤权/浮层/窗口关闭立即撤销 responder 和 native hit test。原生事件由 AppKit/WebKit 直接处理一次，不再编码为 content.Input 后重放；现有 content lease 复用身份/撤权原则，补足 NSView 路径的闸门。网页不注册 automation consumer，不宣称获得 AI 输入能力。

首次实现采用确定可验收的遮挡方案：AI 侧面板通过布局缩小 surface；宿主重叠浮层出现时隐藏整个真实 surface、撤销输入，必要时展示仅作背景的快照，浮层关闭再恢复。这个降级限于宿主遮挡期间，不将正常网页渲染替换为截图；若已有原生层级可正确处理局部裁剪，可用经验证的等价方案。tooltip/popover 同样计入，不能只处理 Modal。

### 17.3 最小 C ABI 约定

`macos_webview.h` 采用 opaque `ZWWebView*`、`ZWDownload*` 与固定整数/长度字段；入口含 create/load/action/attach/set_geometry/set_enabled/quiesce/release，回调经 `{context,event_tag,view_id,generation,sequence,payload,len}` 进入 Zig owned 队列。字符串指针只在回调期间借用，Zig 回调必须复制；Objective-C Block/delegate 由 bridge 持有，不能存 Zig 栈对象地址。

WKNavigationDelegate、WKUIDelegate、WKDownloadDelegate 与 KVO 观察者由 bridge 持有；导航策略 decisionHandler、认证 handler、download destination handler、file open panel handler、JS 对话框 handler 各有唯一 pending ID，必须恰好调用一次。超时、取消、销毁均调用对应拒绝/取消结果，晚到回答忽略。平台句柄释放后保留必要 callback context，直到最后引用/回调完成；generation 过滤不能替代内存生命周期管理。

普通服务器 TLS 使用默认系统验证；网站认证 challenge 转为现有 challenge_host fields（用户名/密码）且一次消费并清零。ATS 对 HTTP 网站需在 App 的实际 Info.plist/构建中核实：若需要，采用仅网页内容的 `NSAllowsArbitraryLoadsInWebContent`，不开放全局任意加载；SDK/部署版本及 ATS 效果列入平台验证。

### 17.4 JS 对话框、弹窗与进程终止

公开 `WKUIDelegate` 的 alert/confirm/prompt 由 bridge 交宿主单一窗口对话框队列，显示真实发起 frame 的脱敏 origin，网页内容不得伪装成宿主提示；不把 prompt 内容/返回值记日志。每 view 同时只呈现一个请求，重复请求有界排队或拒绝，不因脚本循环无限堆积。关闭/换代/文档失效时 alert 完成、confirm 返回 false、prompt 返回 nil；每个 completion 恰好一次，并先于释放 context。

本轮 macOS 14 基线公开头文件没有通用 `beforeunload` 确认/强制派发 API；不能虚构 `runBeforeUnload…` 或调用私有 `tryClose`。普通页面导航的引擎 beforeunload 行为须实测，原生关闭只依赖 §22/§23.5 的宿主风险确认，不宣称必然触发、可检测未保存表单或保留网站自定义提示。用户在宿主取消关闭时不 teardown 文档。

`createWebViewWithConfiguration` 默认返回 nil，不创建第二个窗口。仅对可确认的普通用户 GET 链接允许显式同页转换，保留原请求；无法确认用户发起、依赖 opener、POST/new-window 或非 HTTP(S) 请求拒绝并给出兼容性说明。不得把 POST URL 重新 load 为 GET，也不得加载两次。`webViewDidClose` 转成当前 owner 的标准关闭请求，仍走统一 ClosePlan，网页不能直接释放宿主窗口。

`webViewWebContentProcessDidTerminate` 标记页面失败，撤销输入、结束该文档 pending handlers/面板，下载按真实 producer 回执失败或继续本地 finalizing；不自动 reload/重发 POST。该通知只描述 WebContent 终止，不证明 network process 已结束或所有 WKDownload 已停止，旧代资源继续按 §18.3 收尾。

## 18. 生命周期时序与关闭屏障

### 18.1 解决 ready/mount 循环

```text
SessionHost.open(Envelope)
  → factory.create：分配 Runtime、校验 owner/context、冻结配置并准备异步资源
  → factory.poll：发布 lifecycle + web.page bindings，readyPlugin 一次成功
  → 宿主挂载 renderer（此时页面可处于 connecting，ready 不表示网站在线）
  → renderer 查询 web.page，注册 anchor，controller 得到 surface 可挂载条件
  → proxy worker 完成 SSH 与 SOCKS 监听
  → poll：取得 site data lease → create WebView → attach surface
  → attached 事件 → initial_navigation_decided=false：优先本次显式输入，其次配置 URL，否则空白页并聚焦地址栏
  → 后续事件更新页面状态/标题，普通加载错误不撤掉内容页
```

创建接受前的 payload/依赖错误走 SessionHost.failed；ready 后发生的 SSH 连接或网页错误保留内容页错误状态，由 PageSnapshot 展示，不再次调用 readyPlugin。真正运行资源终止且可以重试时，通过现有 SessionHost 结束/失败路径发布，清理 released 后才调用 retry；仅导航错误使用 reload，不提升会话 generation。

### 18.2 重试与最新配置

`SessionHost.retry` 保留原 Envelope，因此本版“重连”默认复用本次网页首页配置、重新读取保存 SSH 引用并冻结新的 revision。用户编辑网页资产后想使用新 URL，应重新打开该资产；不在重连时悄悄替换整个 Envelope。重连按钮须区分导航 reload 与重建 SSH 会话，不能把 POST 自动重放作为重试。

### 18.3 关闭、卸载与下载

网页代理不注册为 legacy forward，不让通用 release_forwards 提前断流。所有网页网络依赖在 factory.close（close_protocol）内按以下屏障推进：

1. 进入 closing，Page.command 拒绝新命令，撤销 surface native focus，停止新导航/下载；有活动下载先走 §19 关闭选择。
2. 完成/取消待决导航、认证、JS/保存/文件选择对话框与下载 handler；quiesce 并解绑 surface，保留原数据仓代理配置，释放宿主持有的 view/delegate/observer 引用。
3. 撤销代理新流并关闭 owned transport；旧端点进入拒绝连接的 retirement。只有下述 view、producer、transport、endpoint/site-data 的回执均满足释放条件，才向 close_protocol 报 released；否则 awaiting/unknown。
4. 宿主进入 release_content，renderer.unmount 仅幂等 detach anchor 和释放自身 scope，不再负责释放已关闭的 transport。

renderer 临时 unmount（页签表示方式变化）只 detach surface，不关闭会话；真正 SessionHost.close 才关闭 view/network。`quiesce/destroy/quiesced/destroyed` 都是本应用拟定义的操作/回执，不是 WebKit 自带的“全部网络已停止”API。`stopLoading`、delegate=nil、release WKWebView、收到 WebContent 终止或短时间没有流量，都不足以证明 network process、service worker、下载后台引用已结束。回执须分别记录：输入/新任务已撤权、pending handlers 已结清、原生引用已释放、producer 已终态、transport 已停止、旧端点仍被占用以及 site-data 是否可重用；不得把其中一项代替整体 released。

不能证实旧上下文失活时，宿主保留最小 retirement 对象（owner/view/store generation、回调 context、拒绝连接的 listener），旧端点不转交新 transport、不清空旧代理、不把端口立即交还系统。此时 site-data lease 仍排他，不允许同 UUID 更换代理或供新 generation acquire。超时归 unknown，保留有界清理记录与重试回收，达到 retirement 数量/fd 预算后拒绝新建网页会话，不无限积累，也不为腾资源冒充已释放。

G0 必须给出可操作的失活/回收依据及其支持系统范围；公开 API 若不能满足该依据，应明确持久仓复用/安全重连被阻断。程序退出/崩溃后需在下次启动做 §20.1 的孤儿协调；不能因 UI 消失就宣称旧网络上下文已经关闭。

cancel 创建与 close 共用相同逆序释放函数，但使用各自原始 operation key。跨线程 completion 必须经 poll，禁止从 native/worker callback 重入 SessionHost。unknown 无法立即 retry，UI 解释等待清理。

## 19. 网页下载的完整设计

### 19.1 支持范围与浏览器语义

本版支持会话内下载：普通 HTTP/HTTPS 文件链接、Content-Disposition attachment、导航转下载、带当前 Cookie/HTTP 认证的文件、经重定向下载，以及引擎原生支持的当前页面 blob 下载。下载必须继续使用本会话 WebsiteDataStore/代理，不把 URL 交给系统浏览器、curl、独立 URLSession 或 SFTP。blob 本身是页面本地对象，无额外远端请求；其生成所需网络仍按网页代理规则。

对 download 属性使用导航 action 的 shouldPerformDownload；响应按 attachment/不可展示 MIME 的实际策略转为 WKDownload，处理 navigationAction/navigationResponse 的 didBecomeDownload。PDF 等可展示资源默认按引擎正常打开；明确下载动作才转下载。不能把所有 MIME 或 blob 导航无条件下载，否则会破坏正常预览。

WKDownloadDelegate 的 destination 回调允许 blob 的合成响应，公开 API 提供完成/失败回调。支持能力以固定夹具验证；blob 页面已关闭、对象被撤销或站点依赖不支持的弹窗语义时明确失败，不尝试从字符串 URL 重建资源。POST 导出保留当前导航请求，不重新发送一次 POST。

本版支持网页文件选择上传（§23），不支持浏览器下载扩展、批量静默下载、暂停/断点续传、跨应用重启恢复、关闭网页连接后后台下载。系统可能返回 resumeData，但本版丢弃并按敏感数据处理，不展示不可用的“继续”按钮。失败后的重新下载必须由用户在页面重新触发，避免自动重发有副作用请求。

### 19.2 下载状态与保存位置

状态：offered → choosing_destination → receiving → finalizing → completed；旁路 cancelled/failed/cleanup_unknown。每任务有 DownloadId、owner、view generation、事件 revision，关联当前原生 WKDownload 但不向插件暴露它。

每次下载通过宿主原生保存对话框选择文件名和目录；可记忆本机对话框最近目录，但不增加连接级路径配置。suggestedFilename 仅作为建议，去除路径分隔符、NUL/控制字符和目录穿越，最终名称由用户确认。对话框取消将 destination completionHandler(nil) 调用一次，不开始写文件。选择现有文件时走宿主标准覆盖确认，禁止静默覆盖。

WKDownload 要求 destination 为尚不存在的文件，故下载先写入目标目录内宿主独占创建的临时子目录，使用不存在的 staging 文件路径；成功后关闭写入、校验实际文件存在并完成同卷提交。最终目标的替换/冲突检查仍在提交时进行：未授权覆盖且文件已出现则选择新名称/重新确认；已授权覆盖绑定当时目标身份，身份变化重新确认。不得跟随攻击者替换的符号链接写入任意文件。只有提交成功才标 completed，rename/权限/磁盘失败标 finalization_failed，不能只凭 downloadDidFinish 宣告成功。

失败/取消清理 staging，失败删除保留清理状态与实际路径；不删除既有目标文件。已完成文件关闭连接时保留，不自动打开或执行；提供“在 Finder 中显示”。沿用现有 macOS 下载文件隔离/来源元数据设施；若仓库无通用实现，补在下载目的地服务，元数据仅含脱敏来源，不记录令牌查询。不得因元数据不支持而声称已完成来源标记。

### 19.3 通用下载宿主与接口

下载是外部 producer 任务，不声称支持远端目录、SFTP transfer 或 retained transfer owner。先检查现有 manager 的通用 Job/Engine/Mux 能力：若可登记外部进度/取消，使用单个 WebKit adapter；否则在通用 manager 增加 `ExternalDownloadProducer`，不能往 SFTP 目录/文件协议塞入 HTTP URL。新增接口不得要求管理器按 web plugin ID 选择实现。

```zig
// 拟新增；所有调用主线程，snapshot 由调用者 allocator 持有。
pub const DownloadProducer = struct {
    context: *anyopaque,
    cancel: *const fn (*anyopaque, DownloadId) CloseReceipt,
};
pub const Facade = struct {
    context: *anyopaque,
    owner: SessionHandle,
    offer: *const fn (*anyopaque, DownloadOffer, DownloadProducer)
        anyerror!DownloadId,
    choose_destination: *const fn (*anyopaque, DownloadId) anyerror!void,
    take_destination: *const fn (*anyopaque, DownloadId)
        anyerror!?DestinationDecision,
    publish: *const fn (*anyopaque, DownloadId, DownloadUpdate) anyerror!void,
    request_cancel: *const fn (*anyopaque, DownloadId) CloseReceipt,
    active_count: *const fn (*anyopaque) usize,
};
```

DownloadOffer 包含 owner、view token、platform pending ID、脱敏来源、suggested_filename、mime_type、expected_bytes（可空）。DestinationDecision 为 selected(DestinationLease)/cancelled，lease 包含 opaque staging token，不把任意文件系统写权限交给页面。通用平台 bridge 通过下载宿主验证后的 staging 路径调用原生 destination handler；路径只在受信宿主/bridge 内流转。

DownloadUpdate 含 revision、state、received_bytes、expected_bytes 可空、safe_error；进度来自原生 Progress/KVO 并限频合并，未知长度显示已下载字节而非假百分比。WKDownload 生命周期由 WebView platform session 保持；manager 只持 producer callback，renderer 不持下载对象。任务终态前 callback context 不释放；owner 关闭时 callback 可访问保留清理对象，不能访问已释放 renderer。

管理器展示下载名称、来源连接、字节/进度、状态和取消；只对已完成且提交成功的任务提供 Finder 操作。通用视图按任务能力隐藏暂停/继续/后台保留，不增加 web 专用判断。会话内工具栏只提供活动下载数和打开已有管理器入口，不再造第二套下载列表。

### 19.4 生命周期、认证与错误

- 下载启动保留当前原生请求和 Cookie；重定向按 HTTP(S) 协议、同会话代理及 TLS 策略处理，跨 origin 不主动复制 Authorization。下载认证继续走当前 owner 的标准 challenge。
- 仅在用户选择目的地后写文件；程序触发多下载仍逐项确认，不允许网页获得任意本机写路径。
- Tab 隐藏后继续下载，保留 WebView/代理/数据仓；仅暂停 native 输入，不销毁下载 producer。
- 关闭连接有活动下载：标准关闭协调弹“等待下载完成 / 取消下载并关闭 / 返回”。等待期间标记 close_pending，禁止新增下载；下载完成/失败后继续关闭。用户选返回则撤销 pending close。
- “取消下载并关闭”先取消 WKDownload、等待写入/回调和 staging 清理，再执行 §18 关闭屏障；不能先关 SSH 再把失败误记成用户取消。应用退出复用同一影响清单，无无人值守后台保留承诺。
- 断网/SSH 失效立即标任务失败并撤销新请求；已完成但尚未提交的文件可继续本地 finalizing。只完成部分数据不得提交成最终文件。
- 页面普通导航不主动取消已有 WKDownload，但需实测引擎持有语义；WebContent 进程终止导致下载无法继续时标失败。blob 下载必须在对象存活时交给 WKDownload，不能承诺关闭页面后恢复。
- 持久仓清除/资产删除先处理活动下载与页面关闭，不能一边下载一边删 Cookie/仓库。撤回认证、保存对话框和重复 completion 都使用 pending ID 去重。

### 19.5 官方依据与能力限制

[WKDownloadDelegate 目的地接口](https://developer.apple.com/documentation/webkit/wkdownloaddelegate/download(_:decidedestinationusing:suggestedfilename:completionhandler:)) 明确目的文件必须不存在，并允许 blob 合成响应；[导航响应转下载](https://developer.apple.com/documentation/webkit/wknavigationdelegate/webview(_:navigationresponse:didbecome:)) 提供原生下载对象。系统提供 [resumeDownload](https://developer.apple.com/documentation/webkit/wkwebview/resumedownload(fromresumedata:completionhandler:)) 不等于本版提供可恢复产品语义。

必须单独验证 WKDownload 的代理出口、下载重定向、认证和隧道断开无直连。页面代理验证通过不能代替下载代理验证；否则下载功能不得发布为可用。

## 20. 数据仓、错误与验证模块

### 20.1 SiteData facade

拟定 `acquire(owner, connection_id, mode)!SiteDataLease`、`release(lease)CloseReceipt`、`requestClear(connection_id)!ClearToken`、`pollClear(token)!ClearSnapshot`。SiteDataLease 带唯一实例 UUID、lease generation、ephemeral/persistent 模式和排他占用；平台按 opaque lease 取得数据仓，插件不自行拼接 UUID 或访问 Cookie。

持久映射放应用数据域独立 schema 文件并事务写入，记录 connection/instance UUID、store generation、上次 app instance 和状态（idle/leased/retiring/orphaned/clearing/clear_failed）。排他范围覆盖同一应用数据域的所有进程，复用现有数据域进程锁；内存布尔值不足以防两个实例同时改代理。先写映射/lease，再按 UUID 创建仓库；中途崩溃可对账，不能留下无归属仓库。

正常关闭只有 §18.3 证实旧 context 失活后才转 idle。重连获得新 owner/view/proxy generation；临时仓新建，持久仓仅在旧 lease released 后复用原 UUID 的登录数据，并在首次 load 前设置新代理。旧 lease awaiting/unknown 时不把 UUID 交新 owner，不把“再创建一个 WKWebsiteDataStore 对象”误当独立仓库；同 UUID 指向同一持久实例。用户另外打开可新建隔离实例，但不能伪装成原实例安全重连或绕过 retirement 预算。

应用重启将残余占用转 orphaned，禁止直接清空成 idle。持有数据域进程锁、核对旧进程实例已退出、枚举本应用已登记 UUID，并按 G0 验证的 WebKit 失活/重用规则协调；仅 PID 消失不等于 WebKit 网络进程已无旧任务。不能确认的实例继续隔离并给出待清理状态。枚举发现未知 UUID 时不批量删除，只有证明属于本应用登记/事务日志的实例才允许回收。

已确认 idle 的实例按稳定最近使用策略复用，不合并 Cookie；不同实例登录状态可能不同，产品说明为“保留此浏览实例登录”。清除/删除先持久化墓碑、阻止该 connection 新 acquire，统一处理全部相关活动页与下载，再 release 所有使用仓库的 WKWebView，调用 `removeDataStoreForIdentifier` 并等待 completion 成功。失败/应用中止保留 UUID、墓碑及 safe error，下次重试；成功才删映射。禁止调用默认仓库的全局清除、按路径猜目录或绕过 WebKit 直接删在用文件。临时仓不进入持久映射，其内存/进程清理仍服从回执。

| 页面正常与 blob 下载 | 弹出保存位置，经当前上下文下载；任务进度与最终文件一致 |
| Cookie 保护/重定向/POST 导出 | 不丢登录态、不重发 POST，下载出口为同一 SSH 出口 |
| 首页 URL 直接返回附件 | 自动导航转保存流程；取消后可继续地址栏输入，不循环下载 |
| 无 URL 且隧道连接失败 | 保留空白/错误内容与地址栏状态；输入地址不能绕过代理 |
| 下载中切换 Tab | 下载继续，其他 Tab 的焦点/代理不受影响 |
| 下载中关闭连接 | 等待/取消并关闭/返回均有实际效果，文件状态与资源回执正确 |
| 下载取消/同名文件/权限或磁盘错误 | 不破坏原文件、不残留假完成文件，取消和失败分别显示 |
| 下载中断开跳板 | 页面和下载均不直连，任务失败可解释，无自动重放 |
| 两个网页连接/同资产重复打开 | 隧道、Cookie/data store 和下载 owner 不串，关闭一个另一个正常 |
| 宿主浮层盖住网页 | 网页不盖住浮层、不继续收键鼠；关闭后恢复有效焦点 |

本文当前交付为详细设计与静态接口审计；未运行网络原型、WebKit 集成、构建或真实下载测试。上述平台 gate 是后续实施必须取得的证据，不是本次已经通过的结果。

## 22. 公共接线补充：关闭前确认与 probe 资源身份

### 22.1 下载关闭确认发生在 SessionHost.close 之前

不能等会话进入 closing、typed bindings 已失效后才查询 Page/下载状态。现有 workspace.requestCloseTab 通过 close_bridge.risk 预检；本版复用这个入口，由通用 download_host 按 SessionHandle 提供活动下载风险，公共 UI 不查询 web ID。

拟新增通用 `download_host.prepareClose(owners)!ClosePlan`、`resolveClose(plan, choice)!CloseDecision`、`pollClose(plan)!CloseDecision`；choice 为 wait/cancel_tasks/abort，decision 为 deferred/allow/aborted。plan 保存完整 owner 集合、任务 revision 和请求 ID。请求关闭其他页签/整窗/退出时也冻结同一集合，不只处理单页签按钮。

wait 由 download_host 对相关 owner 设置 close_pending，拒绝新的 offer；当前任务全部终态后返回 allow，再调用标准关闭。cancel_tasks 先发 producer.cancel，待写入和清理回执结束后返回 allow。abort 清除 close_pending、不调用 SessionHost.close。风险弹窗等待期间如任务数变化重新校验，不允许凭旧快照漏掉新任务。

直接由应用关闭或异常清理触发的 factory.close 不弹第二个确认框，按已批准关闭策略或强制清理策略取消任务并返回 awaiting。正常用户关闭必须走统一 preflight；强制退出不能保证完成清理，保留日志/下次 staging 清理记录，但不得声称下载继续后台运行。现有 close_bridge 若只支持风险布尔值/固定选项，在此补通用异步 ClosePlan 承载，保持无下载连接的原行为。

### 22.2 Probe 不伪造 SessionHandle

当前 ResourceOwner 只接受 session/retained_transfer，HostContext 要求真实会话；不能把 editor_id 强转 SessionId，也不能借用 legacy `socks_background`。V0.3 已把通用 probe factory 与受管理、不挂 Tab 的真实 session scope 列为最先交付项；本版不再提出另一份 `openProbeScope` 签名或自行扩展 ResourceOwner。

网页 probe 复用应用 SessionId allocator/SessionHost 注册的真实 handle 与子 operation，editor operation 只作为父关联。scope 不附着 renderer、不发布普通内容服务、不自动导航/下载；网页 contribution 只取得 resolver、SSH 认证/owned proxy、受限 HTTP/TLS 探测与取消能力。正常会话的 presentation policy 保持不变。

测试完成先关闭 scope，只有 cleanup released 才标结束；unknown 保留父子关系和回收状态。父 editor 销毁取消子 scope，旧 draft_revision 的结果不得更新新草稿。V0.5 的验收是“网页 probe 使用同一通用实现、无幽灵页签/私造身份/残留 transport”；通用机制的首次交付与接口定义归 V0.3。

### 22.3 本轮明确修订的产品约定

- URL 可选：有值自动打开，空值允许保存并打开空白浏览页，地址栏输入后经既有代理访问。
- 打开空白页仍需建立已配置 SSH 路由，不隐式变为普通直连浏览器；未就绪时手动提交 URL 可保存为本次 pending 地址，连通后只加载最后一次有效输入，关闭/取消后不得继续执行。
- 地址栏输入早于首页首次加载时，用户显式输入优先于配置首页，initial_navigation_decided 置为已决定；不能建链完成后再用配置 URL 覆盖用户输入。
- 空白页无历史时返回/前进禁用，重载禁用；聚焦地址栏不触发访问默认搜索引擎或任何外部网站。
- 下载与网页文件选择上传均为 V0.5 正式功能；关闭后后台下载和断点续传不作为本版承诺。

## 23. 网页文件选择与上传

### 23.1 产品行为与边界

V0.5 支持网页自身的 `<input type="file">` 上传入口，包括单文件和多文件选择。用户点击网站的“选择文件/上传附件”，宿主展示系统文件选择器；确认后交回 WebKit，文件表单提交、Fetch/XHR、分片和业务结果由网站处理。应用工具栏不增加通用上传按钮，不要求 SFTP 服务或额外 SSH 文件传输通道。

文件选择上传属于 WebView 对用户选中文件的受限访问，不等于授予网页任意本机文件读取权限。插件不遍历文件内容、不主动注入 File 对象、不把本机路径写入连接配置/日志/AI 上下文，也不向网页提供宿主文件 API。系统授权沿所用 sandbox/签名方式实际验证，不申请整个文件系统访问。

本版不包含目录上传、拖放文件上传、剪贴板文件上传、File System Access 持久授权或后台上传。拖放/粘贴如可能触发额外文件访问，平台输入入口须明确拦截未支持的文件路径，保留普通文本编辑；不能把这些路径当成已验证的 picker 等价能力。目录选择请求返回不支持/取消并显示原因，不静默替换为单文件选择。

### 23.2 公开平台接口与重要限制

macOS 必须实现 `WKUIDelegate.webView:runOpenPanelWithParameters:initiatedByFrame:completionHandler:`；未实现默认相当于用户取消，不能认为嵌入 WKWebView 自动获得可用上传入口。用户确认时 completionHandler 返回选中的文件 URL 数组，取消时返回 nil。依据：[Apple 文件选择回调](https://developer.apple.com/documentation/webkit/wkuidelegate/webview(_:runopenpanelwith:initiatedbyframe:completionhandler:))。

`WKOpenPanelParameters` 公开参数提供 `allowsMultipleSelection`、`allowsDirectories`。宿主按前者配置 NSOpenPanel；后者触发本版目录未支持行为。依据：[Apple 文件选择参数](https://developer.apple.com/documentation/webkit/wkopenpanelparameters)。

**不能承诺按 HTML accept 精确过滤系统选择器**：上述公开参数没有通用 accept/MIME 列表。本版不通过 DOM 脚本抓取或私有 API 补取，不为此注入宿主消息桥；默认允许用户选择普通文件，网页/服务端负责类型与大小校验。新增 SDK 能力若超出 macOS 14 基线，必须做 availability 分支且保持基线行为；不把文件过滤当安全验证。

### 23.3 模块与接口

文件选择承接于现有拟定 `macos_webview.h/.m` 的 WKUIDelegate 和 `native_surface_host` 的窗口/模态协调；复用现有通用文件对话框能力。若没有合适 facade，新增 `src/host/file_selection.zig` 和窗口级实现，不把文件系统权限塞进 web.page 服务。

```zig
// 拟新增公共文件选择 facade；只返回不透明 lease，不将路径交业务插件。
pub const SelectionRequest = struct {
    owner: SessionHandle,
    view: ViewToken,
    request_id: u64,
    frame_origin: []const u8, // 仅用于展示，不充当 frame/document 身份
    document_epoch: u64, // 应用记录的主文档代际；不能据此证明所有 iframe 仍有效
    platform_pending_id: u64, // 绑定原始 WebKit completion，平台内保存 frame 信息
    multiple: bool,
    directories: bool,
};
pub const FileSelection = struct {
    context: *anyopaque,
    begin: *const fn (*anyopaque, SelectionRequest) anyerror!SelectionToken,
    take: *const fn (*anyopaque, SelectionToken)
        anyerror!?SelectionResult,
    cancel: *const fn (*anyopaque, SelectionToken) CloseReceipt,
};
// SelectionResult = selected: FileSelectionLease | cancelled | failed: SafeFailure
// FileSelectionLease 绑定 owner/view generation/request_id，只允许平台消费一次。
```

WebView 工厂内部接收文件选择 facade，宿主公布 `host.webview_surface@1` 时必须保证该策略的可用性；不新增插件对全局磁盘服务的依赖。Policy 增加 `file_selection =.files_only`，网页插件选择策略，真正文件 URL 数组由受信文件对话框/bridge 保持，不放入 PageSnapshot 或跨插件服务。

bridge 发出 file_selection_requested 事件（不含本机路径），包含原始 callback 的不透明 pending ID、frame 摘要、主文档 epoch、请求序号及参数。controller 只协调状态；文件选择 lease 由平台验证并消费，调用原始 completionHandler。平台不能根据网页提供的字符串构造 file URL。现有平台 ABI 的策略完成入口补充 selection token/lease，禁止任意 pathname 参数从网页进入。

`WKFrameInfo` 公开声明其不能跨 delegate 回调唯一标识 frame，origin/URL 相同也不表示同一文档；禁止自造稳定 frame ID 并宣称已解决身份。平台保存原始 completion 和当次 frame 信息，结果只交该 completion，不能按新 URL 查到另一个 frame 后重新投递。已观察到的主文档或子 frame 导航、owner 换代、进程终止即取消原请求；不能假定 navigation delegate 能观察所有 frame detach/JS 操作。

G0 用“picker 打开期间移除 iframe、同 origin 替换 iframe、父 frame 导航、顶层导航、旧选择结果晚到”分别证明 WebKit 将原 completion 限定在原请求、失效后不向新文档交付；本应用保守取消与 WebKit 原请求约束共同组成证据。若公开 API 与系统行为不足以保证这一点，上传能力保持阻塞，不能注入 DOM/私有 frame 标识来绕过本版边界。主文档 epoch 本身不是该证明。

状态为 requested → presenting → selected/cancelled/failed → delivered；每个 view 同时一个 pending 文件选择请求，重复请求不叠加面板，明确取消新请求。所有 NSOpenPanel 和 WebKit completion 均主线程执行；handler 由 bridge 持有并保证恰好调用一次。lease 消费后立即释放宿主多余路径/授权引用，不等于宣称可以撤销网页已获得的 File 对象；后者寿命由 WebKit/文档管理。

### 23.4 对话框、取消、导航与焦点

- 文件选择器以所属窗口的系统 sheet 显示，保留 connection/frame origin 关联，禁止跨窗口提交结果；iframe 的 origin 不伪装成顶层网站。
- 面板显示期间停用网页 native 输入并沿宿主 modal 遮挡规则处理，选择确认后恢复仍有效页面的焦点；不能因为隐藏 surface 就销毁上传源文档。
- 用户取消、文件不可读/被删除、目录不支持、窗口关闭、导航使原文档失效、renderer owner 换代时，关闭面板并以 nil 完成原 handler；晚到的文件结果不交给新页面。主文档或发起 frame 已失效都要取消，不能只对比 view ID。
- 用户切换到其他页签不把面板移交新 owner；按窗口模态规则暂停切换或取消原面板，采用既有统一行为并验收。面板结束时核验当前 owner/generation/document。
- 对话框返回的是授权选择，不是“上传开始”或“上传成功”；用户选中后网站可能要求再点击提交，UI 不制造传输完成通知。

### 23.5 网络、进度与关闭语义

浏览器提交文件时保留当前页面 Cookie/CSRF/认证上下文，所有 HTTP(S)、Fetch/XHR 上传请求必须走本会话代理，跨 origin 与重定向仍服从 WebKit 的标准凭据和 TLS 策略，不额外复制 Authorization。上传代理覆盖必须独立测量，下载或页面 GET 通过不能代替此验证。

网站掌握分片、重试和业务完成语义，V0.5 **不把网页上传接入通用传输任务列表**，不推算总进度或上传完成，也不声称所有上传可取消。网站有进度/取消控件时由网站展示和处理。应用关闭/断线/重载可能中断上传，禁止自动重新提交 POST 或分片请求；远端可能收到部分或完整数据，不能宣称回滚。

宿主能精确识别待决文件选择，但不能可靠识别所有 JS 上传任务。因此关闭网页连接和显式重建隧道前，标准关闭风险摘要提供“页面表单和正在进行的上传可能中断”，由通用内容风险贡献展示，不编造任务数量。不要为每次选择文件弹第二次权限确认；文件选择本身就是用户授权，标准关闭确认只在关闭动作时处理。

结合 §22 的通用 ClosePlan：拟新增可选 `ContentRiskContribution`（manifest 默认 null），提供 `snapshot(owner,a)!OwnedContentRisks`，网页贡献 navigation/form interruption 风险，公共关闭 UI 只消费结构化风险与 choices，不识别 web ID。风险不依赖注入脚本/读取 DOM；不声称检测出未提交表单或真实上传。普通关闭仍按既有确认偏好处理；有下载时合并同一个确认，不叠两层弹窗。

JS alert/confirm/prompt 走 §17.4 的公开回调；beforeunload 不存在本版可依赖的公开强制派发/专用确认契约，不能以其作为可靠上传检测或承诺原生关窗必弹网站确认。用户取消关闭则保持文档、选中文件与代理；用户批准关闭则先取消待决 panel/handler，再按 §18 quiesce/destroy。上传中切换页签保留文档/隧道，网络继续，网页自身行为由引擎决定。

### 23.6 实施与验收增量

v0.5.1 在 WebView platform/文件选择 facade 中实现回调、opaque lease、文档身份与清理；controller 增加事件处理和通用内容关闭风险贡献。v0.5.2 验证真实网站按钮、系统选择器、焦点恢复和关闭协调，不制作应用自有上传表单。

| 场景 | 通过条件 |
| --- | --- |
| 单文件/多文件控件 | 网页按钮打开真实 NSOpenPanel；多选遵从参数，网页收到正确文件集合 |

| 登录态/CSRF/POST/分片 | 网站使用当前上下文上传，可控服务验证文件内容与请求；业务成功以网站响应为准 |
| 内网 DNS/HTTPS/断线 | 服务端与出口观测证明上传走 SSH；断线无直连/自动重放 |
| panel 打开时导航/关窗/换代 | 面板取消，旧 completion 不交给新文档，无 callback/use-after-free |

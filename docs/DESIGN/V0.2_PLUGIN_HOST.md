## 1. 目标、现状与版本边界

插件化遵循三个原则：**复用已保存的连接配置；每个新会话独立建立运行连接；插件自主决定配置和连接流程。** 顶栏、侧栏、底栏、AI 助手和设置通过标准契约自动接入；插件完全定制的工作区限于内容槽，专属连接编辑界面则运行在宿主分配的创建/编辑槽内。

设计开始时的架构快照（2026-10-23，保留迁移依据）：原有 adapter 生命周期和SSH底层能力尚未完整支持这套接入。下表是当时基础与本版目标，不是当前未完成清单；当前状态以实现记录及其具体证据为准：

| 当前位置 | 已有基础 | 本版必须补齐 |
| --- | --- | --- |
| `src/host/plugin_registry.zig` | 三个内置 adapter 元数据，`host_api_version=1` | `PluginId`、workspace/service 闭枚举、固定 3 项快照及 `u16` 服务位图改为可验证注册表；目标 API 版本为 2 |
| `src/host/session_host.zig` | handle/generation、operation、create/cancel/close/release_stale | 通用插件载荷与控制器分派，版本化 typed service；移除按 SSH/SFTP ID 分派的服务分支 |

## 2. 宿主与插件的职责

| 接入点 | 宿主负责 | 插件提供 |
| --- | --- | --- |
| 顶栏、Tab、窗口/组布局、底栏 | 既有结构、导航、状态投影、关闭协调 | 标题、图标资源、状态摘要、可用能力 |
| 侧栏、资产树、分组、搜索和菜单 | AssetStore 与同一套行/菜单 | 连接记录、协议 ID、名称、图标及能力数据 |
| 新建/编辑/测试/连接 | 标准入口、配置承载槽、公共控件/主题/焦点、存储事务及挑战 UI | ConnectionEditor、ConnectionController、codec、校验和测试语义 |
| 设置 | 统一身份卡、偏好控件与 apply/cancel 事务 | 身份、来源、版本、可选偏好字段及生效时机；空分区不占位 |
| AI 助手 | 工具目录、作用域、权限、执行与结果 | 工具定义引用、处理绑定和所需服务 |
| 认证、信任、通知 | 类型化 challenge、脱敏审计和统一结果反馈 | 认证请求、信任材料、阶段/操作事件 |
| 内容槽（原终端区域） | 分配区域、主题、焦点和 renderer 生命周期 | 原生 ContentRenderer 及 typed binding |

插件不取得全局 UI 根节点或整个 App 指针，不绘制侧栏、TabStrip、全局状态栏、设置页或第二套 AI 助手。连接编辑器可以组合公共控件、动态步骤及协议特有配置视图，但仅挂在创建/编辑槽内，不接管整个向导外壳。内容 renderer 则可完全定制该工作区。

注册后，保存资产由 AssetStore 事件自动更新侧栏；打开连接由 SessionSnapshot 自动建立现有 Tab、状态投影并挂载内容 renderer。关闭、重连、菜单、历史与组功能沿同一能力契约。在线不等于具有终端广播、exec、文件传输或归档能力；未声明或未授权的操作给出准确不可用原因。

## 3. 清单与注册

`PluginManifest` 聚合协议、服务/工具和内容三类贡献，不包含任意全局 UI 回调：

| 字段 | 契约 |
| --- | --- |
| `id`、`display_name`、`plugin_version`、`origin` | 稳定非空 ID；来源为 `builtin` 或 `bundled`，分别显示基础内置/随应用提供 |
| `host_api_version`、`dependencies[]` | 目标 API 为 2；声明公共 API ID 与版本，不依赖其他插件实例 |
| `icons`、`presentation`、`integration` | 提交现有 SvgAsset；设置/协议/Tab 图标及受限状态投影；历史、菜单、广播等能力声明 |
| `connection` | 可空的 ConnectionContribution，含创建方式、editor/controller、validate/codec/migrate、payload 版本及可选 probe |
| `settings_section` | 可选插件级偏好；与连接配置、宿主全局设置分开 |
| `session_factory` | 唯一生命周期 adapter：create/cancel/close/release_stale；create 为当前 owner 创建并启动一个 controller，其他回调转交该实例 |
| `services`、`required_services` | 版本化服务定义/绑定及建立该类会话必需的接口 |
| `tools` | 工具定义引用或新定义、handler、所需服务和权限策略 |
| `notifications` | 宿主通知定义引用/新定义及事件类别，统一 publish/update，不提供通知视图 |
| `workspace_kind`、`content_renderer` | 稳定 kind、mount/update/focus/unmount；可引用共享 renderer |

`connection.create_kind` 为 `saved` 或 `saved_or_temporary`；无连接贡献表示不进入协议选择器。本地快速创建通过宿主标准动作调用其 factory，不制造本地主机资产。生产可执行清单缺 factory、必需服务或 renderer 即注册失败；仅规划的描述符单独存放为 `adapter_not_connected`，不得进入可创建列表。

两阶段注册：收集不可变定义 → 校验 ID、API/服务类型版本、依赖图、工厂、renderer、字段与工具 → 拓扑排序并一次发布 RegistrySnapshot。缺依赖、依赖环、冲突或错版拒绝发布，不能留下半张可用注册表；注册阶段不联网、不启动线程、不修改用户配置。顺序由显式 order 和稳定 ID 决定。

同一 workspace kind 只能有一个 renderer 定义，其他插件可以引用它。terminal renderer 由宿主共享 presentation 模块提供，Local 与 SSH 均引用，不让 SSH 隐式依赖 Local 的注册顺序。文件 renderer 保留现有实现。插件版本、payload 版本、宿主 API 和服务 major 分别管理。

```zig
pub fn registerAll(host: *PluginHost) !void {
    try local.register(host);
    try ssh.register(host);
    try sftp.register(host);
}
```

生产清单本版只有三项；测试用清单另加 `fixture_probe.register`，不注册 `bmc_ikvm`。

## 4. 插件自主配置与创建连接

### 4.1 编辑器和控制器

ConnectionEditor 决定需要哪些信息、配置视图、字段依赖、动态步骤和业务错误；它从宿主获得草稿、公共控件和受限服务，返回版本化非秘密 payload。宿主识别公共信封与 validate/codec 接口，不理解未来所有协议的地址、认证或发现步骤。

ConnectionController 决定 probe、连接、认证、发现、重试、取消及关闭流程；接受宿主分配的 owner/operation/cancel，发布阶段与结果，不能直接重入 SessionHost 或写 UI。session_factory 是控制器的唯一生命周期适配入口；ConnectionContribution 不再另注册一套 controller_factory，编辑器不得直接创建控制器或先建链再调用宿主启动。连接、测试和保存是不同操作，共用草稿时仍各有 operation/generation。

schema 是可选辅助：普通字段可使用 string/port/boolean/choice/secret/asset_ref 和共享字段组，不是全插件统一表单语言或流程引擎。字段类型不限制 editor 能力，也不强制所有插件使用同一三步流程。采用通用字段时声明 key/order/label/help/default、条件可见/启用、校验和持久化策略；choice 使用稳定 value；asset_ref 按支持的配置协议过滤。秘密无字面量默认值。异步探测结果须匹配 draft revision，不能覆盖后来编辑。 编辑器/内容renderer的临时草稿由插件对应的editor或session context持有，公共Popover/Select/Switch只承载交互，不在打开、关闭或跨菜单切换时重建业务默认值；字段变更按key更新，切换一个字段不重置其余字段。

SSH/SFTP 编辑器保留已有认证、私钥选择、跳板排序、host key 挑战、压缩及严格校验等复杂交互；可复用公共字段组和现有控制器，不能为适配 schema 丢失字段。新公共 widget 或 facade 的增加才是 API 变更，不以插件业务流程不同为由修改宿主分支。

### 4.2 存储与事务

```text
ConnectionEnvelope {
  id, protocol_id, revision, name, group_id, payload_version, payload
}
ConnectionContribution {
  create_kind, editor_factory,
  validate_payload, encode, decode, migrate, probe?
}
```

公共 ID、名称、分组、排序和 revision 由 AssetStore 管理；payload 由插件定义，只存非秘密信息及受控引用。`protocol_id` 定位提供者；现有 `plugin_id` 字段可由兼容 codec 映射，不并存两个可冲突的主键。跳板只保存资产 ID，不永久复制整份 SSH 配置或凭据。

保存允许离线，结构合法且引用可解析即可，不要求本次登录密码或设备在线。保存并连接先原子保存再创建独立 attempt，连接失败保留资产和准确错误；临时连接不写资产。probe 是否支持及验证到哪一步由插件明确声明，使用自己的临时资源，不产生持久 Tab，完成/取消均释放；“管理认证成功”不等于“视频已验证”。

旧 HostConfig 通过 SSH/SFTP codec 映射，保留 ID、分组、默认值和可往返未知字段，不在启动时批量破坏性改写。保存先校验再原子替换；迁移为可测试、幂等的逐版本转换，失败保留原记录。未知插件或更高 payload 版本仍可列出、导出及沿既有流程删除，但不可连接或被默认值覆盖，更不能回落成 SSH。

秘密只通过受控凭据引用/本次输入交给认证服务；不从活跃登录会话提取密码、token 或认证结果。现有 vault 继续承担进程内引用与末次释放清零；持久秘密由下述 macOS Keychain 契约负责，不能以内存 vault 代替系统钥匙串。切协议、取消或草稿销毁释放秘密；日志、设置快照和诊断不含原值。

### 4.2.1 macOS 数据目录与兼容迁移（2026-10-24 补充）

本次明确扩展 0.2 的交付范围：采用标准 macOS 用户目录，兼容迁移现有配置，同时接入系统 Keychain，并提供主动清除全部应用数据的入口。以下是实现与验收契约，不能单凭文档更新标记已经完成或通过验证；插件宿主的其余范围不变。

| 数据 | 默认位置与用途 |
| --- | --- |
| 应用支持数据 | `~/Library/Application Support/com.zerowork.app/`；保留 `config.toml`、`hosts.toml` 及长期会话记录，包括会话 logs/raw/checkpoint/historycast |
| 可重建缓存 | `~/Library/Caches/com.zerowork.app/`；不作为长期会话记录或配置的唯一存储 |
| 应用诊断日志 | `~/Library/Logs/com.zerowork.app/`；应用 `app-*.log` 及其 `.1` 轮转文件进入此处，与会话记录区分 |
| 持久秘密 | macOS Keychain；TOML 只保存非秘密配置和不透明凭据引用 |
| OpenSSH 共享资源 | 继续使用 `~/.ssh/known_hosts` 及用户选择的外部私钥；不接管、迁移或清除这些共享文件 |

正式 App 的功能由默认行为、现有设置或对应操作控制，不要求用户配置环境变量，也不通过环境变量启用功能、覆盖数据目录或注入凭据。数据路径由系统账户信息解析到上述标准 macOS 目录，不受进程中的 `HOME` 或其他环境覆盖影响；不新增设置页面、数据目录入口或隔离开关。

完整实例隔离仅供单元测试或显式启用的测试/自动化构建，由测试入口选择经校验的独立 `Paths` 与凭据 scope；正式构建不能通过环境变量启用该入口。隔离测试实例的支持数据、缓存、诊断日志和应用使用的 known_hosts 均限定在隔离根内，不探测或导入默认 `~/.zerowork`；Keychain 使用该实例的独立 namespace，不能读取、更新或删除正式 App 或其他隔离测试实例的条目。

正式 App 与隔离测试实例遵循相同的安全顺序：路径计算不得隐式创建目录、打开日志或加载配置；启动顺序为计算 `Paths` → 获取当前数据 scope 的进程独占锁 → 初始化凭据 scope → `data_lifecycle.prepare(io, &paths)` 完成安全检查与迁移 → prepareCredentials 校验/迁移秘密 → 初始化应用日志 → 挂载窗口。独占锁持有至所有窗口、后台工作和持久写入均结束；同一数据 scope 的第二进程须明确拒绝启动，避免各自缓存覆盖整个 vault；不同隔离测试实例可并行，但不得共享受管路径或凭据 scope。`PrepareReport` 分别记录 legacy 迁移与诊断日志移动。

默认实例兼容旧根 `~/.zerowork`，遵循以下规则：

- **先检查再移动。** 检查迁移源、目标及本次访问的目录链；迁移拒绝符号链接、特殊文件和 hardlink，不跟随路径跳出受管根。私有目录使用 `0700`，私有数据文件使用 `0600`。路径构造拒绝根目录、traversal、系统 namespace、账户 Library 等宽泛祖先目录及 `.ssh`；生命周期阶段复核字段和系统账户目录。逐级 no-follow 也会拒绝 `/tmp`、`/var` 等别名，隔离测试应使用 realpath 根。任何安全检查失败均保留原数据并阻止继续加载，不能悄悄改用空配置。
- **新安装 Support 不存在。** 验证旧树后优先原子非覆盖 rename 到 Application Support，不复制一份含明文秘密的旧树。应用诊断日志另行路由到 Logs，长期会话记录与未知文件仍留在 Support；目录迁移只搬运 TOML 字节，不在文件系统层解释或改写配置。
- **新旧数据并存。** 只原子移动目标缺失项；内容完全相同的文件可去重。不同内容构成 `LegacyConflict`，不覆盖新数据、不删除冲突原件，并阻止后续配置加载。不能用“新路径优先”静默掩盖旧数据。
- **可恢复与幂等。** 中断后重新执行能识别已移动项、继续剩余项；重复启动不再导入相同内容。迁移失败保留可识别的源与目标状态，不创建未受保护的临时秘密副本。跨文件系统等无法满足原子移动条件时明确失败，不退化成未经设计的复制后删除。
- **路径与清除共用边界。** 迁移、运行和清除使用同一组受管路径。清除包含旧根，避免下次启动重新迁入；隔离实例没有默认旧根。清除及迁移都须以根外 sentinel 证明不会跟随链接删除或改写外部文件。

### 4.2.2 Keychain 与秘密读写事务

持久密码、API Key、私钥口令和 TOTP seed 通过系统 `Security.framework` 的 `SecItem` API 保存。同一 scope 集中在单个 `vault-v1` 钥匙串项内，内部按随机引用索引；进程首次读取后使用内存缓存，不能为每个字段反复调用系统读取或弹出授权。固定签名、固定安装路径的同一版本必须经连续重启验证无需再次输入系统密码；若真实验证达不到该条件，则依用户要求撤销 Keychain，保留 `0600` 本地配置，不交付反复授权的方案。测试不使用外部程序读取秘密。私钥文件本身仍是用户管理的外部文件。`credential_store.configureScope(directory, isolated)` 在配置加载之前确定 scope；默认 service 为 `com.zerowork.app.credentials`，隔离测试根的路径摘要只用于 service 隔离，不能用秘密内容摘要生成凭据引用。引用采用随机 `zw1_` 标识；清除只删除当前 service 的应用管理条目。测试通过替身 backend 验证行为，不以测试夹具读写真实用户 Keychain。

配置继续使用现有 TOML 与兼容 codec；保留资产 ID、分组、默认值和可往返未知字段。已知秘密字段转换为不透明 credential reference，运行时由凭据服务解析到短生命周期内存，再透明交给对应 provider。普通保存和旧明文读取都走同一受控事务：

1. 校验本次已知配置与 scope，暂存待写入秘密；未知插件 payload 保持原样，不越权猜测或重写未知秘密字段。
2. 未改变的秘密复用原引用；改变的秘密在当前 scope 新建不透明 Keychain 引用，不原地覆盖原引用指向的秘密。
3. 以原子替换写入仅含引用的 TOML；提交前准备好包含实际新引用的运行时快照，落盘成功后发布同一引用集，连续修改 Key 和 Provider 名称不能回落到已回收的旧引用。成功前不丢弃原配置或原凭据。Keychain 拒绝、写入失败或 TOML 提交失败均返回明确错误，保留原值，并回滚本次新增条目。
4. 提交成功后，仅回收当前 scope 内由本应用管理、已不再被持久配置引用的旧条目；不能按字符串相似度删除其他应用或其他实例的凭据。正常保存回收 retired 引用；删除失败进入有界 pending 集，下次保存先重试，重试失败不继续新增秘密。启动先解析并校验两份应用自有配置，以原始引用并集 reconcile 当前 service 的 vault 内 `zw1_` 记录，清理崩溃或回滚遗留；任一配置解析失败均不 GC，清理拒绝则阻止新增。load/迁移成功后再按已加载配置的引用并集核对，不能只看单个文件判断无引用。

`store.prepareCredentials(io, dir, allocator, config_path, hosts_path)` 在文件系统 prepare 后、窗口创建前执行。旧明文迁移只在相关文件成功脱敏后才算完成；失败时不得声称已安全保存，也不能继续写出新的明文副本。只有配置文件实际缺失才使用默认值；持久引用缺失、Keychain 被锁定、访问被拒绝、不可用或存储失败均返回可区分错误，阻止启动或该次保存，不能用空配置继续，也不能静默回退到旧明文、空密码或其他 scope 的秘密。仅本次连接输入的 connect-time secret 不自动持久化；取消、失败及草稿销毁沿既有秘密释放规则处理。

导入用户选择的外部主机文件使用 `store.loadHostsForImport`，只读取配置并解析凭据引用，不对导入源做明文迁移或写回；真正保存到应用自有配置时才执行上述持久事务，不能为导入改写用户原文件。

### 4.2.3 清除全部应用数据与退出

数据设置新增“清除全部应用数据…”入口，与“清理已结束会话”分别呈现。确认页明确这是不可恢复的本地数据删除，主按钮为“清除并退出”；取消及 Escape 不改文件或 Keychain，并将焦点恢复到入口。卸载 `.app` 默认保留用户数据；本版不监听 Finder 删除应用，也不承诺自动卸载清理。

确认 Modal 为 520×300，默认焦点在“取消”；打开确认本身不派发删除。说明分别列出“配置、主机、会话记录、缓存与诊断日志”“此应用范围的钥匙串凭据”和旧根残余，以及共享 known_hosts、外部私钥和用户下载/导出文件的保留范围。工作中显示“正在清除应用数据…”，禁用操作按钮和 Escape；门禁阻止状态显示宿主给出的原因。设置中的数据位置展示实际 config/cache/log 路径，密码与 API Key 的持久化提示为“存储于 macOS 钥匙串”。

| 清除范围 | 必须保留 |
| --- | --- |
| 当前实例的 Application Support、Caches、Logs，以及默认实例的旧 `~/.zerowork` | 共享 `~/.ssh/known_hosts`、用户选择的外部私钥 |
| 当前实例 Keychain scope 的应用专属 vault 及其中全部凭据 | 其他应用、默认/其他隔离实例的 Keychain 条目 |
| 应用内部配置、会话历史、记录、检查点与缓存 | 用户下载、导出或另存到受管根以外的原文件 |

清除由宿主生命周期统一执行。所有窗口的会话、传输、AI 和后台操作必须 idle；打开确认时检查，用户确认时再次检查，不能只看当前窗口或以按钮禁用代替执行门禁。确认后先阻止新任务并暂停所有持久写入，冻结其他窗口普通输入和业务轮询；随后 `data_lifecycle.beginReset` 同步建立当前实例的私有 `Support/.reset-pending` 标记，并关闭诊断日志，成功后才删除当前 scope 的 Keychain vault 与受管文件数据（清除仅按 service/account 元数据定位，不先读取或解密 payload，旧签名或不可读秘密不能阻止独立的删除尝试），避免日志、设置退出回写或后台回调重新创建已删除内容。正式 App 与隔离测试实例均适用该顺序，不能在删除 Keychain 之后才设置恢复标记。

文件清理由 `data_lifecycle.eraseOwned(io, &paths)` 执行，返回 data/cache/diagnostic/legacy 各区域的成功或具体失败。验证 reset 标记后依次清除 legacy、cache、diagnostic，最后清除 data；data 根内的其他内容先删除，marker 最后删除，最终 rmdir 失败时通过仍打开的目录句柄重建并同步 marker；前三项任一失败时保留 data 和标记，返回 `ResetIncomplete`。启动 prepare 首先检查该标记，阻止重新导入或恢复业务，重试成功才随 data 移除。隔离测试实例只清除精确隔离根，其内部已包含 cache、logs 与隔离 known_hosts。诊断日志 shutdown 在写锁下关闭文件，后续 write 不得重新落盘。

全部删除成功才正常退出；下次启动是空状态，且不能从旧根复活配置。任一步失败必须显示“清除未完成，应用尚未退出”、失败位置和已完成/剩余的清理状态，不显示成功、不假定已删除的秘密可以恢复，也不自动正常退出冒充完成。一旦开始破坏性操作，失败后仅允许重试清除或退出，不能返回可编辑 App；其他窗口和持久写入继续冻结，防止内存快照重建已删数据。重试沿同一安全边界处理剩余数据。重启遇到 `ResetIncomplete` 时，以原生 NSAlert 提供“继续清除并退出”或“取消”；取消不进入普通 App。其他启动错误以原生提示明确保留数据并停止，不能静默忽略。删除范围须在路径检查后确定，父路径与受管顶层 symlink、特殊路径或不受管路径明确失败；受管树内部的 symlink 只 unlink 链接本身，不能递归跟随外部目标。

本轮原型使用现有本地 Figma Bridge 文件 `session-mvlqbdlp-rlzzih`，页面 `214:329905`；三主题确认 root 为 `1391:274863` / `1391:274999` / `1391:275013`，失败/阻止/工作中 root 为 `1391:274921` / `1391:274945` / `1391:274933`。已导出的设计图为[深色确认](../DEVELOPMENT/V0.2_STATUS.md)、[浅色确认](../DEVELOPMENT/V0.2_STATUS.md)、[Sauber 确认](../DEVELOPMENT/V0.2_STATUS.md)、[失败](../DEVELOPMENT/V0.2_STATUS.md)及[阻止](../DEVELOPMENT/V0.2_STATUS.md)。设计导出不能替代最终契约与实际 zenit 截图的对齐验收。

## 5. 配置复用与独立传输

### 5.1 配置解析

```text
ConnectionConfigResolver.resolve(asset_id, expected_protocol) -> ConfigSnapshot
ConfigSnapshot { asset_id, revision, nonsecret_config, credential_reference }
TransportFactory.openOwned(owner, frozen_route, purpose, cancel) -> OwnedTransport
OwnedTransport.openTcpStream(destination) -> OwnedStream
OwnedTransport.close() -> ReleaseReceipt
```

以上为待实现的最小接口。解析器只读 AssetStore，不按地址寻找活跃会话。插件可复用已保存主机的地址、端口、账号、认证方式/密钥引用、显式选定的有序跳板配置、信任策略及明确选择的网络/转发配置；不会继承 SSH 启动命令、PTY、终端环境或原转发监听端口。

每次新连接/手动重连按显式平面 route 逐项解析 SSH 配置引用，检查缺失、类型、版本、重复资产/规范端点及 route 长度上限，并冻结各资产 revision；不递归继承所选主机自身的 route。路径编辑、预览、测试和启动复用 SSH 的有序跳板契约与公共解析器，支持增删及调序。沿用最多8台跳板的产品限制；SSH最终目标独立于route，KVM最终BMC为TCP目标，不作为SSH登录节点，也不额外增加第9台跳板。当前 hop_plan.Plan 的末项仍是SSH登录目标，不能把BMC塞入该数组；公共传输 facade 必须区分有序SSH节点与最终TCP destination，并用8台SSH跳板→BMC的夹具验收。各引用按一致的AssetStore读取快照解析，不能混合编辑前后的revision；无法取得一致快照时整次解析重试或报配置冲突。自动重试使用本次冻结值；运行中配置编辑/删除不打断已建连接，下次新建/手动重连重新解析，失效时要求修复引用，不用活跃会话补齐。

创建与启动共用配置管线：editor.validate/encode产生ConnectionEnvelope，保存只增加AssetStore原子提交；保存并连接、侧栏连接、手动重连最终调用同一SessionHost.open(envelope, intent)，由其分配独立owner/attempt并调用一次session_factory.create，后者启动插件controller。临时连接使用未入库envelope进入同一入口。probe复用校验、冻结、凭据挑战和建链能力，但使用probe目的及独立临时owner，不调用完整视频启动。禁止为创建表单另写一套会话启动逻辑。open 是本版拟新增的统一入口，底层沿现有 SessionHost.create/adapter 生命周期扩展，不是第二个会话宿主；同一用户提交以request key去重，保存回调与按钮回调不能各启动一次。失败页持有原连接信封及完整有序配置引用，重试不能从失败节点重造单跳配置；返回编辑复用同一配置草稿。手动重连保留原Tab归属并生成新attempt；自动重试沿冻结快照，不能触发新建表单。

### 5.2 运行所有权

每个新会话都建立自己的 native SSH Session、socket、channel、监听器、IO owner、队列和取消源。不能复用其他 SSH/SFTP/KVM 会话或正在运行的 SOCKS/端口转发，即使配置完全相同也必须独立。引用 SSH 资产不要求先打开其终端。

TransportFactory 复用 SSH connector、known_hosts、认证挑战和 direct-tcpip 的实现代码，为当前 owner 新建无 shell 路由。多跳逐跳创建自己的资源；最终 BMC 等 TCP 目标不是需要认证的 SSH 节点。同一会话内部可由唯一 IO owner 公平驱动至少两个并发 TCP stream；通过有界队列/socketpair 暴露，禁止多个线程直接并发调用同一 libssh2 Session。

默认内部流转发，无公共监听端口。网络库必须使用 TCP 入口时，为当前会话单独绑定 `127.0.0.1:0`，动态端口不持久化、不接管用户端口或停止占用者。现有转发配置只能作为非秘密选项输入，经插件重新校验后新建本次资源，不能据其 ID 取得运行实例。TLS/HTTP 池也局限当前会话。

原 SSH/转发的关闭或重连不得影响插件；插件取消、失败、关闭也不得改变原会话。跨 Tab 的管理写入协调仅按资源键互斥任务，不共享连接、凭据、token 或生命周期。

## 6. 服务、公共上下文与生命周期

HostContext 只提供受限 facade：sessions、assets、connection_configs、transports、credentials、trust、tasks、notifications、audit、presentation。credentials 按当前授权解析引用；SSH host key 与 TLS 信任使用独立命名空间；tasks 提供取消、有界调度与资源键写操作协调；presentation 提供内容挂载和主线程 FrameTextureSink。插件不持有其他插件私有实例。

服务以 `ServiceKey{name,major}` 定位，另带编译期类型 token、版本化 vtable/context。字符串加 `anyopaque` 不是类型安全；注册和查询必须核对接口，不做错版强制转换。内置服务名保留，扩展使用插件命名空间；消除闭 ServiceKind 和服务位图。

区分 declared（实现）、available（本会话绑定）、authorized（本次允许）。必需服务要求可绑定；输入服务存在但只读不阻止画面打开。可选服务返回 unsupported、temporarily_unavailable 或 denied 及原因/revision，不能只返回布尔值。调用复核当前 binding、权限与 generation。

宿主分配 SessionHandle{slot,generation}、OperationKey 和 owner；worker 只发带代际的事件，主线程消费。旧完成仅释放资源，不挂回新 Tab。create/cancel/close/release_stale 幂等；controller 使用这条生命周期，不再私建会话注册表。

renderer 契约为 mount(context,binding)、update(snapshot)、focus_changed、unmount。视图和网络 owner 分离：窗口移交只移 view，不复制网络；主线程拥有图形资源，worker 只发布 CPU 数据。纹理 facade 在本版以合成 RGBA 帧验证，不等到 KVM 才补私有入口。

关闭先停止输入/新操作，尽力释放远端输入，再取消/排空任务、关闭本次协议会话和流/监听器、stop/join IO worker、逆序释放本次跳板，最后释放 binding、主线程图形资源与秘密。网络不可达不阻止本地回收；远端操作/注销未知与本地已释放分别记账，不伪造撤销成功。全应用退出由宿主协调各独立 owner。

### 6.1 全局统一通知

当前已有 `src/host/notification_host.zig`、`notification_coordinator.zig` 和 macOS 通知驱动，处理传输、重连、AI 及注意标记，不能说全局通知不存在。但 `Kind` 仍是三项闭枚举，publish 接口按业务分别接线；`terminal_surface.zig` 的复制/错误提示又由视图直接创建。它们尚未形成插件可调用的统一应用内呈现链。本版沿现有 Host/Coordinator 扩展，不另建 KVM 通知系统；V0.1.8 的系统授权、勿扰和既有设置继续有效。

```text
Plugin Controller / Builtin Service
  → HostContext.notifications.publish / update
  → NotificationHost（身份、代际、定义、操作 revision 校验）
  → Coordinator（去重、更新、优先级与渠道策略）
  → 窗口唯一 NotificationPresenter（Toast / owner 注意标记）
  → 既有 macOS adapter（仅符合现有系统通知策略的事件）
```

注册 `NotificationDefinition{id,version,category,default_channels}`，ID 使用稳定命名空间；类别为操作结果、连接变化或注意事件。插件只提交类型化内容/动作，不提交颜色、坐标、UI 节点或自定义通知 renderer。通知定义进入清单校验，未知定义拒绝，不为每个插件增加通知枚举。Local/SSH/SFTP 的旧事件由兼容绑定保留原设置键；KVM 管理结果默认应用内反馈，连接变化复用已有 reconnect 策略，不新增 KVM 专属设置或每次请求系统授权。

公共事件含 `definition_id, owner, operation_id, attempt_id?, event_revision, phase, severity, title, detail, actions[]`。owner 含窗口/内容身份与 generation。phase 区分 accepted、verifying、succeeded、failed、outcome_unknown、cancelled；HTTP 接受不得当作 succeeded。相同 owner+operation+attempt+定义构成同一通知事实，单调 revision 更新原记录，例如“已接受→已核实”或“结果待确认→查询结果”；重复投递/旧 revision 不再弹出。同一 operation 的合法后续阶段不能被现有终态冲突判断拒绝，也不能新建多条重复成功通知。业务结果仍由 OperationStore 持有，Toast 生命周期不决定业务状态。

2026-10-29 全局通知收口以[当前通知契约](../UI_V3/notifications/README.md)为准。公共事件新增可选 `attention` 事实：业务类别、需要介入、时效、来源可见性、恢复状态及宿主确认的共享 incident ID。未声明时为局部事件；warning/failure、后台运行或一段错误文字不产生全局资格。宿主复验窗口、来源与实际焦点，普通 AI 结束/失败、命令失败、单文件失败、主动连接失败和自动重连过程留在来源模块，不进入全局列表或未读。

窗口仍只有一个公共 overlay Presenter，复用现有主题与卡片，按内容区右上角锚定并避让 Popover。每窗最多一个横幅；新事项替换普通横幅，应用级持续保存风险优先。被替换、关闭、过期或被勿扰抑制的事项只留在列表，不排队补弹。普通需介入横幅 4 秒、有定位动作 8 秒，hover/键盘焦点暂停；只有持续应用风险保持到关闭或来源更新。全局动作只定位来源；认证、审批、重试和实际核查留在原业务入口。

提醒列表复用顶栏入口，分“待处理”和“最近提醒”。稳定事件/单调 revision 更新原记录；同一宿主确认的共享链路故障按 incident ID 聚合，所有来源都恢复才结束。查看列表只标已查看、关闭只收起横幅，均不解除待处理；清除只删除已结束项。最近历史上限 100，活动事项不因上限丢弃；清除/淘汰后的标量去重记录继续防止旧事件补发。owner 结束后不再弹出或重建同名会话，原记录保留结束事实。

应用前台使用应用内横幅，离开应用才提交系统通知；系统授权、勿扰与真实投递回执独立。普通后台完成默认关闭，仅显式开启的传输/AI 最终完成提醒生效；配置已有保存值继续使用，不在读取时覆盖。打开列表时直接更新列表并收起横幅；切换焦点、偏好或权限不补发旧事件。终端 Bell 和输出圆点仍是独立偏好，不获得全局通知资格。事件内容保持脱敏，不包含凭据、token、画面或输入正文。

原生接入与验收：统一准入、原位更新、共享 incident、待处理/已查看/横幅/系统回执独立；来源核验包括自动恢复停止、AI 审批阻塞与实际远端效果未知、终端录制失败。当前传输模型只有单任务终态，未凭单文件失败虚构“批次停止”；只有真实业务控制器提供批次影响事实时才升级。测试覆盖重复/旧 revision、来源恢复、多窗口/owner 结束、关闭/查看/清除、勿扰、最小窗与主题；真实业务验收与合成展示验收分别记录。

## 7. AI 接入

工具定义和绑定分离：`ToolDefinition{id,version,schema,policy}` 全局唯一；`ToolBinding{plugin_id,definition_id,handler,required_services}` 可多份。共享定义可由多个插件合法引用；同 ID 不同定义或同插件重复绑定才冲突。所需服务必须已声明，服务存在不自动产生工具。

| 既有工具 | 策略 | 插件绑定 | 所需服务 |
| --- | --- | --- | --- |
| `read_terminal` | read_only | Local、SSH | terminal |
| `run_command` | confirm | Local、SSH | exec |
| `list_remote_files` | read_only | SSH、SFTP | directory |
| `read_remote_file` | read_only | SSH、SFTP | file_read |

会话助手只获得该会话插件工具；组助手按定义合并，逐成员检查绑定，不能把不支持的目标改派到其他会话。每插件最多 8 项、每请求最多 16 项；注册超限拒绝清单，组并集超限只拒绝本次请求并提示缩小目标。provider 按请求定义组装参数，移除工具枚举解析与四项固定上限。

新工具内部 ID 可为 `fixture_probe.ping`，通过统一可逆编码器变为 provider 合法名称（如 `fixture_probe__ping`）；注册检查字符、长度与碰撞。模型返回名只从本次不可变请求表解析，不能调用请求外工具。保留四个旧工具模型可见名和原参数/权限语义。

宿主校验参数、目标、generation、权限、服务版本、超时和结果体积；模型不提交裸句柄。confirm 沿现有权限引擎，静态可信插件自称只读不能替代代码审查。日志/结果脱敏、取消与截断沿公共机制；离线返回 unavailable，不编造成功。

## 8. 三个内置 provider 的兼容接入

“内置”决定产品必带与依赖地位，不能绕过注册、服务和生命周期契约。**Local ZSH、SSH、独立 SFTP 全部迁移是0.2的必交付项，不能只迁移测试插件或给旧入口套一层PluginManifest。** 保留 PTY、VT、libssh2、SFTP、历史和传输实现位置，通过适配器实现统一契约，不为目录整齐重搬引擎。适配器位于provider边界；公共宿主不得绕开它继续直接调度旧连接实现。

| provider | 创建/内容 | 配置与服务兼容 | 图标兼容 |
| --- | --- | --- | --- |
| Local ZSH | 本地快捷入口，无远程资产；共享 terminal renderer | 必需 lifecycle/terminal/process/cwd/exec；保持现有 ZSH 行为与本地设置 | 设置 terminal，Tab local_apple，归档保留 Apple |
| SSH | saved_or_temporary；共享 terminal renderer | 保留完整 HostConfig；必需 lifecycle/terminal/auth/route/exec；既有 process/cwd/forward/transfer/directory/file_read 按当前 binding 开放 | 设置 server、协议 terminal；Tab 保留已验证 OS 投影及 terminal fallback，归档 history |
| SFTP | saved；file renderer | 保留已有字段/限制；必需 lifecycle/auth/route/directory/file_read/transfer；独立文件会话 | 设置 folder、协议 folder_open、Tab folder，归档 history |

SSH 附加目录/文件能力仍由既有附加独立连接提供，不变成终端常驻 SFTP 或隐式新 Tab。SFTP 可复用 SSH 的配置和公共传输实现，运行连接保持独立。本地不进入远程协议列表；SSH 保留临时连接，SFTP 仍先保存。三个插件偏好分区为空时仅显示现有身份卡，全局重试/传输偏好仍由原公共消费者生效。

### 8.0.1 必须迁移的调用边界

| 边界 | 三个内置provider必须统一的路径 | 允许保留的差异 |
| --- | --- | --- |
| 发现与创建 | 同一个Registry生成创建入口、协议清单、设置身份与可用状态；快捷键/侧栏/历史恢复也经注册贡献定位创建工厂 | Local不需远程资产；SSH支持临时连接；SFTP要求先保存，由创建策略声明 |
| 配置与编辑 | 统一资产信封、schema版本/codec、编辑槽与保存事务；创建/编辑/复制/恢复不能另走旧HostConfig构造入口 | 协议字段、专用校验和editor/controller由provider提供；旧配置解析仅在兼容codec边界 |
| 会话生命周期 | 所有入口经同一SessionHost的open/connect/cancel/reconnect/close；同一owner、generation、事件与逆序释放规则 | provider内部使用PTY、本机进程或SSH/SFTP引擎；Local退出语义不能伪装成网络重连 |
| 服务与能力 | terminal、exec、route、auth、directory、file_read、transfer、forward等均通过typed binding注册、查询和撤销 | 能力可因会话状态改变；无能力不注册空实现，不用永远成功的占位服务 |
| 内容与公共UI | 内容槽挂载renderer，标题/图标/状态/菜单/底栏/快捷键读取同一CapabilitySnapshot和状态投影 | Local/SSH复用终端renderer；SFTP复用文件renderer；操作系统图标来自可信状态贡献 |
| AI与操作 | 统一工具目录、owner作用域、参数校验、审批、取消、结果和审计；旧四工具保持外部名称和语义 | 终端命令风险分类在对应规则适配器内；SFTP不能假装提供terminal/exec |
| 跨会话功能 | 组、广播、历史、转发和传输通过服务/贡献访问原owner；全局任务独立于当前会话显隐 | 只向声明相应能力的成员派发，禁止把不支持的成员重定向给另一连接 |
| 反馈与挑战 | 统一ChallengeHost、通知事件/Presenter、认证结果匹配、错误/取消和焦点恢复 | SSH host key、凭据和协议错误的内容由provider/公共认证服务生成 |

注册快照是唯一业务入口来源；不存在“内置先查旧枚举，其他才查Registry”的双轨分派。测试可替换/移除某一内置manifest来验证入口和服务确实受注册控制，生产仍必带三种provider，这不新增用户卸载内置插件的产品功能。

### 8.0.2 禁止以兼容名义保留的旁路

- wizard、settings、workspace、SessionHost、侧栏/Tab/底栏、组、AI/provider等公共业务模块不得以Local/SSH/SFTP或插件ID进行连接创建、能力判断、工具分派、内容选择和UI显隐；把旧switch搬到一个“万能插件适配器”仍不合格。
- 公共宿主不得import并持有具体PTY/libssh2/SFTP会话实现、向下转换插件context，或从活跃SSH会话提取连接供其他会话复用。公共transport/认证实现可以使用libssh2，其资源须属于当前owner。
- 不允许插件声明与公共菜单各维护一份能力表；不允许先显示/派发再由空实现吞掉不支持的动作；隐藏动作仍必须在执行门禁拒绝。
- 不允许迁移后仍由原全局事件消费者和新插件消费者同时处理同一事件，造成重复连接、重复工具派发、重复通知或两次释放。
- 仅允许兼容codec识别历史协议枚举，以及插件自身实现中的协议分支、组合注册模块中的显式注册、工具参数的类型化分支。实施审查必须列出这些保留点及原因；不得借允许项重新引入公共业务分派。

### 8.0.3 三种连接的行为回归基线

| provider | 必须保留并实际验证的行为 |
| --- | --- |
| Local ZSH | 快捷创建/新Tab/分栏均走注册工厂；真实PTY启动、输入/IME/尺寸变更/进程退出、cwd与独立exec、历史归属、本地设置与Apple图标；关闭不会影响其他owner |
| SSH | 已保存和临时连接、认证挑战/host key、跳板顺序与失败/取消、断线重连及旧generation丢弃；真实终端与独立exec、附加文件连接、转发/传输/组内能力和设置保持；原SSH关闭不影响独立SFTP或引用相同配置的插件 |
| SFTP | 保存后创建独立文件会话、目录/文件读取、上传下载/冲突/暂停恢复/取消及关闭后的任务归属沿既有规则；未知或不支持的跳板/功能明确禁用；不分配终端或exec占位服务，不依附活跃SSH连接 |

兼容基线还包括资产ID/分组/默认值/未知字段往返、旧工具名称/参数/权限、主题、最小窗、归档图标、全局重试/传输配置与现有错误文案语义。迁移不能以“接口统一”为理由减少已有能力或偷偷修订产品行为。已知旧实现缺口应单独列出，不计作迁移通过，也不隐式扩展本版范围。

## 8.1 公共 UI 能力投影契约

每个入口声明 scope=application/session、required_services、visibility_policy 和 action_id。宿主从同一 CapabilitySnapshot 计算 visible/enabled/reason/revision；菜单、底栏、快捷键、程序化调用与AI执行共同消费，不按插件ID分支。插件不支持的会话功能隐藏且不占槽；支持但断线、未授权或暂不可用时禁用并显示原因。隐藏不是授权，执行前仍复验服务与权限。用户外观偏好不得覆盖安全门禁。

| 公共功能 | KVM 投影 |
| --- | --- |
| 资产、Tab、重命名、编辑、重连、关闭 | 保留，绑定原owner |
| 当前会话文件列表、上传下载、传输列表及底栏进度 | 未声明transfer即隐藏，不保留空槽 |
| 全局传输管理器 | 保留应用入口；其他SSH/SFTP任务继续且标原归属 |
| shell/cwd、命令历史/补全/搜索、终端广播与终端组 | 不适用即隐藏，快捷键同样不可执行 |
| SOCKS/用户转发 | 未声明forward隐藏；内部SSH路由不产生forward能力 |
| 连接/路由详情 | 显示本会话真实路由，不引用活跃SSH |
| 录像/回放 | 未声明recording隐藏；截图不意味着录像 |
| AI | 按ai能力开放，与terminal解耦 |
| 底栏 | 按适用状态贡献组合；无内容分区收起，不重复堆放工具栏信息 |
| 全局设置、审批、通知、停止/接管 | 插件不能关闭或屏蔽其他owner任务 |

## 8.2 通用接入 API 冻结要求

以下接口须在0.2由fixture实际消费，不仅预留字段。名称为待实施契约，非已存在源码API。

- EditorHost.openChild(parent_editor_id, draft_revision, contribution_id, intent)返回request_id；完成为saved(asset_id, revision)/cancelled/failed。父草稿销毁或revision不匹配时不回填；子编辑器仅经宿主访问注册贡献，不持有其他插件私有实例。临时连接进入同一open入口，不写资产。
- ContentContext提供受限input和window facade：acquire/release输入租约、撤销事件、原生全屏请求/状态与窗口移交；不交App指针。宿主先处理最高层挑战/浮层及保留快捷键，再按租约路由内容输入，单个事件只消费一次。人工焦点租约与自动化执行租约分离；切换owner、失焦、关闭、撤权撤销对应租约，不能在AI面板获焦时将自动化误判为普通键盘输入。
- ChallengeHost.offer(owner, request_id, generation, kind, payload, deadline)支持secret_input、trust_material、choice；答复必须匹配原请求。支持服务端撤回、超时、后台来源提示与取消；信任材料、选项和密码生命周期分开，秘密不入快照/日志。
- ServiceBinding明确类型token、major、context/vtable、owner和generation；注册/查询均核对类型。同步借用仅在调用期间有效；异步请求拥有参数副本；结果显式release。UI资源仅主线程，worker经有界队列发布。能力变化发布revision，所有消费者拒绝旧绑定。
- AiContextContribution提供身份、状态与可选上下文；terminal上下文是可选贡献。移除助手入口、作用域、发送与上下文组装的terminal硬门禁，未提供terminal的插件不得伪造终端服务。
- ToolDefinition包含版本化参数schema、业务校验器、required_services、effect和approval_policy。宿主验证schema和目标，插件验证业务值；不保留command/path专属公共参数结构。旧四工具保持原语义。
- ToolResult为status＋text/structured/image_ref内容块＋来源/操作回执。ImageRef由宿主管理不可变内容、mime/尺寸/预算/引用释放；不以路径字符串或base64文字冒充模型可见图片。UI通用结果卡和provider adapter消费同一结果；声明图像输入/工具图像结果能力，不支持时明确拒绝，不静默丢图。插件不拼provider请求。
- PolicyHost统一read_state、observe_image、remote_input、resource_write效果类别及按工具声明的审批策略。always_confirm优先于完全控制；插件或模型不得自行降低策略。shell命令分类保留为终端规则，不用于判断所有图形动作。
- OperationStore保留目标、参数hash、授权revision、阶段和结果；运行资源与历史记录分离。关闭owner停止新动作并回收资源，保留有界脱敏结果/unknown；记录保留到显式清理或既有保留策略到期。旧binding不能查询网络；重新查询须显式新建授权的只读操作，不复活旧会话。

审批冻结owner/generation、目标、参数hash、能力与策略revision、有效期；参数改变、重连、权限变化或过期须重新审批。取消未发送为cancelled_unsent；发送后不确定为outcome_unknown，不自动重放。操作去重只保证本应用不重复派发，不承诺远端exactly-once。危险策略不得由UI显隐绕过。

静态插件是可信进程内代码，受限facade与依赖检查属于架构约束，不宣称沙箱隔离。

## 9. 实施顺序与完成门槛

1. **0.2.1：** 注册表/typed services、公共信封及兼容 codec、editor/controller 入口、只读配置 resolver、独立 TransportFactory、受限 HostContext、工具目录、统一通知事件和生命周期；以可控替身验证流与纹理 facade。
2. **0.2.2：** 协议选择、配置承载、设置、侧栏/Tab/状态投影、内容挂载、宿主统一通知 Presenter 与能力菜单全部消费注册快照；迁完三个内置 provider，保留原字段与风格。
3. **测试插件验收：** 只增加 fixture 目录与测试注册调用，完整走新建→离线保存→既有侧栏行→独立连接→内容槽→AI→关闭。通过全部门槛后才进入 0.3。

改造后，wizard、settings、session_icon、workspace、SessionHost、AI/provider 等公共业务文件不得再为新插件添加 ID 分支、闭枚举或手写协议卡片。若缺公共能力，先在本版完成并验证公共契约，不能在 KVM 回调伸入宿主私有对象。

`fixture_probe` 有自己的配置视图、多阶段控制器、独立内容 kind，一个普通偏好字段和一个无默认值的 connect-time secret，以及只读 ping 工具；只需 lifecycle 服务即可打开基础页面。扩展场景引用同一个 SSH 配置，用可控 transport 替身/loopback 验证两个并发流与独立资源，合成 RGBA 验证纹理。它不执行远端命令，不进入生产清单，不强制自己伪装成终端或文件插件。

| 验收项 | 必须观察的结果 |
| --- | --- |
| 注册 | 打乱顺序仍成功；缺依赖/环/错版/冲突拒绝且无部分发布；共享 renderer/工具合法；规划描述符不可创建 |
| 自动接入 | fixture 仅注册即出现在协议选项、设置、资产、Tab、工具和内容槽；公共模块没有 fixture 专属分支或重复外壳 |
| 配置自主 | 非固定三步编辑、条件校验、离线保存、probe 取消与过期草稿结果；未知插件/新版 payload 不损坏 |
| 配置引用 | 缺失/改动/删除/错协议、重复资产/端点和0/1/2/8跳及超限校验；本次冻结、自动重试冻结、手动重连重新解析 |
| 运行隔离 | 原 SSH、原转发及两个 fixture 连接拥有不同 native Session/流/取消源/监听器；无原会话也能建立，任一取消/关闭/重连不影响其余资源 |
| 释放 | 各阶段失败/取消、端口冲突、逆序释放和旧 generation；远端 unknown 与本地 released 分离，无秘密泄漏 |
| 内置兼容 | Local 创建/退出；SSH 认证/重连/附加文件；SFTP 传输/取消；旧配置往返、默认值、权限、归档图标及全局设置不变 |
| 全局通知 | 内置与 fixture 调用同一 facade/Presenter；去重与阶段更新、未知结果/关闭、多窗口/后台、队列、主题/焦点/系统拒绝无事实丢失 |
| AI | 四工具共享无冲突；组逐成员校验；名称编码及上限；confirm 不绕过权限 |
| UI | 三主题、小窗、错误/取消、焦点恢复，公共界面无插件重复绘制；纹理只在主线程处理 |

以上是未来实现的验收要求。本次交付为设计整理，没有将 fixture、公共 API 或 KVM 源码标为已实现。

### 9.1 后续插件接入的强制验收

fixture不提供terminal/exec，必须从实际公共入口完成：配置→嵌套SSH编辑→离线保存/临时连接→独立双流→合成画面→AI看图→结构化模拟鼠标/键盘动作→再观察。验证图像真实进入provider请求及结果卡，不能只测dispatcher。

模拟电源/配置写工具使用always_confirm：完全控制仍待批；拒绝/超时/改参数/重连零派发；批准仅一次；响应丢失只查询。人工接管、停止、队列满、失焦及窗口移交后无旧输入。fixture隐藏会话传输/终端入口，其他SSH传输仍在全局管理器。真实SSH测试验证双流与独立关闭，loopback不替代libssh2所有权验证。

公共业务文件不得有fixture专属ID分支。Local/SSH/SFTP必要回归、未知配置保留、三主题/最小窗、挑战和通知通过后才冻结API。0.2.3的真实KVM自动化不提前实现，但公共多模态与审批链必须先用合成场景证明。

原型以[KVM统一评审入口](https://www.figma.com/design/FOPeYuvmCL86rgev6Niobz/ZeroWork?node-id=1132-223506)和[当前验证记录](../DEVELOPMENT/V0.2_STATUS.md)为准。0.3手动操作细节与0.2.3完整工作区/AI状态是同一插件的不同验证范围，不是两种实现方案。早期60态补充稿已标记历史并撤出入口，不能代替当前原型或业务实现验收。

### 9.2 macOS 数据与 Keychain 的交付验收

§4.2.1–4.2.3 的新增范围须在最终发布候选上完成下表，已有插件宿主、真实 Grok、VM 或旧 DMG 通过记录不能替代新增契约的验证。表内是待完成的验收要求；具体结果、候选 SHA、证据位置和剩余限制由本轮最终交付报告记录。

| 场景 | 必须观察的结果 |
| --- | --- |
| 正式 App 默认启动与现有设置 | 无需配置环境变量即可使用正式功能；功能选项由默认行为、现有设置或对应操作控制。进程环境不能切换功能、覆盖数据目录、注入凭据或启用测试入口；标准路径来自系统账户信息，不新增页面或开关 |
| 隔离测试全新安装 | 测试入口显式构造隔离账户根或 `Paths`，不依赖正式 App 的环境覆盖；目录计算无 IO，prepare 后 Support/Caches/Logs 及权限正确，诊断日志与长期会话记录分离，不修改真实账户数据 |
| 旧配置与会话迁移 | 固定旧数据集的配置、主机 ID/分组/默认值/未知字段和会话记录完整；秘密经受控迁移后 TOML 只有引用；再次启动与中断恢复均幂等 |
| 新旧目录并存 | 缺失项移动、相同项去重、不同项明确冲突；冲突原件及新数据都保留，配置加载停止，不以空配置启动 |
| 路径与权限边界 | 迁移源/目标链接、链接目录链、特殊文件、hardlink 及不安全路径被拒绝；清除内部链接只 unlink；根外 sentinel 字节与权限不变；私有目录/文件为 0700/0600 |
| 隔离测试实例 | 仅测试/自动化构建接受测试入口指定的独立受管路径，不导入默认旧根；cache/log/known_hosts 及 Keychain scope 均隔离；清除一个测试实例不改正式 App 或另一测试实例，不能借隔离测试放宽路径、权限或清除边界 |
| 秘密事务与兼容 | 密码/API Key/私钥口令/TOTP seed 读写与现有 provider 一致；普通 save 和明文 load 都脱敏；已知秘密不出现在日志/诊断，未知插件载荷无损往返，connect-time secret 不自动保存；外部导入源字节保持不变 |
| Keychain 使用体验 | 固定签名及安装路径，同一 App 首次保存后连续两次退出重启，密码和 API Key 均可用且不要求重复输入系统密码；不使用外部 observer 读取秘密。每 scope 仅一个 vault，进程内 cache，系统交互关闭，拒绝/锁定明确报错；达不到用户条件则撤销 Keychain |
| 同 scope 多进程 | 读取/迁移前获取独占锁，第二进程明确拒绝；正常退出释放并清理运行锁，崩溃后可恢复；仅隔离测试构建中不同受管实例可并行，凭据 scope 和路径均不共享 |
| Keychain 失败与回滚 | 替身 backend 覆盖缺失引用、访问拒绝、写入失败及 TOML 原子提交失败；原配置/原凭据保持，新条目回滚，无跨 scope 回退或删除；两配置引用并集、解析失败不 GC、pending/orphan 回收有界；真实 Keychain 只使用明确隔离的验收 scope |
| 清除门禁与失败 | 活跃会话、传输、AI、后台工作及第二窗口均阻止清除；确认前状态变化再次拒绝；先同步 reset marker 再删 Keychain，覆盖两者之间崩溃；模拟部分失败显示准确状态，仅重试/退出且其他窗口冻结；重启 NSAlert 的继续/取消均不进入可写 App，重试完成后移除 marker |
| 原生取消与确认 | 经公开数据设置入口验证取消/Escape 零改动及焦点恢复；明确确认后当前 scope 与全部受管根清空、外部私钥/共享 known_hosts/用户导出保留，进程正常退出 |
| 清除后重新启动 | 空状态，不从 legacy 重新导入，不复活历史或秘密；取消清除后的重启仍能读取原数据 |
| 设计与实际窗口 | 本地 Figma Bridge 目标文件中的原生可编辑确认流程已保存，导出设计图；查看真实 zenit 窗口截图并对齐尺寸比较，覆盖必要窗口尺寸及主题 |

| 新 DMG 安装验证 | 基于完成上述改动的候选重新打包，记录 App/DMG SHA；挂载检查包内容、从 DMG 的应用验证启动与标准路径行为，最终交付指向本轮新包 |

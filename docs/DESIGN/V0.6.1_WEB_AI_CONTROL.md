# V0.6.1 AI 浏览器交互（可选、非必要）

> 状态为可选扩展设计，待实施。依赖 V0.6 的网页插件、真实 WebView 会话和已交付的附着式 AI 工具链。可以延期或不实施，V0.6 的发布与验收独立完成。选择实施本扩展后，本文列出的核心交互和验收成为 V0.6.1 的交付要求。

## 1. 用户目标与入口

用户在网页连接页签打开既有 AI 助手，用自然语言要求读取页面、查询和筛选、翻页、填写表单以及执行已授权的页面操作。AI 操作当前绑定的网页实例，使用同一条直连或 SSH 路径及同一份网站登录状态。切换网页、重连和人工接管都通过宿主身份与控制权管理。

示例流程为「打开告警中心，筛选最近一小时的严重告警，汇总数量和来源服务」。AI 观察现有页面，点击告警入口，选择时间和级别，执行查询，再读取更新后的列表并给出结果。填写和提交是两个独立动作，界面反馈应能看出当前正在观察、输入、等待还是完成。

入口复用当前页签的 AI 浮窗、消息、工具卡、审批与停止按钮。工具仅在本扩展已实现且绑定目标具有浏览器能力时发布。V0.6.1 为交付可选项，不要求为了可选标记增加一个全局开关或第二套浏览器页签。

## 2. 核心能力与范围

| 能力 | 交付要求 |
| --- | --- |
| 观察 | 返回当前地址、标题、可见正文摘要及可操作元素，可按需附当前网页视口截图 |
| 导航 | 打开有效 HTTP(S) URL、前进、后退、刷新，沿 V0.6 的页签路径执行 |
| 点击 | 根据当前观察中的元素引用点击可见且可操作的目标 |
| 输入 | 填写 input、textarea、可支持的 contenteditable，选择下拉项和设置勾选状态 |
| 滚动与键盘 | 滚动页面或已识别容器，向已验证的目标发送 Tab、Enter、Escape 等有界按键 |
| 等待与复查 | 等待目标出现、值变化、导航完成或页面结果，然后取得新观察 |
| 中断与接管 | 用户停止、直接操作页面或关闭连接时，撤销后续 AI 输入 |

最低兼容范围为主文档、可访问的同源 iframe 和 open shadow DOM 中的常见 HTML 控件。跨域 iframe 只有在对应 frame 已注册并经平台验证时才提供能力，否则返回明确的不可访问原因。canvas/WebGL 内部语义、closed shadow DOM、浏览器扩展、CAPTCHA、系统 Touch ID、文件选择器与独立弹窗登录不纳入核心验收。遇到这些步骤允许用户接管，完成后重新观察继续。

网站内容与截图只在当前任务需要且权限允许时发送到所选 AI provider。普通连接和人工浏览不持续采集页面。自动化不获取 Cookie、Authorization、localStorage 或网站密码明文。敏感输入可由用户在页面完成，未来如接入已有秘密引用服务，工具结果和日志继续只记录引用与执行状态。

## 3. 接入结构

```text
当前对话 / 绑定的网页会话
  → 既有工具目录、权限策略、审批和任务预算
  → web.ai_control typed service（拟新增）
  → 网页 controller 的身份、导航和输入协调
  → WebKit 平台适配器
  → 当前 WKWebView 与 V0.6 的网络路径
```

web 插件追加 AI 工具贡献、页面观察和执行服务，继承原有 session factory 与 renderer。人工浏览、书签和 AI 导航共用 controller，任务结束只释放 AI 控制权。既有 content_context 的自动化租约、取消标记、授权 revision、输入接管和 tool operation 账本可复用，需要补齐 NSView 输入绕过普通 Zenit 事件路径的挂接。[控制权接口](../../src/host/content_context.zig) · [现有 KVM AI 服务参考](../../src/plugins/bmc_ikvm/ai_control.zig)

平台适配优先通过 WKWebView 的指定 frame/content world 脚本调用执行固定的观察与交互程序，模型只提交结构化参数。脚本参数使用 arguments 传入，避免把用户文本拼进脚本源码。网页观察脚本随插件交付，模型不获得任意 JavaScript、系统命令或额外网络请求的执行入口。DOM 输入、事件分发与真实用户激活的差异要通过目标站点测试，对要求 trusted input 的控件返回不支持或用户接管，不能以调用无异常宣称输入成功。[Apple 脚本调用](https://developer.apple.com/documentation/webkit/wkwebview/callasyncjavascript%3Aarguments%3Ainframe%3Aincontentworld%3Acompletionhandler%3A)

隔离的 WKContentWorld 用于避免脚本变量冲突。DOM 修改仍可被页面脚本看见，不将该命名空间当作安全隔离或可信页面证据。平台 frame 注册表记录对应会话、文档代次和 origin，旧 frame 失效后销毁引用。WKFrameInfo 是短期对象，不能以对象地址作为跨回调的稳定 frame ID。[Apple WKFrameInfo](https://developer.apple.com/documentation/webkit/wkframeinfo)

如果使用脚本消息 handler，只接受当前会话与有效 frame 的有界观察回执，并复验其 generation 和请求 ID。消息体始终是不可信输入，页面消息不能触发新工具、扩大权限、改变 SSH 配置或调用宿主文件/终端服务。结束任务时移除临时观察对象与 handler，公共浏览器生命周期继续由 V0.6 管理。

## 4. 观察与元素引用

一次观察至少包含下列身份及内容。

| 字段 | 含义 |
| --- | --- |
| owner / binding_revision | 捕获的 SessionHandle、会话 generation 与当前对话绑定版本 |
| page_generation / document_generation | 当前 WebView 实例与已提交文档代次 |
| observation_id / timestamp | 本次观察 ID 与采集时间 |
| frame_ref / origin | 当前平台登记的 frame 引用与实际来源 |
| element_ref | 此文档内由宿主登记的元素引用，与快照绑定 |
| role / name / state | 控件语义、可见名称、可用性、选中状态及可披露值 |
| text / bounds | 有界可见文本与视口坐标，用于解释和验证目标 |
| image_ref / transform | 可选截图引用、裁剪及像素坐标变换 |
| incomplete / reason | 因预算、跨域、隐藏结构或平台限制而缺少的信息 |

观察只收集任务所需的可见内容和可交互控件，隐藏 input、密码值、脚本源码和存储凭据不进入结果。文本、元素数量、截图尺寸和请求序列化沿用现有工具/图像预算，超限分页或说明截断，不能把截断摘要声明为页面全部数据。

每次执行前复验元素仍属于当前文档、类型与关键语义一致、仍可见、启用且具备所需操作条件。重载、跨文档导航、WebView 重建和接管使旧引用失效。普通动态内容更新不使整份观察无条件失效，但变化的目标必须重新观察，禁止在引用失效后自动寻找第一个同名元素继续点击。

截图从 WKWebView 的内容快照取得，只包含网页视口，经过现有图片预算与工具结果通道返回。模型不支持图片时仍可使用文本观察。历史图像可用于解释记录，新的输入仍要复验当前页面。截图不是操作成功的唯一证据。[Apple 网页快照](https://developer.apple.com/documentation/webkit/wkwebview/)

## 5. 工具契约

下列七个工具名为拟定契约，实施时经插件工具注册校验后冻结。目标会话由本次 invocation 绑定注入，模型参数不接受任意系统窗口、调试端口或进程 ID。

| 工具 | 核心参数 | 返回与校验 |
| --- | --- | --- |
| web.observe | 可选区域、内容上限、截图开关、等待条件和有界超时 | 新观察、当前目标信息、截断/不可访问原因。等待可取消 |
| web.navigate | open/back/forward/reload、open 的 URL | 导航 operation，沿原会话路径，回执区分已受理和页面实际到达 |
| web.click | observation_id、element_ref | 命中目标、已派发范围和后续观察要求 |
| web.set_value | observation_id、element_ref、类型及目标值 | 文本/下拉/勾选的实际读回值，密码类型不回传值，默认不提交表单 |
| web.scroll | observation_id、页面或容器引用、方向与距离 | 实际滚动位置与是否到边界 |
| web.key | observation_id、目标引用、允许的单键或组合键 | 焦点归属、派发结果。Enter 作为独立可能触发提交的动作 |
| web.operation_status | operation_id | 已接受/执行中/已完成/失败/结果未知及可用证据，无重放副作用 |

首版优先元素语义操作，坐标点击、任意脚本、隐式文件上传、Cookie 导出和任意请求工具不作为这七项能力的一部分。扩展到复杂控件时需另补对应目标验证和测试。

## 6. 授权、页面内容与任务范围

复用宿主当前的确认、自动执行和完全控制模式，以及工具读取/输入权限。不得为了每次普通点击再增加一套独立确认开关，也不能把提供了浏览器工具当作对所有网站操作的授权。工具作用范围来自用户当前任务、对话绑定与宿主策略。

观察中出现的网页指令、提示、聊天文本和隐藏内容均作为站点数据处理，不得据此更改任务、选择另一个连接、上传本地文件或扩大权限。导航遇到业务无关的目标、需要新增授权或系统认证时通过现有用户交互机制处理。

待确认的操作展示目标页面、控件、拟变更内容与效果，绑定 owner、document_generation、参数摘要和授权 revision。批准后派发前再次验证目标，关键目标或参数改变时重新确认。已有用户授权足以覆盖的动作继续执行。提交、删除、发布或修改配置等操作按用户授权和宿主策略执行，并读回结果。普通控件的 action 名和网站文字不能自动证明行为无副作用。

现有 always_confirm 为兼容名称，自动模式/完全控制可能跳过基础审批。V0.6.1 的实现和文案必须遵循实际策略，不能仅凭该字段名称声称所有模式都强制确认。[工具权限实现](../../src/ai/plugin_tools.zig)

## 7. 执行、验证与恢复

执行循环为观察 → 形成一个有界动作 → 权限/目标复验 → 按需确认 → 派发 → 等待相关变化 → 新观察或读回 → 记录结果。等待条件优先使用导航提交、元素出现、值变化或加载状态，避免以固定延时推定成功，也不因长期轮询或 WebSocket 使页面永远无法完成等待。

一个网页同一时刻只有一个 AI 输入执行者，沿用宿主任务预算与取消机制。同一工具调用的重试使用 operation_id 去重。再次查询返回已有回执，已派发点击、提交或键盘动作不能自动重发。操作中断而远端结果未知时，先观察或查状态，再由用户任务与当前证据决定后续。

派发成功仅证明本地操作已经执行。填写动作需要读取实际值，勾选需要读取状态，导航需要看到实际目标，查询需要读取结果列表。提交表单后的页面提示作为观察证据记录，不能在没有业务回执时断言服务器已经完成更改。

用户在页面输入、点击星标或书签、手动导航时优先取得控制权，撤销 AI 租约和待发动作。切换到其他页签或窗口失焦时，首版暂停待发 AI 输入。返回后需复验目标并取得新观察。打开助手浮窗本身不等于用户接管网页。宿主「停止」始终可用，不依赖模型再调用工具。

断线、WebContent 退出、重连、新文档和关闭均使相关引用失效。V0.6 完成重连后，用户明确继续任务才能重新观察和恢复输入。任务停止只能取消尚未派发的动作，已发生的站点变更保留真实回执与未知状态。

## 8. 界面与记录

复用既有 AI 浮窗、标准步骤卡、确认卡和问题交互。工具卡用站点与目标控件名称描述动作，例如「填写搜索条件」「打开告警详情」，避免只展示裸元素 ID。失败卡提供具体原因，诸如页面已变化、目标不可操作、路径断开、等待超时或结果未知。

控制期间在已有会话/助手状态位置显示 AI 操作状态并保留停止入口。人工接管后显示已暂停原因。截图按需进入当前对话结果，默认不持续录屏。日志保留 operation、目标引用、动作类型、时间、派发范围和验证结论，URL 查询、敏感输入及页面正文按既有脱敏/历史策略处理。

本扩展直接复用以下网页内容和导航基准。

| [手动网址页](../../design/web-connection/manual-entry.svg) | AI 导航前的空白内容状态与用户网址输入 |

## 9. 分阶段实施

| 阶段 | 输出 |
| --- | --- |
| A 观察 | 固定观察脚本、frame/element 引用、文本/图片预算、跨文档失效与内容脱敏 |
| B 交互 | 七项工具、自动化租约、点击/输入/选择/滚动/按键、取消与 operation 去重 |
| C 验证与产品接线 | 模型实际工具循环、共享 AI UI、同跳板路线、确认/接管与结果未知恢复 |

新增网页自动化服务与平台能力均按实际完成情况注册，依赖服务不可用时工具目录明确不提供该能力。按已有插件接口扩展，避免公共工作区按 web ID 硬编码动作。

## 10. 独立验收矩阵

| 场景 | 通过条件 |
| --- | --- |
| 未交付/未启用扩展 | V0.6 人工浏览、书签、连接与关闭可独立完成，没有不可执行的 AI 页面工具 |
| 实际模型端到端 | 所选 provider 观察测试站、输入筛选、执行查询、读取结果并正确回答 |
| 表单控件 | input/textarea/contenteditable、下拉和勾选实际改变且有读回，文本输入不隐式提交 |
| 导航与等待 | 前进后退、SPA 更新、整页导航和长连接页面均能按具体条件完成或超时 |
| frame 与元素失效 | 同源 frame/open shadow 可用，目标被替换、文档更新或跨域不可用时准确拒绝旧引用 |
| 人工接管 | 点击页面、书签或手动导航立即清除待发 AI 动作，继续前重新观察 |
| 身份与并发 | 两个网页或对话不会串目标，切页签和关闭后的迟到结果不作用于新页面 |
| 权限模式 | 确认/自动/完全控制遵循宿主实际策略，拒绝的动作零派发，旧批准不套到新参数 |
| 内容边界 | 网页注入任务指令不能改变授权或执行宿主操作，密码/存储凭据不出现在观察结果 |
| 多跳网络 | AI 使用页面原代理出口，断链不改直连，API/WS 和页面请求符合 V0.6 约定 |
| 重试与未知结果 | 超时、重复调用、发送后断线不重复提交，status 查询无副作用，结果有证据或明确未知 |
| 图像与日志 | 截图限于网页，预算受控，历史图像不能凭空恢复当前输入权，日志脱敏 |
| 生命周期 | 停止、任务结束、重连、内容进程终止和页签关闭均释放租约、引用和临时 handler |

本扩展的完成证据为真实 WKWebView、真实工具调用与测试站行为的闭环。模型生成了操作描述、脚本返回成功或仅有静态截图都不足以标记完成。当前仅交付设计文档，核心功能尚待实现与验证。

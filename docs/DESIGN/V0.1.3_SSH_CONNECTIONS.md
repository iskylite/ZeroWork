#### 2.2.1 新建与修改属性共用的严格主机密钥校验字段

<a id="hostkey-policy-editor"></a>
唯一持久字段为`SavedConnection.options.strict_host_key: bool = true`。新建主机和修改已有主机属性使用同一schema、同一ConnectionDraft字段和同一高级区控件；“修改属性”对应已有主机菜单“编辑连接配置”，不新增平行属性窗口。新建步骤1→展开“连接高级选项”可取消勾选，默认true；编辑从冻结ConnectionId/revision载入真实已存值，步骤1同位置可开启/关闭，不能把已有false显示回默认true，也不能仅显示只读off状态。核对步骤的连接摘要明确“严格校验主机密钥：开启/关闭”，其“修改”返回同一草稿的高级区并聚焦此字段，不另生成草稿。

当前新建三主题`235:370377/370690/371006`的高级卡内保668×24双列行：strict为独立312×24命中组，16×16复选框位于`(0,4)`、label从`(22,4)`起290×16，右侧SSH压缩组350×24、两组gap6；不可因共处父Action行而一次切换两值。点击复选框或所属label只改变strict，Space在该组键盘焦点上切换；Tab顺序中strict与压缩独立，焦点2px ring，不冒泡折叠卡片。开启/关闭都可读出真实checked状态；新建/编辑采用同一视觉配方，正文超高时只滚高级正文，字段和原固定保存/取消动作可达。复用现有canonical状态：新建保默认on且须可关闭并验证关态，`connection-edit`展示高级展开/已存off，核对摘要显示该值；不为此增加平行属性窗口或强制增加canonical状态，也不能用`r25-hostkey-strict-off`的连接事实卡代替可编辑入口。

**`r25-auth-otp-inline` · 验证码模态关闭后的连接内认证**：前置为已保存`ssh.otp_modal=false`，原连接attempt已通过当前hop前置认证并收到仍有效的OTP challenge。360×320场景在原连接进度内显示普通受保护单字段表单、当前hop/用户/端点、服务器prompt、提交和原连接取消，不另弹modal。本例prompt要求6位验证码；空值/不符本例prompt规则禁提交，填满或TOTP填充仍须显式提交。Enter提交当前request一次，提交后门控重复，取消仍可达；成功沿同attempt后续方法/下一hop推进，不重新建链或直接假在线。普通失败原位错误并可重填；到期清旧输入等待有效下一组，断线/取消使request失效并按ledger收敛，旧request/旧generation晚回复不进入新连接。非UI先冻结`AuthChallenge.presentation=protected_form`、原owner/attempt/hop/request_id和prompts/echo，UI只消费同一状态机；输入/粘贴/Enter/Esc不发VT，不日志化秘密。验收须实际覆盖输入、已填未提交、submitting、错误、到期、取消/释放及旧回复；确认过程始终没有第二个modal，切tab不改变目标，取消不放行晚成功。焦点非UI/UI门槛分别为v0.1.3.1/v0.1.3.2；其他未来外壳入口按组合依赖另计。

<a id="case-r25-hostkey-strict-off"></a>
**`r25-hostkey-strict-off` · 关闭严格校验后的已知密钥变更**：前置为对应连接revision显式保存`options.strict_host_key=false`，握手得到的该规范端点新key与可读取的既有记录不同。360×260场景显示该连接属性off与已发生的非交互继续事实、当前hop/端点及原记录未改说明；不显示changed确认、不出现yes输入、不用“继续”按钮再门控已裁决行为。非UI按§4.2发布`accepted_changed_for_attempt`，仅本attempt采用收到的新key并继续加密SSH/认证，保known_hosts字节不变；事件/详情保原连接revision、route/hop、旧新指纹与非交互风险提示。unknown即使strict=false仍转首次三按钮确认，其他跳仍用自身策略；读/解析/撤销/不支持错误不能伪装成known_changed放行。取消走原连接关闭协调，晚策略、旧generation或不同hop的事件不能放行当前请求。验收比较known_hosts前后字节、确认没有changed/yes请求、加密及认证真实继续，并在两跳route中证明目标关闭不关闭上游strict；同一资产后改设置不热改该attempt。焦点非UI/UI门槛为v0.1.3.1/v0.1.3.2，核对矩阵同时覆盖known_match、unknown、known_changed的两种strict值。

## 4. 创建、保存、主机信任与重连算法

### 4.1 事务顺序

1. 命令发起时捕获asset/session/草稿revision，注册表核对插件、参数、权限与route；同步错误不开始IO。分配handle/attempt，深拷贝所有字符串及嵌套route，凭据另由临时引用持有。
2. 检测使用purpose=test的独立资源；全部节点open_shell=false，执行TCP/隧道、SSH握手、主机密钥及认证，完成后逆序释放。不开PTY/shell、SOCKS、启动命令、不写远端文件、不保存资产，不能把探测连接转交正式session。
3. 保存有效草稿为资产原子事务；写盘成功才更新baseline/revision。保存失败保草稿且不创建session；保存并打开先保存，再从新revision创建。打开失败保已保存资产和原失败pane，不重复创建资产。
4. 正式SSH目标完成PTY/shell后，将服务/VT/workspace接入原handle，宿主attached才呈现在线并关进度。启动命令只在正式初次接入后按序投递一次；检测不执行，重连不自动重放可能有副作用的启动命令。
5. 取消先门控新请求、使challenge失效，再逆序关闭目标channel、下游隧道/relay、上游SSH/transport；各资源ledger收敛后发released。accepted非完成；清理未知保诊断和原owner门控，不定时假释放。

### 4.2 OpenSSH known_hosts

握手后、发送认证秘密前核对主机密钥。原型要求真实读写`~/.ssh/known_hosts`，显示路径必须来自实际TrustStoreRef，不能将应用私有TSV伪装成该文件。已vendored libssh2有knownhost相关接口，可经项目shim最小适配；需要取得服务器公钥本体/算法，不能只存SHA256指纹。

按规范端点（含非22端口/IPv6）核对普通与hashed host记录；读取/解析失败、无法安全解释的记录、撤销/不支持标记仍返回明确错误，不能借关闭strict静默归为known_changed或“未知”绕过。核对后按以下矩阵推进，已知端点的不同公钥才归known_changed：

| 核对结果 | strict=true | strict=false | known_hosts副作用 |
| --- | --- | --- | --- |
| known_match | 继续当前hop认证 | 继续当前hop认证 | 无 |
| unknown | 始终显示首次密钥确认 | 同样显示首次密钥确认，不能因关闭strict自动信任未知主机 | 仅本次信任不写盘；“保存并继续”只追加已核对目标，等原子写盘回执 |
| known_changed | 原型changed确认，完整小写yes后才可替换并继续 | 不显示changed确认、不等待yes；本次采用所收新key继续连接并发非交互风险提示 | strict=true只替换匹配host/port及旧key的记录；strict=false不写、不删、不静默覆盖旧记录 |

严格开态的替换需复验旧key与文件revision，保其他主机、注释与无关key；外部程序改文件后重新读取核对，原子写盘成功才继续，失败/取消保原记录。严格关态将`accepted_changed_for_attempt`绑定原operation/generation/attempt、连接ID/revision、route快照、hop、规范端点、旧/新指纹及所用store revision，详情与日志明确“本次采用新密钥，已存记录未改”；事件不含认证秘密。收到当前key并冻结decision后才进入认证；晚到其他hop、旧revision或旧attempt事件不能放行当前请求。仅本次采用不是持久信任，下次attempt仍重读known_hosts并按该次冻结策略核对。应用私有旧信任记录的迁移需明确来源与可恢复副本，不通过一次接受偷换为已持久替换。

`strict_host_key`是连接属性，默认true，保存形成该连接的新revision；编辑不热改运行attempt。route中的每个跳板使用自身来源连接revision的独立HostKeyPolicySnapshot，目标strict=false不关闭Bastion或其他连接的严格校验，临时跳板也需显式策略来源。此开关仅放宽已知密钥变更时的身份连续性核对，SSH握手、密钥交换、加密与认证仍执行；风险是关闭的该端点发生身份替换时，客户端不会再要求changed交互确认，可能接受冒充服务器。风险范围与非交互提示必须逐hop/连接revision可追溯，不新增全局关闭行为。

凭据默认本次内存；复制、普通日志、诊断导出、AI上下文不含密码/私钥口令/OTP。当前0600明文文件不等于加密或Keychain；旧配置可兼容读取，写新schema前明确处理旧秘密，不在普通编辑中悄悄传播。Agent/凭据缓存按目标+用途+生命周期复用，OTP不可作为长期凭据；不能承诺每次重连或独立连接永不再次挑战。

### 4.3 重连与普通输入缓存

断线冻结原VT，复制/搜索/记录仍可用；所属pane顶部固定34px横幅、tab状态同步，显示故障阶段、倒计时/次数、立即重试⌘R和日志。失败留原pane，成功接回原逻辑SessionId的新generation并短暂反馈；新shell不等于恢复旧进程。Local退出不进入此状态机。

断线时冻结已保存策略。auto_reconnect=false或reconnect_max=0不安排计时；第n次取退避数组第n项。立即重试取消倒计时、占下一attempt；到期事件与手动事件通过token保证只创建一条连接。取消/关闭使原attempt失效，睡眠恢复不补发全部错过的重试。失败重建完整route，绝不降直连。

普通键盘缓存仅在buffer_input启用且当前逻辑session允许时，按原事件/字符边界最多8KiB；满明确拒收，不截半个UTF-8字符。分别记录queued/sent/acknowledged/uncertain，通道写成功只证明本地接受、不能证明远端执行；断线瞬间uncertain字节不自动补发。恢复复验owner/attempt/VT模式，单次移交尚未发送的普通缓存并标移交；重复成功回调不能二次回放。目标改变、用户取消、关闭缓存策略或只读/结束态立即作废未移交缓存。AI调用、应用`@`动作、已提交历史、旧多行粘贴批准都不缓存/重放。

## 5. 错误、取消、关闭与生效边界

错误至少含`domain/code/stage/hop/retryable/effect(none/partial/unknown)/cleanup`；网络不可达、认证失败/partial、密钥不匹配、channel拒绝、超时、IO分别在原节点/pane落点，不统一瞬时toast。输入保留、恢复入口可达；合法但暂不可用动作显原因，能力本来不存在的常驻入口隐藏。

正常shell EOF/退出转38px墓碑，保只读输出、exit/原因、复制/搜索/历史；重建会话不重放旧输入或批准。关闭确认捕获原owner和传输/AI/SOCKS影响：先暂停传输并保续传数据→停止AI回合→释放SOCKS→关闭协议资源/页签，逐步等回执。V0.1.4/0.6/0.7接入前也要有可扩展协调接口，未启用服务不得虚报活动。远端exec取消只关闭本地channel不足以证明进程停止，结果可为unknown；不向独立exec写Ctrl-C后声称必然SIGINT，不补杀可能复用的旧PID。

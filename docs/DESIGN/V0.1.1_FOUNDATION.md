## 1. 版本产出、依赖与范围

本版本建立可持续接入Local/SSH/SFTP的宿主、稳定身份、异步事件、工作区、浮层与设置事务。后续功能必须复用这些入口，不再各自绕过宿主创建进程或网络连接。没有前置功能版本；沿用当前Zig 0.17/Zenit/Ghostty/SSH构建基础，不因文档重排重写已有后端。

需求归属：W1工作区/页签、S1全局设置事务、S7三插件注册信息与规划只读页；X1通用规范从本版本开始执行并在每个UI版本验收。资产行与连接业务归V0.1.3，Local运行归V0.1.2，FileWorkspace归V0.1.4；本版本不能用fixture或空VTable宣称三插件已经运行完成。

## 2. 数据身份与宿主控制器

### 2.1 稳定身份

| 对象 | 字段/取值 | 约束 |
| --- | --- | --- |
| 持久实体 | ConnectionId、AssetGroupId、config_revision | 非零u64、不复用；跨重启保持，显示名不作主键 |
| 运行会话 | SessionHandle{session_id,generation} | session_id非零且本进程内不复用；transport重建增加generation，Local重新打开分配新session_id |
| 操作 | OperationKey{owner,operation_id,attempt_id?} | 目录/执行/关闭分别operation；完整连接重试另分attempt；取消只作用于同key |
| 服务 | ServiceHandle{resource_owner,origin_session?,kind,binding_id,binding_generation} | resource_owner为存活session或V0.1.4的保留任务owner；来源身份不等于运行资源所有者；重建服务增加binding_generation，UI不持有裸PTY/SSH句柄 |
| 内容 | TabId、PaneId、GroupId、HistoryId | 各有独立身份；Tab内容owner为session/group/history，不复用为资产索引 |
| 窗口 | WindowId、WorkspaceId | 应用内稳定不复用；Tab/Panes归具体workspace/window，不能用“当前窗口”代替异步创建/关闭目标 |
| 错误 | domain/code/stage?/hop?/retryable/effect/cleanup/safe_message | effect=none/partial/unknown；cleanup=not_started/releasing/released/unknown，两个维度独立 |

revision/generation耗尽返回错误，不回绕。请求参数在接收成功时深拷贝或转移所有权，发送失败仍由发送方释放；自有事件payload由唯一消费者释放。取消后的晚到回调只做原资源清理，不复活原UI或写入新一代会话。

### 2.2 单一命令入口

`UiCommand{command_id,kind,owner,view_revision,selection_snapshot?,payload}`由click/Enter/快捷键/应用指令共用派发。owner为app、asset(id,revision)、session(handle)、group(id,revision)、history(id)，V0.1.4增加保留任务`transfer_owner(id,original_handle)`；强类型区分，不把JobId冒充SessionId。控制器同步校验返回rejected(reason)或accepted(operation_id)，之后发布有序progress/completed/failed/cancelled/cleanup_unknown事件；accepted不是已完成。

同operation的sequence递增且终态只发布一次；cleanup可在业务失败之后继续发布，不被连接Journal的“终态后忽略”规则误吞。同一输入事件只消费一次；关闭按钮不冒泡为先激活再关闭，列表行按钮不双击重建连接。控件负责呈现、焦点与事件；控制器复验身份/能力/权限后调服务。

| 控制器 | 持有状态 | 后续功能通过什么接入 |
| --- | --- | --- |
| SessionController/Registry | handle、创建/关闭operation、服务binding、生命周期 | 插件factory与typed服务事件 |
| WorkspaceController | WindowId/WorkspaceId、有序TabId、activeTab、pane内容、stripOffset、sidebarPreference | session/group/history内容安装与关闭回执；V0.1.3新窗口请求复用同一宿主 |
| OverlayHost | owner、trigger、anchor、focus return、dismiss policy、z-order | 当前owner的菜单、认证、AI、确认和工具浮层 |
| SettingsController | baseline/draft/raw/typed/dirty/error/preview/saveOperation | 字段schema注册、提交revision与消费者订阅 |
| 后续域控制器 | 资产、记录、任务、转发、AI分别保稳定实体 | V0.1.3–V0.1.7按本域契约接入，不复制全局状态源 |

关闭请求先门控新操作，按固定扩展槽依次“暂停并保留传输→停止所属AI→释放SOCKS→关闭协议资源→释放内容”。本版本建立hook及await/unknown聚合；对应资源在V0.1.4/V0.1.6/V0.1.7接入。单会话没有额外活动资源时立即通过，不能为不存在的危险弹确认；确认取消回原焦点。**组页签关闭按用户裁决必须先确认，再关闭该组全部成员**，即使没有活动任务也须该组确认；批量队列同时含组tab与同SessionHandle独立tab时复用关闭请求/回执，不能重复释放；cleanup_unknown等待原请求收敛，不能并行再关。由V0.1.6的组关闭协调器展开成员并逐一走本关闭链，不能只移除组view；成员冻结、共享呈现、部分失败、取消及unknown回执唯一归V0.1.6。本地cleanup unknown不能假报释放完成；若本地handle已释放、仅远端effect unknown，转交有界诊断/核查记录后可释放请求与呈现资源，不无限等待远端结果阻塞关闭，具体AI结果见V0.1.7。

窗口创建/关闭由应用级WindowController协调，V0.1.1冻结`create_window(request_id)→ready(WindowId,WorkspaceId)/failed`与关闭回执；V0.1.3资产“新窗口连接”在新workspace ready后才按冻结配置创建独立session，失败不把连接塞入后来激活的窗口。全局SessionRegistry/配置/任务归应用，WorkspaceController与焦点/浮层锚点归各窗口；跨窗口事件保源WindowId/TabId。关闭窗口以捕获的workspace内容集合为入口，其中组内容交V0.1.6冻结成员并确认关闭全部成员；不额外关闭无关窗口/会话或丢弃Manager保留任务。关闭按钮、⌘W、中键、关闭其他及窗口关闭均按目标内容owner路由，不能给组保留绕过确认的“只关view”路径。

窗口命令带`role=workspace/transfer_manager`。V0.1.4全局传输管理器原型具有minus/maximize/x三窗控，采用独立工具窗口承载；`show_transfer_manager(request_id)`返回其WindowId，重复打开聚焦同一实例。关闭/最小化只改变该视图可见性，不触发workspace关闭链、不取消或暂停任务；重新打开从Manager快照恢复筛选和实时任务。任务由应用级资源owner持有，工具窗口不可持唯一任务句柄。会话内620×330传输浮卡仍是OverlayHost的popover，关闭只是收起，不能与工具窗口关闭混用。独立窗口关闭/再开、主窗口仍存活、任务进度连续分别在v0.1.4.1与v0.1.4.2验收。

## 3. 静态插件宿主

### 3.1 注册与创建

应用随版本静态提供`local`、`ssh`、`sftp`三个描述符，`PluginDescriptor{plugin_id,display_name,icon,host_api_version,plugin_version,workspace_kind,create_kind,services}`。启动校验ID唯一、源码接口版本、workspace与必需服务一致。先落实宿主及接口，再按V0.1.2/V0.1.3/V0.1.4逐个接真实adapter；未接通时明确不可用，不能注册点击后假成功的空实现。首版没有dylib市场、热卸载或通用表单DSL。

`SessionCreateSpec`为tagged union：local{initial_cwd,fixed_backend=zsh}、saved{connection_id,config_revision,protocol,immutable_config,credential_ref?,route_snapshot,private_options}、temporary_ssh{structured_endpoint,auth_options,route_snapshot}。Local没有HostConfig/host/port/认证；SFTP与SSH有独立持久ID与协议选项，临时SSH不强制先保存。

`create(spec,runtime)`由宿主分配handle/operation并校验，异步结果只回原key。共用生命周期creating→ready/failed→closing→closed/cleanup_unknown，业务状态在各插件扩展。ready带服务binding；Workspace安装完成的attached回执后才显示已接入，不把认证完成当UI就绪。

### 3.2 服务与能力

| 服务 | 概要接口与归属 |
| --- | --- |
| 基础生命周期 | create/queryState/requestCancel/requestClose；所有插件共同提供 |
| TerminalService | write(bytes)/resize(cols,rows)/output/eof/modes；Local与SSH，接口实现见V0.1.2 |
| Process/CwdService | running/exited、exit/signal、known/unknown cwd；Local及明确支持的SSH事件 |
| Auth/RouteService | 带attempt/hop/request_id的挑战回复和阶段事件；V0.1.3，SFTP复用底层但不共享逻辑session |
| Directory/FileRead/TransferService | 有界目录、读取、enqueue/pause/resume/cancel/query；V0.1.4 |
| ExecService | immutable call/cwd/stdout/stderr/exit/cancel/unknown；V0.1.2/0.3提供Local/SSH基础，V0.1.4可消费校验能力，V0.1.7增加AI权限/审批/调度；不能模拟终端输入 |
| ForwardService | start/stop/query及真实绑定信息；V0.1.6仅实际支持的SSH |

queryService返回available(handle)、temporarily_unavailable(reason)或unsupported；服务不能超过其实际resource_owner生命周期。会话关闭使该session的Terminal/Exec/Auth等binding失效；原Job暂停保留不让旧SessionBinding继续存活。V0.1.4的Manager可持独立RetainedTransferOwnerId、原handle仅作来源标识和冻结连接快照；显式恢复后创建归该保留owner的新传输binding，operation/event使用保留owner+JobId+新binding generation，不向已关闭的SessionRuntime发请求、不复活shell。任务终结/释放保留记录后才结束该资源owner；不能把“保留归属”解释为关页后仍继续传输。

动作可执行条件为“描述符支持 ∧ 当前服务ready ∧ 生命周期允许 ∧ 用户权限通过”。不适用常驻入口隐藏；合法但暂不可用动作显示原因；用户明确输入的不支持命令原位说明，不换其他会话执行。

SFTP左卡是宿主FileAccessService，不要求同时开Local zsh；SSH的独立传输连接也不是SFTP活动页签。复用底层模块不等于复用连接实例或凭据授权，后续详细绑定归V0.1.4。

## 4. 线程、数据流与渲染接入

UI/IO/计算按现有边界适配；kqueue使用实际platform.Queue，没有可照抄的Runtime.add_fd公共插件API。UI→worker输入保序且背压，worker→UI输出字节不丢，dirty/进度可合并，认证/退出/错误/清理可靠投递。多个worker各有SPSC或明确的汇聚通道；不能把共享队列变为多生产者后继续称SPSC。

| 数据流 | 接入顺序 |
| --- | --- |
| 终端输出 | 插件IO→旁路记录入口→VT feed/dirty snapshot→UI帧消费→对应pane绘制；记录在V0.1.5接入 |
| 输入 | IME/当前编辑器/最上层浮层→快捷键→可信行命令/候选→VT编码→原owner写队列；增强路由在V0.1.5 |
| 目录/任务/转发/AI | 不可变请求→域服务→带key结果→控制器复验→所属视图；各功能版本实现 |

VT/渲染快照的发布生命周期必须明确，UI不能持有下一次publish后失效的PageView或借用切片。现有VT可能有互斥边界，应保持安全并用明确帧快照演进；不要因旧架构图写“无锁”就删除必要同步。

终端绘制分背景、字形、装饰三类批次；CustomDraw使用Zenit公开DisplayItem/DrawContext，不另建raw Metal层。选区/时间/光标为旁路装饰；浮层采用portal、真实anchor与统一clip转换。旧DrawCmd.blur示意不是当前公开API，材质能力和渲染缺口见设计规范§7。

| --- | --- | --- |
| 标题卡 | 8,8,1424,46 | 8,8,844,46 |
| 侧栏 | 8,60,224,794 | 8,60,48,374 |
| 内容pane | 238,60,1194,794 | 62,60,790,374 |
| 状态卡 | 8,860,1424,32 | 8,440,844,32 |

原生红绿灯的原型目标为12px圆，位于标题卡内x14/34/54、y17，保留系统关闭/最小化/缩放行为；实际窗口控件位置通过Zenit公开平台能力对齐，不画无事件的仿按钮。

任意窗口内容高H−106、宽W−22−sidebarWidth，状态y=H−40。侧栏折叠保留48图标栏，⌘B/头部按钮等效，<1100自动折叠但手动偏好优先；具体资产行在V0.1.3。底栏状态入口独立固定112×26，不随侧栏展开或折叠改变宽度；状态点、最多四字状态与展开箭头居中排列，具体主机/进程身份由同锚点浮卡显示；没有活动session时不显示伪网络/AI/传输所属状态。

首次无资产、有资产无会话和关闭最后tab均保留居中“本地终端/选择连接”，无幽灵tab，不强制启动即创建进程。资产留存，AI仅在真实可用owner满足能力时开放。全局设置与全局任务入口不借活动session伪造归属。

### 5.2 页签、溢出与生命周期

Tab高32/y7/r8/gap4，簇从标题卡x82起。内容类型为终端、文件、终端组、只读历史；每项独立TabId/owner。自然宽clamp(真实12px Inter Medium标题度量+76,96,200)，76为左10+类型/系统图标14+gap6+gap6+状态6+gap8+关闭20+右6。标题x30/y7/h18、单行TRUNCATE；状态在关闭槽左8，关闭槽x=width−26/y6/20×20，图标12。活动底条x8/y29.5/h2.5/宽tab−16。

| 状态 | 计算与行为 |
| --- | --- |
| normal | 自然宽总和+gap4≤headerWidth−82−150−40，页签保持自然宽 |

## 6. 设置事务、配置与插件页

### 6.1 单份草稿及保存协议

`SettingsDraft{draft_id,baseline_revision,raw_fields,typed_values,dirty_fields,field_errors,effective_preview,pending_assets,page/search/scroll/fold,save_operation?,close_after_save}`。状态clean/dirty_valid/dirty_invalid/saving/save_failed；非法raw也dirty，即使typed仍旧值。字段改回baseline可恢复clean，搜索/帮助/导航/只读规划不dirty。八分类共享同draft，后续字段在所属功能版本注册，不能各页持有互相覆盖的完整配置副本。

1. 冻结draft/revision及dirty字段，与最新已提交值合并；未改字段保最新，相同dirty字段由本次明确保存值提交。整份/交叉校验失败定位并解锁，不写盘。
2. 准备主题/图片等不可变素材与内存快照，后写配置引用。素材启用且不可用阻保存；关闭保旧参数，不阻其他合法字段。晚解码按asset revision丢弃。
3. 同目录临时文件、flush/原子替换、0600；跨文件先准备素材后提交引用，旧资源成功且无引用后清理。失败不更新runtime/baseline；不让配置先落盘再因分配失败无法发布。
4. 成功一次发布ConfigSnapshot/revision+changedFields，消费者只订阅相关字段；成功清dirty/更新baseline，普通保存留窗，保存关闭成功才关。
5. 回调必须匹配save_operation；失败保输入/页面/滚动/有效预览。Discard仅撤本draft预览与暂存，恢复最新提交值，不回滚外部已提交主题或运行任务。

保存仅dirty_valid可用；saving锁编辑/重置/关闭/重复保存/分类切换。Reset确认后载入统一Defaults草稿，主题为原型Sauber且仍可放弃，不立即写盘或清记录；全局`@theme default`恢复应用默认，不硬编码字符串别名。未配置Provider、禁用槽和只读规划不使其他合法分类无法保存。原型当前明文600标签如实显示，新的secret策略按规范与V0.1.3/V0.1.7执行。

现有SessionRuntime/TerminalView仍硬编码SshWorker，缺三描述符与通用create/service边界；session_lifecycle已有Ticket/深拷贝Snapshot可复用，HostId仍是进程内身份。现有纯模型/历史勾选不能当成本版本UI完成；不删除已有可用SSH通路后另起平行实现。

当前窗口配置没有minimum字段，部分原生菜单队列、主题rebind、TabStrip横滚/拖序和控件精确配方仍需按设计规范适配。设置部分字段尚未贯穿运行消费者；v0.1.1建立订阅和失败边界，V0.1.2–V0.1.7分别闭环各域字段，V0.1.8只做完整整合/发布收口。

迁移来源为原总体架构、接口的中性会话/线程/全局状态部分、工作区/页签、新建菜单、设置事务及插件通用宿主；逐原章节与状态映射保存在[迁移记录](../DEVELOPMENT/V0.2.1_STATUS.md)，无须返回已移除的主题文档读取执行规则。

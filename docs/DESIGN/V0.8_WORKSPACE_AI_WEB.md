# V0.8 · 工作区浮岛、独立 AI 连接与浏览器原生子窗口

> 状态：版本规划与实施设计，待实施。日期：2026-11-21。设计编号不修改构建版本号，也不代替原生代码实现或运行验收。

## 1. 版本目标与范围总览

V0.8 聚焦于三项面向工作区形态、AI 助手架构与浏览器连接完备性的结构性调整：

1. **工作区 UI 调整（顶栏全局单岛化 + 右下角 LOGO 吉祥物单向工具条）**：厘清「全局/窗口级控制」与「当前会话/任务级控制」的物理边界；顶栏右侧收敛为单一全局岛（窄窗三点按钮原地展开并隐藏自身），会话级功能与合并后的统一端口转发入口下沉至右下角可拖拽吉祥物单向工具条，采用「瞬态默认隐藏、活动态常显、悬停/点击全展开」策略；保留 Tab 左侧透明连接身份触发器原位。
2. **AI 助手右侧固定双卡与独立 AI 会话连接插件**：
   - 既有附着式 AI 悬浮窗顶部新增「固定到右侧 / 恢复悬浮」开关，支持将 AI 助手固定在内容区右侧形成双卡片布局，**不改变单会话/会话组原有属性、不允许调整卡片位置**；
   - 新增标准内置连接插件 `ai`（独立 AI 会话连接），支持多页签并行与自由加入/离开会话组并来回换位；采用通用 AI Agent 三栏式内容页设计（左侧纯 AI 对话历史与线程管理 + 中央对话流与 `@`/按钮目标选择器 + 右侧按需开合的多智能体检查器与工作区文件浏览器），严格区分**独立页签（可显式选择当前窗口的活动目标，默认无终端授权）**与**会话组内成员（仅限组内活动连接）**的访问边界，并实施**按关联会话与协议动态区分的三层工具装配架构**。
3. **浏览器连接原生新窗口支持（方案 3：独立 macOS 原生子窗口）**：解决服务器 BMC 等网页通过 `window.open` 或目标外链接打开 HTML5 远程桌面（iKVM）被拦截的问题；在保持父会话非持久 `WKWebsiteDataStore`、`window.opener` 脚本互操作与独立 SSH SOCKS5 代理继承的前提下，以独立 macOS 原生 `NSWindow`（`ZWWebPopupWindow`）承载子网页。

## 2. 工作区 UI 调整：顶栏全局单岛化与右下角 LOGO 吉祥物单向工具条

### 2.1 顶栏职责重划与全局单岛（`toolbar.group.global`）

#### 2.1.1 全局 vs 会话级归属重划

现状顶栏右侧（[main.zig](../../src/main.zig#L17774-L17814)、[workspace_chrome.zig](../../src/ui/workspace_chrome.zig)）包含 `connection`、`history`、`application` 三个分离胶囊岛，将全局按钮与会话按钮混排。V0.8 确立**「顶栏只承载窗口与全局应用能力，会话及任务级控制全部下沉至右下角吉祥物浮岛」**原则：

| 原顶栏入口 | `test_id` / 源码位置 | 作用域属性 | V0.8 归属与处理 |
| --- | --- | --- | --- |
| **Tab 左侧连接身份触发器** | `identitiesAtTabs`（`status.connection.identity` / `local.status.identity`） | Tab 附着态 | **保留原位**。不属于右侧功能区按钮，继续叠放于活动 Tab 左侧图标槽，用于查看 RTT、终端编码、网格或图形会话摘要。 |

| **通知** | `toolbar.notifications` | 全局级 | **保留在顶栏全局单岛（第 3 位）**。全局待处理事项与提醒列表。 |
| **全局主题** | `status.connection.theme` | 全局级 | **保留在顶栏全局单岛（第 4 位）**。 |
| **AI 助手** | `ai.strip`（`AiHost`） | 当前会话级 | 不占全局工具位。附着式会话用三点条或快捷键；独立 AI 会话从新建会话菜单打开。 |
| **偏好设置** | `toolbar.settings`（`SettingsHost`） | 全局级 | **保留在顶栏全局单岛（第 5 位）**。 |
| **通信链路（连接）** | `status.connection.chain` | 会话级 | **移入右下角吉祥物浮岛**。 |
| **当前会话端口转发** | `status.connection.forward` | 会话级 | **移入右下角吉祥物浮岛**，与后台端口转发**合并为统一「端口转发」入口**。 |
| **后台端口转发** | `status.background.forward`（`socks_background_host.zig`） | 脱离会话的转发任务 | **合并入右下角吉祥物浮岛的「端口转发」入口**。 |
| **传输列表** | `toolbar.transfers` | 任务级 | **移入右下角吉祥物浮岛**。 |
| **命令历史** | `command_history` | 当前终端会话级 | **移入右下角吉祥物浮岛**。 |
| **组广播** | `status.group.broadcast` | 当前会话组级 | **移入右下角吉祥物浮岛**。 |

合并后的顶栏右侧仅保留 **1 个独立胶囊岛**（`toolbar.group.global`），内部固定排列置顶、回看日志、通知、主题、偏好设置五个全局图标。按照 [mist-design.md](../UI_V4/workspace/mist-design.md) 现有按钮几何（按钮 `28×28`、组内间距 `4pt`、左右内边距各 `4pt`）：

- **全局单岛固定宽度**：`4 + 5 × 28 + 4 × 4 + 4 = 164pt`，高度 `36pt`，圆角 `18pt`。
- **空间收益**：消除了原 3 岛拆分造成的 `2 × 8 = 16pt` 岛间距及多个会话图标的动态占位，为左侧 Tab 胶囊释放固定且更大的展示空间，切页签或进出会话组时顶栏工具区宽度不再发生抖动。

#### 2.1.2 窄窗三点按钮原地切换交互

对应 [workspace_chrome.zig](../../src/ui/workspace_chrome.zig#L125-L210) 的窄窗折叠机制优化如下：

1. **触发折叠条件**：当顶栏可用宽度 `< 850pt` 或 Tab 胶囊自然宽度超过完整全局单岛（`164pt`）左侧预留空间时，进入紧凑态（`compact = true`）。
2. **收起态**：仅在顶栏最右侧显示 `36×36` 的三点胶囊按钮（`toolbar.compact`），完整全局单岛隐藏（`display = .none`）。
3. **展开态（关键调整）**：当鼠标悬浮（hover）或点击三点按钮时，**三点胶囊按钮立即隐藏（`display = .none`），原地切换显示为完整的全局功能单岛（`right: 0` 贴齐顶栏右边界）**。
   - **取消三点常显占位**：展开时不再保留右侧 `44pt` 的三点占位，视觉上呈现为“三点胶囊原地舒展为完整功能岛”，与现有滑入动效（220ms cubic-out；`reduceMotion` 开启时直接显示）衔接，整体交互及收回判定（鼠标离开功能岛热区且无任何所属弹层如主题、通知、回看日志、设置等处于打开状态时，恢复为三点按钮）保持一致。
4. **安全布局预算**：展开时 Tab 胶囊按 `width - 164 - 16 - 40` 临时避让收缩（保留最小 `16pt` 安全间距），收回后恢复 `width - 36 - 16 - 40`。

```text
[窄窗收起态]  [ Tab 胶囊 ................................. ]   ( ··· )
                     │ 悬停 / 点击（三点按钮隐藏）
                     ▼
[窄窗展开态]  [ Tab 胶囊 .................. ]   ( 置顶 日志 通知 主题 AI 设置 )
                     │ 移出功能区热区且无关联弹层打开
                     ▼
[窄窗收起态]  [ Tab 胶囊 ................................. ]   ( ··· )
```

### 2.2 工作区吉祥物与单向工具条

[原生组件局部原型：工具条与端口转发预览](../../design/workspace-refinements/mascot-tools.svg)。普通工作区只挂一枚 44×44pt 品牌徽章，默认距内容区右下各 16pt；拖动后保存窗口内相对位置，缩放时限制在可见边界。会话组按当前聚焦成员选择工具，**独立 AI 会话不显示徽章、工具条或这些预览**。展开工具不能移动徽章、改变终端尺寸或打断输入。

#### 工具的顺序和内容

从徽章向外依次为下列工具。空闲时只保留进行中的传输、转发或广播；其余工具在展开时出现。不适用的工具不占空位。

| 工具 | 悬停读到的实际内容 | 点击后的行为 |
| --- | --- | --- |
| 传输 | 当前传输面板，保留任务、筛选、状态、空状态和已有按钮，不以数字替代列表。 | 固定当前面板以便继续操作。面板不是可拖动的窗口，不显示拖拽条。 |
| 端口转发 | 同一面板同时显示当前会话转发与后台保持转发；两者各自显示状态。没有转发也明确显示，不使用空白代替。 | 固定面板。选择有数据的行才打开对应详情；会话转发和后台转发的生命周期仍然独立。 |
| 组广播 | 仅在含终端的组中显示；读取组名、广播状态及参与数，悬停不创建广播草稿、不开始广播。 | 明确点击才进入组广播配置。 |
| 通信链路 | 仅在有连接信息时显示。SSH 读取当前连接链路；SFTP 或图形插件预览连接名称及实际状态。 | 打开对应连接详情，悬停不另开图形连接窗口。 |
| 命令历史 | 仅在可用终端显示当前会话历史列表及空状态；不执行命令。 | 固定列表以便浏览，仍通过原有列表操作选择命令。 |

#### 展开、停留与收起

1. 徽章悬停后，28×28pt 工具以 4pt 间距**沿一条直线向有空间的一侧**展开。下方右侧向左，下方左侧向右；横向不足时再选上下空间更大的一侧。打开和收起使用同一段 220ms 的缓动，反向时从当前进度继续；系统要求减少动态效果时直接切换。
2. 指针在某工具上短暂停留（150ms）即出现对应内容。工具和气泡之间保留跨越宽限（270ms）；移入浮层可阅读、滚动或点击，不抢走原有文字输入焦点。离开两者自动关闭悬停预览；明确点击固定的面板按其正常关闭方式收起。一个工具的预览不替换用户自己打开的面板。
3. 气泡跟随**实际工具按钮**而非屏幕固定点；优先在上下空间较多的一侧展开，必要时平移或约束尺寸，长列表内部滚动，不覆盖触发按钮。只有徽章可以拖动；不能拖动的预览不画拖拽暗示。
4. 各窗口独立管理当前的预览与鼠标位置。吉祥物本体、实际可见的工具条和浮层参与原生 WebView 遮挡计算；切入独立 AI 页时应同时撤销工具预览与遮挡。

## 3. AI 助手调整：悬浮窗右侧停靠与独立 AI 会话连接插件

V0.8 将 AI 助手的使用形态明确拆分为两个定位正交、边界严格区分的产品入口：**「附着式 AI 助手的双布局模式（悬浮 ⇄ 右侧固定）」** 与 **「独立 AI 会话连接插件（标准连接页签 / 通用 Agent 三栏工作台）」**。

新增的对话栏、检查器和 Composer 沿用主工作区的主题材质。导航分组和附件菜单以留白区分，不加常态描边或分隔线；选择用主题色块，键盘焦点保持可见。

### 3.1 形态一：附着式 AI 助手悬浮窗 → 右侧固定双卡片模式

#### 3.1.1 布局切换、快捷键与持久化语义

- **附着式入口**：三点条（`120×6pt`）始终以整个内容区为锚，停靠不挪动入口。悬浮模式可停留预览，鼠标进入预览保持显示，离开延时收起，点击可固定本次打开。右侧停靠会改变终端可用宽度，因此仅响应三点条点击或 AI 快捷键，不响应悬停。点击停靠/还原保留当前卡片和草稿。独立 AI 页不显示三点条。会话组已内嵌 AI 时，三点条和快捷键只把输入焦点交给组内 Composer，不会再生成第二个浮窗。
- **新增切换按钮**：在悬浮窗顶部标题栏（[ai_assistant_header.zig](../../src/ui/ai_assistant_header.zig) 的窗口控制按钮组左侧，紧邻折叠/最大化/关闭）新增 **「固定到右侧 / 取消固定恢复悬浮」** 切换按钮（`ai.dock_right`）。
- **右侧固定双卡片呈现与持久化**：
  - 点击「固定到右侧」后，AI 助手从覆盖层退出，嵌入到当前窗口内容区（`workspace.pane` 同级水平容器）的**最右侧独立槽位**；
  - 内容区立即呈现为**左右两个并排圆角卡片**（间距 `12pt`，圆角 `16pt`，遵循现有卡片材质）：左侧为当前连接会话（或当前会话组）卡片，右侧为 AI 助手卡片；
  - 支持在左侧主内容与右侧 AI 卡片之间在两块圆角卡片之间的透明间隙拖动以调整右侧 AI 卡片宽度，不绘制常态分隔线（受最小/最大宽幅约束，如 `360pt` 至窗口可用宽度的 `50%`，确保左侧会话区不被挤垮）；停靠模式开关（悬浮 / 右侧固定）与右侧栏宽按全局界面偏好持久化。

#### 3.1.2 核心不变量（与会话组的本质区别）

| 约束维度 | 右侧固定 AI 卡片（Docked Right） | 普通会话组（Session Group） |
| --- | --- | --- |
| **会话属性** | **绝不改变原会话属性**。若切换前当前页签是单会话（如单个 SSH/Local/Web），切换为双卡片后**依然是单会话**（Tab 标题、Tab 图标、Tab 菜单、`SessionHandle` 均不变，不生成 `GroupId`）；若切换前是会话组，左侧卡片保留原会话组分栏树。 | 必须显式建组（生成 `GroupId` 与 `GroupOwner`），Tab 切换为双叠窗口组图标。 |
| **位置灵活性** | **位置严格固定在内容页最右侧**。**不允许**拖拽调整到左侧、顶部或底部，也不允许嵌入到左侧会话组的内部嵌套分栏树中。 | 组成员支持上下/左右自由分割、拖拽来回跳换位置。 |
| **绑定与任务连续性** | 与悬浮窗共享同一个附着 `AgentRuntime`、`ConversationId`、`binding_revision` 与 Worker 线程。`悬浮 ⇄ 右侧固定` 切换瞬间**不断流、不重连、不重建上下文、不丢失未输入草稿或待审批队列**。 | 各分栏拥有独立插件会话，组内成员变动触发群组 `membership_revision` 更新。 |
| **多页签切换行为** | 停靠状态属于窗口布局偏好（右侧固定模式开关）：切换顶栏其他单会话或组页签时，左侧主卡片切换为目标页签内容，右侧 AI 卡片同步切换显示该页签当前附着的 AI 助手上下文（各自独立 `AgentRuntime`，后台运行中的前一个页签 AI 任务继续不中断）；若切到**独立 AI 会话连接页签**，该右侧附着 AI 槽自动隐藏，避免“AI 嵌套 AI”。 | 每个组页签独立保存自身分栏结构 JSON。 |
| **原生视图协同** | 右侧 AI 卡片占用独立布局空间，直接压缩左侧内容槽可用矩形 `slot`。因此左侧若为 `WKWebView`（浏览器）或 `FrameTextureSink`（KVM），原生画面自动随容器收缩重排，无需叠加遮挡挖空。 | 分栏矩形各自独立同步给原生表面。 |

#### 3.1.3 工作区布局配置与启动反馈

V0.8 在 `config.toml` 的 `[ui]` 中定义 `ai_dock_preferred`、`ai_dock_width`、`mascot_anchor_x`、`mascot_anchor_y`。升级时，V0.7 配置中缺失的新字段采用默认值（AI 悬浮、吉祥物在右下角）。窗口根据可用空间限制宽度和位置。切换停靠或完成拖动时，从最新配置快照更新本次涉及的字段，经现有的配置事务原子保存。V0.7 使用自己的字段定义。

- **开发版过渡。** 此前生成的 `workspace-layout.json` 只作为一次性导入来源。启动时在数据独占锁下导入有效偏好，`config.toml` 已保存的值优先。原子提交前保留原文件，随后由 `config.toml` 提供布局偏好。开发和自动化验证使用隔离数据目录。
- **配置警告与读取失败。** 遇到当前版本未识别的配置项时，使用已知配置进入工作区，通过应用通知和日志提示数量及首个行号，保存普通设置时保留这些配置项。语法错误与已知字段的非法值阻止工作区启动。独立的启动错误窗口沿用现有错误通知卡的宽度、图标、文字层级和按钮样式，给出文件、可确定的位置和处理说明，等待用户退出。窗口无法显示时改用原生弹窗。macOS 已有通知授权时，以「ZeroWork」为系统通知标题、正文首句说明启动失败与原因，新的失败替换上一条。通知、错误窗口和日志只使用安全的定位信息，保留原始文件和凭据。

### 3.2 形态二：独立 AI 会话连接插件（`plugin_id = "ai"`）—— 通用 AI Agent 三栏工作台

#### 3.2.1 标准插件注册、壳层声明与会话组协同

- **内置插件注册**：在 [application_plugins.zig](../../src/plugins/application_plugins.zig) 与 [plugin_registry.zig](../../src/host/plugin_registry.zig) 注册内置插件 `ai`（显示名 `AI Agent` 或 `AI 会话`，`origin = .bundled`，`host_api_version = 2`），提供：
  - **`quick_create` 专属创建**：仅通过 Tab 栏「+」新建菜单或会话中键/成员菜单「在当前会话组打开 AI 会话」创建，历史会话直接在 AI 自身对话左侧栏恢复 `ConversationId`；**不作为主机配置资产写入全局主机列表**（不注册 `connection` 资产表单）；
  - `session_factory`（创建真正的 `SessionHandle`，仅管理 AI 会话内容生命周期，不强依赖单一 PTY 或 SSH 传输）；
  - `workspace_kind = "ai"` 与 `content_renderer = "ai"`（支持同时挂载多个实例）；
  - **`workspace_chrome.show_host_sidebar = false`（新增 `PluginManifest` 壳层声明）**：扩展 [plugin_registry.zig](../../src/host/plugin_registry.zig) `PluginManifest`，新增壳层策略结构 `workspace_chrome: WorkspaceChrome = .{ .show_host_sidebar = true }`（默认保持原样显示主机左侧栏）。独立 `ai` 连接单页声明 `.show_host_sidebar = false`：**当活动 Tab 为单独的独立 AI 连接页签时，自动隐藏全局主机左侧栏**（直接让 AI 自身的对话左侧栏承接左栏职责，消除双重左侧栏挤压，Mac 交通灯贴齐窗口左上角，Tab 胶囊无缝右避，且 **`⌘B`（`workspace.toggle_sidebar`）改为折叠/展开 AI 自身的纯对话左栏**；左右侧栏折叠态按单会话/页签记住）；当切回普通主机页签、其他插件或包含 `ai` 的多会话组时，按成员/壳层策略自动恢复全局主机左侧栏及 `⌘B` 对主机侧栏的控制权。
  - `integration = .{ .ai = false, ... }`：独立 AI 插件自身即是 AI 工作台，不对其再挂载二次“附着式 AI 悬浮窗 / 顶中三点 AI 条”。
- **多开与组内统一卡片外观**：
  - 允许同时打开**多个独立 AI 连接内容页**（多个独立 Tab，各自绑定不同 `ConversationId`、不同项目工作区和独立 `AgentRuntime` 并行运转）；
  - 允许作为标准连接会话**加入任意会话组（Group）**：在会话组内与 Local / SSH / SFTP / Web / KVM 一样作为标准 Pane 参与上下/左右分栏与拖拽换位。**加入会话组时，`ai` 内容槽必须直接套用既有会话组的统一样式卡片壳层**（[group_workspace_styles.zig](../../src/ui/group_workspace_styles.zig) / [workspace.zig](../../src/ui/workspace.zig#L3330-L3436)）：外框圆角 `11pt`、分栏间距 `4pt`、顶部 `28pt` 统一成员头（包含 `13×13` `grip-vertical` 拖拽把手、`AI · {对话标题} · #{id}` 标签、`6×6` 在线状态点 + 状态文案、`pin` 置顶图标与 `ellipsis` 成员菜单，聚焦态头部背景取 `selection` `#EAEDFD`，非聚焦态取 `surface_2` `#E7E7E8`），**禁止单独发明异形会话组卡片边框或额外顶栏**。
- **会话中键 / 成员菜单快捷入组入口**：
  - 在既有会话中键菜单（`terminal_middle_click` 等 [context_menus.zig](../../src/ui/context_menus.zig) 入口）以及会话组页签/成员菜单中，增量添加**「在当前会话组打开 AI 会话」**；
  - 若当前为单会话（如单个 SSH / Web），点击后按现有入组语义就地创建或切换为混合会话组（原会话 + 新建独立 `ai` 成员分栏）；若当前已在会话组内，直接将新建独立 `ai` 成员追加分栏到当前组并立即继承组内全部活动连接上下文。

#### 3.2.2 三栏式通用 AI Agent 内容页设计

由于独立 AI 连接独占工作区内容槽，空间远比 600×456 悬浮窗充裕，V0.8 参考主流桌面通用 AI Agent（如 Codex Desktop / Cursor Agent 等）采用**「左侧纯 AI 对话栏 + 中央核心对话与目标选择区 + 右侧按需开合的多智能体与工作区文件检查器栏」**三栏式内容页架构：

```text
┌───────────────────┬───────────────────────────────────────┬──────────────────────────┐
│ 左侧栏 (可折叠)    │ 中央主区 (对话流 · 目标选择 · Composer) │ 右侧栏 (按需开合，可关闭) │
│ 纯 AI 对话管理     │                                       │                          │
│                   │  工作区 · 权限域 · [文件/检查器开关]    │ [文件] [成员] [协同] [轮次]│
│ [+ 新建 AI 对话]   │ ───────────────────────────────────── │ ──────────────────────── │
│ [搜索历史对话…]    │                                       │ ▼ ZeroWork (工作区文件)   │
│                   │  [用户提问 / 引用目标上下文]             │   📁 src/                │
│ ▼ 当前与历史对话   │  [AI 推理过程 & 工具调用折叠卡]         │     📄 main.zig     +12  │
│   • 排查网关超时   │  [内联终端回执 / 文件 Diff 卡]          │     🐳 Dockerfile        │
│   • BMC 固件巡检   │  [主对话子任务审批透传卡]               │   ────────────────────── │
│   • 集群巡检草稿   │                                       │   [内联文件内容 / Diff 预览]│
│                   │ ───────────────────────────────────── │                          │
│ (不放主机列表，    │ [ 输入消息… ]                         │ 或切至 多智能体面板:      │
│  不与全局侧栏冲突) │ [+] [关联] [权限] [执行] [编排] [用量] │  #1 worker · Graph/Board │
│                   │ [模型与推理强度]                  [↑] │  Boost Rounds · 停滞警示  │
└───────────────────┴───────────────────────────────────────┴──────────────────────────┘
```

实际外观见 [独立 AI 工作区 SVG](../../design/ai-agent-mode/standalone-workspace.svg) 和 [吉祥物工具与端口转发 SVG](../../design/workspace-refinements/mascot-tools.svg)。设计稿采用 [主工作区的晴霜参考主题](../UI_V4/standards/STYLE_GUIDE.md)；原生继续使用当前主题，不强制更换颜色。栏与操作组用留白、底色和轻阴影分隔，不添加装饰性边框、分割线或选中下划线。焦点轮廓、状态点、进度、文件修改标记和关系图连接线仍表达真实信息。

各栏具体职责如下：

1. **左侧栏（纯 AI 对话/线程管理，可折叠）**：展开宽 `238pt`，与宽窗主机栏采用同一尺寸和表面；与中央保留 `12pt` 留白。
   - **只管理 AI 对话本身，不放主机或连接资产列表**：应用窗口最外层已拥有全局左侧栏（「主机与连接」资产树），且独立 AI 内容页会被放入会话组（Group）分栏中；内容页左栏保持纯粹的 AI 对话职责，避免内部再嵌一套主机列表造成视觉与语义冲突。
   - **对话操作**：支持一键新建 AI 对话、按标题/时间搜索过滤、查看当前绑定与历史对话列表、恢复未绑定的原 `ConversationId`、复制分支（Fork）或归档删除，免去浮窗二次弹窗打断。
2. **中央主栏（核心对话流、既有 Composer 与增量目标指定，弹性填满剩余宽度）**：
   - **同一个 Composer**：附着浮窗、固定侧栏和独立页签移动的是同一份输入组件；草稿、焦点、选择器及发送均属于当下对话。附件、关联（仅独立页签）、工具权限、执行方式、编排、用量、模型与推理强度、发送／停止依序排列；紧凑宽度缩写或只显示图标，保留同样的点击动作。模型列表来自启用的模型配置，不虚构没有配置的模型。
   - **输入与选择**：行首输入 `/` 可用键盘或鼠标选择当前可用的技能、模型、权限、执行方式和关联入口；还可直接选择编排模式。选择只打开相应控件或设置模式，不提交模型请求。编排命令 `/auto`、`/swarm`、`/boost` 与命令执行方式是两件事：前者决定如何组织智能体，后者决定命令能否走批处理或原终端。
   - **三种会话的目标边界**：
     - **单会话附着 AI（悬浮窗／固定侧栏）**：目标就是被附着会话，不展示额外的关联选择器。
     - **独立 AI 页签**：新对话不默认获取任何终端权限。点击「关联会话」、输入 `@` 或选择 `/session`，可选当前窗口中允许 AI 使用的活动会话，或选一组并加入其当下的有效成员。选中项可在同一菜单中点按移除；输入名称未选中不构成授权。选择「新建本地终端」会建立真正的本地会话并返回原 AI 页签，只关联新建的会话。
     - **组内 AI**：仅使用所属组的活动成员，不提供跨组关联入口。指定具体成员不会增加权限。
   - **执行与权限分开**：「确认后执行／自动执行」控制授权，「交互式／批处理／自行判断」控制路径。交互式需要已关联且就绪的原终端；未关联时，用户可先选择或新建。自行判断可在已授权且支持的目标上使用独立批处理；不把 AI 页签、未选终端或本地 Mac 当成默认执行目标。报告执行成功要有工具回执，不能凭助手文字判定。
3. **右侧栏（按需开合，随时可关闭，复用工作区文件浏览与既有多智能体检查器）**：宽窗展开宽 `340pt`，与中央保留 `12pt` 留白。检查器和预览页签的选中状态复用侧栏的填色，不另画分隔线。
   - **开合状态机（非死板常驻占位）**：
     - **默认收起**：新建空白独立 AI 对话且尚未绑定工作区文件展示、尚未创建多智能体子任务时，右侧栏默认关闭，把全部空间让给中央对话区；
     - **有内容时打开**：当用户点击本地工作区目录/文件条目、本轮产生了本地或远端文件变更、或启动了多智能体任务（子智能体 / Swarm / Boost）时，右侧栏自动展开（或从顶部状态条的入口按钮一键打开）；
     - **随时可关闭**：右侧栏顶部提供显式关闭按钮（`×`），用户可随时关闭；重新点击顶栏工作区/文件/子智能体角标即可再次打开。
   - **内置子视图页签（直接复用既有子智能体视图，取消二次弹窗阻塞）**：
     - **工作区文件（Files）**：详见 §3.2.3，提供本地工作区完整目录树、搜索、变更文件筛选（`+N −N`）、全面文件类型图标，以及点击后的**内联文件内容查看器 / Diff 对照预览**；
     - **成员（Members）**：直接复用 [ai_children_view.zig](../../src/ui/ai_children_view.zig) 的成员列表、角色模板、状态徽标、Token 用量、停滞警示条与「提醒 / 停止子任务」；点击成员在同栏内展开事件流并支持 Steer 引导；
     - **留言板（Board）**：直接复用共享留言板卡片流（`host.post`）与筛选条；
     - **关系图（Graph）**：直接将既有 [ai_children_view.zig](../../src/ui/ai_children_view.zig#L390-L470) 与 [graph.svg](../../design/ai-agent-mode/graph.svg) 的**「协调者」居中正交连线关系图**（协调者 `68×28` 胶囊 + 按留言量着色的正交双段连线 + `#seq name` 成员胶囊）内嵌至右侧栏展示，不再阻塞在全屏 Modal 弹窗后方；
     - **轮次（Rounds）**：Boost 模式下直接复用“实现 → 挑战 → 修复 → 终验”纵向轮次与终验证据视图。
4. **分栏窄宽响应式适配**：
   - 当独立 AI 插件放入会话组并拖拽为较窄分栏（例如宽度 `< 780pt`）时，左右侧栏默认自动收起为切换按钮，保证中央对话区始终拥有最小可用宽度（`≥ 360pt`），点击按钮仍可按需展开。

### 3.3 核心权限与可见域契约：独立单页签 vs 会话组内部成员

独立 AI 连接在「单独页签」与「会话组内部成员」两种拓扑形态下，必须严格执行不同的信息可见域与工具授权范围：

| 维度 | 独立单会话页签（Standalone AI Tab） | 会话组内部成员（Grouped AI Pane） |
| --- | --- | --- |
| **宿主绑定所有者（`scope.Owner`）** | 独立页签仍以自己的 `.session` 绑定拥有对话；这个所有者不是终端。用户所选的活动连接按完整 `SessionHandle`（ID 与代际）记录；请求冻结后，调用时再次核对当前选择。 | 所属会话组 `.group(GroupId)`，按组的成员及成员修订校验。 |
| **关联与会话读取边界** | 只有显式选中的当前活动会话才可作为终端目标；已保存主机配置、名称文本或工作区文件选择均不是终端权限。选择、移除在同一菜单；`@` 只是该菜单的输入入口。 | 仅查询或操作已授权的组内活动成员，不提供跨组关联。 |
| **AI 工具可读/可操作目标** | 1. 本地工作区工具（`host.local_*`）、已开放笔记知识库（`notes.*`）、`fetch_url`、Skills、MCP；<br>2. **主机配置工具**：`host.list_hosts`、`host.get_host`、`host.create_host`（读取全部已保存主机，按现有权限策略审批新建）；<br>3. **跨会话/跨组活动连接目标**：只能使用用户已显式关联且当前仍有效的会话；读取主机配置不授予该主机的终端权限，经当前权限引擎与终端输入租约（`V0.7 PATCH`）仲裁后执行读取或命令调用。 | 1. 本地工作区工具（`host.local_*`）、已开放笔记知识库（`notes.*`）、`fetch_url`、Skills、MCP；<br>2. **主机配置工具**：只允许在本组上下文内按需新增打开新工作会话；<br>3. **活动连接目标**：**`ToolScope` 强校验只包含同组 `GroupId` 内的活动成员 `SessionHandle`**，任何针对组外会话或跨组 ID 的工具调用在宿主派发门禁层直接返回 `TargetOutsideAssistant` 拒绝。 |
| **同组内来回换位** | 不适用。 | **保持组内作用域不变**（分栏拖拽上下/左右换位不改变 `GroupId`，不打断正在运行的模型轮次与子智能体）。 |
| **入组 / 出组动态转换** | 当独立 AI 页签被用户**拖入或加入某个会话组**时：宿主立即切换其所有者为组内成员、推进 `environment_revision`、清除已关联的组外目标、更新 `ToolScope` 与可选目录收敛至组内成员；若队列中存在引用了组外会话的待消费输入，按 `V0.3 PATCH` 环境变更门禁暂停并提示范围已收敛为当前会话组。 | 当 AI 分栏从会话组中**移出为独立页签**时：所有者恢复为自身页签的 `.session`，推进 `environment_revision`；重新开放显式关联入口，不自动授予组外或原组成员的终端权限。 |

### 3.4 按关联会话动态区分与分层装配的工具架构

ZeroWork 完整工具池（[host_tool_catalog.zig](../../src/ai/host_tool_catalog.zig) 与各连接插件绑定工具 [plugin_tools.zig](../../src/ai/plugin_tools.zig)）包含本地文件、终端控制、SFTP 传输、BMC iKVM 图形键鼠、Web 浏览器控制、会话生命周期与扩展服务等 **45+ 项工具**。如果将全量 Schema 无差别注入独立 AI 会话的每次请求，会造成严重的 Prompt Token 膨胀与模型跨协议误调。

为此，V0.8 对独立 AI 会话连接设计**「三层按会话与协议动态装配」**机制，在保留全工具支持能力的同时，将单次请求实际暴露的工具数精准收敛：

#### 第 1 层：轻量常驻内核工具（Core Baseline，按当前环境开关裁剪）

仅包含不依赖具体远程协议的通用基础能力，且对可选扩展实行**状态门控挂载**（未开启时不注入 Schema）：

| 模块 | 工具集 | 挂载条件 |
| --- | --- | --- |
| **交互与记忆内核** | `host.ask_user`、`host.get_current_context`、`host.recall`、`host.fetch_url`、`host.agent_tasks` | 常驻挂载（`host.agent_tasks` 按 `V0.7` 子智能体开关及父子深度规则控制）。 |
| **目标发现与建立（独立页签按需）** | `host.list_hosts`、`host.get_host`、`host.list_sessions`、`host.open_session`、`host.create_host` | 独立页签下用于发现/打开已保存主机与会话；当用户已显式通过 `@` 或按钮关联了目标会话时保持精简发现能力；组内成员按组生命周期规则裁剪。 |
| **本地工作区工具** | `host.local_read_text`、`host.local_list_dir`、`host.local_search`、`host.local_write_text`、`host.local_edit_text`、`host.local_delete`、`host.local_move`、`host.local_changes` | **仅当当前对话已设置 `Local Workspace` 时挂载全部本地写/删/移工具**；未设置工作区时按现有工作区门禁收敛（避免无意义工具占位）。 |
| **笔记知识库** | `notes.list_libraries` / `notes.search` / `notes.read` 等 | **仅当存在至少 1 个开启了「允许 AI 读取」的知识库时挂载**。 |
| **Skills 与 MCP 网关** | `host.skills`、`host.mcp_catalog`、`host.mcp_call`、`host.mcp_request`、`host.mcp_result` | **仅当存在已启用本地 Skill 或已勾选 MCP Server 时分别挂载**；MCP 维持二级按需懒加载（`mcp_catalog → mcp_call`），不将第三方 Server 工具全部平铺进主工具列表。 |

#### 第 2 层：按「当前已关联目标会话协议」动态挂载专属会话工具

宿主从当前对话的**活跃关联目标集（Active Target Set）**（独立页签下由用户通过 `@` / 按钮勾选的会话与会话组 + AI 本轮经审批新打开的会话；会话组内模式下固定为同组活动成员）中提取**实际存在的连接协议集合**，在每次组装 `RequestTable` 时**仅注入已关联协议对应的工具子集**：

| 已关联目标包含的协议 | 动态挂载的专属会话工具 | 未关联该协议时的处理 |
| --- | --- | --- |
| **未关联活动终端**（纯对话／本地工作区） | 没有可执行批处理或交互命令的终端目标。选择「自行判断」不会增加一个隐含授权；本地工作区读写按其独立授权处理。 | 可以显式关联活动会话，或在关联菜单新建本地终端后再执行。 |
| **本地终端（`local`）** | 终端查询（`host.read_terminal` / `search_terminal` / `list_terminal_commands`）、交互式 PTY（`host.run_in_terminal` / `get_execution` / `wait_execution` / `send_execution_input` / `stop_execution` / `attach_shell`）、批处理与文本（`run_command` / `file.*`）。 | 不挂载 SFTP 传输、BMC、Web 工具。 |
| **SSH 终端（`ssh`）** | 终端查询与交互式 PTY 全套 + 批处理与文本 + 远端目录/文件读取（`list_remote_files` / `read_remote_file`）+ 传输队列（`host.upload_file` / `download_file` / `get_transfer` / `wait_transfer` / `cancel_transfer`）。 | 不挂载 BMC、Web 工具。 |
| **独立 SFTP（`sftp`）** | 远端目录/文件读取（`list_remote_files` / `read_remote_file`）+ 传输队列（`host.upload_file` 等 5 项）。 | **不挂载**任何 `run_in_terminal` / `run_command` / `attach_shell` 终端工具。 |
| **带外管理（`bmc_ikvm`）** | BMC 专属 8 项工具（`bmc_ikvm.read_power_state` / `read_boot` / `describe_frame` / `screenshot` / `pointer` / `keyboard` / `operation_status` / `image.read`）。 | **不挂载**终端 PTY、SFTP 传输、Web 工具。 |
| **浏览器连接（`web`）** | 浏览器观察与交互工具集（`web.*`，沿用 [V0.6.1](V0.6.1_WEB_AI_CONTROL.md) 工具策略与能力开关）。 | **不挂载**终端 PTY、SFTP 传输、BMC 工具。 |

同时执行**能力维度的目标枚举收敛（Per-Tool Target Filtering）**：
- 若当前同时关联了 `SSH 会话 S1` 与 `BMC 会话 B1`，则 `host.run_in_terminal` 的 Schema `session_ref` 枚举**仅包含 `S1`**，而 `bmc_ikvm.screenshot` 的 `session_ids` **仅包含 `B1`**；模型在工具参数层即无法跨协议错选目标，宿主派发层亦复验目标能力快照。
- 支持动态生命周期工具门禁：仅当当前已关联 ≥ 1 个外部活动会话时，才按需要挂载 `host.close_session` / `disconnect_session` / `reconnect_session` / `wait_session_ready` 等会话控制工具。

#### 第 3 层：多协议混合场景的子智能体目标分流（Subagent Target Sharding）

当一次复杂任务同时关联了包含 3–4 种异构协议的会话（例如同时排查 `SSH + SFTP + BMC + Web`）时，主智能体在 `Swarm / Auto` 模式下通过 `host.agent_tasks` 委派子智能体：
- 创建子智能体时可指定该子任务负责的精确 `session_refs` 子集（例如 `#1 查日志` 仅绑定 `SSH S1`，`#2 看控制台` 仅绑定 `BMC B1`）；
- 宿主在为子智能体构建 `RequestTable` 时，**按该子智能体被分配的 `session_refs` 协议子集重新执行第 2 层裁剪**：`#1` 只获得 SSH 终端工具，`#2` 只获得 BMC 图像/键鼠工具；
- 由此保证哪怕在全栈混合场景下，每个并发 Worker 请求的工具定义依然保持高信噪比与最小 Token 开销。

### 3.5 接口适配与架构解耦要点

1. **对话渲染组件去单例化（`AiConversationSurface`）**：
   - 将当前 [main.zig](../../src/main.zig#L17911) 中的 `mountAssistantConversation` 及其在 `AiHost` 中的硬编码 UI 节点指针抽离为独立的、可多例挂载的 `AiConversationSurface` 结构体；
   - 宿主级「悬浮窗 / 右侧停靠槽」持有窗口唯一的附着视图适配器，而每个独立 AI 插件内容页的 `ContentRenderer` 实例拥有自己独立的 `AiConversationSurface` 实例及左右侧栏状态，底层均通过标准消息邮箱与事件总线订阅各自绑定的 `AgentRuntime`。
2. **`AgentRuntime` 归属与生命周期扩展（[session_runtime.zig](../../src/ai/session_runtime.zig) / [attached_service.zig](../../src/ai/attached_service.zig)）**：
   - 扩展 `scope.Owner`（[tool_scope.zig](../../src/ai/tool_scope.zig#L6)）或引入 `RuntimeAttachment` 枚举区分：`attached_session(SessionHandle)`、`attached_group(GroupId)`、`standalone_ai(SessionHandle)`、`grouped_ai(SessionHandle, GroupId)`；
   - **唯一可写原则不变**：无论有多少个独立 AI 页签与附着式 AI 助手同时开启，每个 `ConversationId` 同一时刻仍然至多只绑定在一个 `AgentRuntime` 上；多开的独立 AI 页签各自启动独立 Worker 线程、独立取消令牌和独立持久化记录；
   - **并发输入安全仲裁不变**：当全局独立 AI 页签与某个 SSH 会话自身的附着 AI 助手（或用户人工键盘）同时试图写入同一台 SSH 终端时，由宿主级终端输入租约与 [V0.7 PATCH 冲突仲裁器](../SPEC/V0.7_PATCH_TERMINAL_INPUT_CONFLICT_ARBITRATION.md) 按 `SessionHandle` 逐句柄串行仲裁，避免多路并发直写导致命令交错或 PTY 损坏。
3. **统一资源上下文与工具表装配服务（`HostContext` / `RequestTable` 装配器）**：
   - 在宿主层提供只读且带 `revision` 的**活动目标快照投影接口**，按调用方策略输出「全局可选列表（全部组 + 全部独立会话 + 已保存主机）」或「组过滤列表（仅指定 `GroupId` 成员）」；
   - `@` 指令补全器、目标选择器按钮、`ToolScope.inventory` 与三层动态 `RequestTable` 装配器共同消费同一权威快照与活跃目标集合，确保前端可选范围、模型可见工具 Schema 与后端 `DispatchFence` 校验三者严格一致。

## 4. 浏览器连接支持打开新窗口（方案 3：独立 macOS 原生子窗口）

> **UI 边界声明**：V0.8 **不修改、也不重绘既有浏览器连接主标签页的工具栏、书签条与站点网页视图**（浏览器主页面仅随第 2 节自动复用新的顶栏单岛与右下角吉祥物）。本节 UI 与原型的全部增量工作严格聚焦于 `ZWWebPopupWindow` 独立子窗口的原生顶栏与子 `WKWebView` 托管。

### 4.1 场景与问题根因

服务器带外管理（BMC / iDRAC / iLO / Supermicro / Sugon / iBMC）网页中点击「打开远程桌面（HTML5 iKVM / 虚拟控制台）」或部分管理页的「新窗口查看报告」时，网页通常通过 JavaScript `window.open(url, name, features)` 或携带特定窗口特性/脚本依赖的 `target="_blank"` 触发打开新窗口。

现状 [macos_web_surface.m](../../src/platform/macos_web_surface.m#L368-L374) 与 [L459-L463](../../src/platform/macos_web_surface.m#L459-L463) 中：
- `webView:createWebViewWithConfiguration:forNavigationAction:windowFeatures:` 直接返回 `nil` 并弹出 `"暂不支持此网页弹窗。"`；
- `decidePolicyForNavigationAction:` 仅对用户点击的普通 `GET` 链接做了当前页覆盖降级，无法满足需要保留父管理页（挂载虚拟介质/电源控制）并同时操作远程桌面的场景。

### 4.2 WebKit 桥接铁律与配置继承

实现浏览器新窗口有一项不可绕过的平台契约：BMC 远程桌面子窗口高度依赖父页面的**非持久 `WKWebsiteDataStore`（登录 Cookie、SessionStorage）、`window.opener` 跨窗口脚本通信（读取 KVM 一次性 Ticket / CSRF Token）以及父会话建立的 SSH 跳板 SOCKS5 代理**。

因此在 [macos_web_surface.m](../../src/platform/macos_web_surface.m) 中必须遵守：

1. **原样消费回调传入的 `WKWebViewConfiguration`**：
   - 在 `webView:createWebViewWithConfiguration:forNavigationAction:windowFeatures:` 内，**必须直接使用参数传入的 `configuration` 初始化子 `WKWebView` 并同步返回该 `WKWebView` 实例**；
   - **禁止**自行重新 `alloc/init` 新的 `WKWebViewConfiguration` 或重新构造 `WKWebsiteDataStore`，否则 `window.opener` 会直接断裂且丢失父页面的代理配置与登录态。
2. **协议与入口准入校验**：
   - 若父 `ZWWebSurfaceOwner` 正处于 `closing`、已断开重建前状态或已达到单会话子窗口数量上限，拒绝创建（返回 `nil` 并入队提示）；
   - 当 `action.request.URL` 非空时，沿用 `zw_is_web_url` 检查（允许 `http`/`https` 以及老旧 BMC/WebKit 初始化弹窗使用的 `about:blank` + `document.write()` 脚本过渡页，其后的所有顶层导航跳转继续由子窗口 `decidePolicyForNavigationAction:` 严格校验 `http`/`https` 并拦截 `file://` / `javascript:` 等危险 scheme）；
   - 子窗口内触发的文件下载继续沿用 V0.6 一致的宿主显式未支持提示，不静默丢弃请求；
   - 保持现有用户普通 `GET` 外部链接处理清晰一致：当触发了 `createWebViewWithConfiguration:`（包括 `window.open` 与显式新窗口打开）时，统一以独立原生子窗口承载。
3. **响应脚本主动关闭**：
   - 实现子 `WKWebView` 的 `WKUIDelegate` 方法 `webViewDidClose:`，当远程页面通过 `window.close()`（例如完成 OAuth/SSO 回调后自动关闭）触发关闭时，立即有序销毁对应的原生子窗口并归还配额。

### 4.3 独立 macOS 原生子窗口（`ZWWebPopupWindow`）设计

采用**方案 3（独立 macOS 原生子窗口）**，每个新窗口由 AppKit 原生 `NSWindow`（`ZWWebPopupWindow`）独立托管，不挤占主窗口工作区内容槽或增加主窗口 Tab 栏负担。

| 设计要素 | 规格与行为 |
| --- | --- |
| **窗口形态与多屏支持** | 标准可缩放 macOS `NSWindow`（支持标题栏拖拽、自由调整尺寸、拖放至外接副屏及系统原生全屏），与主窗口独立切换焦点，互不遮挡原 BMC 控制页。 |
| **初始尺寸与位置** | 解析 `WKWindowFeatures` 的 `width` / `height` / `x` / `y`；未指定时默认 `1280×800`；施加最小尺寸下限 `480×360` 并按当前屏幕 `visibleFrame` 进行安全区 clamp，防止页脚或标题栏跑出屏幕外。 |
| **精简原生窗口顶栏** | 顶部集成轻量化原生控制条（高度约 `38pt`），展示：<br>1. **归属徽标**：父连接名称及当前网络路径模式（如 `SSH 代理 · 跳板链路` 或 `直接连接`）；<br>2. **只读地址与来源胶囊**：显示当前真实 `origin` / 只读 URL 与 TLS 状态指示（支持一键复制 URL，不开放自由输入跨站跳转以免脱离父连接上下文语义）；<br>3. **窗口标题**：实时同步 `WKWebView.title`；<br>4. **基础动作**：刷新/停止加载、关闭按钮（可选保留开发者检查器调试入口，受同策略控制）。 |
| **父地址栏子窗口找回入口** | 当某父网页会话存活 ≥ 1 个子窗口时，仅在其既有地址栏尾端（收藏星标旁）显示轻量**「子窗口 N」**胶囊角标（`0` 个时不显示）；点击可展开当前会话派生子窗口列表并一键前置聚焦（解决子窗口被移到副屏或被遮挡后难以定位的问题）。 |
| **独立挑战与对话框队列** | 子窗口 `ZWWebPopupOwner` 持有独立的有界 `ZWWebPendingRequest` 队列：子窗口内触发的 JS `alert` / `confirm` / `prompt`、HTTP Basic/Digest 认证以及同源 TLS 证书例外审核，均呈现在该**子窗口自身上下文中**（或以归属明确的原生 Sheet / 对话框挂载于该子窗口），不污染或阻塞主窗口其他页签；沿用父会话的 TLS 信任策略或独立确认记录。 |
| **键鼠与 BMC iKVM 适配** | 子 `NSWindow` 拥有独立完整的键盘焦点与 `firstResponder` 链，确保 HTML5 iKVM 画布对组合键、功能键（`Ctrl` / `Alt` / `F1-F12`）、中文 IME 与鼠标相对/绝对坐标捕获正常工作；仅在子窗口内保留常规窗口关闭 `⌘W`，避免截获远程桌面常用快捷键。 |

### 4.4 生命周期归属、数量上限与资源回收

```text
父网页会话 (SessionHandle + generation, web_proxy.Proxy)
  ├── 父 WKWebView (主窗口内容槽挂载)
  ├── 子原生窗口 #1 (ZWWebPopupWindow + 子 WKWebView, 共享 DataStore & opener)
  └── 子原生窗口 #2 (ZWWebPopupWindow + 子 WKWebView, 共享 DataStore & opener)
```

1. **单会话子窗口数量上限**：
   - 每个父网页会话同时允许存活的原生子窗口数量上限设为 **8 个**（`max_popups_per_session = 8`）。超出上限时拒绝新的 `createWebViewWithConfiguration:` 请求，并在父会话呈现非模态提示「已达到单会话子窗口数量上限」。
2. **独立关闭 vs 级联关闭**：
   - **子窗口单独关闭**：用户点击子窗口关闭按钮、`⌘W` 或页面 JS 调用 `window.close()` 时，仅结清该子窗口的 `pending` 回调、解绑 `WKNavigationDelegate` / `WKUIDelegate` 与 KVO、销毁子 `WKWebView` 与 `NSWindow`。父网页会话与 SSH SOCKS5 代理继续正常运行。
   - **父会话关闭 / SSH 断线重连 / 应用退出（含会话组内浏览器成员）**：
     - 父网页会话关闭，或依据 [V0.6 §3.1](V0.6_WEB_CONNECTION.md#31-重连与网页会话重置) 发生 SSH 断线重连需要重建非持久 `WebsiteDataStore` 与代理代次时，**父表面必须先同步/有序级联关闭全部派生子窗口**（拒绝再接纳新弹窗，取消所有子窗口 `pending` handlers 并完成一次回调，销毁所有子 `WKWebView` 与 `NSWindow`）；若该浏览器是会话组成员，仅级联关闭隶属于该浏览器成员 `SessionHandle` 的子窗口，不牵连同组其他成员会话；
     - 父会话 `V0.6 §6.4` 的自有资源回收账本须将**「全部派生子窗口已完成 `pending` 回调结清、KVO/delegate 解除及强引用归零」**作为前置条件之一；全部满足后方可发布父会话的 `.released` 回执。
3. **代理并发流预算评估与扩展**：
   - 当前 [transport_factory.zig](../../src/host/transport_factory.zig#L13) 与 [web_proxy.zig](../../src/host/web_proxy.zig#L11) 中，单个网页会话代理的最大并发活动流为 `max_streams = 16`。当主 BMC 管理页与多个远程桌面子窗口（每个通常包含视频流 WebSocket + 键鼠控制流 + 媒体/健康轮询 HTTP 长连接）同时并发工作时，需要评估并压测多路流峰值；
   - 若 16 条流在高并发下触及排队饱和，在**阶段 A** 将网页会话代理的活动流与待开流预算按有界安全上限调优（例如评估提升至 `32` 并维持单会话有界配额），同时保持单次失败/关闭归还全部槽位。
4. **C/Zig 桥接接口扩展（[macos_web_surface.h](../../src/platform/macos_web_surface.h) / [web_surface.zig](../../src/host/web_surface.zig)）**：
   - 在 `ZWWebSurfaceOwner` 增加子窗口注册表与生命周期事件回调（子窗口创建通知、关闭通知、代理/TLS 审核委托）；
   - 通过 [web/runtime.zig](../../src/plugins/web/runtime.zig) 纳入网页插件统一轮询与关闭收尾协调，保证无孤儿 `NSWindow` 或野指针回调。

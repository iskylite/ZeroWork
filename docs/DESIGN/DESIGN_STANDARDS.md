# ZeroWork 设计规范与通用要求

**主背景与四大卡片规则（2026-11-03）**：设置中的透明度 T 与模糊 B 控制最底层画布。先以 100% 不透明绘制画布底色及顶栏、主机栏、主内容区、状态栏的背景填充，再将这组背景作为一个整体，以不透明度 `1−T` 合成到共享图片上；不能在已调透明的画布上再次给卡片设置 `1−T`。四块前景容器本身不再重复填背景，文字、图标、控件及其输入命中保持原样。背景图片只按 B 模糊一次，B=0 时关闭；AI 助手三点入口一并纳入这组背景。主机列表卡片、AI 助手及设置窗口在 L0 上，均为 L1；内部卡片与后续菜单按实际承载关系逐层增加。原生使用独立 `composited_group` 背景节点。

> 当前界面设计入口：[UI_V4 设计说明](../UI_V4/README.md)。

## 2. 主题与颜色

### 2.1 全局主题语义

主题选择气泡使用单一表面、紧凑选项行和当前主题浅色选中态。标题“全局主题”已说明作用域，不再叠加“应用与全部终端”“全局生效”或常驻成功说明。选择后以当前项反馈；管理主题保留次操作。选项行不各自包裹玻璃卡片或多层阴影。 同一裁决覆盖`@theme`候选、行内补全、帮助与短时Toast：键盘提示只写“Enter 应用主题”等操作，不在各入口重复作用范围；删除纯重复行时同步收紧容器。


**原则**：APP 界面与所有终端网格**共用同一套全局主题 token**。底栏、设置和`@theme`均选择全局主题，同时作用于标题栏、侧栏、浮层、设置和全部终端；不提供单会话主题覆盖或“恢复跟随全局”分支。换主题只改 token 值，不改任何布局/结构。`default`恢复应用默认全局主题，和显式选择Sauber分开。

**Token 表**（产品语义映射；现有 `Theme` 尚未一一覆盖以下全部字段，不能把目标表写成已接入结构）：

| Token 组 | 变量 | 说明 | Zig `Theme` 字段 |
|---|---|---|---|
| 强调 | `--accent` / `--accent-2` / `--accent-fg`及R15 `action-*` | 强调、渐变副色、白字动作底分别有明确值，不能只给一个accent便认为足够 | `accent`为现有基础；UI token层须扩展 |
| 背景层级 | `--bg-app` / `--surface-1` / `--surface-2` / `--well` | app底、卡片、次卡、输入井是独立语义槽；按§2.2精确值，不用任意统一提亮算法代替 | `bg`不足以表达全部槽位 |
| 终端 | `--bg-term` `--ansi-g/b/r` `--gutter` `--cursor` | bg-term与bg-app不同；VT原ANSI保留，当前时间戳用fg-2而非旧gutter色 | `bg`/`ansi[]`/`gutter_*`/`cursor`及UI映射 |
| 文字 | `--fg-1/2/3`及可读语义ink | 主文/次文/弱文按各主题取值，语义小字有独立可读变体 | `fg`及扩展UI token |
| 语义 | `--ok` `--warn` `--danger` | 状态底、图标与小字可读ink分开，不改原VT ANSI调色板 | ansi[2]/[3]/[1]为基础来源 |
| 强调透明度梯度 | `--accent-05/06/07/12/22/30` | 逐主题alpha见§2.2；token后缀不保证等于百分比，禁止按名称重新推算 | accent与显式alpha |
| 玻璃 | `--glass-hi/lo` `--glass-spec` | 玻璃渐变两端 + 顶部高光线 | 见 §3.3 |
| 阴影 | `--shadow-1/2/tab/float` | 层级投影阶梯 | 见 §3.3 |

**默认主题**：`Vanta Dark`（`--accent: #6366f1`）与 `Vanta Light`（`#4f46e5`）为出厂黑白双主题；Sauber是蓝色强调`#1345F6`与薄荷背景`#ECFFE5`，为首个第三方主题验证样例（来源`.itermcolors`，UI层级另有产品语义值）。

**Reset的默认值**按当前原型`settings-reset/reset-draft`载入Sauber草稿，保存前可放弃；出厂提供Dark/Light与Reset选择哪一主题是不同概念，不根据本段把Reset静默改为Dark。全局`@theme default`继续恢复应用默认值，不能把字符串default当Sauber的硬编码别名。

**规则**：
- T1. 任何新 UI 元素的颜色**必须引用 token**，禁止写字面 hex。主题导入色是受校验的配置数据；运行时所有控件仍引用同名语义槽，不能把某主题色抄进单个view。
- T2. 启用的普通UI小字须按实际底色合成后检查4.5:1；基础ok/warn/danger值本身不保证小字通过，使用§2.2的可读ink与R15动作底。不能为了UI对比度改写VT原ANSI输出；禁用状态、纯装饰与可读正文分别验收。
- T3. 浮层颜色永远从 `--bg-*` 派生（提亮或压暗），禁止引入体系外颜色。

## 3. 布局、边界与材质

### 3.1 卡片与间距


```
.window { padding: 5px; gap: 8px }        ← 页面外边距5pt，卡片间隙8pt
├─ 标题栏卡片  h36  r11  shadow-1
├─ 主区 (gap 8)
│   ├─ 侧栏卡片  w224 ⇄ 48  r11  shadow-1
│   └─ Pane 卡片  flex1  r11  shadow-1   ← 终端/浮层锚定容器
└─ 状态栏卡片  h26  r11  shadow-1
```

当前最终值（2026-10-27）：外边距5pt、顶栏36pt、底栏26pt、页签30pt。主窗口与传输面板复用圆角页签；自定义页签颜色在复制会话时继承。普通控件的焦点/按下使用hover中性表面，选项状态保留selection色。

**间距分级**（窗口层级的三种用途；控件内部及组pane另遵循其精确4/6/8px规格）：

| 级别 | 值 | 用途 |
|---|---|---|
| 页面呼吸 | 5pt | 窗口外边距 |
| 卡片间隙 | 8pt | 卡片与卡片之间 |

**规则**：
- L1. 浅色主题的 `--bg-app` 与 `--surface-1` 明度差**不得超过一档**（≈4-6%）；深色可略大。间隙突兀一律先收背景差，不是加阴影。
- L2. 圆角分级：卡片11px / 内容器9px / 控件7–8px / chip5–8px；有实体背景的卡片与控件按角色取值。无背景布局Frame、VT单行裁切框、文字和SVG内部几何可以0圆角，不能为套规则改变裁切或文字基线。
- L3. 侧栏默认 224px，折叠 48px 图标栏（`⌘B` 或头部折叠钮）；<1100px 窗口宽自动折叠（SPEC §2.0c），用户手动偏好优先于自动。

### 3.2 描边允许场景

**总纲：先用对齐、间距、文字与状态组织层级；只在输入、路径摘要、日志视口及当前选中项等有明确含义处加井底或浅色底。投影用于浮层及唯一主操作，不为普通信息行和分区标题加影。描边仅保留虚线空槽和组页签标记。**

| ✅ 允许描边 | 样式 | 理由 |
|---|---|---|
| ① 虚线井 | 1.5px dashed `--well-bd`，hover 变 accent | “可填充的空槽”（如拖放区），虚线本身表达可放置 |
| 键盘焦点（不画描边） | `--sel-bg` / `--surface-2` 底色变化，输入保留 caret / IME | 所有普通控件、菜单、状态栏入口及浮窗操作均不画外框 |
| ③ 页签身份色与组卡片 | 所有会话／组Tab左缘常驻2.5×18pt色条，仅活动项显示同色底线；选色不染标题文字或系统图标，不铺组色tint底 | 组内pane分别绘制r11卡片底色，4pt间隙露出底层画布，不在会话卡左侧画蓝细线 |
| 危险提示（不画描边） | danger tint 底、图标与短文 | 保留警告含义，不添加整圈框线 |

| ❌ 禁止描边 | 替代方案 |
|---|---|
| 外层容器与浮窗 | 主题表面与必要的浮层投影；内部信息分组靠留白和对齐，默认无子卡投影 |
| 分区边界（标题栏底/状态栏顶/侧栏缘） | 8pt 间隙 + app 底色透出 |
| 按钮 | 主操作保留渐变轻影；普通图标次操作默认透明，hover浅底；取消等文字次按钮可用surface-2 |
| 菜单/chip/标签/选中态 | tint 底（`--accent-07`/`--sel-bg`） |
| 终端 gutter 与正文之间 | 弱文字明度＋8px留白；时间列48px右对齐，完整规则见V0.1.2，不画分隔线 |

**违规自检**：界面里每看到一条线，问"它属于虚线空槽或组页签标记吗？"——不属于就删掉，改用层级表达。

**统一全局背景与半透明层次（2026-10-29 当前生效）**

应用内只有一个全局主题背景层。根部绘制主题基色与可选图片，常驻卡片和内容容器按表面角色绘制背景，临时浮窗、菜单与气泡按实际浮层层级绘制背景；四块主卡片的背景透明程度直接由设置决定，内部填充与临时浮层沿用各自角色和层级规则。无背景图片时仍使用同一映射，不能因关闭图片而额外恢复实色容器。文字、图标、输入内容和状态标记保持自身语义颜色；禁止降低整个控件树的 `opacity` 来实现背景透明。

| surface-2 | 内部卡片、次级容器 | 72% | 90% |

| tab-on | 活跃页签表面 | 68% | 82% |

**视觉层级（2026-11-03）**

L0 是最底层画布与四大卡片。实际绘制在 L0 上的主机列表卡片、AI 助手、设置窗口均为 L1；在 L1 卡片上的结果卡片或菜单为 L2；其内部命令／输出卡片以及菜单触发的 Tooltip 为 L3。每个实际卡片或独立浮层边界增加一层，透明布局容器、标题、工具栏不增加层级。菜单和 Tooltip 沿触发控件的实际所属卡片回溯，不能只计算浮窗深度。

浮层之间依靠背景实度、间距及必要的柔和投影区分，不追加整圈 border、outline 或描边式阴影。输入与键盘焦点同样遵循§3.2：使用底色、文字/图标与 caret/IME 表达状态，不以焦点 ring 补框。虚线空槽和组页签标记保留各自语义。

临时表面的透明度由其所在的视觉层级决定，不由 Tooltip、Popover、Modal、卡片等组件类型决定。`overlay` 只提供主题底色和首层的兼容参数；`well`、`surface-2` 等内部填充角色不能用于决定新浮层的透明度。实际卡片增加一层，输入内容及 hover 行反馈不单独增加卡片层级；纯布局节点的嵌套不计层。

| 实际浮层层级 | 最终透明程度 P（T=0） | 最终透明程度 P（T=1） | 最终不透明度 alpha8（T=0 → 1） |
| --- | ---: | ---: | ---: |
| L1：画布上的卡片／首层浮窗 | 0% | 80% | 255 → 51 |
| L2：L1 上的卡片／子菜单 | 0% | 60% | 255 → 102 |
| L3：L2 上的卡片／说明气泡 | 0% | 40% | 255 → 153 |
| L4 及以上 | 0% | 20% | 255 → 204 |

`T=clamp(background_transparency/100,0,1)`；最终透光率 `P(L)=T×Q(L)`，`Q(L)=(5−min(L,4))/5`，最终不透明度为 `1−P(L)`。在直接父表面上绘制时，实际填充 alpha 为 `1−Q(L)/Q(L−1)`（T=0 时用不透明填充），不能把最终不透明度再当作每层填充 alpha。L4+ 保留 20% 的设置透光率，不再强制全不透明。文字和图标保持独立。

浮窗按实际覆盖区域补偿：若该区域下方实际最高表面为 K，则所需填充为 `max(0,1−Q(L)/Q(K))`。超出父卡片、圆角之外或完全落在画布上的部分分别计算；同层浮窗重叠不再次累加实度。已更实的下层保持其现有透光率，避免用新的浅层窗口继续加实。原生在背景专用绘制节点中按窗口坐标分区，不降低前景透明度，不复制背景图片。背景补偿不改变浮窗的布局、排序、输入或局部模糊设置。

父层按触发控件实际所在表面确定；原生 portal 浮层沿 OverlayStack 的存活 trigger 引用回溯父表面，手工定位的现有浮窗以其 overlay 材质边界识别。组件种类、节点嵌套深度、浮层 tier 和原始 z-index 均不直接选择透明度百分比；它们的排序、定位和交互职责保留。同层的独立浮窗共享 L1，不能按当前已打开窗口的数量升级透明度。

模型示例：工作区 → AI 浮窗 L1 → 模型选择 L2 → 模型说明 L3。同一个 Tooltip 直接由工作区触发时是 L1，放在模型菜单里时是 L3。移动父表面、关闭重开、切换主题或全局材质参数后须重新解析；气泡伸出父浮窗边界也使用同一层级底色。L2/L3 与 L1 同步局部背景模糊 `max(12,B)`，不模糊自身文字。

实现入口：`src/ui/app_theme.zig` 的 `layerAlpha/layerBackground` 和 `src/ui/layer_materials.zig`；原生主窗口与辅助窗口安装同一策略。

最终数值（全局滑块 T=0；alpha 表示不透明度，文字和图标不受影响）：

| 表面角色 | 最终基础透明程度 P（量化前） | 实际背景 alpha8 | 实际不透明度 |
| --- | ---: | ---: | ---: |
| surface-1 | 0.00000000% | 255/255 | 100.000000% |
| surface-2 | 72.00000000% | 71/255 | 27.843137% |
| well | 64.00000000% | 92/255 | 36.078431% |
| overlay | 0.00000000% | 255/255 | 100.000000% |
| hover | 82.00000000% | 46/255 | 18.039216% |
| tab-on | 68.00000000% | 82/255 | 32.156863% |

唯一实现来源为 `src/ui/app_theme.zig` 的 `material_transparency_base`、`material_transparency_span` 与 `material_ratio`。`T=clamp(background_transparency/100,0,1)`，`P=min(M,P0+D×T)`，`alpha8=round(255×(1−P))`。`P0`为代码直接使用的最终基础透明度，`D`为当前滑块全程增量，达到角色上限`M`后保持不变；不存在历史调节倍率。此表达保持当前滑块响应与各角色上限。滑块 0 表示采用基础透明层级，**不再表示所有表面完全不透明**；滑块 100 也不能令浮窗完全透明。8 位 alpha 会产生不超过约 0.2 个百分点的舍入差异。

图片沿用独立合成关系：图片 alpha 为 `T`（0% 隐藏图片，100% 完整显示图片），其开关只控制图片可见性，不关闭 UI 图层透明公式；不增加新配置字段。草稿预览与已保存值使用同一公式。根背景图使用 `B=clamp(blur_px,0,96)`；普通表面不额外模糊；临时浮层的局部背景模糊为 `max(12,B)` 逻辑 px，B=0 时也保留 12px，防止下层文字重影。采样应用窗口内已绘制的内容，不复制背景、不增加不透明地板，也不模糊浮层自身文字。

可读性优先：主动作、状态色、媒体和显式 ANSI 色块保留语义颜色；不将其当作普通大面积容器底。修改参数时核对 T=0/中间值/100、角色上限和顺序，并检查有图/无图、普通/最小窗口的实际浮层。当前参数见 `src/ui/app_theme.zig`；通知历史浮窗现已在自身 panel 样式接入统一策略，并在 blur 单独变化时同步到保留节点。记录仍仅证明所列场景，不宣称全部主题和业务状态均已验收。

- **原生能力以vendor 0.17源码为准**：`ui.Color`支持RGBA，`BoxStyle.background`可用alpha；通用`opacity`存在，但不能用它降低整份前景透明度来冒充背景材质。`glass.backdrop_blur`范围为0–96逻辑px，采样窗口自身`mainRT`中已经绘制的内容，可作用于下层app背景图片；公开`GlassParams`也有`backdrop_saturation/brightness`并已传至shader。这不是桌面采样，与CSS `blur(28px) saturate(1.5)`的最终视觉等价仍须同尺寸实机验收。旧文的`DrawCmd.blur(r, radius, saturate)`不是当前依赖的API，不得据此推导实现或性能保证。
- **窗口边界**：根窗口surface为`fully_opaque`，`WindowConfig`没有透明窗口或`NSVisualEffect`接入；图像alpha与窗口桌面透出是不同能力。桌面透出需要独立原生窗口接入，原型不得承诺已具备。blur的应用绑定、采样顺序与性能仍需实机验证。
- **图片边界**：`ui.image`及`loadTexture`可绘制RGBA纹理，现有`ImageProps`没有Fit/Fill等适配属性；缩放、等比裁切、平铺、对齐和遮罩须由应用布局/clip与绘制逻辑接入。背景图片的路径、适配、透明度与模糊使用项目当前配置；HTML模拟或Figma静态材质不能代替原生实机验收。

### 4.1 按钮、输入和chip

**角色边界与内容撑高**：表单内“选择文件/编辑路径”等尾部次操作仍用24px槽/14px图形，不能把34px提交/保存/恢复的规格套到它们上。传输管理器是锚定气泡，只保留右侧24px关闭，不放最小化/最大化；AI浮窗原22px三态控制继续保留。13/Bold/20适用于面板、分类及历史标题，首次使用主视觉18/Medium/26、对象身份和核心确认14/Medium/21、快速命令主输入14/Regular/20各有独立语义。修改共享文字源后检查所有实例的FIXED/HUG高度，18px行高不得留在16px固定槽中。

### 4.2 图标语义

**总纲**：界面上所有图形元素必须先回答"它是**区域标识**还是**功能操作**"——两者的视觉规格完全不同，不可混用。这是避免"看着像按钮但不能点 / 能点但认不出"的关键。

#### A. 区域标识图标（Decorative Icon）—— 纯视觉锚点，不可点击

| 特征 | 规格 |
|---|---|
| 用途 | 卡片/浮层/分区的标题左侧，标记"这个区域是什么" |
| 样式 | **单色线稿**（Lucide/Feather 风格），accent 色或 fg-2 色 |
| 尺寸 | 16-18px（设置页分区 16px，卡片标题 18px） |
| 底板 | **无底板、无背景、无圆角** |
| 交互 | **无 hover 态、无点击**——鼠标移上去不变样 |

**应用清单**：
| 位置 | 图标 | 色 |
|---|---|---|
| 侧栏"主机与连接" | 服务器（双机架） | accent |
| AI 浮窗"AI 助手" | ✦ 四角星（AI 符号） | accent |
| 设置页各分区标题 | 齿轮/调色板/钥匙等 | fg-2 |
| 状态栏只读指标的图形本身 | 终端 / activity / network；14px；可点击入口整体按下方功能按钮 | fg-2；活跃功能用语义色 |

#### B. 功能操作按钮（Action Button）—— 可点击，必须有反馈

| 特征 | 规格 |
|---|---|
| 用途 | 工具栏、操作行、窗口控制 |
| 样式 | 图标＋独立命中区；默认透明，hover显示圆角浅底，不要求常驻底板 |
| 尺寸 | 32×32（标题栏）/ 28×28（Tab 栏）/ 24×24（侧栏头部）/ 22×22（AI 三态钮） |
| 底板 | 圆角 7-9px，默认透明，hover 浅底 `--hover` |
| 交互 | **必须有 hover 态**（底色变化或上浮），点击有 active 态 |

**应用清单**：
| 位置 | 按钮 | 样式 |
|---|---|---|
| 标题栏 ⚡⇅✦⚙ | 功能入口（快速连接/传输/AI/设置） | 32×32 r8，hover 浅底；激活态 `.hot` 渐变 accent 底 |
| AI 浮窗 –⤢× | 三态控制（收缩/放大/关闭） | 22×22 r6，hover 染黄/绿/红 |
| 侧栏 ＋⟨ | 新建/折叠 | 24×24 r8，图形14px居中，hover 浅底 |
| Tab × | 关闭页签 | 行内，hover 显现 |

#### 判定自检

看到一个图形元素，问三个问题：
1. **它能点吗？** 不能 → 区域标识（A）；能 → 功能按钮（B）
2. **它有独立命中区和交互语义吗？** 有 → 按钮（B）；静态Tag有底色仍是分类标识，不能只凭底板判断
3. **hover 有反馈吗？** 没有且不可点 → A；必须有反馈 → B

**禁止**：
- 区域标识用按钮规格（渐变底板+色影）——会让用户以为能点
- 同层级元素混用两种规格（如侧栏图标是线稿、AI 头部图标是渐变方块）

#### 灰区：chip 算什么？

chip（如 AI 浮窗底部的 `✋ 确认后执行 ▾` / `Sonnet ▾`，推理另用sliders图标）是**功能按钮的变体**——它可点击（展开下拉），因此具备稳定命中区、可访问名称及hover/open/focus底色反馈；默认可透明或使用`--surface-2`，不强制微影和上浮。**chip = 小型功能按钮**，不是区域标识。

### 4.2.1 内容尺寸与固定尺寸契约

宽、高必须分别按内容与父容器决定；原型里测得某次的矩形，不等于原生组件永远固定为该宽高。新增或修改尺寸时，在样式函数、原型说明或对应测试中说明用途及超限策略。

| 场景 | 宽度选择 | 高度选择与超限策略 |
|---|---|---|
| 普通文字动作、图标＋文字按钮 | 默认内容自适应＋左右padding；需要等宽或稳定基准时用`min_width`，同时核对整排预算 | 单行文字可用角色固定高度，必须容纳实际行高、图标、上下padding和边框；状态切换后重新核对 |
| 图标按钮、关闭/展开/拖拽命中槽、头像、色块、分隔线 | 明确角色的固定逻辑尺寸 | 固定；图形居中，命中区不可随hover/pressed动画缩小或移位 |
| 表单输入/选择器/路径字段、表格列、页签标题、模型名、身份与计数 | 对齐或数据浏览需要时可固定或填充剩余空间；动态文字用独立可收缩label、`min_width=0`与省略 | 单行槽高度容纳实际行高；省略值必须有可访问全名，并按用途提供完整值提示/详情。禁止直接把长路径放入普通固定宽Button标签 |
| 错误、帮助、认证问题、动态说明、消息正文 | 受父容器/最大阅读宽度约束 | 内容撑高＋必要最小高度；长词/路径定义字符换行。不能固定成“一两行”后静默裁掉错误、风险或影响说明 |
| 日志、长命令、文件/结果列表、附件预览、长表单 | 有界视口，内容填充 | 内容自然高度；超过可用区域后由指定ScrollArea滚动。标题/确认/取消等固定操作区留在视口外部，保持可达 |
| 弹窗、气泡、AI浮窗、侧栏、预览媒体 | 产品布局可规定目标或初始宽度，但要受实际可用视口限制 | 上限由视口减去安全边距、标题/底栏及间隔决定；固定的是外框或滚动视口，不是无限长正文。宽高任一变化都须重新约束 |
| 终端网格/视频/画布/图片缩略图 | 按网格、宽高比、缩放或裁切模式决定 | 固定像素/比例有明确渲染意义；和普通文字布局分开，仍核对裁切范围与操作覆盖 |

**尺寸预算**：单行按钮可用内容宽度必须不小于实际字体测得的标签宽度＋图标/指示器槽＋内部gap；外宽另加左右padding/边框。外高至少容纳`max(实际文字行高, 图标槽高)`＋上下padding/边框。整排子项外宽＋gap＋父padding须落在父内容宽度内；固定高度父容器也须核对所有子项高度、margin、gap、padding。不得用UTF-8字节数、字符数×常数或截图估算代替生产字体的度量；无真实字体的单测只证明结构，不能作为像素验收。

**原生文字裁剪**：当前zenit依赖中，布局的`overflow =.hidden`与绘制的`overflow_hidden = true`分别控制不同层面。长路径等文字槽需在自有内容容器设置绘制裁剪，并在创建文字时定义省略；同时保留完整值提示。必须查看真实长文本截图，不能仅凭节点矩形在界内判定无重叠。

**重复条目与已确认密度（2026-10-27 最新修正）**：传输样式以原生组件为准；Figma `320:826473`保留为历史来源，不再沿用52px／54px和折叠式验收。当前所有入口统一76px浅卡片、84px排列节距（卡间距8px）、圆角8px、内距上/下9px与左/右10px；主行24px、元信息16px、组间距7px；会话名、状态、结果／速度统一右对齐。状态76px、结果／速度112px、操作槽102px固定；会话列按同一列表最长名称统一测量宽度，有空间完整显示，优先保留列表最长文件名所需宽度（至少120px），会话名使用剩余空间并在超长时省略；极窄时保留48px会话省略槽，再截断文件名，不能逐条自适应造成列线错位；文件名吸收其余空间；会话专属浮层继续隐藏重复会话名，SFTP窄列沿用既有紧凑列宽及次要列显隐，长值省略并通过详情查看，3px进度轨道始终显示，完成及未知大小任务也保留。默认浏览，点击顶部“管理”才显示复选框与批量操作。状态统计靠左，管理／搜索／筛选靠右，在同一行。会话浮层保持原owner，不显示全部会话切换或底部跳转全局入口。操作按钮一排靠右直接展示，不使用三个点和展开／折叠箭头；上传完成也保留复制远程路径和任务事件。详情仅hover显示，450ms延迟、8px偏移、宽420px受视口约束、内距14px、圆角10px、组距12px；字段顺序为任务编号与归属、文件名、本地路径、远程路径、非空传输选项；不显示动态状态，路径点击复制，允许鼠标移入详情，离开延迟250ms关闭；任务身份使用well底色、8px圆角、7px/8px内距；路径标签与值间距4px，文字11px/16px、路径使用等宽字体并换行。HTML和原生仅展示各自真实任务事实，原型不得用固定成功校验值代替未知结果。后续条目内部滚动，不添加细线分隔。完整值通过hover详情查看；窄列保持按钮可达。

**状态与嵌套**：检查默认/选中/禁用/加载/错误/完成以及最长受支持标签。加载文案或spinner确实改变内容时，必要时预留最大的内容槽；不向原本没有loading的按钮强加loading需求。修改字号、行高、图标、文案或本地化后，重验父槽和同排兄弟。固定栏需要时设置`flex_shrink=0`；可收缩文字/滚动体设置`min_width=0`/`min_height=0`并沿祖先传递可用尺寸。不能只改最内层的`fit`或`fill`而忽略外层固定槽；不能用overflow hidden掩盖应展示的内容。约束失败时改布局或滚动策略，不缩字掩盖问题。

**控件语义**：动作按钮必须核对实际回调、启用条件及操作结果，`click`返回ok只证明输入已发送。单选控件保留标准RadioGroup指示节点及状态生命周期；不要销毁组件仍引用的内部节点来换装饰。静态预览说明选项内容，同一单选状态通常由单选圈表达；额外底板/勾须有明确不同语义。主题缩略卡和列表选中形态按各自设计判断；临时键盘focus背景与持久selected背景分别验收。

**验收门槛**：本项目用1440×900和最小860×480逻辑窗口检查相关状态；组件另有更小有效viewport时再测该边界。提供至少一个真实长中英文名称/路径、多行错误或可增长列表用例（按被改组件适用项选择），同时验证文字/图形在槽内、相邻控件不重叠、外框在视口内、滚动确实发生、底栏可点击。查看真实Metal截图，不能以编译、节点存在、固定矩形相等或全局裁切代替验证。记录未覆盖的系统选择器、真实输入/远端操作；旧精确尺寸快照必须先与现行设计核对，不可自动改成当前输出。

审计入口：`python3 scripts/audit_ui_constraints.py --out /tmp/ui-constraints.json`盘点源码；`node e2e/button_constraints_native.ts /tmp/ui-button-evidence`检查原生导航和布局；长目录回归加位置参数`path`。静态盘点只列出候选，实际问题由数据、布局和像素共同判定。

### 4.3 图标提示与必要文字

高频且语义明确的复制、刷新、文件选择/替换、移除、保存、导入/导出、展开和窗口控制优先使用图标按钮，不为同一动作再占一行长文本。图标必须有独立命中区、hover/pressed/disabled/focus反馈、可访问名称，450ms hover或键盘focus显示短tooltip，Esc关闭；命中区一般22/24/26/28/32px，不能只给细线图形本身命中。

同一卡片的行内操作靠行尾，固定提交动作靠右；文件身份与选择/替换/移除在同一行，标题、路径、必要状态在剩余宽度内单行省略，完整值放tooltip或详情。能力如识图/推理用图标表达，重复说明与次要元信息移到tooltip。危险确认、首次理解成本高或图标有歧义的动作保留简短标签及必要影响说明，不能以省空间隐藏目标、错误、审批影响或禁止原因。

#### Tag 与 Tooltip / Popover 的分工

标题旁的 `SSH`、`SFTP`、`KVM` 使用无描边、小尺寸、中性底的静态 Tag；转发协议/方向、能力类别及确有区分价值的状态也可使用 Tag。协议Tag不着成功色，不用一串Tag复述整句正文。状态Tag配短文字，颜色仅辅助；同一行已有清晰状态文字或图标时避免重复。静态Tag不加关闭钮、不伪装按钮；筛选、选择及下拉入口仍是有交互语义的chip/Button。§4.2的“有底板应为按钮”判定针对图标，静态文字Tag是分类标识例外。

同一身份Tag统一20px高、Inter10/Regular/16并双向居中；短协议基准宽40px，本机身份`LOCAL`保48px宽容纳五个字母，不以加高或加重字体区分。协议选择列表保其交互控件规格，不套静态身份Tag的固定宽高。

本轮“toolkit”按上下文中的轻量提示诉求落实为 Tooltip / Popover：短动作名、快捷键、截断后的次要完整值用 Tooltip；包含多字段、逐跳关系、复制/刷新、滚动或其他交互的详情用 Popover。Tooltip 默认 hover 450ms、focus立即显示；点击底栏连接详情打开可停留的 Popover，不能点击后仅出现一句状态。两者都从当前数据读取，详情不复制独立状态；原生能力限制见§7.3。

### 4.3a 信息组织与组件复用

先确定“对象 → 当前状态 → 可执行动作”，再布局。普通信息行用48px两行结构：图标槽18px、与内容间距6px、主文字12/18、次文字11/16、数值右侧等宽10.5/16；路径摘要用井底9px圆角与11px文字，步骤当前项用约7%强调底，其余行并入面板。连接路径图标11px、步骤状态图标14px、标题身份图标18px，不能混成一组相同大小的大图标。

信息从左到右共用固定内容起点；标题与Tag同一行，状态只显示一次。避免“标题＋大号状态卡＋指标卡组＋重复摘要＋操作卡”逐层堆砌。先合并表达同一对象的身份、路径、状态，再把认证、故障恢复等必须操作放到相应当前行；日志、高级字段、逐跳详情按需展开。设置、多列文件列表和KVM工作区按自身内容宽度组织，540px仅是连接弹窗宽度。

组件源按语义命名，使用主题/状态变体与实例文本属性；同一语义只因示例宽度不同不新建组件家族。拆分只为不同任务或独立交互；同一任务的阶段、主题、颜色、数据及开合优先归入变体/状态。合并前保留状态映射与交互目的地，不能把“减少占位”当成删功能。

## 6. 浮层、焦点与可访问性

主窗口的同级临时气泡共用一个互斥组，包括工具栏状态与转发详情、历史、通知、快速连接、会话入口、侧栏和会话操作菜单。打开下一项时立即收起当前项，悬停预览等待指针离开并重新进入。传输面板、AI 助手和笔记浮窗可与其他面板共存，打开或点击后按窗口浮层栈顺序置顶。子菜单和确认操作保持所属面板的关系，模态和非交互提示保留各自的层级与输入规则。

层级依次为常驻工作区、所属pane浮层、锚定菜单/tooltip、需明确决策的模态。OverlayRecord保存owner、trigger、anchor rect、focus return、dismiss policy；同一次动作绘制与命中使用同一几何来源。Modal及自定义模态遮罩统一使用`app_theme.modal_barrier`，保持全透明并保留原有交互拦截；弹窗面板材质独立维护。普通popover不加整窗scrim；局部删除确认、单字段编辑、列表选择及滑块使用锚定Popover，复杂表单、批量不可恢复操作、运行资源关闭与安全核对保留Modal。Esc先处理IME，再最上层可关闭浮层，不能穿透触发终端行为；焦点回到原触发项，触发项已不存在时回所属内容区。

表单、菜单、选择器、chip、图标和开关使用当前设计及对应原生组件参数；静态标识无点击/hover，动作有独立命中/名称/禁用原因。焦点、hover、selected、pressed不是互斥一枚enum；disabled与业务门控优先，focus独立，操作中的停止除外。主工作区的 Tab 关闭按钮常显；隐藏的行内按钮不命中不入Tab，显示不挤动文字。

默认图标优先，危险影响与歧义操作保留短文；完整身份、路径、错误、审批目标不能仅藏tooltip。长内容用内容视口滚动/省略+详情，不缩字。进度未知不画假百分比；错误持续至原因解除/主动关闭，成功提示所属pane3s且hover暂停，不抢焦点。

动效使用对应组件的 recipe，位移仅绘制、不移动命中区；循环随可见/运行生命周期取消。减少动态效果保状态静态呈现。VoiceOver提供控件名称、状态、列表选中/排序和操作结果；真实IME、右中键、拖动捕获、Esc取消、系统文件选择与读屏必须在Zenit运行验收，静态图不证明已接通。

**状态入口、折叠侧栏与终端反馈**：本机及SSH/SFTP底栏状态入口固定112×26，独立于侧栏224/48宽度；点、文字、箭头左坐标为18.5/29.5/79.5，不随折叠漂移。折叠主机详情使用公共Popover，触发图标、连接间隙与portal面板共同保持悬停，允许移入面板操作；移出整体、外部点击或Esc关闭，键盘焦点打开仍可用。当前三行文字加按钮的主机详情为320×135、padding14；外框、背景和阴影随实际内容同步，不能保留旧154高度。终端输入高亮仅保整行底色，隐藏左侧竖条；彩色/加粗SGR文本仍按VT固定列宽advance定位，不能因指定字体走比例定位。本机身份浮层360×152是另一角色，不能混用主机详情尺寸。

### 6.2 连接流程与底栏链路详情



日志默认折叠，展开区域124px，顺序为“时间戳｜耗时｜日志”，只有正文换行；开始事件耗时为“—”，耗时为事件/步骤耗时，非累计会话时间。新增日志不改变展开高度；仅位于末尾时跟随新日志，上翻阅读保持位置。用户展开/收起允许改变弹窗高度。取消、清理与失败显示真实结果；SSH shell、SFTP初始目录或KVM首帧实际就绪后自动关闭，仅140ms退场，不再要求点击“完成”，不因单跳认证成功提前关闭。此关闭行为不套用§6普通成功提示3s驻留规则。

底栏连接详情采用同一链路模块的**运行态视图**：

- 点击已有连接入口打开锚定Popover，标题为目标身份＋协议Tag＋当前连接状态，下方按“本机 → 跳板 → 目标”真实顺序展示路径与逐跳行。直连保留本机与目标，不虚构跳板；本机只显示发起端信息，不附虚构认证或网络延迟。
- 每跳行默认展示名称/角色、地址与端口、连接/认证状态以及可用的延迟；账号、协议、上游和阶段耗时在同一详情内按需展开。失败行明确哪一跳、哪个阶段及简短原因；等待认证、重连、断开和未知各有可读文字，不能只画红绿点。长链路滚动，头部身份与必要操作保持可达。
- **RTT延迟、建立连接耗时、认证耗时、会话存续时长分别标注**。RTT仅展示真实探测结果并说明测量范围和更新时间，未测量用“未测量”，过期用“已过期”，不填0ms、不将多跳RTT直接相加。端到端指标与逐跳指标分开，无法获取逐跳数据时明确不可用。
- 底栏入口保留简短摘要，Popover承担具体链路信息与按当前状态可用的操作，复制/刷新用图标提示；重连或断开复用已有命令和确认规则。端口转发复用此信息层级：名称＋类型Tag，源端点→目标端点，绑定会话/链路、运行状态与必要故障原因；详细配置按需展示，不把“监听中”写成远端目标已连通。

### 7.2 主题、动效、渲染与平台差距

- **全局主题需补旧式控件rebind**：当前`Cx.setTheme`会遍历主树、portal与overlay，view式Button/Switch/Card/Steps/Badge/MenuEntry能够响应主题；Input/Textarea/Slider/Select/ComboBox/Tabs/Chip及部分Popover/Tooltip仍保存mount-time tokens，`useFocusRing`也捕获旧色。优先统一theme signal/rebind，不能笼统宣称“所有widget快照”或“setTheme已覆盖一切”。确须remount时，draft/selection/scroll/owner在外部，禁止销毁正在组字的编辑器。依据`vendor/zenit/src/ui/core.zig:1974`、`ui/view.zig:3522`、`ui/hooks.zig:775`。

### 7.4 原生资源与性能设计基线（2026-11-03）

性能属于组件设计和完成条件，覆盖原生 App 的主线程、后台任务、CPU、内存及 GPU。原生仍由 Zenit/Metal 实现。不得以减少功能、丢弃终端输出/录制、停止隐藏会话的真实工作、取消既定模糊或降低前景可读性来换取指标。材质层级与最终合成规则遵守§3.3，具体映射见 `src/ui/app_theme.zig`。

- **更新必须幂等**：相同文本、颜色、图标、透明度、几何和设置值不得再次标脏或请求重绘。按实际变更选择绘制、合成、布局或尺寸失效；单个属性优先使用对应 setter，不以重复写整组样式更新颜色、位移或进度。当前帧已能绘制的更新，不额外形成下一帧的自激刷新循环。
- **计算随事实变化，而非随帧变化**：状态投影、AI 历史估算、文本度量和列表派生结果按原始事实的 revision/generation、实际模型配置、主题及必要几何缓存。等长内容替换也须失效；不能只用条目数、字符串长度或悬空节点地址作版本。缓存更新保留原 owner、焦点、选择、滚动位置和业务状态。
- **轮询只取所需字段**：连接重试等高频生命周期检查使用轻量状态投影，不为读取完成、失败和清理事实而复制完整 Journal、历史日志或端点配置；完整进度界面仍按原语义读取全部数据。交互脏版本仅在标志实际翻转时更新，重复标记/清理已稳定的隐藏分支不得反复使同窗或其他窗口的索引观察失效；真实几何、事件语义、显示和节点增删仍更新索引。
- **材质以真实表面为单位**：结构、材质声明、portal 锚点和绘制排序变化时更新表面索引；普通滚动不重扫完整视图树。计算采用真实祖先裁剪后的可见范围，包含滚动与圆角承载关系；已被父卡片裁剪的内部卡片不生成越界补偿。只为实际越界或交叠区域补偿，按相对几何复用分区与保留绘制节点，不复制壁纸、重复模糊或反复写入未变样式。
- **可见性控制展示成本**：隐藏、离屏和关闭的内容停止纯视觉动画、耗时文字、装饰状态及不必要的布局。实际连接、后台执行、文件传输、录制、生命周期回执和必要通知继续推进；切回时显示最新真实状态。暂停展示不能让有界生产者阻塞，也不能丢结果。
- **唤醒必须有原因**：后台优先由 readiness、队列通知或版本变化合并唤醒对应窗口；光标、动画、超时按下一真实 deadline 调度。接收/轮询回执与整窗重绘应分开，无变化的周期性检查不得持续驱动整窗绘制。多窗口、后台页签及隐藏浮层不能因一个局部更新全部高频刷新；显示时钟按窗口复用、按实际动画需求启停，避免随输出分片反复启动线程。共享状态竞争不得无限自旋；按所属线程和延迟要求采用有界尝试、阻塞等待或已发布快照。安全超时、取消、重连和关闭兜底保留其必要时序，不靠一味加长轮询掩盖忙循环。
- **长内容的成本必须有界**：可能超过约 200 行的列表采用可见行复用/虚拟化，或给出经实测成立的等价有界方案。配套 Tooltip、菜单、订阅、Scope 与绘制节点也应按需创建或复用；不能只虚拟文字，却按全部数据条目预占浮层槽位。终端输入、光标和局部状态更新不得无条件复制、重排、整形或重建全部历史正文。
- **固定网格只失效必要内容**：终端绝对定位、固定像素宽高、单行叶文字可通过 `Node.setTextFixedBounds` 更新字形与绘制；宽高、位置、换行及普通内容自适应文字仍走正常布局失效。不得为省布局而清除已有 dirty，或以该接口掩盖尺寸变化。隐藏且已稳定的分支可短路重复布局/绘制检查，子树结构或布局状态变化后必须重新处理。
- **关闭的大面板离开活动树**：设置、AI 等可复用面板关闭后保留所属窗口 Scope 与草稿状态，并在安全帧边界脱树；重开按原顺序附着。脱树仍撤销旧输入句柄、焦点和 pointer capture，待新索引发布后恢复必要焦点，不能覆盖更新的用户焦点请求。业务资源在原生命周期继续推进，不能把保留节点当成仍可交互的隐藏控件。
- **选择器不使用固定条目位图上限**：选择状态按实际数据量分配，以业务值跨重排保留；超过 200 项复用可见行，搜索索引只随查询/选项更新。键盘首尾定位、过滤、禁用项、可访问选中与多选标签必须覆盖虚拟化路径；样式通过公开 `option_style` 输入，不遍历全部内部行打补丁。
- **缓存与生命周期共同设计**：位图/纹理、字形、正文、补偿分区和会话快照均说明所有者、失效条件、容量及回收时机。对象销毁释放其记录和资源；保留关闭内容的复用缓存须有边界。主线程避免逐帧分配大块临时内存、解码图片、解析全量历史或执行同步磁盘/网络等待；重任务在后台基于数据快照执行，按 generation 回到原 owner。

### 7.5 多线程与多核心的性能边界

先减少重复计算、无效唤醒及锁竞争，再依据原生调用栈拆分可独立的工作。CPU 总占用仍按所有线程累计；把单核工作搬到其他核心不能单独视为节能或吞吐改善。验收同时检查主线程尾延迟、全进程 CPU、吞吐和内存峰值。

- **保持单一所有者**：UI 的 Node/Cx/Signal 和当前渲染树在主线程更新。同一 SSH Session 的 libssh2 调用由其 IO owner 串行执行；同一终端的字节流解析与状态变迁保持输入顺序，不把连续字节块分给多个线程同时修改 VT。
- **在独立任务之间并行**：不同会话可由各自 IO owner 推进；录制持久化、导出、历史搜索、图片解码等耗时工作可基于自有数据或不可变快照在后台执行。已经后台化的工作优先复用现有执行路径，不为每一帧、每次输入或每个列表项创建线程。
- **并发有预算**：CPU 密集任务限制同时运行数和排队容量；取消、背压与关闭可推进，不能让线程池任务等待同一池中尚未运行的任务而死锁。没有独立任务或数据仍被同一把锁串行保护时，不以增加线程数作为优化方案。
- **结果回到原对象**：任务携带 owner、generation/revision 和参数快照，通过有界队列或最新值邮箱合并发布；原始输出、录制及生命周期回执可靠保留。主线程只应用仍有效的结果，关闭或切换后不误写新对象；展示消费不得迫使 UI 等待后台 join 或长时间持锁。

当前 SSH 全历史搜索使用共享的 **2 条 CPU 工作线程、16 个排队槽、每个 Provider 至多 1 个任务**，首次使用按需启动，后续复用。使用 Ghostty 公共 RenderState 两阶段快照：短持 VT 锁复制独立数据，解锁后在后台完成 `end_update`、UTF-8 与样式展开；不得将仍借用 VT 内存的行交给 worker。UI 只做有界尾部预览、结果绑定与导航，持续输出时允许展示一致的较早快照，导航仍核对行身份和版本。取消先撤销发布资格，后台释放路径等待任务退出后才能销毁 Provider 的同步对象；重连保留任务所有者地址，旧代结果不能落到新连接。

终端展示通知绑定窗口的数字 generation token，与 pending 位原子更新；worker 不持有 Cx/Node。旧窗口 token 不得唤醒复用槽位的新窗口；未知来源或注册容量耗尽保留全局安全回退。此合并只针对可重复的展示提示，认证、退出、录制及资源释放回执仍可靠投递。

## 8. 数据、线程和安全要求

UI/Cx/Node/Signal只在主线程访问，worker处理IO与计算，以不可变或自有payload发布结果；跨线程借用切片必须拷贝或明确转移所有权。单libssh2 Session由一个IO执行者串行访问；SPSC只能一个生产者一个消费者，多worker不能直接共写同一SPSC。输出/输入原始字节不能静默丢弃；进度/dirty可合并，认证、退出、失败和清理回执可靠投递。

所有异步动作捕获实体ID、generation/revision、operation/attempt及参数快照；结果只更新原owner，晚回调不查active tab替代。accepted不等于completed，cancel函数返回不等于资源已释放，exit0不等于远端业务收敛；失败域、可能副作用与cleanup分开。不可用能力、生命周期、用户权限都要验证，不能只禁按钮却让命令/快捷键绕过。

凭据、OTP、私钥口令、API key不进入manifest、普通日志、tooltip、AI上下文或错误正文。V0.2持久秘密使用macOS Keychain单scope vault，TOML只保存不透明引用；0600是私有文件权限，不能代替凭据存储。旧明文迁移遵循[V0.2§4.2.1–4.2.2](V0.2_PLUGIN_HOST.md#421-macos-数据目录与兼容迁移2026-10-24-补充)的原子移动、失败保留和秘密事务，不额外生成明文备份。主机信任与替换落盘在V0.1.3，AI工具参数/范围/审批在V0.1.7；文件内容和工具输出都是不可信数据，不执行其中的宿主指令。

每个字段同时区分raw输入域、typed持久化域与引擎可应用域；范围由对应版本唯一字段表规定。有限浮点拒NaN/Infinity；整数检查符号、尾随垃圾和乘法溢出；单位不混bit/byte、MB/MiB。输入错误保raw并定位字段，禁止静默clamp再保存。

### 9.1 资源与性能验收口径

- 资源结论以原生优化构建和实际工作负载为准，注明二进制、构建模式、窗口/像素比例、主题/模糊、数据量与会话数。Debug 用于正确性和泄漏排查，不能与优化构建混作前后对照；编译器、App、shell/子进程和 GPU 分开归因。
- CPU 采用进程 CPU time 增量除以真实墙钟时间，统一以单核满载为 100%；同时说明平均值、峰值和持续时间。空闲测试预热后不发 Harness RPC，正式采样至少 30 秒，8 秒用作快速回归。持续 100%+ 必须定位到具体线程/调用栈，不能仅以帧数下降、编译成功或 GPU 较空闲宣称解决。
- 分别测空工作区、单会话静置、失焦/隐藏、多会话、设置滚动、逐字符输入、突发/持续输出、AI 展开/后台执行和反复打开关闭浮层；没有真实协议负载的测试不得宣称覆盖 SSH/KVM 传输性能。保留常规刷新≤4ms的目标，60Hz 交互的 CPU 与 GPU P95 分别核对 16.7ms 帧预算；120Hz 对照 8.3ms。平均值不替代尾延迟，RPC 往返不冒充物理按键到屏幕延迟。
- 单会话无任务、无交互时，以优化构建接近零负载、稳定低于单核 1% 为持续优化目标；必要光标/回执检查说明其增量成本。持续输出按实际字节率报告 CPU/内存与结束后的恢复情况。上述目标不是当前已达标声明，允许的短暂工作峰值不能成为长期满核的理由。
- 内存同时观察空闲基线、峰值、关闭后的稳定值、重复开关后的增长趋势，以及 CPU/RSS 与 GPU/纹理资源的区别。不能将逻辑释放量直接当成 RSS 降幅，也不能通过缩短用户历史、取消录制或无限增长缓存来换取局部速度。
- 以有针对性的状态、生命周期与结构性回归约束“未变化不标脏”“可见节点数有界”“稳定几何不重建”“销毁后记录释放”；时间数据用于同机同负载对照。中间配置、采样、日志、视频和截图放隔离临时目录，核对后清理，设计基准只保留规则与可复现入口，不堆积运行流水账。

原生 SSH 资源回归入口为 [ssh_output_performance_native.ts](../../e2e/ssh_output_performance_native.ts)：从仓库根目录运行，使用 `fast`、`test-mode=true` 的隔离构建，`ZW_TEST_PYTHON` 指向提供 Paramiko 的测试 Python，参数为二进制和隔离输出目录。覆盖静置、连续行输出、ANSI 原位刷新、输出后恢复、设置浮层和正常退出；可用 `ZEROWORK_PERF_SAMPLE=1` 在 CPU 测量结束后另行采样。测试保留 Harness，其结果须注明该开销；正式构建关闭 `test-mode`，不得放宽发布环境隔离。原生列表滚动入口 [ui_scroll_performance_native.ts](../../e2e/ui_scroll_performance_native.ts) 通过 `ZEROWORK_SCROLL_HOSTS` 指定数据量，几何观察使用有界节点查询，不能为测量滚动而把观察目标自动滚回视口。

高频刷屏对比可设 `ZEROWORK_PERF_FOCUS=screen`、`ZEROWORK_PERF_SCREEN_REPEATS=3`，使用同几何、字体、真实 SSH 输出和无 Harness 请求的测量窗口，检查 CPU、实际帧数与输出完成标记；编译和采样不得混入 CPU 区间。可将 [native_thread_cpu.c](../../e2e/native_thread_cpu.c) 编译到临时目录，通过 `ZEROWORK_PERF_THREAD_PROBE` 读取线程累计 CPU，同时报告全进程和最忙存续线程，不能仅凭线程编号推断主线程。`ZEROWORK_PERF_INTEGRATION=1` 另验设置脱树、AI 草稿恢复、真实搜索后台路径及跨窗口刷新隔离；列表使用超过 200 个主机的数据验收新建连接的复制来源选择器，传输范围只包含已有任务的会话，不能以保存主机数冒充该选项数。测试凭据、截图、日志、基线副本和隔离构建只放任务临时目录，完成后清理；保留可复用的回归源码与正式构建。

### 10.1 交互状态验收

### 2026-10-26 补充：反馈、浮层与内容密度

- 提示按语义选组件：字段校验放字段下；任务进度、失败与重试放任务行；AI 压缩状态放上下文用量浮层；复制、刷新、选择完成等短确认放触发控件附近；跨会话不自动构成全局提醒的理由；只有用户未在关注且值得及时介入的事件，或用户显式开启的后台完成提醒进入全局消息。原位置保留业务事实，全局渠道只做必要定位，不重复弹局部反馈。
- 说明性内容优先使用 tooltip（悬停及键盘聚焦可达），默认只保留名称、当前值和必要动作。tooltip 不承载确认、重试等交互，不将关键错误原因仅放入 hover。
- 消息级别由事件语义传递，不能仅根据中文文案判断错误。消息格式为“结果/问题”短标题，可附一行必要原因和一个明确动作。无需重复显示当前页名称。输入错误需要关联字段，任务错误需要关联任务；确认对话框仅用于不可逆或重要决策。
- 所有浮层必须保存触发控件与所属窗口。打开二级菜单前先保存触发矩形，不能在原菜单隐藏或销毁后读取。顶部工具向下、底部状态栏与 AI 输入工具向上；空间不足时翻转并限制滚动，窗口边距以对应原生组件为准。不使用页面全局坐标直接冒充局部坐标。
- 浮层打开、子菜单替换、滚动、窗口缩放、侧栏显隐、会话切换及 AI 拖动后都需检查。触发器消失时关闭，禁止回退到左上角或沿用旧会话坐标。菜单随几何变化关闭，详情浮层重新计算锚点。
- 卡片不画整圈描边或描边式阴影，配合已有层级底色、留白和对齐表达边界；仅浮层保留必要的柔和投影。浅色设置导航继承设置根材质，选中行仅使用 10% 强调色。
- 传输入口复用原生传输条目及直接操作、悬停详情，详见 §4.2.1 和 `src/ui/transfer_styles.zig`。暂停、继续/重试、查看、取消按真实状态及能力显示；完整路径可在提示/详情查看。
- 按连接能力显示功能：本地 Shell 不展示 SSH 端口转发与跳板链路；SFTP 不展示终端广播；尚未就绪而可恢复的功能保留禁用态及原因，永久不适用能力直接移除。主机配置不等于会话。
- 内置主题明确标注“不可删除”；自定义主题才提供删除。侧栏使用“显示/隐藏”，不再使用“折叠”。数据设置可展示配置路径，不提供“打开配置目录”。SSH 使用一个终端窗口图标，不附加 SSH 文字小标。

传输列表使用卡片背景和间距区分条目，不使用细线分割。SFTP每列仅在存在该会话、该方向任务时显示列表；空列表不保留标题、占位内容或高度。

SFTP内容区顶部与侧栏同一基线，不为三点AI浮条预留独立高度；此页不显示重复浮条，AI从全局工具栏进入。传输入口需在实际整页验证可见反馈、关闭和重新打开，不能仅验证独立组件。

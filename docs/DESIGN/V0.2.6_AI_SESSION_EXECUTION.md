# V0.2.6 PATCH：AI 会话执行、统一记录与全局历史回看

> 本文定义 V0.2 的会话执行与记录契约，不提前引入 V0.4 的独立 Agent、集群、子智能体或插件 API 3。

本文是 AI 会话执行与全局历史会话的统一设计方案。默认 shell 集成见 §9.4 和 §10.3；§1–15 定义 AI、会话与执行，§10 定义统一记录格式，§16 定义历史交互与持久化，§17 定义当前审批、顺序与输入控制契约。

## 1. 目标、约束与旧契约覆盖

单会话与真正的终端组都保留 AI 入口。打开 AI 时绑定用户实际打开的对象，不按后来激活的 Tab 重新选目标。AI 可以继续通过既有独立 exec 服务批量执行，也可以按策略控制当前交互终端，或在当前组内新建一个工作终端，持续完成同一任务。每个有副作用的步骤具有实际工具调用、独立权限检查、状态和可追溯结果。

本 PATCH 保留 `run_command` 的机制、参数、权限、连接、输出捕获、停止和清理行为；界面只增加“批处理”标记。PTY 路径新增 `run_in_terminal`，标记“交互式”，同样展示命令、目标、状态、耗时及结果。PTY 的完整交互留在终端记录中，卡片只是有界结果与稳定跳转入口。

**当前范围修订：助手只可访问其绑定 Tab 的会话／会话组及该绑定合法保存的记录，不允许发现或接入绑定外已有会话／组。** 保存的主机配置目录是独立能力：允许只读查询非秘密静态配置，确认后新增主机并在当前组创建新会话；不提供修改或删除已有主机的工具。此约束覆盖下文日期化记录中的旧 workspace inventory 授权方案，当前规范以 §4.3 和 §17 为准。

另增加一个本机网络读取工具 `fetch_url`，用于按 URL 获取文档、发布说明及文本接口内容。请求由运行 ZeroWork 的客户端发起，不依赖远程服务器或跳板机联网；远端连通性诊断仍通过原命令工具在明确的目标服务器执行。工具保持单一用途，不扩展成搜索、浏览器或文件传输工具，具体契约见 §6.7。

单会话显式创建组，或选择需要新工作终端的流程时，先正式创建组并把原会话作为初始成员。**当前 AI 对话的绑定随之从单会话迁到组**，保留同一 ConversationId、历史、草稿、附件、Controls、阅读位置和有效窗口状态。此后成员减少、只剩一个成员、任务完成或工作终端关闭，都不退回单会话。组关闭仍是关闭全部成员的现有业务，不增加“只关闭组视图”“自动解散”或“解散后恢复单会话”。

## 3. 身份、状态和资源归属

### 3.1 数据模型

```text
Conversation {
  id: ConversationId, schema_version,
  initial_kind: session | group, origin_ref,
  current_binding: session(SessionId) | group(GroupId), binding_revision,
  history, wire_history, draft_revision, text, attachment_refs,
  controls { model, effort, thinking, permission,
             execution_mode_override?, session_retention_override? },
  presentation { rect, reading_anchor }, last_context_notice_revision
}
Task {
  id: TaskId, conversation_id, initiating_turn_id, authority_grant,
  state: active | stopping | completed | failed | handed_off,
  work_session_ref?, frozen_retention_policy, resources[]
}
SessionRef = opaque reference bound by host to SessionId + generation
GroupRef   = opaque reference bound by host to GroupId + identity_revision
Execution {
  id: ExecutionId, conversation_id, task_id, immutable_call_key,
  authority_revision, mode_snapshot, target_snapshot,
  state, started_at, elapsed_ms, input_fence?, completion_evidence?,
  recording_ref { RecordingId, generation, start_offset, end_offset? },
  local_release, process_exit?, business_effect: known | unknown
}
Resource {
  SessionHandle, task_id?, ownership: borrowed_user | created_task | handed_to_user,
  retention_snapshot, references, terminal_visibility, close_receipt?
}
```

ConversationId、TaskId、ExecutionId、RecordingId 使用宿主生成的不复用稳定 ID。本文把 SessionRef/GroupRef 显示成 `s_101_g3`/`g_7_r1` 仅作示例；模型不得自行拼装引用。SessionRef 已包含宿主可检验的代次，模型不传裸 generation、插件指针或 transport handle。查询结果另外返回旧 run_command 可直接使用的整数 `session_id`；宿主仍在旧调用派发前捕获并复验 live generation，不要求模型拆解 opaque ref。组改名不更换 GroupRef；成员变化增加 membership_revision；组对象销毁/替换才使 GroupRef 失效。

每次用户发送形成一个默认 Task，任务内的 provider 多轮及顺序命令复用同一个工作会话。任务停止、失败、完成后进入收尾；不自动把下一次新提问认定为同一任务。用户明确“继续刚才任务”时，可在会话仍存在、授权和代次复验后创建续接 Task 并引用该工作终端，旧调用不复活。`keep` 保留的终端成为可选择资源，不能因为保留就获得永久执行授权。

### 3.2 绑定迁移规则

1. 单会话当前对话发起 create_group 时冻结原 SessionHandle、ConversationId、binding_revision 和 TaskId；原会话成为新组初始成员。不是把旧对象的 `type` 标志改成组，也不是新开一个空组助手。
2. 创建组、加入原成员、建立对话绑定索引、迁移当前呈现入口与写入 handoff journal 为一项宿主事务。成功后同一对话 current_binding 指向组。原历史调用保留原 owner；历史附件继续引用原内容。
3. 本对话的文字/附件草稿、模型、推理、权限、运行/保留 override、阅读锚与窗口期望矩形逐项保留。迁移不清草稿、不重新解释附件来源、不克隆对话。
4. 原会话的其他历史对话不批量迁移。之后从原独立成员 Tab 打开 AI，可创建/恢复仍属于该单会话的另一对话；已迁移对话只在组入口续接，不再作为该单会话当前对话返回。
5. 组当前对话只在当前组内创建工作会话，不再次 create_group。组成员变为 1 或 0 时仍为组；零成员显示“尚无可用成员”，只读历史可看，执行需有明确新来源。
6. 成员在其他组的既有关系不由本 PATCH 自动移除或设置 V0.4 的独占父级；成员变化按现有 roster 语义办理。生命周期和执行权限仍以本对话当前组及本次授权快照为准。

### 3.3 三类所有权不能互换

| 类别 | 获得方式 | 自动清理权 |
| --- | --- | --- |
| borrowed_user | 打开 AI 前已存在，或用户明确选择已有终端 | 只释放本任务的控制/引用；不能因任务结束关闭。 |
| created_task | open_session 为本 Task 创建且提交成功 | 满足保留策略、无活动引用、无接管时可逐个关闭。 |
| handed_to_user | 用户点击接管/保留为我的终端；created_task 身份单向让渡 | 自动关闭权立即撤销。旧清理计划必须因 ownership_revision 失效。 |

引用分三层：Task/foreground/transfer/forward 等活动引用决定 owned shell 是否可关闭；SharedLease 计数决定 transport 的最终释放；RecordLease/ExportLease 只保护记录文件和只读读取。历史记录视图持有 RecordLease 不阻止空闲 owned shell 关闭，不获得输入权，也不创建执行引用。正常关闭 owned shell 只释放其 channel 与 retained lease；仍有其他 SharedLease 引用时共享 transport 继续存活。任务拿到最后一个引用也不意味着可以关闭 borrowed_user 源会话；共享 native 故障的影响见 §11。

## 4. 配置、五种模式与授权

### 4.1 配置字段与生效点

```toml
[ai]
execution_mode = "auto"          # auto | ask | isolated_exec | attached_pty | new_pty
session_retention = "auto_idle"  # auto_idle | ask | keep
```

上述为新增持久字段提案。旧配置缺字段时分别补 `auto`、`auto_idle`，读取不改写未知字段；只有用户保存设置时按现有事务落盘。非法值报告明确配置错误，不静默改用高权限模式。对话持久状态新增 `execution_mode_override: ?Mode` 和 `session_retention_override: ?Retention`；null 表示跟随全局，不序列化为字符串 `"null"`。迁移旧对话时两者设 null，已有权限选项不变。

设置页保存全局默认；composer 运行方式菜单选择“跟随全局（自动）”或五种显式 override，保留方式在同一相关设置区选择“跟随全局/空闲后关闭/每次询问/保留”。权限继续是独立控件，不把“交互式”显示为“完全控制”。全局默认变化只影响下一个尚未开始的执行/新建资源；对话显式 override 保留。已创建执行对象冻结本次有效运行策略、权限 revision、目标和能力；已创建资源冻结保留策略，设置变化不追溯关闭现有终端。用户显式修改现有资源保留方式须走 set_session_retention 并增加 revision。

### 4.2 模式决策表

| 有效运行模式 | 宿主允许的执行路径 | 无法满足时 |
| --- | --- | --- |
| auto（默认） | 模型按任务建议：不依赖交互 shell 状态、有限输出的命令用既有 run_command；需要持续 shell 状态、readline、可视交互或用户明确新终端时建议 PTY。宿主复验目标、能力和授权。 | 能力不支持时明确说明可选路径；不能未经授权静默换目标或新建连接。 |
| ask | 每次将要执行命令时选择“批处理/当前终端/新工作终端”；与本次必要的权限审批合并为一张卡。 | 用户取消形成 cancelled_unsent，零派发；不保留成下一条永久选择。 |
| isolated_exec | 固定 run_command。 | 请求交互执行或依赖 shell 当前状态时返回 ExecutionModeConflict，等待用户明确一次性例外或修改配置。 |
| attached_pty | 固定当前绑定范围内、明确选中的已有终端。单会话可直接用自身；组不能默认取 pin/activeTab，须有确切目标。 | 目标忙、未集成或用户已有未提交输入时不给另一个终端代办，返回具体冲突。 |
| new_pty | 当前 Task 首次创建工作终端，同 Task 后续命令复用它。单会话先正式转组，组跳过 create_group。 | 创建失败、能力缺失或代次变化时停止并保状态；不能每条命令开新终端、不能自动回到原终端。 |

运行模式限制的是命令执行路径，不把 open_session 与 PTY 执行绑成不可拆整体。用户要求“新开一个会话再批量跑”时，可按权限组合 create_group → open_session → run_command；open_session 本身不执行命令，new_pty 作为固定运行策略时仍选择 run_in_terminal。

自然语言明确“这次在当前终端执行”“新开终端运行后保留”等目标/保留指令，由宿主在用户本次请求中形成一次性 intent grant；不再只为问相同选择弹第二张卡。它不修改全局/对话 override，不能由模型工具参数自称用户已授权。固定模式遇到相反请求时，只有宿主确认来自当前用户的明确一次性例外才能放行；模型在工具参数写 `mode_override` 无效，schema 也不提供此字段。需要权限审批时，明确自然语言选路不会代替该审批。

审批卡记录“为什么使用此方式”、完整命令、实际目标/身份、本次创建与保留影响。ask 的选路与权限确认共用一个批准动作；new_pty 跨多个真实工具的计划可提前展示，但授权必须分别绑定每个步骤及具体依赖，不能用一次总批准覆盖未知的后续命令。对于同一张卡已完整展示的 source identity、创建 operation、后继工作会话约束、精确 command/hash 和保留方式，批准可生成有依赖关系的有限 grants：新 session 只有确证由该 operation 创建、实际身份和能力符合快照时才能承接对应 command grant；任何命令/来源/路由变化都重新审批。用户已经明确的新建/转组请求可直接执行相应管理步骤，命令仍按既有规则判断。

若用户在 run_command 待批卡改选当前/新工作终端，当前 run_command 返回 `requires_plan_change/cancelled_unsent`，零派发；宿主保存一次性 selection grant，下一 round 由模型产生真实 create_group/open_session/run_in_terminal 调用。反向选批处理同理。不能让一种工具的 handler 隐式执行另一条路径。后续调用消耗已批准的精确 grants，不再重复问相同选路；超出原批准快照时仍需必要审批。

### 4.3 授权域

权限判断顺序为：工具注册及版本 → conversation/task 授权 → 当前绑定或静态主机目录权限 → 对象身份/代次/有效成员 → 运行模式 → 能力 → 禁止规则 → 必要审批 → 派发前再验。运行模式不会提升权限；完全控制不会取消组写确认或禁止规则。

`list_sessions/list_groups` 只返回当前绑定。`scope=workspace`、绑定外对象的存在性／名称／状态／数量查询、终端读取、执行、生命周期动作及加入组请求直接拒绝；不提供“仅此一次／持续允许”扩权入口，旧 inventory grant 或 selected/owned 标记不能绕过。先验范围再查对象，未知外部引用与真实外部引用使用同一拒绝，不泄露其是否存在。执行卡按钮、附件、任务收尾和晚到回调也复验此范围。组内创建会话使用正常内部成员提交；`add_group_member` 仅能幂等确认现有有效成员，不能用于接入组外已有终端。

`list_hosts/get_host` 只投影保存配置的 `source_ref/name/protocol/host/port/user`，不返回密码、私钥、凭据引用或任何已有活会话信息。`create_host` 无论权限模式均需精确确认，保存成功后再以真实 `open_session(new_only)` 在当前组连接；单会话先转组。主机修改／删除不在能力目录。有效静态 SourceRef 不能取得该主机上其他已打开会话的正文或连接租约；只有当前绑定中的实时来源可按既有规则复用连接。

成员移出后保留此前合法取得的聊天／模型历史，禁止新的越界读取和控制。当前 Tab／组关闭工作终端后，可继续只读查询自己合法归档的终端／执行记录，包括同绑定后续 Task；宿主以真实绑定、SessionHandle、RecordingId/generation 和关闭回执证明归属。不得扫描全局归档猜测归属；缺少稳定证据则明确拒绝，不把用户全局回看 UI 的权限授予模型。

`fetch_url` 使用独立的 `local_network_read` 授权域，由现有权限模式及宿主网络访问规则决定放行或必要审批；终端读取权、SSH 连接权不自动授予该能力。它不受五种命令运行模式限制，不为获取网页创建会话、占用 PTY 输入租约或申请组写权限。请求前复验实际 URL、网络策略与本对话授权；用户只授权读取终端时，不能将其中的日志、配置或秘密拼入外部 URL 发出。精确网络边界见 §6.7。

## 5. 端到端流程

### 5.1 已有单会话或组中执行

1. 打开 AI 捕获对象与 ConversationId；发送时冻结用户 intent、Controls 和初始 authority。get_current_context 返回本对话的实际 current_binding，不读 activeTab。
2. 需要事实时调用 get_session/list_group_members/read_terminal 等查询，输出进入真实工具卡和 tool result。用户未附加的完整终端不会自动塞进 system。
3. 模型生成完整命令与精确目标，宿主决策/校验运行模式和权限。run_command 沿原管线；run_in_terminal 先准备记录、检查空闲和输入、取得控制租约，再输入命令。
4. 卡片实时显示路径、实际状态/耗时、有界结果。PTY 的 wait/input/stop 是分别可观察的工具，终端显示全过程。
5. 当前执行完成后释放控制租约；同 Task 可以继续在该终端执行下一命令。最终答复完成后处理 owned 资源保留，borrowed 终端保持用户所有。

### 5.2 单会话新建工作终端

```text
get_current_context
→ create_group(initial_session_ref, name?, request_key)
  [原会话是初始成员；正式迁移同一 AI 对话；安全边界刷新 scope]
→ open_session(group_ref, source_ref, connection_policy, request_key, retention)
  [只创建会话；内部就绪后登记成员并呈现；不执行命令]
→ 必要时 get_session / wait_session_ready
→ run_in_terminal(session_ref, command, request_key)
→ get_execution / wait_execution / send_execution_input / stop_execution（按实际需要）
→ 后续命令复用该工作会话
→ set_session_retention / close_session（仅实际需要的 owned 资源）
```

从组开始时跳过 create_group。**不提供 attach_session 工具，不产生“附加会话”工具卡。** open_session 内部的就绪、成员登记、呈现阶段只是该工具的进度，不伪造成模型调用。RecordingId 与可持久记录能力必须在 run_in_terminal 派发前准备好。

### 5.3 open_session 的内部创建事务

open_session 根据 source_ref 捕获非秘密配置、已授权路由和 connection_policy；先预留 request_key 与 provisional SessionId，再经原 SessionHost/session_factory 创建运行时。结果可以先返回 `opening` 及稳定 operation/session 引用。会话在 transport/shell ready 后内部加入目标组、更新 membership revision 并呈现；此时返回/查询可见 `ready`。模型需要等就绪时调用有界 wait_session_ready，不在工具外追加 attach。

SSH工作会话创建的认证前传输失败复用已有有界退避，总共最多3次（500ms、1000ms）。重试仍属于同一ConnectJob、SessionHandle/generation、operation/request_key，不再调用open_session、不提前提交组成员或发布可执行ready。前worker必须已join且完整资源released，才以已有ResourceLedger重开传输；诊断缺失、任何跳板已进入认证、host-key/认证/凭据拒绝、共享连接、cleanup未知或已有runtime均不重试。取消退避阻止后续连接，耗尽正常失败清理；记录每次真实失败并保持日志序号递增。此策略只覆盖首次建连，不能用于命令重放、恢复已断开的运行会话或替代shell初始化失败的一次专用重连。

若连接 ready 但成员登记失败，不能返回可执行 ready。事务先阻止 AI 输入，再沿原关闭编排清理该 provisional owned 会话；清理未完成返回 `failed_cleanup_pending`、稳定引用和回执，保留记录供核查，不交给任意组代替。若 create_group 已成功而随后 open_session 失败，新组与迁移后的对话保留；不偷偷转回单会话。用户能修复来源后重试 open_session。

新终端是新 shell，不克隆原终端的历史、未导出的变量、shell functions、前台进程或登录会话状态。cwd、环境和尺寸只应用已知且被能力支持的非秘密显式参数；未知值明示，不声称“完全复制”。本 PATCH 的最小 open_session 不提供任意环境变量批量复制工具。

### 5.4 连接策略与既有 SSH 复用

| connection_policy | 实际行为与授权 |
| --- | --- |
| reuse_only | 通过 source Runtime.reuseConnection 取得 SharedLease，再由现有 shared_ssh_connection.openShell 开新 channel。来源不具备健康可复用连接则 ReuseUnavailable；不新拨连接。 |
| new_only | 使用已授权 ConfigSnapshot/credential reference 经原连接创建器建立独立连接。不能从旧活跃 shell 提取认证。 |
| prefer_reuse | 先尝试复用；只有本次 grant 已明确允许失败后新建时才使用原连接器后备。否则返回 FallbackAuthorizationRequired，将具体新增连接影响并入必要审批。 |

当前绑定内的 SSH 实时来源建议 reuse_only；主机目录的静态来源仅允许 new_only，不查找或复用绑定外连接。Local source 用现有本地 session factory 创建独立 PTY，connection_policy 仍必填，只有 new_only 合法，错误值不悄悄解释。默认 UI 按源类型给合法值。复用保留原 source ref 和 route identity，正常关闭只针对新 channel；共享 native 故障或无法安全 rollback 的共因影响按 §11 逐对象报告。认证、host key、OTP 等继续走宿主安全界面，不经模型传递秘密。源码共享连接的等待、取消、引用图和最后引用释放沿现设计，不在本 PATCH 重写底层复用实现。

### 5.5 失败、拒绝、停止与接管

| 发生点 | 必须留下的事实与下一步 |
| --- | --- |
| create_group 前取消/批准失效 | 原 session 绑定和草稿完整；未创建组。 |
| create_group 事务未提交 | 回滚新建索引/组引用；保留原绑定。无法完成补偿时显示恢复错误并禁止新派发，恢复 journal 后再继续。 |
| 组已创建、会话创建失败 | 组绑定保留；卡片标失败、零命令派发；同 request_key 查原结果，新尝试用新 key。 |
| 等待 ready 中停止 | 取消 open operation，清理 provisional owned 资源；已有组不消失，源 borrowed 会话不关闭。 |
| 审批等待时用户继续打字 | 不锁终端；批准后重新检查未提交输入和队列，有冲突返回 InputConflict。 |
| 命令尚未写入前取消 | cancelled_unsent，区间留元数据但无命令注入；释放已取得的租约。 |
| 已部分/全部写入后中断 | 保写 receipt、输入字节/序号、记录区间和 unknown；不重发未确认字节、不自动补 Enter。 |
| 用户接管 | 原子撤销 fence、取消后续 AI input、让渡资源 ownership；用户可输入，旧 execution 标 handed_off/outcome_unknown，不能显示成功。 |
| 停止AI／关AI× | ×先显示确认气泡；取消、外点或Esc零停止／零隐藏；确认后停provider／待批／后续派发，按stop_execution请求中断已知执行并释放或撤销控制权，关闭窗口但保留对话与历史。收起仍只隐藏并继续任务；删除只走会话列表垃圾桶。不得把UI关闭当进程退出。 |
| 网络断线/进程退出未知 | 记录和卡片保留；输入租约 watchdog 释放，禁止自动重连/重放。后续用户显式重连需新 generation 与授权。 |
| 任务清理失败 | 保 cleanup_pending/unknown 与资源列表；允许用户选择保留/接管或明确重试关闭，不无限重试、不锁用户终端。 |

## 6. 工具目录与调用契约

### 6.1 通用规则、引用和限额

下面是逻辑工具名；新增工具按宿主命名空间 `host.<name>` 注册，经现有 encodeName/decodeName 形成 provider wire 名称，例如 `host.get_current_context` 编码为 `host__get_ucurrent_ucontext`。工具卡展示友好标题与具体参数投影，不重复显示机器工具名；结果始终引用真实 provider call ID。`run_command` 的既有注册名、schema 和路径原样保留。旧 `read_terminal(session_ids)` 继续兼容，旧 provider schema 不增加 max_bytes 或范围字段；需要本节范围查询能力时注册 `host.read_terminal`，不能让两个同名不同 schema 的贡献互相覆盖。

新增管理、查询工具由受信宿主贡献提供，只有明确依赖终端/连接服务的部分委托相应 typed service。其 schema 不列举所有可用 SessionRef/GroupRef，不按成员数扩大 enum，也不通过 tools description 偷渡动态名称/列表。引用一律来自用户选择或查询结果，宿主在派发前解析并复验。

| 项目 | 默认与硬上限（新增设计值） |
| --- | --- |
| 分页 | limit 默认 50、最大 200；cursor 不透明、绑定查询过滤/来源代次与授权；过期返回 CursorExpired。 |
| 文本 | 默认 max_bytes=8192，范围 1–65536；最多 max_lines=500（默认 100）；字节与行限制先到为止，不无界抓取再裁。 |
| 搜索 | literal 默认；可显式受限 regex，最长 512 字符、受 host 时间/复杂度预算约束；默认最多 50 匹配、最大 200。 |
| 等待 | wait_ms 默认 1000、范围 0–30000；到时返回现态与 next_cursor/可继续等待，不把 timeout 当失败或完成。 |
| 命令 | PTY command 上限 65534 UTF-8 字节，无 NUL、trim 非空；规范化、控制字符及提交方式以 §9.5 为准；原 run_command 保持现有上限与参数。 |
| 输入 | text 最多 4096 UTF-8 字节/次；按键为受控枚举；secret 只走 host prompt，不在参数中传值。 |
| 本机网络读取 | `fetch_url` 只收 URL；总超时 15 秒、最多 3 次重定向、接收正文最多 2MiB、解压后最多 4MiB、返回正文最多 32KiB；均为宿主固定限额，不增加模型参数。 |
| 结果 | 单调用文本/结构化结果总量不超过现有 64KiB；分页元数据计入限额。card 与 provider 同用已验证不可变结果，不分别偷读更多数据。 |

会话、组、执行和记录查询返回 `observed_at`、`source_revision`、`truncated`、`next_cursor?`；终端还返回 `range_requested/range_returned`、`gap[]`、`timestamp_basis=client_receive`。时间范围按客户端接收事件粗粒度筛选，不宣称远端逐行真实发生时间。缺失/轮转/掉段必须明确，空结果与未知/不可读取分开。`fetch_url` 的网页读取结果按 §6.7 返回，不伪造远站 revision 或可续读 cursor。

除旧工具外，所有副作用工具必传 request_key，宿主绑定 `ConversationId+TaskId+logical_tool+request_key` 与 canonical argument hash。相同键同参数返回同一个 operation/对象/结果；不同参数返回 IdempotencyConflict；工具调用 call ID 变化不能绕过这个去重。只读查询可重试，但结果有新 observed_at，不承诺快照永不变化。不得因回包丢失自动再次提交命令。

通用错误：InvalidArguments、ToolNotAvailable、PermissionDenied、ApprovalRequired/Rejected/Expired、ModeConflict、ScopeChanged、StaleReference、TargetOutsideScope、CapabilityUnavailable、OperationBusy、CancelledBeforeDispatch、OutcomeUnknown、ResultLimit、JournalUnavailable。错误结果包含 `code, stage, retryable, operation_ref?, side_effect_started, local_released, remote_effect_unknown, recovery_hint`；不通过输出字符串猜成功。专有错误见各工具。

### 6.5 命令、输入和停止工具

| 工具 | 依赖与参数 | 结果与权限 | 专有错误与幂等 |
| --- | --- | --- | --- |

| send_execution_input | execution_ref、input_kind=`text\|key\|host_secret_request`、text?、key?、request_key；需 execution 仍持有效 fence，且具有受控等待或显式 `terminal_stream` 输入能力。 | input_sequence、queued/written/consumed receipt、执行新 revision；`written` 仅指 native write 完成，`consumed` 仅由受控消费者确认。text/key 都是副作用，按执行授权与输入影响复验。 | InputNotExpected、UnsupportedInteraction、SecretMustUseHost、FenceRevoked、InputConflict；同 key 返回原 receipt，不补写失败尾部。 |
| stop_execution | execution_ref、request_key；只针对本次 execution，不调用 close_group 或停止整个 shell 作为默认。 | stop_requested → interrupted/exit_confirmed/handed_off/outcome_unknown，实际方式与local release；停止是幂等，不承诺业务回滚。 | UnsupportedInterrupt、TargetChanged、RemoteUnverified；同 key 沿原停止 operation，未知结果允许只读核查，不盲目补杀。 |

PTY 合流只报告 `terminal_output`/screen 与真实观察到的完成事实，绝不伪造 stdout/stderr 或 exit。run_in_terminal 返回 running 是“调用已提交”的工具结果，execution 后续独立存在；工具 callback 的资源已转交 Supervisor，并确定完成本次受理，不能因为远端进程仍在运行就返回 outcome_unknown/!local_released，触发旧 Loop 的 uncertain 门闩而阻断后续 wait/input。真实派发或控制状态不确定时才报告 unknown 并阻止后续影响型输入。wait_execution 返回 waiting 也不等于任务结束。输入工具只支持 §9 的交互矩阵，不提供任意鼠标脚本、任意远端按键原始字节或可读取秘密的通道。

PTY 权限分类不能照搬原 exec 的 `ps/df/cat/ls` 等只读前缀白名单。已有 shell 的 alias、function、PATH、环境、cwd、options 会改变相同文本的实际行为，新建 shell 也可能读取启动配置。新增 PTY classifier 默认对未证实解析结果/运行上下文的命令要求确认；只有受支持受控 shell 能证明解析对象与只读语义时才允许自动执行。审批快照增加 shell/integration/context_revision；批准后上下文变化即失效重新评估。禁止优先和组写确认不变，原 run_command classifier 完全保留。

stop_execution 仅在集成确认该 ExecutionId 对应的 foreground 及终端 signal 模式支持时发送受控 interrupt，记录实际 write/ack；不能假定任何 `\u0003` 都是 SIGINT，不能按未校验 PID/PGID 补杀或默认退出整只用户 shell。中断等待最多 5 秒后无退出证据标 outcome_unknown/交用户，取消控制不推定业务回滚；raw/TUI 不支持中断时明确返回 UnsupportedInterrupt。

> 在当前对话绑定的组内创建一个工作会话，不执行命令。group_ref 必须来自本对话当前组；单会话需先调用 create_group，并在收到成功结果和刷新后的上下文后调用本工具。source_ref 只接受用户授权的既有会话或连接来源。reuse_only 不新建连接；prefer_reuse 仅在宿主已有后备授权时可新建。返回 operation_ref、session_ref 和 opening/ready；opening 时用 wait_session_ready，ready 后才能执行。会话内部就绪后登记为该组成员，不需要也不存在 attach_session。相同 request_key 返回原创建，失败回包不能换 key 盲目重试。

### 6.7 本机网络读取工具 `fetch_url`

仅新增一个逻辑工具，注册名为 `host.fetch_url`。用于获取已知 URL 的资料；不需要先调用会话查询、创建组或打开终端。首版参数只有必填 `url`，不提供 `session_ref`、执行位置、请求方法、headers、body、Cookie、凭据或保存路径。

```json
{
  "type": "object", "additionalProperties": false,
  "properties": {
    "url": {"type": "string", "minLength": 1, "maxLength": 8192}
  },
  "required": ["url"]
}
```

| 项目 | 固定契约 |
| --- | --- |
| 执行位置 | `execution_location=client`，由 ZeroWork 本机 HTTP 客户端发起 GET；复用适用的本机网络/代理配置，但不继承模型服务的 API key、专用鉴权头或登录态。不经 SSH/跳板机发请求，不隐式改走其他出口。 |
| 能力范围 | HTTP/HTTPS；HTML 提取可读文本，JSON/纯文本返回有界文本，并保留内容类型。HTML 不执行脚本，不能承诺 JavaScript 动态页面完整；图片、PDF、压缩包和二进制返回 UnsupportedContentType 及必要元数据，不另行下载/落盘。 |
| 正常结果 | `execution_location, requested_url, final_url, http_status, content_type, title?, text, observed_at, elapsed_ms, truncated, truncation_reason?`。网页标题与正文均来自不受信外部内容；没有真正取得正文时不编造摘要。网页结果没有终端区间、ExecutionId 或 RecordingId。 |
| 限额 | §6.1 的总超时覆盖 DNS、连接、TLS、重定向与读取；流式限制接收和解压大小，不先无界下载再裁。提取后的正文超 32KiB 明确截断；所有元数据与正文合计仍不超过单结果 64KiB。无分页、无隐藏后台续抓。 |
| 失败 | InvalidUrl、UrlNotAllowed、NetworkUnavailable、DnsFailed、ConnectFailed、TlsFailed、FetchTimeout、RedirectLimit、ResponseTooLarge、UnsupportedContentType、HttpError；沿通用错误结构返回真实阶段。HTTP 4xx/5xx 保留实际状态及有界文本错误体；DNS/TLS/连接失败没有 HTTP 状态，不能伪装成空页面成功。 |
| 取消与重试 | 复用对话工具调用的取消路径，停止 AI/关闭对话后取消未完成请求并释放本机连接；晚结果只能回原 call。取消不能撤回已发出的请求。无 request_key；同 URL 再次读取是新观察，不承诺内容不变；失败不自动切到远端、不无限重试。 |

网络访问只面向公共地址：拒绝 URL 中的用户名/密码及非 HTTP(S) scheme；初始地址、每次重定向和实际连接解析地址都须复验，拒绝回环、私网、链路本地和云元数据等保留目标，防止重定向或 DNS 变化绕过。校验必须约束实际连接；代理出口无法保证相同目标约束时返回 CapabilityUnavailable，不以本机预解析代替代理实际目的地检查。HTTPS 校验证书，禁止跳转降级为 HTTP。内网 API、带认证网站及自定义请求头不在首版范围，不能借已有 SSH/模型服务凭据绕过。

只读 GET 仍会向目标站点发送 URL；获取资料不能隐含授权外传终端内容、附件或凭据。URL 来源和数据外发按 §4.3 宿主规则检查。响应正文按外部资料处理，不能成为新增用户指令、宿主通知或权限 grant；从网页提取出的新 URL 也须经过同一网关。普通 HTTP 链接可读取，但应保留 scheme，不把其内容标成经过 TLS 保护。

工具描述须明确：**“在运行 ZeroWork 的本机获取指定 HTTP/HTTPS URL 的有界文本内容，用于查阅资料。请求不从远程会话发出，结果不能证明目标服务器或跳板机可联网；需要检查远端网络时，使用已有命令工具在明确的目标服务器执行。仅支持 GET，无浏览器脚本、搜索、认证或文件传输。”** 本机不可联网时直接报告，不尝试创建终端代办。

工具卡沿用现有卡片，标题为“获取网页”，右侧投影显示域名/页面标题等具体信息，展开后显示实际 URL、来源“本机网络”、HTTP 状态、内容与截断提示。卡片不重复显示 `fetch_url`，不提供终端“查看过程/记录”入口，不增加助手标题栏按钮或 composer 控件。

## 7. system、动态上下文与可见通知

system 只放固定角色、工具安全行为与稳定产品契约；若模型确需初始种类，最多加入创建时不可变 `initial_kind=session|group`。不得在 system 中放完整终端、所有会话/组列表、当前名称/序号、成员和动态运行状态；工具 schema/description 也不承载动态 inventory。

current_binding 改变、成员有效性改变或用户接管时，宿主生成 `host_notice`，而非伪造模型 tool_call。通知具有 `notice_id, conversation_id, event_revision, kind, prior_binding?, current_binding?, changed_refs, reason, created_at`；无密码、完整终端或无界成员列表。UI transcript 显示“此对话现属于组「排障」；原会话已加入，历史与草稿继续保留”等简短事实，点击可查真实对象。

provider wire 中，host_notice 由 adapter 渲染为有明确来源前缀的普通上下文消息（在现有协议没有专用 notice role 时用 user role 的 host-context 信封），同时明确“这是宿主事实，非用户新增命令或授权”。它不生成工具调用、不使用 tool role 冒充不存在的 call，也不修改既有 system。模型看到 notice 不得自行扩权，实际权限仍靠工具网关。

排序规则：

1. 每个真实 assistant tool_calls 消息之后必须先补齐该 batch 所有真实 tool result；不能把 notice 插在其中，不能因变组丢弃旧 owner 的 result。
2. 同一 batch 的 scope-changing call 必须作为屏障。尚未派发的兄弟调用以 `ScopeRefreshRequired/cancelled_unsent` 结束对应 slot；不自动继承新的组范围。已经派发的合法旧 scope 调用留在原 ledger 直到有界终态/unknown 交接。
3. 全部 pair 闭合后，提交 handoff/结果，追加本次最小 notice，刷新下一 provider round 的 authority/table 与上下文摘要，再继续请求。
4. 运行时通知按 revision 去重；每次后续 request 只补尚未发送的事实变更摘要。同一 revision 不反复注入，不每轮重发完整组列表。
5. notice 纳入已有预算与 wire_history 上限。历史压缩保留当前绑定快照、最后已发 revision 和必要变更原因，旧逐条 notice 可合并为单个有来源摘要，不能无限追加；tool pair 不拆散、不删除尚待回灌的结果。

UI 可先投影已提交的绑定变化，但 provider 只在上述合法边界看到通知。通知发布与 journal commit 使用同一事件 revision，崩溃恢复按 revision 续发，不制造第二次转组事件。

## 8. API 2 内部接入、scope 交接与持久化

### 8.1 RequestTable 与 dispatch 的具体扩展

维持现有 provider `session_targets` 分支及四工具兼容；新增宿主注册表、请求 entry authority 与结果适配，不把任意 host 动作塞入一个 `manage(action,...)` 万能工具。

```text
RequestEntry.authority =
  session_targets { binding, membership_snapshot_ref, TargetBinding[] }
                                                          # 原执行语义，调用时投影有限 Scope
  conversation_context { ConversationId, binding_revision, grant_revision }
  lifecycle { ConversationId, TaskId, binding_revision, frozen grants }
  execution_control { ConversationId, TaskId, execution capability }
  local_network_read { ConversationId, TaskId, grant_revision, network_policy_revision }
```

宿主 entry 不强制 `session_ids`，由独立 validator 校验 SessionRef/GroupRef/ExecutionRef；入口先校验 invocation 的对话/任务，再解析引用。不用伪造一个 session target 承载组管理或本机网络读取。新增 `HostInvocation/HostReceipt` 保存 conversation/task、operation、原 call key、适用的 binding_revision 与明确资源回执；原 plugin Invocation/Receipt 仍使用真实 SessionHandle。`local_network_read` 使用独立 URL validator、网络策略和受控 HTTP 请求，不经过 provider exec/PTY handler；没有会话引用时也可合法注册。其 receipt 记录请求是否已发出、取消及连接释放事实，不生成远端命令执行或录制回执。

session-target 分支在当前 round 固定 membership snapshot 的引用/revision，目录可保存授权全组；解析真实调用的最多 16 个 session_ids 后，逐个查该快照/TargetBinding，再投影一个有限 `Scope` 给原 exec/Legacy adapter。派发时再对 live group membership、SessionHandle、能力/权限复验。这样保留原每调用 16 目标和旧 exec 参数/执行语义，不用一个固定 Targets 数组冒充完整目录，也不让新成员自动继承该 round 的 authority。provider 定义验证应分别处理 authority metadata 与调用级目标上限，不能再对整个动态目录套 `session_ids.len<=16`。

修改点必须覆盖 RequestTable.init/parse、providerDefinitions、provider_http 的 tool definition 验证、tool_loop 的动态调用/结果路径、Bridge 注册/泵和权限预检。当前 provider_http 也要求 tool definition 的 session_ids 非空，仅改 parse 不够。新增 host definition 在内部带明确 authority tag；序列化给 provider 时仍是正常 JSON tools，不能把 session_ids=[] 当旧有效定义。

当前单请求 16 工具不足容纳拆分目录。实施选择为**保留插件每个最多 8、原插件请求池最多 16，另设 host 请求池最多 32，总工具最多 48**，同步调整 `plugin_tools.max_request_tools` 的分池校验与 `provider.max_tool_definitions`，每响应 max_tool_calls 仍维持现有 16。只装载本对话权限/协议支持的 host 定义及原 plugin 定义，保留统一名称冲突检查、schema/描述字节总预算和 provider 能力交集。请求定义文本建议总预算 96KiB，并计入模型上下文估算；provider 已确认更低工具数量/字节限制时提前明确 ToolCatalogLimit，不能悄悄只保前 16、只显示一半、删除必要查询工具或隐式轮换令模型误以为工具永久可用。上限改动属于 API2 宿主容量扩展，须以现有插件测试证明不降低旧限制或放宽权限。

当前 main.currentScope 要求全组成员装入固定 16 位 Targets，且零成员返回 null；它不能继续作为 AI 入口/Controls/host 查询/绑定有效性的判断。新 CurrentBindingResolver 只解析稳定 owner 和授权，不依赖成员非空或完整成员数组；0 成员与超过 16 成员的组都能打开对话、查询和管理。旧 session-target 执行仍每 call 最多 16，模型通过查询选择精确 session_id 子集；RequestTable 的 session binding 目录可保存全部授权成员，调用级 Targets 仍有界，不把目录截成前 16 伪装成全组。附件所属对话存在性也不能只检查 active member 数，零成员组仍保草稿与历史。

### 8.2 单→组 handoff 的安全状态机

```text
stable(session, revN)
→ prepare_handoff(tx, old_scope, triggering_call)
→ commit_group_and_binding(group, ConversationId, revN+1)
→ finish_old_batch(all tool pairs, immutable old keys)
→ publish_notice(revN+1)
→ refresh_authority(next round, new Scope/RequestTable)
→ stable(group, revN+1)
```

当前 Loop.start 冻结整 turn table、nextRequest 只换 messages；Bridge 对 membership revision 变化会撤销全部 child 权限。实施必须新增 round-boundary `refreshAuthority(snapshot)`，一次性替换 loop table、Bridge children/services、captured scope、roster revision、provider definitions 和通知水位。下一 round 新 call 属于新 owner/scope；Turn/Conversation 可连续，旧 ledger 的 owner/turn/call 不改。不能只改 State.owner 后继续拿旧表执行，也不能仅把 old child.authorized 改 true。

create_group 的触发调用是明确的 handoff 边界：其 invocation 仍属于旧 session owner，返回结果也用旧 key。该次事务记录授权允许创建后继组，并返回 handoff token 供宿主续接；不把旧批准复用于新成员。普通成员新增/移除也只使之后 round 获得新快照，未派发调用按旧表拒绝；已经发出的调用保结果。

迁移当前对话时，Store 的 selected-owner 索引、UI host、附件 chooser/draft ticket、wire history、result card 路由和审批关联必须同事务更新或通过稳定 ConversationId 间接定位。历史结果增加 immutable_call_owner 与 presentation_conversation_id，查询当前对话的历史可涵盖其 handoff lineage；不修改旧 key、不在新组伪造一套旧调用。查询 lineage 只授予当前对话已有历史，不获得原 session 其他对话或新成员历史。

主线程 retainToolResults/request_owner 校验改为先按稳定 ConversationId/turn 找调用所属记录，再验 immutable original owner/代次，不能只比较当前 owner。Manager 重跑/重试保护以 ConversationId+turn 的既有 ledger 检查是否已派发；不能在 owner 变成 group 后绕过 previous.scope.owner 的旧条件而 clearToolRun。附件 picker/reader ticket 以 ConversationId+draft_epoch 路由，原 source SessionHandle 只证明内容来源；迁移时 pending 图片/文件 completion 仍写原对话，过期 ticket 只释放，绝不能经旧 owner→Store.get 误写新生成的单会话草稿。

仅 metadata/name 变化不失效身份或重审批；target generation、能力/权限 revision、成员边界或精确命令变化必须复验/失效。名称不能作为 hash 中决定身份的字段。

### 8.3 控制线程、worker 与避免自等待

现 Bridge.pump 在 mutex 内执行 controller handler。生命周期 handler 不得直接进入会 stopOwner/clear/join 当前 AI worker 的普通路径，否则会出现“工具等待控制器、控制器等待当前工具线程”或重入 mutex 的死锁。

采用宿主 LifecycleSupervisor 的异步 operation：handler 在短锁内只验证并 enqueue 版本化命令，返回 Pending token；释放锁后由应用控制循环推进 SessionHost/roster/存储。工具 worker 等待有界 operation 事件，不能持 Bridge mutex、native guard 或存储锁。迁移回调标记 `initiator_call`，把本次触发 worker 登记为 handoff participant，不走停止它后再 join 的通用路径。屏障完成后由原 worker 在下一 request 边界接收 refresh。

关闭/断开恰好涉及调用方资源时同样拆两阶段：先记录该管理工具的已接受结果/执行取消状态，再由 Supervisor 在当前 handler/worker 之外收尾，不在 handler 内同步销毁自身桥或 join 自身线程。显式用户关闭仍保旧影响预检/确认；任务自动收尾由独立 Supervisor 推进，不能借普通 close hook 停掉自己后丢结果。

open_session 的 member/container commit 不能假定现链路已原子：现 Roster.join 先增 revision 再 fallible append，installTabModel 也存在 join 后 setContainer 失败的窗口；creation_group 的当前自动 join 发生在 starting 而非 transport ready。新 open_session 显式携带 GroupRef/ownership/operation，抑制该路径的 ambient creation_group 早 join，创建 pending 对象；ready 后由唯一事务入口提交一次 member/container。预分配 roster/模型/索引容量后，提交阶段只做已预备的不失败变更，普通用户新建路径保持原行为。异步失败补偿只移除本 operation 创建的成员、container 和 record 引用，核查 ID/revision 后执行，不删除用户原成员；失败卡与可核查清理记录保留，但不能留下可选 ghost member。

### 8.4 journal、崩溃与幂等边界

新增对话级 lifecycle/execution journal，复用既有数据目录、私有权限和原子落盘；不存秘密。最少记录：transaction/request key、canonical hash、ConversationId/TaskId、old/new binding、资源 ownership、operation stage、创建 SessionId/代次、dispatch_started、输入 receipt、RecordingId/ranges、cleanup receipt、notice revision。不得只依赖容量 128 的内存 operation_store 承担重启去重。

| 记录点 | 崩溃后行为 |
| --- | --- |
| prepared 未 commit | 根据 journal 回滚未发布索引和 provisional 资源；不自动执行。 |
| group/binding committed、result 未确认送达（含结果分配 OOM） | 恢复同 ConversationId 的绑定/ledger关联和原 call committed receipt；同 key 或只读查询返回原组，不再次创建。完整对话内容能恢复到哪一步沿已有存储能力，不凭 journal 伪造历史。 |
| session 创建/成员提交中 | 根据 operation ID 区分创建中/已成员/待清理；恢复元数据及记录，不自动重连终端。无法证实 ready 时标 unknown，等待用户选择。 |
| command dispatch_started/partial write，无完整回执 | 标 outcome_unknown；只读记录可查；无论 provider 是否重试都不重放。 |
| execution 完成、清理未完成 | 恢复记录与 cleanup_pending；不因“任务完成”自动销毁未知活动资源，重新进行关闭资格检查。 |
| notice commit、wire 未发送 | 按最后成功发送 revision 续发一次最小摘要，先保持 tool pair 合法。 |

执行记录写入 dispatch_started 与 durable recording barrier 必须先于第一输入字节。存储失败则零派发或在已派发情况下标 RecordDegraded/unknown 并阻止后续 AI 输入；不能宣称完整可回放。所有异步回调携 ConversationId、operation、代次和 fence，已撤销后只释放资源，不覆盖新对话。journal 有界保留与归档策略跟随对话/终端记录，不无限保存每个输出 chunk。

## 9. PTY 控制租约与交互协议

### 9.1 “只读”是宿主输入控制权

AI 使用已有终端时，宿主暂时阻止用户向该 PTY 发送输入；远端文件系统、进程权限和 shell 并未变成只读。UI 文案为“AI 正在控制此终端 · 可滚动、复制与搜索”，并提供“停止 AI / 接管终端”。审批期间不取得租约，不阻止用户输入。

执行服务在命令派发前自动取得租约，执行结束/失败/接管自动释放，不向模型提供 lock/unlock 工具。租约包含 `SessionHandle, ExecutionId, lease_id, fencing_token, input_epoch, expires_at, owner_task, ownership_revision`。每次取得/撤销递增 fence，worker 在消费输入时再验 fence，不只在排入队列时检查。

输入权限使用 §10.4 的来源矩阵；日志阅读状态不撤销执行授权。输入网关须覆盖键盘、粘贴、IME 最终提交、程序化文本、拖入文本、广播、终端鼠标输入/快捷键、多个窗口持有的同一 SessionHandle 视图。滚动、选区、复制、搜索、查看记录不受影响。VT 协议回复、窗口尺寸同步及必要终端应答走单独 protocol source，正常运行；不能用“一切输入禁止”让程序卡死。广播预检遇被控制成员时返回冲突并沿现有全目标门控，不悄悄漏发个别目标。

现 InputQueue 是 SPSC，新 runner 不能开第二 producer 直接写队列。用户输入与 AI 输入都先到原 controller mailbox 的唯一提交入口，再携来源/fence 交给 worker；共享 SSH 操作沿 worker 的 lockNative/shared guard，控制器不能直接调用 libssh2 或绕开通道锁。旧 queued input 携原 input epoch，撤销后不能作为新 owner 输入补发。

### 9.2 取得、续租与撤销

1. 先校验完整命令/审批/目标，确认 recording start barrier，并按后端能力检查输入状态。Local 读取私有 input barrier；SSH 结合已建立的命令事件状态与宿主输入账本判断是否可提交，不将 OSC 当作远端 buffer 证明。两者都检查用户草稿、prebuffer、IME/尚在途 commit、host pending input bytes 和已排队普通输入；无法排除冲突时拒绝。
2. 在同一输入序列化边界比较 `input_epoch` 并获取 fence；检查到获取之间发生任何用户输入都失败重验。不能通过清空用户行、补 Ctrl-C、自动按 Enter 或丢弃队列“制造空闲”。
3. 获取后发送命令使用新 input sequence，保每次 write receipt。文本和提交边界一并记录；partial write/EAGAIN 只允许原 native in-flight 请求按既有传输约定继续相同缓冲，不能另行排队、改写尾部或由超时重放。
4. Supervisor 每 5 秒续租，TTL 15 秒（新增设计默认）；TTL 仅控制本地输入权，不作为进程超时/远端空闲证据。续租依赖 holder 仍存活及 fence 未撤销。
5. 正常完成/取消、代次改变、连接丢失、应用 worker 故障或用户接管都撤销 fence。watchdog 撤销 AI 控制并释放其独占权，但旧 execution 如无退出证据保 unknown；不能因业务效果未知永久锁用户。
6. 接管按 `revoking → draining_native_or_unknown → user_ready` 推进：先撤销 AI input grants 和尚未进入 native write 的 host 队列，发布新 epoch；已进入 native write/SSH EAGAIN 的 pending buffer 必须按原 write 约定保同一字节序列与回执，不清空后混入用户输入，已上网络的字节不可撤回。短时有界等待排空或经证实的 channel 局部取消后才开放用户写入。无法证实时显示 input_not_ready/unknown 并提供明确断开本会话/核查路径，不为立即解锁 abort 共享 transport，也不能仅因远端业务效果未知继续持租约。晚到旧 fence 不得提交新的写入；既有 native in-flight 只可完成原回执。created_task 会话在接管请求被接受时即转 handed_to_user，自动关闭权立即撤销。

终端“显示/隐藏/关闭视图”与 execution 生命周期分开；收起 AI、切 Tab 或终端视图不可见不能中断执行。用户实际关闭会话仍按影响预检/确认办理；只读记录视图关闭只释放视图引用，不发送远端命令。输入等待超过提示阈值只提醒，不暗中输入默认答案或关闭会话。

### 9.3 首版交互支持矩阵

| 场景 | 首版契约 |
| --- | --- |
| 在原 shell 中持续发命令 | 本地私有后端保留严格屏障；远程按 §9.4 的现有事件/最小文本适配能力执行。无私有模块不再单独构成拒绝理由；未知输入目标、非空草稿或未就绪初始化不盲目写入。发送、shell 报告与确定结果分别记账。 |
| 进程普通 readline 问答 | execution 仍持有效输入租约且尚未观察到结束时，可按显式 `terminal_stream` 能力发送有界 text 或独立 Enter。它表示对原 PTY 的流输入授权，不证明程序正在 read、身份或已经消费；原进程在检查与写入之间退出仍有目标竞态。受控 `controlled_line` 消费者继续使用更强回执。提示文字不创建能力，未知 TUI/raw/秘密交互仍按下列限制处理。 |
| sudo/password/OTP/密钥口令 | 宿主显示安全输入提示，秘密经临时受控引用直接交终端服务；模型只见 awaiting_host_secret / secret_submitted / cancelled。不写 transcript、普通输入日志或工具参数，不记录秘密按键；远端是否回显仍须检测与保护，无法保证时暂停交用户接管。 |
| TUI、alternate screen | 可读取 screen snapshot 与记录；只有明确声明且验证的应用/受控按键集合可驱动。首版不承诺 vim/top/全屏安装器等任意 TUI 自动操作；未知应用返回 UnsupportedInteraction，保执行并给用户接管。 |
| raw mode | 不能把普通换行或 Ctrl-C 当作可靠语义。仅协议明确支持的 key/interrupt 可用，否则拒绝输入或交用户。 |
| 多行 shell 语法、heredoc、括号未闭合 | 支持集成明确确认完整提交/continuation 状态；不知道是否完整时不追加猜测收尾。命令受宿主有界长度与禁止规则检查。 |
| 后台/守护作业 | 前台命令结束报告不代表所有后台任务退出。保 job/引用状态；无法枚举时 idle=unknown，不自动关闭。 |

输入授权只针对执行中的具体交互，不授予模型任意后续 shell 注入权。动态回答产生新的业务影响时按相同权限策略复验；未知目标/secret 内容不因“交互式”而免审。用户安全输入界面与“用户接管”不同：前者只授予一次秘密提交能力，AI 不能读取，也不永久控制用户后续输入。

### 9.4 同一 PTY 持续执行与命令事件（2026-10-30 修订）

**当前需求：**AI 附加已有会话，或创建一次新会话后，持续操作该会话原有的 PTY、channel 和 shell。连续命令保留 `cd`、变量、函数、激活环境以及当前前台程序。不能用一条命令一个 SSH exec/channel、替换 shell 或保留同一 Tab 但重建进程来冒充持续执行。执行范围限本项目现有 Local zsh 与远程 SSH。

本地沿用已存在的 zsh 集成、私有输入协议和终端事件，不重做一套执行器。远程复用现有 SSH channel、单 IO owner、输入队列、SessionHandle/generation、授权与录制；**BootstrapV1、上传二进制或模块不再是远程 PTY 执行的前置**。之前的版本化 helper 路线仅保留为实现历史，不再继续扩展 bash 模块、部署资源或要求服务器安装 zsh。

**默认启用的含义：**命令事件属于终端会话基础能力，人工输入与 AI 使用同一份集成、状态和记录；AI 附加时复用已就绪会话，不再触发远端 Bootstrap 安装。Local 沿现有创建路径启用集成；用户已选择新建 SSH 会话默认自动初始化，沿原 shell 启动输入通路提交一次文本，并先检查已知兼容事件生产者以避免重复钩子。该行为以常规交互 shell 启动为前提；创建 channel 或等待一段安静时间不证明原 shell 处于安全输入点。登录配置若进入未知前台程序，仍存在初始化输入被该程序接收的限制，不能称为私有 input barrier。是否已连接与是否可执行分开报告，不能由 SSH connected 直接置 interactive_execution=ready。初始化在同一 shell 内定义函数/钩子，属于远端代码执行；首次启动命令仍在原 shell 中执行，并可能按用户原有策略进入 shell history。客户端只在首片发送至匹配首 ACK 的有界窗口内，移除与本次随机 nonce 启动命令完整匹配的回显（含已验证的 readline/ZLE 折行重绘）；统一输出随后进入终端、录制和 AI 观测。保留其他登录文字、提示符和程序输出；未完整匹配、超时、超过16KiB或连接释放时原样释放待处理字节，首 ACK 后不再匹配。后续 payload 进入静默接收器，不再逐片经 readline/ZLE 显示或作为独立命令历史输入。不修改 HISTCONTROL/HISTFILE、不清理用户历史，不能称为无痕初始化。后续业务命令仅发送原命令，事件以 VT 控制序列消费，不为每条命令打印可见的“开始/完成”文字。

自动初始化提供两个配置层级：App 全局开关默认开启；每个 SSH 主机为“继承全局 / 开启 / 关闭”三态。连接创建时计算并冻结最终 bool，同一会话不因之后设置变化重复初始化或切换行为。修改只影响后续新会话；关闭开关不卸载当前 shell 中已安装的钩子，不停止消费原本存在的 OSC 命令事件，也不关闭普通 SSH 终端。启动配置不适合自动初始化的主机可单独关闭，无需修改其他主机。

文本初始化沿原输入队列完成：首个有界启动命令在原 shell 内定义临时接收函数，保存原 TTY 状态及 INT handler，使用现有 stty 关闭输入 echo 后才发送 ready ACK；不安装软件。脚本拆为 128 字节片段，以有界单行编码发送给接收函数，不再经过 readline/ZLE；各片仍沿 `OSC 133;P;zw_init=<nonce>;<sequence>;<raw_length> BEL` 流控，宿主核对 nonce、递增序号和长度后推进。字符接收有超时；成功、超时、取消均尝试恢复原 termios 与 INT handler，只有全部恢复成功才发 `zw_restored=<nonce>`，恢复或接收失败不执行 payload/不发最终成功 ACK。恢复成功且 payload 完整后才在原 shell eval 钩子并清理临时变量，最终 raw_length=0 ACK 后还须观察到 A+B 才公布 ready。每片等待5秒、整体60秒，失败停止后续片段，不重放启动输入。宿主未收到恢复收据时保持 input-not-ready；原 native 写入缓冲先排空，仅可取消其仍独占的初始化接收器一次，不能对业务命令发中断。ACK仅为合作式流控/恢复报告，不是安全认证或业务完成凭据。业务命令路径仍是完整批准命令排队和一次提交，不使用初始化分片协议。整个过程不上传/落成远端脚本文件，不创建常驻 runner。

统一命令模型使用 OSC 133 的 `A/B`（提示符/可输入阶段）、`C`（命令输出开始）、`D;<status>`（前台结束与退出码），工作目录沿 OSC 7 更新。`A/B` 只形成协作式事件状态，不能单独证明远端输入行为空。初始化、宿主输入序列、会话代次和执行 ID 共同约束关联；每条命令仍需独立审批与租约。

执行事实由 `Snapshot/PublicReceipt.completion_source` 保留，取值如下，而不是把 `interactive_execution` 一个布尔值当作所有能力：

- `private_protocol`：现有本地私有集成的提交、输入屏障与完成事实；继续满足原严格校验。
- `shell_reported`：该持续 shell 发出的命令开始/结束/退出码事件；复用 VT 的统一事件模型与现有非零退出通知。事件序号和会话/命令关联用于防误配，不构成防同 PTY 程序伪造的安全证明。
- `unknown`：没有相应报告或报告链失效。已派发执行保留未知结果，不捏造退出码、确定完成或远端输入屏障；拒绝依赖这些未知事实的后续自动输入。普通人工终端仍可使用，不能用新建终端代替原目标。

远端首先复用已有完整命令事件。普通 PTY 是字节流，SSH `exit-status` 对应整个 channel 主进程；当主进程为持续 shell 时，它不逐条报告 shell 内命令的退出码。相同无输出命令可能返回不同状态，提示符或输出安静不能补出退出码。只有在确认缺少现成事件、而任务要求准确逐命令报告时，才采用用户已允许的**统一事件协议下的会话内纯文本薄适配**。它在当前 shell 中初始化一次，不上传二进制、`.so` 或包装程序，不逐条包裹用户命令，不替换 shell，不改 dotfiles，也不借内联解释器部署另一套 runner。适配仅覆盖实际能力，当前 bash 4.2 不能依赖新版 PS0。

薄适配的 shell 差异局限在事件钩子：zsh 使用 preexec/precmd；Bash 4.4 及以上可用 PS0，较早 Bash 通过 DEBUG/PROMPT_COMMAND 适配并保留原钩子行为，不为集成改变 functrace/extdebug。旧 Bash 的纯 subshell 等语法可能没有可靠父 shell 开始事件；旧 DEBUG 路径对以 `(` 开头的已知不支持命令在写入前拒绝。完整 native-written 后 5 秒仍未取得 C 时保留 unknown，不追加 Enter、不重发、不补造开始。Bash 4.2 是目标环境兼容要求，语法兼容不等于该版本实机通过；测试记录须注明实际版本。未知 shell、现有 DEBUG 冲突或无法安全串联的钩子不能静默覆盖。

这条事件路线已有 [Ghostty shell integration](https://ghostty.org/docs/features/shell-integration) 与 [VS Code terminal shell integration](https://code.visualstudio.com/docs/terminal/shell-integration) 的公开实践；Bash 旧版本钩子可参考 [bash-preexec](https://github.com/rcaloras/bash-preexec)。开源实践证明的是方案类型，不替代 ZeroWork 本次初始化脚本、输入竞态和录制链路的验收，也不意味着不经初始化的默认远端 Bash 原生提供这些事件。

已有会话的首次初始化需要明确可交接的空命令行和可安全安装的钩子条件；未知前台程序、未提交草稿或现有钩子冲突时保持待启用，不盲目发送初始化或 Enter。初始化的文本执行与影响应在默认能力及设置说明中明确，不藏在 AI 已批准的业务命令之后；已选择的新建自动初始化不另加每会话 Bootstrap 部署审批。缺少准确事件时如实说明能力边界，不以创建新终端代替。

用户接管只撤销 AI 的后续输入权，按原队列约定处理已经进入 native write 的字节；不取消 AI 回合、不发送 Ctrl-C、不关闭 channel、不停止正在运行的命令。原执行 observer 和录制继续，结束事件晚到仍归原 ExecutionId；同会话后续重新授权须取得新 fence/epoch。用户明确 Ctrl-C、断开或关闭会话另按真实回执处理。

命令开始/结束是 shell 对一次顶层命令的报告；PTY 输出保存为该会话的观测区间，可能混入后台输出，不宣称分离 stdout/stderr 或收齐所有后台作业。断线、事件丢失、适配失效或未收到结束保持 unknown，不自动重发命令，不由 OSC、提示符或安静输出生成新的执行权限。

### 9.5 精确命令与交互文本提交

本节原私有 `set_buffer/accepted/submit` 契约继续适用于具有该能力的本地后端；它不能成为普通 SSH 持续终端操作的统一前置。远程后端按 §9.4 分别记录已批准的输入、客户端排队/native-written、shell 报告的开始/结束与未知状态，不能把本地单写入者串行化冒充远端空 buffer 或程序已消费的证明。已有未提交输入、未知前台目标或尚在 native write 的旧输入未处理完时，不强行追加 Enter。普通交互输入与命令提交分别授权、分别记录；用户接管后原命令观察保留。

输入授权与前台完成分开：`local_released && grant == null` 表示本次输入租约已释放，包含 native 排空；`input_ready` 仅用于下一次AI命令的安全空编辑边界，不应让已结束任务因延迟提示符或人工草稿而挂起。`handed_off` 只表示输入权归还用户，原执行保持只读观察：journal继续running，Driver计为活跃handoff observer，不冻结输出、不记为outcome_unknown。只有真实前台结束与记录结算后，才发布该执行的退出结果/完整观测区间；接管本身不停止或重放命令。

Local 私有后端通过 `set_buffer(execution_id, fence, input_epoch, command_hash, utf8_bytes)`，在 shell 编辑边界原子替换经确认的空 buffer；核验完整 buffer/hash 的 accepted 后，再对该 revision 发一次 submit。不得把 command 当普通按键流写入 PTY，不依赖 bracketed paste 转义或拼接 Enter。借用 Local trusted_edit 的编码和 buffer 回执，新增 submit 必须绑定 ExecutionId，不能把编辑租约当执行授权。

宿主先把 CRLF 规范为 LF；孤立 CR、NUL、ESC、DEL、除 TAB/LF 外的 C0，以及 C1 控制字符全部拒绝，禁止静默删除。Local 再校验 UTF-8 字节上限及完整语法/continuation 能力；其支持的 TAB/LF 是精确 buffer 数据。普通 SSH 首版仅允许不超过 4094 字节的单行命令，并拒绝 TAB/LF，避免把补全或多次提交冒充一次已批准命令；使用原 PTY 输入通路提交该文本与一次换行，记录实际 native-written 与 shell-reported 阶段，不声称拥有 Local 的 set_buffer/accepted 证明。UI 展示最终规范化内容，审批 hash、幂等 canonical hash、回执均引用同一字节串。用户修改内容必须重新审批；断线、输入冲突或未知部分提交不补 Enter、不重发。

`InputWait.kind` 明确区分 `controlled_line`、`host_secret` 与 `terminal_stream`。前两者由受控消费者报告；`terminal_stream` 是对仍运行执行的有界 PTY 流输入授权，不是 read 等待证明。即使执行曾报告开始，普通终端也不能原子保证“目标检查之后、write 之前”程序没有退出；原始流模式必须显式保留这项限制，不能用于秘密提交或自动认证。观察到结束、接管、代次变化、租约撤销或目标不明后，拒绝新的输入。

输入回执分成两条独立路径：`terminal_stream` 使用 `queued → written`，表示宿主排队及真实 native write 完成；`controlled_line` 使用 `queued → consumed`，由受控消费者确认。`written` 是该流输入的最终态，不再升级为 consumed，也不证明远端已经 read 或处理。每次 text/Enter 绑定独立 input_sequence 与原 execution/fence；重复 request_key 只返回旧回执，不重复写入。

`send_execution_input.text` 首版仅允许单行普通 UTF-8 文本（4096 字节以内；拒绝所有 C0/C1/DEL，包括 CR/LF/TAB/ESC）；提交使用独立 `key=enter` 调用与 request_key。secret 经专用 host 路径；key 只允许已协商交互协议中的有限枚举，不能在 text 中夹带。结果记录 received/queued/native-written 等真实阶段，不能把 native-written 冒充程序已消费。文本/按键影响与等待目标变化仍需复验授权。

## 10. 终端记录、执行区间与关闭后查看

### 10.0 唯一记录身份、manifest 与目录

一份可独立打开的终端归档持有一个 `ArchiveKey`，只对应一个终端内容成员和其 `RecordingId`。RecordingId 在首次启用录制时生成并持久化，同一 Tab 重连保留 RecordingId，但增加 `recording_generation`，每个 generation 明确绑定一个 SessionHandle；轮转增加 segment_id。ExecutionId 只引用自己的 generation 和区间，不能跨重连拼成一次执行。ArchiveKey 在录制开始时预留，关闭后发布全局目录；失败也沿原键记账，不生成第二条归档。组合布局只保存其他 ArchiveKey 的引用，不能以一个 cast 冒充全部 pane。旧 cast 无 RecordingId 时只生成 legacy ArchiveKey，禁止反推精确 AI 区间。

全局列表和 AI 卡片共用 `resolveRecord(archive_key? | recording_ref, execution_ref?)`。它先在受管根内解析 RecordingId→ArchiveKey，再返回同一版本的 ArchiveDescriptor；按窗口以 ArchiveKey 去重。卡片在活动终端定位和关闭后打开历史使用同一 generation/range，记录不存在时返回 tombstone 原因，不能以主机名查替身。

唯一权威文件为 `<stem>.session.json`，以下原 `recording.meta` 结构是该 manifest 的 `recording` 子对象，**不是第二个 sidecar**。schema v1 包含 archive_key、recording_id、manifest_revision、来源/展示元信息、generations/segments、execution_ranges、baselines、完整性、文件清单和提交收据。`execution_range` 同时保存 raw_offset 与 event_sequence 两种边界，避免无输出命令、resize、应用事件共享 offset 时发生歧义；同时保存 completion_source，旧记录缺失时为 unknown，shell_reported 不能恢复成 private_protocol 或 sealed。TSV 仍保持8/10列，只做兼容发现索引，不承载另一套事实。

完整性使用两轴：`coverage=complete|retained|gapped|partial|unavailable`（完整生命周期/连续保留片段/区间内掉段/收尾或写入未完成/无可读内容），`replayability=verified|legacy_unverified|baseline_unavailable|unsupported`。retained 不等于可准确解码，进程结束也不等于记录完整。UI、列表、AI卡片、导出共用这两个值及 retained_range/gaps/redactions，不自行翻译成相冲突的状态。

文件发布由一个记录 owner 串行推进：写入并同步数据/匹配 checkpoint → 冻结 committed_length 与 checksum → 原子发布新 manifest revision → 最后更新 TSV。目录项与卡片解析同一 committed revision；失败只留下可恢复 pending，不发布假成功。读取取得覆盖 manifest 全部依赖的租约；清理原子预留整组，删除时同时提交 tombstone，使列表与卡片一致失效。用户清除全部数据先冻结读者与 writer，再沿现有销毁流程办理，不让卡片引用永久阻挡清除。

### 10.1 RecordingStartBarrier

run_in_terminal 派发前，记录服务创建/取得稳定 RecordingId 和 recording_generation，持久写入 header/源身份/起始逻辑序号，成功打开数据与执行 sidecar，发布 `recording_ready(barrier_id,start_offset)`。服务确认 barrier 已覆盖当前输出位置后才能写命令。仅在内存中有 timeline、当前 UI 勾选了“记录”或导出按钮可点，不构成该屏障。

执行开始前固定引用 `RecordingId+generation+start_offset`；完成/中断时补 end_offset、command/execution ref、证据和 gap。recording generation 代表同记录的代次/段，不随 History 视图重开变化；连接重连是新 session generation，不能续成同一次未完成 execution。卡片对记录持有受限引用，关原终端不使跳转目标变成另一个同名会话。

当前 archive index 只有 id/started_ms/cast_path 等，当前 cast 导出时间归零且不保存 stream_offset；local recording queue 掉段也只累计 dropped_bytes。实施须补版本化 sidecar，不假定从旧 cast 可恢复精确字节区间：

```text
manifest.recording { version, RecordingId, generations[] }
generation { recording_generation, SessionId, session_generation,
             source_kind, source_ref_hash, started_at, receive_time_origin,
             initial_cols/rows, segments[], baselines[] }
segment { id, logical_offset_start/end, event_sequence_start/end,
          receive_time_start/end, data_file_ref, checksum, committed_length }
execution_range { ExecutionId, RecordingId, recording_generation, call_key_ref, command_ref,
                  start_offset, end_offset?, start_event_sequence, end_event_sequence?, completion_evidence,
                  output_scope, output_attribution, output_attribution_reason?, process_receipt?, interval_saved,
                  gaps[], secret_redactions[] }
gap { offset_start/end?, event_sequence_start/end?, reason, known_dropped_bytes? }
```

执行区间使用 worker 接收的单调 raw stream_offset，sidecar 同时保存原始事件 offset 范围、retained 起止和 total_received；不能用 cast 文件字节偏移或显示行号替代。cast 转义/UTF-8修复/时间归零会改变编码长度，需靠 sidecar 的 raw-event→文件位置映射。最后一次 append 失败也必须比较 total_received 与 committed_offset 生成尾缺口，不能仅靠 dropped_bytes 推断完整。重连即使复用 runtime/VT，也创建新 session generation segment，旧卡永久指向原代次区间。

可复用现 cast/raw/checkpoint 数据和只读渲染，记录输出限额/轮转需保可寻址分段；内存 timeline 仍可有界淘汰，长期索引不随其淘汰而假装完整。积压丢段、存储失败、秘密屏蔽分别作为 gap/redaction；完整性统一使用 §10.0 的 coverage/replayability，不能承诺始终无损原始转录。

如果派发后记录失败，已有命令不重放。执行标 `recording_degraded`，保最后确认 offset 与缺口；阻后续 AI 输入并提示停止/接管，按已支持方式请求中断。不能仅因磁盘失败关闭用户已有终端，也不能把录制错误伪造为远端命令失败。必要控制协议与 write receipt 元数据要先保留，记录服务失败不能破坏清理权。

### 10.2 卡片跳转与 @log

“查看终端”按以下顺序定位：精确 SessionHandle 的活动终端仍在时，展示它并定位对应执行区间；否则按 RecordingId 打开只读历史视图，默认滚到该 execution_range。按钮和 `@log <recording_ref>` 共用同一记录解析器；无参数 @log 沿既有行为。History view ID 可以每次不同，稳定关联必须是 RecordingId。

只读重开不建立 SSH/Local 连接、不重新输入 command、不创建新 Task、不触发 bootstrap；记录缺失显示“记录不可用/已被清理”与已有卡片结果，不自动连回主机“补看”。重放指记录渲染/时间线播放，不是再次执行命令。复制命令/复制输出分别只复制真实字段，不附 UI 标记、耗时或 gap 装饰；输出本身的省略处必须有结构化完整性提示。

记录/卡片保留跟随现有用户数据保留和清除政策。用户主动清理记录后保最小 tombstone 让旧卡片有准确原因；记录 lease 不绕过用户“清除全部数据”，清除仍沿全局 idle/冻结/销毁流程。秘密输入不记录明文；普通远端输出可能包含业务敏感信息，沿现有内容权限及用户明确附加规则，不因记录存在自动发给模型。

### 10.3 输出有序边界、结束封存与可恢复基线

输出边界按 `completion_source` 分别取得，共用同一 RecordingId、timeline 与持久化模型，不把一种来源提升为另一种证明。

- **Local / private_protocol：**私有控制通道和 PTY 数据通道没有天然全序。沿现有 `BoundaryFenceV1`，native shell module 在私有通道登记 execution/fence/一次性 token/递增序列，并在同一 PTY 流写对应边界帧；宿主有界配对，校验 owner、generation 和顺序。START 持久化确认后才允许精确 buffer submit；END 与私有 finished 分别证明流位置和前台状态，finished 先到只进入 output_draining。token 不进入模型或普通录制，记录保留 raw_offset 映射。
- **SSH / shell_reported：**直接在原 channel 的接收流中解析完整 OSC 133 C/D，绑定正在观察的 ExecutionId，并记录实际 raw_offset/event_sequence；C 之后、D 之前的数据构成同 PTY 观测区间。D 携带退出码时才保存该退出码，缺失状态不得填 0。解析器必须覆盖跨 read 分片、BEL/ST 终止、长度上限及未知序列，普通终端字节继续交原 VT 渲染；无需第二控制 channel、私有 token 或远端模块。事件可以由同 PTY 程序伪造，因此只提供 shell_reported 来源，不作为批准命令、证明前台身份或秘密输入的权限依据。

两条路径都要先确认 RecordingStartBarrier，再提交命令；边界、进程回执与实际保存结果分别记账。没有开始/结束、重复或错序事件、generation 变化及流中断不能用提示符或安静超时补齐。观察到完成后仍须完成该区间持久化，不能收到状态就提前释放记录。用户接管后保留原 execution observer，晚到结束仍归原执行，不能把接管后的下一条人工命令误配给它。

用户于2026-10-29确认：新产品请求默认采用 `output_scope=session_interval`，不再为输出归属无法证实而拒绝已批准命令。命令受理/提交/前台状态、同PTY观测区间、输出归属为三个独立事实轴。`ProcessReceipt.foreground_finished`只表示本次受控shell回到前台结束边界及其真实返回状态，不推导所有后代进程均已退出。START/END只定位该PTY接收流中的区间，区间可能混入其它写入者的字节，命令的后台后代也可能在END后继续输出，不能声称全部内容都来自本次命令或已收齐后台输出。

输出观察使用 `output_attribution=unverified|no_concurrent_owner_observed|concurrent_observed` 及有界原因。guard的0仅表示本次非原子观察没有发现并发持有者，不是排他性证明；确有后台job/其它持有者则记录concurrent_observed；权限不足、元数据不完整或观察期限等记录unverified。START与END的观察保守聚合，后一次0不能消除之前的不确定或已观察并发。这些输出事实不能改写已取得的提交/前台状态及其 completion_source，也不单独使工具调用变为远端效果unknown。错身份、部分提交、集成失联、界标短写/丢失/错配及录制失败仍维持原unknown/degraded门禁；不能用quiet timeout猜END，不重放已派发命令。

新默认阶段为 `running → process_finished → output_draining → recording_sealing → interval_recorded`。分别保留ProcessReceipt、OutputBoundaryReceipt及实际持久化收据；它们含RecordingId/generation、起止boundary/event sequence、raw offsets、manifest revision、committed length及记录完整性。`interval_recorded/interval_saved=true`仅表示相应来源所定位的边界间观测数据实际保存成功，不能将 shell_reported 升级为私有可信证明。manifest以 `completion_evidence=foreground_finished`、`sealed=false` 保存同一三轴事实，不另造sidecar。无输出命令也以有序boundary/event_sequence定位区间；非0退出仍保留真实退出码和已保存片段。UI显示“前台已结束 · 观测片段已保存”或真实执行失败，并明确输出范围/归属局限。

原 `output_scope=exact` 与 `sealed` 仅保留旧记录兼容及内部严格调用；新观测区间不得改名为原sealed通过，保存失败保留已提交内容并标partial，不把存储失败写成命令失败。TaskFinish可以结算已释放的输入/控制和已保存的观测记录，但归属未证实不能授予confirmed idle或自动关闭资格；auto_idle保留会话，用户明确ask/keep/close仍沿原权限与关闭确认执行。此修订不新增全局模式设置，不改变接管只转移输入权的§9.1契约。

普通非受控终端可继续沿现有接收流录制；其时间是客户端接收时间，用户/后台程序并发输出不宣称归属于某次命令。旧无有序边界记录可查看会话范围，AI精确区间能力为不可用。活动窗口 resize 和成功重连造成的网格变化必须在对应 worker 输出顺序中写入 resize 事件；header 保存不可变初始尺寸，请求失败不录入，不能用最终窗口尺寸解释早期输出。

每个可独立回放的保留 segment 必须具备匹配 baseline：在事件边界序列 n 保存 VT/parser continuation、网格、screen/alternate、颜色/模式与 document 应用记录状态；从 n+1 的原始事件续放。checkpoint 必须与数据提交版本匹配且预算有界，不能用更晚 checkpoint 复原更早内容。ring 淘汰前先确保新保留范围有合法基线；无基线则标 baseline_unavailable，允许导出真实保留数据并禁用准确回放。不得从空VT灌入任意ANSI尾段。旧文件未知基线标 legacy_unverified并显示局限；本轮新写cast对已淘汰起点显式标记并拒绝错误解码，完整checkpoint恢复仍为本PATCH实施项。

### 10.4 阅读视图、执行授权与协议输入矩阵

| 输入来源 | 实时视图 | 活动 @log 阅读视图 | 已关闭归档 |
| --- | --- | --- | --- |
| 用户键盘/IME/粘贴/广播/程序化用户操作 | 经当前输入门禁，AI持租时拒绝 | 此视图拒绝；不清除其他来源的队列 | 始终拒绝，无live服务 |
| AI execution input | 有效fence/阶段/授权才提交 | 相同执行门禁，阅读状态不撤销授权 | 无执行目标，拒绝 |
| VT协议回复/必要终端应答 | 经独立protocol source | 原live worker继续响应 | 仅离线渲染，禁止外部副作用 |
| resize | 真实运行视图按会话尺寸所有权发送并记录成功事件 | 此阅读视图只改变离线布局；后台尺寸按既定owner处理 | 只改离线布局 |

用户在另一个窗口/视图申请输入须经同一session输入权检查；日志只读不修改资源ownership，不取消AI或丢弃它的输入。当前 `discardBufferedInput` 仅针对旧ordinary用户断线预缓冲，新增AI队列必须独立携source/fence，禁止调用全来源清空替代授权撤销。回放ANSI不得写剪贴板、自动打开URL或回复网络；用户明确复制/关联配置操作仍走各自真实入口。

## 11. 任务完成、保留与自动关闭

### 11.1 宿主完成回执

每次用户任务分配稳定 `task_execution_id`（对应 §3 TaskId），Supervisor 记录模型运行阶段和全部 lifecycle/execution refs。provider stream done 只表示一轮流结束，provider round done 只表示可回灌/继续，wait 超时只表示未观察到变化；模型完成答复也只是 `model_done` 候选，均不能直接触发关闭工作终端。

只有宿主收齐下列条件才生成 `TaskFinishReceipt`：无未处理工具 slot/审批/新派发；provider 已结束或被用户停止；所有执行处于确证终态、明确 handoff 或已登记 unknown 追踪；资源清理引用已转交 Supervisor；本任务输入授权全部释放/撤销。回执含 `task_execution_id, finish_revision, model_done, execution_outcomes[], pending_external_jobs[], owned_resource_disposition[], remote_effect_unknown`。

TaskFinishReceipt 可标 completed、failed、cancelled 或 completed_with_handoff/unknown。它不等于每个远端业务效果已知，更不等于所有 owned 终端有资格自动关闭。模型答复结束时仍 running/awaiting_input 的执行保活，界面显示“执行仍在进行”；可等、停止或用户接管，不能后台悄悄结束或隐藏为完成。后台作业如被用户明确接管，可结束本 Task 的 AI 控制，但该会话保留并撤销自动关闭权。

### 11.2 保留策略与关闭资格

| 冻结策略 | TaskFinishReceipt 后行为 |
| --- | --- |
| auto_idle（默认） | 只对 created_task、未接管、无活跃引用且 idle=confirmed 的会话请求逐个关闭；不是定时杀进程。 |
| ask | 显示有界收尾卡：实际 owned 终端、活跃/未知状态和“关闭可安全关闭的终端 / 保留 / 接管”；必要关闭审批与选择合并。用户未响应不默认关闭。 |
| keep | 保留会话，释放 AI 租约；记录保留原因。用户明确接管后转 handed_to_user，保留并不意味着 AI 下次可无条件继续输入。 |

自动关闭前须再次验证：SessionHandle 未变；ownership_revision 未变；无其他 Task/用户接管；无 foreground execution/inputwait；无已知 background job；无 transfer/forward/共享服务引用冲突；无待写输入；执行记录已sealed或有明确失败收据（partial时提示记录风险）；idle由受支持协议/服务给出confirmed。`session_interval`的 `interval_saved` 只结算记录，不授予confirmed idle；此类auto_idle会话保留，用户明确关闭仍走原关闭确认。不能按“10秒没有输出”、model_done、终端不在前台、Ctrl-C已发送或用户取消provider推定idle。

idle=unknown 时提示“终端是否空闲尚未确认”，保留并提供查看/接管/明确关闭；不循环弹窗、不永远锁输入。用户明确关闭可沿原关闭影响预检/确认承担业务影响，仍记录 unknown。created_task 的任务间命令间隔不触发关闭，只在本任务收尾后评估；同一任务不会每条命令开/关终端。

TaskCleanup 不调用 close_group，不移出 borrowed 原成员，不设置“只关组 view”，不降级身份。自动关闭一个 owned 会话后，组仍存在，当前 AI 对话仍绑定组并保留结果。用户显式关闭组时沿既有 GroupClosePlan 全成员快照/确认/部分结果/重试语义；取消确认不停止组 AI，接受后才阻新派发并收尾，不能因为任务自己的工作终端是可关闭的就省略整组影响。

正常 owned channel 清理只处理新 shell 和它的 lease；共享 transport 本身故障或 channel rollback 无法安全完成时，现底层可能把共享 native 标 broken 并中断 siblings。此时按各真实 SessionHandle 分别发布断线/unknown，不能承诺共享连接下源会话绝不受故障影响，更不能把这类共因故障伪装成“只关闭了工作终端”。

- fetch_url 复用现有工具卡，显示“获取网页”、具体域名/标题及“本机网络”来源；展示真实 HTTP 状态、正文和截断，不占用终端，也不借本机成功标记远端连通。卡片契约见 §6.7，助手外壳与 composer 不因该工具改变。
- 生命周期每次真实调用各有步骤卡：创建组、创建会话、必要等待、执行、输入/等待/停止、按需关闭。open_session 内部 ready/登记/呈现为进度，不显示虚构“附加”步骤。
- 会话组与会话卡片完全沿用既有布局、标题、成员操作、终端和输入方式。AI 持有控制权时，只有对应会话卡片变为只读；在该卡片右下角增加一组“AI 控制 • 只读”tag 与“接管”按钮，不新增顶部控制栏、底部输入栏、发送按钮或 AI 专用终端。滚动、选择、复制和搜索仍可用。这里的只读必须由普通输入准入实际执行，不能只显示标签：AI租约有效时，键盘、Enter、Ctrl+C、粘贴和IME提交不得进入PTY或排队等待接管；已知控制权下未接纳的UI输入不能解锁后补发，原生commit仍须在同一执行锁下复验。物理连接writable不等于普通用户可写，不能为了输入门禁隐藏真实控制标签。用户接管后撤销 AI 写入，移除这组标记，恢复原终端输入；不改变前台进程与输出，不影响其他会话卡片。
- tag 与接管按钮直接复用已有主题组件：HTML 使用 `.badge.accent` 与 `.button.secondary`，原生落地复用相应状态标记/次级按钮配方及主题语义色。不新增独立 AI 色值或局部控件皮肤。该组 tag 与按钮统一采用28px紧凑高度、11px字号、20px行高并居中；颜色、圆角、描边、阴影及交互态复用既有组件。
- PTY 内的命令输入、回显、执行和输出直接复用现有终端渲染与输入组件，不另做底层输入组件或上层封装组件，不按 AI 来源增加背景框、徽标、“AI 命令”行或额外过程文字。宿主不得为美化终端伪造写入 stream。ExecutionId、记录范围及 AI 来源保留在宿主元数据、工具卡和历史索引中，不改写原始 PTY 内容；历史查看复用既有 @log/历史页。服务层的输入租约与 fence 加在现有输入提交入口，不产生新的可见输入层。
- ask 的模式选路与必要审批放同一卡，信息含实际影响。用户改选了与当前工具不同的路径时，当前调用零派发并返回 requires_plan_change；下一 round 产生正确真实工具。选择形成一次性 grant，不再问相同选路，仍不能隐式把 run_command handler 变为创建/PTY 执行。
- 活动终端关闭后“查看记录”重开只读区间；缺口/记录已清理显示原因。任务模型答复已完成但 execution 仍活跃时保持续状态与控制入口。
- 最小窗下菜单、审批动作、停止/接管、composer 仍可达；正文与终端记录独立滚动，不能删实际目标/影响来腾空间。沿 V0.1.7 已冻结的最小窗口与紧凑审批契约，不扩大应用最小尺寸。

原型不等于 Zenit 原生验收。界面与交互须用当前构建的真实窗口验证，不能用其他环境或旧构建的结果替代。

## 13. 实施阶段与实际文件边界

实际依赖顺序为 A可行性 → B绑定 → C创建 → E1统一记录/目录 → D执行 → E2收尾 → F原生UI；G本机网络读取只依赖A/B的host接入与对话路由，可独立于会话创建、PTY和记录阶段实施。每阶段可用 fake service 验收核心边界，涉及真实 I/O 的阶段必须补真实 Local/SSH 或本机网络验证。

A 分为公共 host/Local 基础与远端默认 shell 集成能力两个门禁。前者通过后继续 B/C/E/G 和 Local 路径；远端成功协议门禁只限制相关 SSH PTY 能力的启用和成功交付，不使无关实现等待一个异常环境恢复。用户于 2026-10-29 确认本聊天提供的私钥缺失与跳板超时均为异常场景：验证错误分类、零后继派发、释放和可恢复 UI，不能反复要求修复该环境，也不能计为成功登录。成功 SSH 路径须以可用真实环境或项目受控实机 loopback 取得独立证据；缺少完整命令事件或安全提交条件时明确报告 IntegrationUnavailable，不再因缺少远端 helper 单独拒绝。

## 15. 发布阻断项、设计判断与未决边界

| 项目 | 当前结论与必须解决的条件 |
| --- | --- |
| host authority 和 provider 定义 | 现 API2 不支持无session目标的host工具；A/B阶段必须补全gateway/definition/receipt/审批/容量/主线程结果路由，保旧exec兼容。仅文档/提示词变更不算完成。 |
| 同 turn scope handoff | 必须用ConversationId汇聚旧结果、round boundary刷新新authority、解除self-join风险；owner变更不得绕过已派发ledger保护。未验证前不开放模型create_group。 |
| SSH 持续交互 | 原 shell 的默认文本集成与 OSC 133 开始/结束/退出码、同 channel 连续状态、输入回执及录制必须实证。不需要 private FD 或临时 helper；已有无事件且输入目标不明的会话不能盲注。`shell_reported` 不承诺防同 PTY 输出伪造，未通过的 shell/前台交互保持能力限制。 |
| 接管与native in-flight | fence只能阻止新写入/host排队字节，不能撤回已进入native的pending bytes。必须证明EAGAIN/partialwrite的排空或channel局部取消及user_ready门控；无证据不能立刻开放混写或abort共享transport。 |
| record durability | 现timeline/cast/archive不足以稳定execution interval；sidecar、start barrier和gap恢复是强制依赖。缺记录不启动PTY，新路径不得悄悄退为仅临时屏幕。 |
| foreground/background/idle | 首版仅对已验证集成支持的状态给confirmed；任意shell/TUI/job未知就保留并交用户，不用超时猜测。 |
| 任务完成 | TaskFinishReceipt由Supervisor生成；模型答完仍running不能关。unknown与handoff可结束AI控制，但不授予自动关闭权。 |
| 对话重启持久化范围 | 本PATCH强制持久化的是必要handoff/request去重、资源ownership、记录关联和执行回执；完整AI历史/Controls跨重启保存若当前未具备，不借本次扩展成全量存储重做。运行内迁移必须完整保留；恢复UI明确哪些原对话内容可恢复，不伪造已恢复。 |
| 工具和模型容量 | 新host池与原plugin池独立有界，provider限制前置核验；大组查询与绑定不能依赖固定16成员数组。旧每call16目标与exec参数不变。 |
| 本机网络读取 | fetch_url 随host池注册；实际连接地址/重定向/代理约束、凭据隔离、取消及有界提取须经G验证后开放。只覆盖本机公共网络读取，不承诺远端连通、认证站点、内网访问或完整浏览器能力。 |

已作出的保守设计选择：默认 auto/auto_idle；当前绑定内SSH实时来源建议reuse_only，保存主机静态来源仅new_only；Local限受支持zsh；unsupported交互明确失败/接管；Task与会话所有权分开；运行方式与权限独立；迁移为单向组身份。这些均可按实际实现证据调整细节，但任何变更都须继续满足本文用户已确定的不变量，不能以“实现方便”撤回真实工具步骤、记录、控制权或范围检查。


## 16. 全局历史会话与原会话回看

本节与§10共享唯一持久化/解析/租约/清理契约；原SPEC全文迁入，保留业务与视觉要求。

### 16.1. 用户可观察的结果

1. 右上角原闪电快速连接按钮改为“回看日志”，点击展开**全局历史会话列表**。列表独立于侧栏选中主机、当前 Tab 和活跃会话；所有会话与页签关闭、App 正常退出再启动后仍可找到持久记录。快速连接继续保留 `Cmd K` 等既有入口。
2. 点击历史记录，在现有工作区打开一个新的原有 Tab/内容页。使用原会话的终端内容、复合命令记录、页面结构、布局与菜单；只把 Tab LOGO 换为日志图标。不能用另一个精简日志阅读器代替原会话页面。重复点击同一记录聚焦已打开的回看 Tab。
3. 终端内容只读，选区、复制、搜索和导出沿用原页面。进入日志模式始终显示原有顶部时间滑轮卡片；鼠标滚轮/触控板在正文自然翻阅，顶部滑轮、阅读位置和真实时间锚双向同步。记录的是当时发生的内容和状态；打开记录不执行命令、不建立网络连接。
4. 主机配置仍存在时，回看 Tab 右键保留“新建同主机会话”和该配置支持的转发入口。它们解析当前主机配置，独立新建真实连接/后台 owner；关闭回看 Tab 不停止新会话或转发。
5. 活动会话执行 `@log` 时，在原 Tab 原地进入日志模式并换日志图标，复用与归档回看相同的顶部滑轮及滚动定位规则；`Esc` 恢复实时内容与原图标。它与“打开已结束记录”是两条入口，不能把活动内存时间线当作全局持久归档。

“原样复原”指在保留范围内复原已记录的内容、内容结构和展示参数，并沿用现有会话 UI。密码、私钥材料、传输实例、监听端口、进程和网络连接不能由历史记录自动复活。已结束记录没有可返回的实时终端，`Esc` 只关闭最上层菜单/搜索等浮层，不退出成可写会话。

#### 16.3.1 现有 cast 与 rich command 记录的准确边界

[Timeline](../../src/vt/timeline.zig) 输出 asciicast v2 header 和三类事件：`o` 是收到的终端输出，`r` 是录制的列/行尺寸，`a` 是 JSON 编码的 [ApplicationRecord](../../src/host/terminal_service.zig)。`a` 含原命令记录 ID、源 owner/generation、时间、可选 `anchor_row`、命令文本、输出和 pending/success/failure。

[terminal_document.zig](../../src/ui/terminal_document.zig) 恢复这些应用记录时以源 owner/generation 和记录 ID 区分，更新同一条记录而非重复追加，保持与 VT 行的顺序；记录卡片不把应用结果重新灌入 VT。已有测试覆盖 ANSI、resize、离屏搜索行、应用命令结果更新和跨 generation 身份。这说明已有复合终端记录的基础，不能把它描述成只剩纯文本。

但这些事件不是所有 shell 命令的完整语义数据库：它们不自动提供每条命令的 cwd、退出码、可信提示符状态、原页面布局、连接生命周期和传输任务。`r` 是终端网格尺寸，不是窗口/分栏布局。当前 rich 记录和录制都有容量边界；未保留的历史与缺失的字段不能从 cast 推算出来。旧记录仅能在原会话页面中展示实际已保存的内容，并标明“旧版记录，部分展示信息未保存”。

### 16.4. 最小持久化契约

身份、基数、RecordingId映射、manifest提交与完整性以§10.0为唯一契约；本节补充历史展示和旧格式兼容字段，不引入独立sidecar。

下列字段和 API 定义持久化契约；接口名称以当前源码为准。继续复用 cast、索引、VT 与终端 document，不引入第二套记录引擎。

#### 16.4.1 身份和关联

| 身份 | 用途与规则 |
| --- | --- |
| `ArchiveKey` | 每次可独立回看的归档的持久、不可变、不复用的键；新记录生成并保存。不能使用进程内 SessionId、TabId 或主机显示名称充当它 |
| `HistoryId` | 每个已打开回看内容的运行身份，沿用 `ContentOwner.history`；分配自独立 allocator，不冒充原 SessionHandle，不授予网络能力 |
| `ConnectionId?` | 可选稳定资产关联；从现有 `saved_connection_id` 转换到类型化 ConnectionId。只定位当前保存配置，不从 host/user、侧栏序号、地址或名称猜匹配 |
| 源 owner/generation | 只保存在归档记录中用于事件关联与诊断；禁止据此查询已失效服务、派发命令或停止新资源 |

旧记录使用现有 `{id, started_ms, cast_path}` 组成兼容查找键；首次加载可以得到稳定编码的 legacy `ArchiveKey`，不改写原 cast，也不把旧 id 单独视为全局唯一。新旧键都以当前受管数据根为域；独立测试实例的数据不混合。重命名资产保持关联；删除后新建同名/同地址资产不能继承旧关联。

#### 16.4.2 保持旧索引可读的 sidecar

唯一 `.session.json` manifest同时容纳§10的recording子对象和本节展示字段。保留现有 TSV 的 8/10 列读取与写回契约；现有 parser 会拒绝多余字段，不能直接追加列声称向后兼容。为新记录增加与 cast 同 stem 的版本化 `.session.json` sidecar，按确定规则定位。旧索引仍指向 cast；sidecar 缺失按 legacy 能力处理。避免为本 PATCH 改造全局数据库。

| 分组 | 最小字段/语义 |
| --- | --- |
| 版本与身份 | `schema_version`、`archive_key`、来源/provider 标识、源 owner/generation；可选 `connection_id`、录制时配置 revision（仅说明来源） |
| 列表元信息 | 会话原标题、录制时主机显示名称/非秘密 endpoint 摘要、开始/结束时间、时长、真实结束原因与可选 exit code；未知值保持未知 |
| 内容清单 | cast 路径、字节长度、可校验的内容标识；若恢复需要 checkpoint/附属文件则逐项列出；路径仅允许受管根内相对路径 |
| 内容完整性 | §10.0统一的 `coverage/replayability`、实际保留起止时间、丢弃量/首错、录制是否从会话开始启用；与“进程已关闭”分开 |
| 原页展示 | 内容/布局版本、终端初始及结束 cols/rows、当时 cwd（若已可信获取）、时间戳显示、终端字体/字号/行高及原页支持的布局参数。新记录不写主题引用或配色快照；旧字段仅兼容读取，不用于覆盖当前全局主题。 |
| 状态摘要 | 已记录的 shell/连接结束状态、记录卡片状态和必要展示标志；都是历史事实，不是当前 live 状态 |

展示字段从原会话实际模型采集，不靠截图猜测。使用现有 renderer 的布局 schema，只持久化原内容页已有结构。若页面确有由多个内容成员组成的布局，成员必须显式引用自己的归档记录和保留范围；不能把一个成员的 cast 复制成全部 pane，也不能把无关活动会话自动加入。没有记录的旧布局保持缺失提示，不能伪造“原样”。

sidecar 不保存密码、私钥正文、connect-time secret、socket/channel、凭据 cache、正在运行的传输对象或监听器。凭据引用也不用于离线读取；发起新连接才经当前配置 resolver/vault 使用。原 cwd 是展示元信息，不在历史打开时 `cd` 或执行启动命令。未知 schema 不覆写原件；仅独立可读的旧cast可走legacy_unverified展示，不能跳过manifest中的必要baseline/完整性校验，不授予AI精确区间能力。

#### 16.4.3 关闭、退出与发布顺序

1. 原会话进入关闭流程后拒绝新输入，按现有生命周期取得 worker/PTY/应用记录最终收据；排空录制队列。采集原页展示快照必须早于 UI 销毁，文件 IO 继续由后台 owner 执行。
2. 在同一归档键下准备 cast 与 sidecar 的临时文件，逐项写完、关闭并按持久化要求同步后原子 rename；最后原子发布索引条目。只有完整的可发布清单才标记成功；索引发布失败不留下假成功条目。
3. 关闭 Tab、关闭窗口、最后窗口退出、正常 Quit 均等待已接受的归档任务得到成功/明确失败收据，不能先释放 Timeline 或直接退出。相同关闭收据重复到达只 finalize 一次，避免索引重复；失败不把已释放进程误判为仍在线。
4. 若存在已成功保存的部分录制，保存真实可读内容并标 partial/retained；若没有可读文件，记录 unavailable 原因并禁用打开，不能写空 cast 冒充成功。录制从未启用时显示“未录制”；不补造终端内容、不悄悄更改用户录制配置。
5. 为 unavailable 元信息保留一个小型失败目录项（由 sidecar 管理，不向旧 TSV 写不存在的 cast）。列表加载时合并新元信息与旧索引，按归档键去重。成功后只保留一个目录事实，重试不能生出第二条会话。

复用 `session_archive` 的索引互斥与原子替换，但多文件发布需要明确提交边界：启动时只扫描本应用归档目录中有界的 pending/sidecar 集合，处理未索引成品和失败收据；不遍历用户文件系统。已发布 cast 缺失时保留错误状态，未发布临时文件按现有保留策略回收。异常崩溃不能保证最后一段尚未落盘的输出；只恢复已提交的数据并标“异常结束/可能不完整”，不承诺断电零丢失。

索引和 sidecar 使用现有私有目录/文件权限与标准数据路径。原子 replace 不等同于整组多文件事务；故障注入必须覆盖文件提交后、索引提交前及索引失败路径。保留策略使用现有设置，不另添永久保留开关；到期清理同时处理索引、sidecar 和其清单，不把到期数据无限累积。

### 16.5. 全局列表与打开流程

新增应用级“回看日志”动作/入口，required services 为空，不要求有当前会话、侧栏主机或 live terminal；既有 `open_history/@log` 仍针对活动终端。优先扩展 `HistoryHost` 与 `Model`，保留主机菜单来源过滤作为同一列表模型的可选范围。

列表默认全部来源、结束时间倒序，搜索仅查标题/主机/用户/endpoint 摘要等索引元信息，不为列出结果解码全部 cast。空态、加载失败、搜索无结果和未录制分别表达，不能显示原型示例数据作为真实记录。

打开记录按以下顺序进行：捕获 `ArchiveKey + catalog revision` → 查找当前窗口已打开的回看 Tab（有则聚焦）→ 获取整组文件 read lease → 后台读取、校验并构建归档 document/Timeline → 主线程以原会话内容 renderer 挂载 → 成功后关闭列表并移交数据/租约。失败保留列表与选中行，显示具体原因，不挂载空页。加载期间重复点击合并到同一个任务，取消/关闭窗口后丢弃旧 generation 的完成回调。

将 `openArchivedSession(host,user,history)` 扩展为接收归档描述/内容的版本化入口：包含归档键、只读内容 owner、可选资产关联、展示快照、完整性信息与被持有的数据。尽量复用 `TerminalViewNode`、`terminal_document` 和原菜单挂载流程，避免另造页面。原记录里的 source SessionHandle 仅用于解析历史事件；读取、搜索和完成回调在控制器边界核对新的 HistoryId。若内部 VT/document 接口仍需临时 SessionHandle，它只能用于隔离的解码实例，不注册真实连接能力，不要求为本 PATCH 改写所有 terminal service 的 owner 类型。

默认打开保留范围最后一个真实帧的末端阅读位置，顶部滑轮同步到实际可浏览末端；滚轮和原时间滑轮共同回看保留的早期内容，具体定位规则见§16.7；录制网格尺寸参与解码和断行，页面随当前窗口自适应，不把旧窗口物理像素强加到当前显示器。时间戳、字体、行高等已保存展示参数在兼容范围恢复，字体不可用时走现有 fallback 并提示。主题始终取当前全局配置，打开中的回看页随全局主题刷新，刷新不重置阅读位置或覆盖已恢复的字号、行高和布局。VT 默认/索引/RGB 的类型语义必须保留，不能在解码时统一压成录制时的 RGB。

去重以每个窗口 `ArchiveKey → TabId/加载任务` 为界，关闭回看后释放映射与所有 lease。不同窗口可以各自查看同一归档，各持自己的只读内容 owner；不增加强制跨窗口抢焦点行为。

### 16.6. 原菜单、只读内容与独立网络操作

沿用原 Tab 菜单结构、顺序、图标和动作目录；按每个动作的目标评估能力。不能在 archived 分支整体删掉菜单，也不能给回看内容伪造 terminal/forward live binding。

| 目标 | 行为 |
| --- | --- |
| 回看内容（HistoryId） | 重命名当前 Tab、关闭、关闭其他 Tab、搜索、复制、滚动、记录导出及原有外观操作，按原入口和权限工作；重命名 Tab 不篡改已归档命令内容 |
| 只读终端 | 粘贴、键入、补全执行、广播、向原进程发 resize/命令等写操作拒绝；键盘/程序化入口也必须执行同一门禁 |
| 关联配置（ConnectionId） | 保留新建同主机会话、编辑配置、该 provider 支持的转发等既有入口；执行前重新解析当前配置/修订并复验能力，配置失效时给出原因 |
| 旧网络/传输状态 | 仅展示当时摘要；不把旧连接详情伪装成在线，也不恢复传输或原监听端口。需要网络的原菜单动作仍保留其位置和语义，经明确用户动作创建独立操作或给出真实不可用原因 |

“新建同主机会话”从当前保存的配置走 Registry/SessionHost 工厂，得到新的 SessionHandle、generation、认证挑战、worker 和资源；不克隆归档的失效 handle。原配置被改名仍可找到；被删除、provider 卸载/不支持时禁用并显示原因。Local 沿用 Local 工厂；无 ConnectionId 的临时/旧记录不能凭显示名冒认保存配置。

转发先复用 [现有后台入口](../../src/ui/socks_background_host.zig) 与 [ApplicationHost](../../src/ui/application_host.zig) 的 `.socks_background` 创建路径：当前已实现范围是 provider 声明并支持的 SOCKS5，沿用其配置、认证/host key、端口冲突、暴露确认和管理界面；不把它扩大成新转发产品。资源拥有独立真实后台 SessionHandle/operation/取消源和 listener，归档键只作为来源说明。已有同配置后台转发按当前管理规则进入管理，不偷偷创建冲突监听器或接管其他 owner。

关闭回看仅销毁回看 UI、解析任务和 read lease；后台资源由自己的停止/关闭流程管理，并继续出现在既有全局后台管理入口。打开新会话、关闭它、关闭回看三者分别验证，不借活跃终端转发的 SharedProvider 来冒充独立后台连接。菜单展示与执行同时校验 owner、配置 revision、能力 revision、权限和 handler；过期菜单拒绝派发并要求重新打开。

### 16.7. 日志阅读位置、活动 `@log` 与键盘行为

#### 16.7.1 正文与顶部滑轮共用真实阅读位置

以下 `HistoryReadingPosition` 是待实现的 UI 内部契约，不是新增归档字段或另一套记录引擎。在原有 Timeline、帧和 document 之上，每个日志 Tab 仅持有一份阅读位置：内容 owner/文档 revision、实际保留 frame、对应逻辑 row（含必要的行内/像素偏移）及其真实 time anchor。顶部滑轮、正文滚动和搜索定位都消费与更新这份位置，再由同一次状态更新派生可见内容、进度及时间标签；不能各存一套互不对应的百分比或行号。切换 Tab 保留各自位置，关闭后按原生命周期释放，不增加跨启动阅读书签要求。

浏览范围由实际保留的帧及其 scrollback/document 共同确定。当前帧中的离屏行必须能读，跨帧时只定位真实存在的帧与行；按既有 row identity 与帧关联处理共享行，不能把每帧视口盲目拼接、重复显示同一段 scrollback，或删掉同一逻辑行在不同帧中实际变化的内容。进度按这一保留文档的逻辑行和可浏览范围归一，窗口可见行数/布局参与末端计算；行内偏移供平滑阅读。实现沿用已有索引与 renderer，不借本次交互修正重构记录引擎。

正文使用鼠标滚轮/触控板自然连续翻阅实际记录，保留小幅输入的余量，不把不足一行的触控板输入全部丢弃。每次滚动后，由真实位置同步顶部 fill、位置标签和对应的时间锚；拖动滑轮则把目标进度解析为同一文档中可达的 frame/row，再滚到该处，fill 反映解析后的实际位置。禁止仅改变百分数、时间文字，或截取固定条目替换内容来伪造翻页。HTML 原型以实际 `scrollTop/maxScrollTop` 驱动同一阅读状态；原生映射到 frame/row/像素位置，不照搬 DOM API。

时间取对应行的已记录时间，缺少行时间时可明确标为该真实帧时间；两者均未知时显示未知。不得按会话原始起止时间线性估算没有保存的内容，也不得把滑轮百分比写回为归档事实。旧版仅保留视口帧时，只在真实保留帧/行间定位，明确未保存 scrollback；ring 淘汰或部分归档的进度只覆盖实际保留范围，缺口不插值、不补造命令。正文不足一个视口、只有单个可达位置时，固定在实际末端并禁用滑轮定位；时间仍显示唯一真实锚或未知，不伪造时间跳转。

搜索命中将共享阅读位置定位到实际 frame/row，并同步滑轮；关闭搜索保留已定位位置。resize/自动换行后以稳定逻辑行锚重算布局和可浏览边界，必要时夹取到最近仍存在的位置，不因旧像素偏移变化跳到别的内容。顶部/末端滚动均夹取到实际范围，读到末尾仍处于日志模式；未有新真实内容时不能继续推进时间。选区与复制仍取当前帧及其 document，搜索或滚动改变位置时按现有规则清理失效选区。

#### 16.7.2 活动与归档入口、只读门禁

`@log` 继续在原 Tab 读取活动终端自己的保留历史，不替换 content owner，不创建第二条持久归档；与归档共用§16.7.1阅读逻辑。进入时冻结本次阅读文档与位置，实时后台接收/录制按原机制继续，新输出不抢当前阅读位置、不改变当前阅读范围。退出后再次进入，才以最新可用的真实保留内容建立阅读视图。原型与原生均不得把活动输出写入当前只读阅读页制造跟随末端。

进入日志后禁止该阅读视图发起用户写入；仍在运行的AI执行与protocol source按§10.4独立校验，不因阅读状态停机或清空其他来源输入；历史帧变化或退出会触发 Tab 图标更新。活动日志中的 `Esc` 在最上层浮层先消费；没有浮层时结束活动日志选择，恢复最新实时视图与原 provider 图标，同时隐藏顶部滑轮卡片。归档始终只读并保留顶部卡片，`Esc` 只关闭浮层，没有可恢复的旧进程。不能因某一历史帧缺失而显示日志图标后仍向实时终端写入。滚轮、拖动、搜索和 resize 仅更新回看文档/UI；不得向旧 owner 派发命令或 resize，不触发网络、URL 自动打开、剪贴板写入等副作用。

#### 16.7.3 列表与键盘焦点

全局列表打开时焦点进入搜索/首个可操作项，方向键移动、Enter 打开、Tab 遍历真实控件，Esc 关闭并恢复触发入口焦点；小窗口列表内部滚动、头部与关闭按钮可达。历史加载可取消，错误后保留焦点。右键菜单与键盘触发同一捕获目标，不因为当前活动 Tab 改变而操作另一个主机。原型与原生实现均检查这些行为。

### 16.8. 读取租约、保留策略与性能边界

复用 [RecordLease/RemovalGuard](../../src/vt/session_archive.zig)：先获取 lease 再读取，不能仅 `replayPath` 检查后裸读。租约覆盖 cast、sidecar、需要的 checkpoint/附件；当前 Local stem 已共享 cast/raw/checkpoint 租约域，新增 sidecar 也必须进入同组；SSH 同样按显式归档清单分组。保留/显式清除必须先原子预留整组移除，遇到读者延后清理；不能先删一半再报告忙。

当前 `RecordLease.readAll` 冻结 inode/长度并检查变化，适合已完成归档；不把仍写入文件当作关闭归档。回看 Tab 的 lease 生命周期覆盖读取/按需加载和导出需要，错误/取消/关闭均释放，导出持独立 lease。清除和归档 append 并发时保留后发布的新条目。

本 PATCH 不为超大日志提高无界上限：沿用现有 cast 读取与解析 Timeline 各自 128 MiB 的硬限，明确两者分别计费；一次只解析被选记录，列表不持有全部录制，后台任务并发及队列有上限。列表每批最多 100 条、虚拟/分批渲染，索引现有 16 MiB 上限错误必须明确显示。按既有资源预算限制同时打开的已解码记录总量，达到预算时提示关闭记录，不静默截掉开头伪装成功。具体全局预算在实现时从现有配置/常量确定并记录，不新增调优页面。

解码和文件 IO 离开 UI 线程，带取消 token/窗口 generation；关闭应用不再发布 UI 回调。搜索使用已有文档快照并保持预算；损坏、不支持版本、空记录、文件缺失、超限分别报错。ANSI 解析只恢复显示，不能把历史控制序列变成剪贴板写入、URL 自动打开或终端输入等副作用。

## 17. 审批、顺序与输入控制契约

- 当前串行回合先显示对应工具请求的审批卡，批准后才派发并显示执行步骤；准备参数、等待审批不显示为执行中。审批卡与后续执行占用同一消息位置，不在对话尾部复制审批面板。
- 模型正文与工具步骤按实际输出顺序交错排列；用户消息保留右侧 75% 最大宽度。正文、步骤卡、审批卡、任务状态条统一消息区左右各 14px 留白；卡片内距不作为额外外层缩进。
- 等待或过期均暂停当前调用、后续工具与下一轮模型请求。过期保留原请求，只能由用户显式重新确认或拒绝；重新确认仅恢复待审批，仍须另行批准，派发前复验目标、参数、权限及输入状态。不自动重申请。
- 处理用时排除审批等待；未批准、未派发不显示命令执行耗时。执行卡的命令运行证据仍以真实 execution snapshot 为准。无活动执行时，不因存在任务终端而显示“执行仍在进行”。
- 组内会话卡保持 11px 圆角、4px 间隙，无整圈边框；焦点通过头部底色反馈，拖拽结束不得恢复描边。
- 可编辑参考：`../UI_V3/ai/conversation.html?approval`、`?approval&expired`、`../UI_V3/ai/host-approval.html?kind=terminal_command&expired` 与执行整机参考 `?state=ask-expired`。

### 17.1 逐段时间线

显示列表按同一事件队列记录并渲染，不按内容类型重新分组。连续、未被其他事件打断的同一输出段内可追加流式字符；切换思考／正文、出现新工具调用或开始下一轮 provider 输出时，关闭前一段并追加新的独立条目。工具声明只记录参数准备；实际进入宿主处理流程时才分配工具条目位置，避免乱序到达的参数片段提前占位。工具的后续状态只更新原调用条目，不重新插入、不移动后续模型消息。每段思考分别保存展开状态、内部阅读位置及耗时。回合完成、历史复制、窗口尺寸变化均保留条目顺序；网络重试仅撤回当前失败尝试的内容，不删除既有工具结果或宿主事实。

可编辑顺序参考：`../UI_V3/ai/conversation.html?timeline`；使用 `?timeline&stream` 可在产品画布外逐事件推进，检查各段只追加到对应位置。

### 17.2 终端只读准入

AI 持有输入租约时，SSH Provider 在接纳粘贴、保存 pending 数据或推进 sequence 之前取得并校验 execution guard。拒绝的内容不进入待发送队列。TerminalSurface 对已知 AI grant 拒绝文字、按键、粘贴、IME、鼠标报告和可信编辑；WorkerBusy 不隐藏已确认的控制状态。未接纳文字仅可保留为本地草稿，待发 Enter 与粘贴取消，不在解锁或 pump 时自动补发。显式接管须实时复验 grant；选区复制与滚动保持可用。

## 2. 三条输入路径与单事件仲裁

### 2.1 共同输入上下文

每个输入事件携带`eventId, SessionHandle, focusTarget, inputRevision, composing, terminalModeRevision, alternateScreen, promptContext, cursorAtEnd, selection`。一个事件只有一个消费者，`handled`后不得继续送Shell、广播或快捷键处理。

优先级固定为：IME组字→当前模态/快捷键捕获→聚焦编辑器/最上层锚定菜单→终端辅助候选或应用指令→VT模式编码及TerminalService。仅提前仲裁产品明确的应用快捷键；不能普遍截住普通Tab/Control或TUI输入。失焦取消按键捕获；按键释放仍属于原捕获操作，不能关闭菜单后把同一按键释放误派给新pane。

| 路径 | 进入条件 | 输入与IO边界 |
| --- | --- | --- |
| 普通Shell行历史 | 非空、当前可写且聚焦、可信prompt编辑态、行末、无选区、非IME/alt-screen | 仅查本应用观察的该owner提交记录；不发AI、不读取任意shell history文件、不做远端往返 |
| 行首`@` | 同一可信prompt的行首进入本地命令编辑 | 本地目录/解析/参数；Enter经控制器执行应用动作，不把`@`动作作为Shell字节 |
| 显式资源/路径 | 用户已进入应用指令参数或明确资源选择流程 | 按本机/远端实际服务读取，标来源/缓存；普通Shell Tab不进入此路径 |

可信prompt必须来自该session的Shell集成/命令边界和应用维护的草稿、光标及模式，不能只看最后一行`$`/`%`。必须提供与prompt token和inputRevision绑定的安全草稿替换能力；采纳复验后只改原输入，不发送Enter。前缀可安全追加的情况与整行替换分开，不能按UTF-8字符数发送DEL猜测ZLE状态、宽字符、用户键位或多行输入。

Local zsh须接通受控Shell集成以获得prompt/command/cwd及安全编辑边界，保留用户启动配置和zsh原生Tab；SSH按实际Shell集成声明能力。无法证明可替换时关闭辅助并原样输入，同时显示功能受限的可查原因。缺此能力不能作为V0.1.5正常态的长期替代，更不能对执行中程序注入“替换输入”控制字节。

### 2.1.1 固定实施方案：zsh/ZLE私有编辑通道

本节为实现方案，依据本机zsh 5.9的`zshzle(1)`、`zshmodules(1)`及`add-zle-hook-widget`实际能力；原型规定可见交互，没有规定此物理协议。首个适配器固定使用**会话内zsh集成＋私有Unix socket＋`zle -F -w` widget**。不用DEL修补真实行，不向PTY插入私有控制按键，不改用户键位，不把普通技术方案留给用户选择。当前未编码、未启动PTY或运行spike；以下接口是本版待实现契约，不能据此声称原生已经可用。

1. **启动与配置保留**：Local仍由V0.1.2创建`/bin/zsh -l -i`。宿主为该session生成0700的临时bootstrap目录，仅含`.zshenv`包装器；记录原ZDOTDIR是否设置及原值。包装器先恢复原ZDOTDIR，再按原规则读取用户原`.zshenv`，保留其中对ZDOTDIR/RCS的修改，让后续系统/用户zprofile、zshrc、zlogin继续正常加载。只在交互zsh注册一次precmd初始化钩子；首个precmd时用户配置已经完成，再安装本节hooks。禁止修改用户启动文件、全局环境或持久bindkey。用户配置禁用RCS、覆盖初始化hook或所需模块不可用时给明确capability失败，继续原生终端。
2. **双向通道**：宿主在当前应用0700运行目录下创建该SessionHandle专用的0600 Unix socket。zsh用`zsh/net/socket`连接；宿主校验本机UID及Darwin peer PID确为该session的zsh子进程，再校验随机nonce、session/generation和协议版本。IO仍由所属worker承担，UI只调控制器。`zsocket`本身不提供设置非阻塞/close-on-exec的参数，不能把`syswrite`直接称为非阻塞：随集成包提供匹配受支持zsh ABI的小型`zw_ipc`加载模块，在该zsh进程内对本模块连接fd设置`O_NONBLOCK`和`FD_CLOEXEC`，仅暴露本连接的prepare/close，不提供任意路径/文件访问；外部子进程设置close-on-exec不能代替父进程设置。模块加载/flag验证失败即safe_replace不可用。zsh随后以`zsh/system`的sysread/syswrite做有界分块读写，保未写余量/字节计数，EAGAIN返回编辑器而非忙等；读侧`zle -F -w fd widget`收到控制或drain-credit时继续冲刷，队列满撤销增强而不阻普通终端。以`zle -N`注册私有widget，在编辑器安全上下文处理请求；修改后调用`zle -R`，控制帧绝不进入PTY输出、VT、记录或Shell命令解析。preexec/line-finish撤销编辑token，preexec关闭控制fd，下一precmd重建；普通exec子进程不继承可编辑控制连接。
3. **真实编辑快照**：通过`add-zle-hook-widget`追加line-init、line-pre-redraw、history-line-set、keymap-select和line-finish钩子，保留并先调用已有hook。以`BUFFER/CURSOR/MARK/REGION_ACTIVE/KEYMAP/CONTEXT/PREBUFFER`读取真实ZLE状态；只有PS1/start上下文、非补全/搜索临时编辑、行末且无选区满足普通候选门禁。快照有promptToken、bufferRevision和generation，内容或游标/模式变化才增加revision并发布，不能用UI预测草稿代替。原生Tab、历史导航、vi/emacs键位仍由zsh处理；hook只观测，不重绑这些键。
4. **原子替换**：用户采纳时先冻结该owner新的普通输入派发，取消旧候选，发送ReplaceDraft。widget在执行瞬间复验token、revision、当前BUFFER/CURSOR/KEYMAP及`PENDING==0 && KEYS_QUEUED_COUNT==0`，存在尚未消费的终端/内部按键即拒绝busy_input。Darwin待输入检测必须在非UI验证中实测可用，不将不支持时恒0当证明。通过后在同一次widget调用直接赋BUFFER、按zsh字符单位设置CURSOR到行末、清选区、增加revision并回ack；不调用accept-line、不追加CR、不发执行键。UTF-8字节与zsh字符索引显式转换，不按字节数删宽字符。
5. **输入与ack仲裁**：成功ack包含operationId、旧/新revision及替换后的真实buffer/cursor；UI核对后才宣告采纳成功。pending期间后续普通文本保持有界队列，成功后按原顺序恢复；Enter等提交事件必须仍归原owner并重新经过最新输入状态，失败/超时不得把其自动补交给未知buffer。Ctrl+C等中止操作可立即取消pending并撤销trust，按VT原语义只派发一次。拒绝保原输入；用户已经改变内容时不自动重试旧采纳。更换session/generation丢旧队列并给可读原因。
6. **应用指令分支**：空PS1编辑行收到首个`@`时先暂存该字符，发BeginAppDraft；widget按同样token/revision、真实空BUFFER、模式及待输入条件复验，返回draftLease才进入本地指令分支，不能仅凭UI缓存的空行抢走按键。pending期间有界暂存后续文本，拒绝/超时保可恢复草稿并说明，不自动回放为Shell命令。持lease时原ZLE BUFFER保持空，目录/路径/IME用现有终端锚定编辑层展示，字节不送Shell；prompt撤销、真实BUFFER变化或generation变化即撤销lease。业务Enter复验lease后只提交解析后的UiCommand；完成后EndAppDraft释放lease、移除本地草稿并请求同一prompt重绘。`@@`经同一ReplaceDraft将真实空BUFFER设置为一个字面@，成功ack后退出本地分支、恢复按序普通输入；不追加CR。当前prompt标为literal分支直到提交，之后字符不重新误触发应用目录。Esc恢复本次补全前的本地草稿；失效/断开保可恢复文本，不把它回放成Shell命令。

| 协议消息/限制 | 固定数据与结果 |
| --- | --- |
| 帧与所有权 | 版本化长度前缀帧；头含version/session/generation/nonce/messageSequence/kind/payloadBytes，payload为长度明确的字段和原始UTF-8文本，不用eval、Shell引用或JSON代码执行。单帧上限128KiB、可观察buffer上限64KiB；超限只停增强并给原因，不截断用户实际终端输入。zsh编解码辅助函数使用局部byte模式，不能改变全局MULTIBYTE或ZLE字符索引 |
| Hello/Capabilities | 握手2秒deadline；公布zsh版本、PS1观察、真实buffer替换、待输入检测和模式能力。缺任一替换前提返回unsupported(reason)，只观察OSC边界不等于可改buffer |
| EditableSnapshot/Revoked | 含promptToken、bufferRevision、真实buffer/cursor/selection/keymap/context和单调序号。每prompt只保最新未消费snapshot，可合并；Revoked和替换终态可靠，不与普通输出竞争到丢失 |
| BeginAppDraft/EndAppDraft | Begin含operationId/expectedToken/revision并要求真实空BUFFER，成功返回绑定同prompt的draftLease；按Replace相同500ms deadline和幂等结果处理。End匹配lease后只释放本地指令占用并`zle -R`，不accept-line；`@@`改BUFFER必须走Replace确认，不能把本地草稿逐字补送PTY |
| ReplaceDraft/Ack/Rejected | 请求含operationId、expectedToken/revision、expectedBuffer/cursor及replacement；同prompt最多一个pending。结果为applied(newRevision,真实buffer/cursor)或stale_prompt/revision_changed/busy_input/mode_changed/unsupported/integration_lost。ack必须来自widget实际赋值完成，不把worker接收成功当替换完成 |
| 取消/超时 | 本机ack deadline500ms；超时撤销trust并请求新snapshot，不重发替换或Enter。同operation幂等保留最后结果，晚ack只更新其已确认结果而不执行旧输入。恢复前必须重新确认真实buffer；连接失效先恢复基本VT输入，旧提交动作需要用户重新触发 |
| 关闭 | 清ZLE fd handler、关闭本端连接、撤销token并释放session临时目录；已在处理的旧代结果只清理，不向新进程安装hook |

SSH不假定远端prompt形状或shell种类。复用同一TrustedEditProvider接口，首个远端适配器同样为实际支持所需模块的交互zsh；连接准备阶段通过该session的独立exec辅助通道探测真实login shell/版本/模块，未支持则照常开启原shell并给增强能力受限原因。支持时，辅助通道在远端以umask077创建本连接专属临时目录和0600 Unix socket，部署有版本/大小上限的同一bootstrap与纯zsh relay；relay以`zsh/net/socket`和`zsh/system`、`zsh/zselect`转发私有长度帧，其stdout专供协议，不能混入普通诊断。该PTY channel的exec请求通过严格Shell quoting仅传受控绝对路径与随机nonce，启动已探测zsh的`-l -i`及临时ZDOTDIR包装器，仍按第1项保留用户启动配置；不要求服务器接受ZDOTDIR环境请求、不把bootstrap文本粘入终端、不安装全局启动脚本。远端0700目录/0600端点、同SSH账户及nonce/session/generation握手共同限定配对；relay只接本session，一次连接的旧端点不得配到重连新generation。模块/部署/权限/握手失败清临时资源并降级该会话增强，已打开PTY继续原生输入；无足够能力时不能显示“可安全替换”。

SSH通道仍经其原owner的IO执行者保序驱动，不借其它SSH session或SOCKS、不中转PTY控制帧；私有通道断开只撤销trust，不连带杀正常Shell。远端同时验证`zw_ipc`模块与其zsh ABI/OS/架构匹配，只部署受支持且摘要校验通过的构建产物；不在用户远端临时编译或下载未知模块。远端替换/Begin的ack deadline为`clamp(4×当前真实RTT,500ms,2s)`，RTT未知取2s，不用本机500ms硬套高延迟连接。关闭/重连负责释放relay/channel并清理其临时文件；清理无法确认时记录cleanup_unknown，不能为删除目录发未经归属校验的任意Shell命令。未支持shell保持基本VT/原生Tab，不以屏幕文本猜buffer；其增强正常态只有对应安全适配器接入后才可验收。该限制是协议能力条件，不要求用户切换所有SSH资产的默认shell。

非UI实现须在真实Darwin PTY和交互式zsh/ZLE验证：系统`/bin/zsh`加载`zw_ipc`、fd flag与exec不继承、默认及自定义ZDOTDIR启动、已有hooks/bindkey、emacs/vi、原生Tab/历史导航、多行PREBUFFER、中文宽字/组合/emoji、执行中程序/TUI；再验证PENDING竞争、BeginAppDraft与`@@`握手、EAGAIN/队列满、拒绝、丢/晚ack、超时、Ctrl+C与退出。验证应证明真实buffer、显示及命令执行次数一致，不能只mock ReplaceTrustedDraft返回成功。SSH支持的协商/安全通道、模块ABI与高RTT deadline单独验证；未支持shell不得显示可替换候选。本轮只确定设计，不声称已通过这些门槛；基本输入不依赖增强协议。

### 2.2 普通本地历史候选

匹配前缀或连续字符串，最多6项，不使用子序列/fuzzy代替需求。相同命令合并为一条，维护使用次数与最近提交时间；原型未规定精确排名，本版实施确定为前缀优先、之后连续字符串，类内最近使用优先、次数用于同新鲜度排序，最后用稳定记录ID破同分。只从真实观察到的提交入库，导航、候选文本、应用`@`动作、IME中间态和收到的终端输出不能被误记为用户命令。

| 输入/状态 | 必须行为 |
| --- | --- |
| query非空有匹配 | 自动出现，焦点仍在原终端；不要求先按快捷键 |
| ↑/↓ | 仅移动候选高亮并使当前项可见，不改变原输入、不送Shell |
| → | 仅在可信行末且无选区时采纳高亮命令，原子更新草稿、增加revision、立即关闭，不执行 |
| 鼠标主键点击候选 | 复验捕获owner/generation/revision，采纳并关闭，不执行、不切其它pane |
| Enter | 关闭候选，将**当前原输入**提交Shell一次；不能先采纳高亮再执行 |
| Tab/Shift-Tab | 关闭候选后原样交Shell；继续zsh/远端原生Tab行为 |
| Esc | 保当前输入，记录同owner+generation+inputRevision的抑制，不按定时器重新弹出 |
| 显式⌘; | 在仍满足门禁时重新查询当前草稿，解除本次抑制；不能为不可信输入绕门禁 |
| 清空/零匹配/采纳/提交/离开行末/外点或失焦/切pane或tab/只读或断开/IME/alt-screen | 立即关闭，零匹配不留空卡；再次真实输入产生新revision后才重新自动查询 |

候选浮卡通常596px宽，r14、内距12；行高32、gap6，三条示例高154。第一条直接从y12开始，无“本地历史”标题、关闭叉、倒计时或幽灵空头。命令JetBrains Mono11.5/20、弱元信息Inter10/18，history图标与单行命令、次数或匹配说明同排，长命令省略但可取完整值。底部简短手势提示Inter10/16。596和154是当前样例，真实宽度受所属pane安全边界约束，6项以内按内容增高；高度不足只滚候选区，不缩字号。光标行下方放不下时翻上方，不覆盖正在编辑的行。

`HistoryCandidateState`保存`owner/generation/inputRevision/query/queryRevision/activeCandidateId/rows/scrollOffset/suppressedRevision?`。异步或延迟结果命中旧revision只释放，不显示、不改新草稿。切主题/重排不改变候选身份，重复同命令不变成多个可执行动作。

普通历史候选初显时第一项为活动项，↑↓到首尾停止、不循环；键盘改变活动项后，静止指针不能因重绘夺回高亮，实际pointer move才切换。列表锚在原输入光标行下方8px，空间不足按安全边距向上翻转；捕获同一owner/inputRevision，resize或滚动后重算锚点。

## 3. 应用指令目录、语法和调用

### 3.1 目录与补全UI

一份CommandCatalog供解析器、光标目录、帮助、菜单和快捷键描述使用，含13条动作及1条字面转义，共14项。不能另写只有12条的帮助表。命令名按目录规范化为小写，参数中的路径、问题、组名和主题身份保持原数据，不因匹配而改大小写。

行首`@`打开目录，`@xx`实时过滤，`@d`只匹配`@dl/@dup`；未知命令、缺参数或参数无效保留输入并原位错误，不回退Shell执行。目录锚光标行，优先下方、空间不足翻上方，再按窗口/pane8px安全区夹取。

### 3.3 显式路径候选与安全替换

参数schema声明`local_path / remote_path / enum / group_id / theme_id / free_text`，解析器按类型读取，不能把普通历史命令当路径项。路径候选保存`sourceEndpoint, owner, bindingGeneration, requestedPath, pathRevision, inputRevision, requestId, cacheFreshness`；用户换目录/来源后清除旧选择，晚到响应不得覆盖新路径。

## 5. 记录服务、事件与完整检查点

### 5.1 记录实体与写入

记录服务旁路接收V0.1.2输出/resize/生命周期；不额外记录认证秘密、键入字节或IME中间态。终端本身已经回显的内容仍是实际输出，不能宣称日志自动无敏感信息。记录写盘与队列有界，不阻塞VT feed；磁盘错误降级记录并报告，不能断开正常Local/SSH。

| 实体 | 必须字段与约束 |
| --- | --- |
| Recording | `recordingId, sourceSessionId, pluginId, savedConnectionId?, identitySnapshot, startedWallTime, endedAt?, formatVersion, availableRange, gaps, storageRevision`；用持久ID，不按主机名合并 |
| RecordEvent | `recordingId, sequence, generation, monotonicOffset, wallTime, kind, payloadLength`；kind至少output/resize/checkpoint/gap/session_end及实际产生的command_boundary/typed_event，同一时刻以sequence排序 |
| CheckpointRef | `recordingId, sequence, streamOffset, formatVersion, geometry, snapshotBlobRef, snapshotIntegrity`；对应完整VT状态而非只存offset |
| RecordLease | `recordingId, storageRevision, retainedRange, readerKind`；回放/导出持有，环形覆盖后不能把同一物理offset新数据当旧历史 |
| ArchiveEntry | `recordingId, sourceIdentity, startedAt, duration, exitOrReason, actualPath, availability, error?`；缺失/权限错保可诊断条目 |
| HistoryMarker | `markerId, recordingId, storageRevision, sequence, monotonicOffset, wallTime, generation, sourceKind, type, boundedLabel, sourceRowId?, availability`；marker是记录中的可定位元数据，不是新的可执行工具或任意日志字符串 |

历史顺序、播放速度和超时用monotonic/sequence；HH:mm:ss显示用带本地时区的wall-clock。系统时钟回拨不重排记录；重连generation写入边界，不暗示旧Shell进程恢复。时间戳旁路metadata随记录保存，具体产生、冻结、空行和当前时钟契约唯一归V0.1.2。

环形记录默认64MiB，单位2²⁰；按逻辑顺序管理原字节和事件索引。队列丢块、磁盘失败、环形覆盖或checkpoint依赖丢失必须形成可观察gap。可回放范围只包括存在有效起点且后续事件可读的区间；只有中段原始字节、没有可恢复VT起点时不能假装完整画面。

事件轨只消费两种可证明来源：①已写入记录且带明确type/sequence的typed_event（如真实生命周期事件或既有有类型事件源提供的标记）；②集成已观测到并写入记录的command_boundary（prompt/command开始或结束），按自身类型标示。边界观察和§2.1安全替换是不同能力：已有可信OSC/集成边界可记录，不因能观察边界就宣称能改ZLE buffer。不得扫描任意日志中的`restart/Running/Error`就生成“服务重启”等语义事件；终端状态词chip仍只是V0.1.2装饰。离线原型的“14:27重启事件”仅在记录真有对应有类型事件时展示，旧文件只有output或缺少边界时保普通输出/真实gap，不补造标记或回填假来源。

### 5.2 Ghostty快照和旧格式兼容

使用当前vendored`vendor/libghostty-vt/include/ghostty/vt/snapshot.h`的完整快照C ABI：`ghostty_snapshot_encode`及对应buf/alloc接口，解码使用`decoder_ready/next/decode`。底层已有`GHOSTSNP`、版本与逐记录CRC，READY包含可渲染/可继续解析状态及未完成VT/UTF-8输入，FINISH表示完整滚动区。应用只包装调用与上限/错误处理，不另造一套“用文本重画即等价完整VT”的快照格式；实际链接库符号和版本必须在非UI阶段验证。

检查点默认每30秒，来自`log.checkpoint_sec`；捕获与feed/resize在同一个VT所有权边界序列化，发布blob与sequence一致。重建时先恢复最近有效完整检查点，再按sequence应用resize和output到游标；UI可在READY后显示有效帧，声明完整记录前仍须检查所需FINISH/后续事件。损坏/不兼容checkpoint只使对应起点不可用，可退到更早有效点或标gap，不能关闭实时连接。

当前`ZWRAW001`32字节头记录容量/sequence/长度，Tap的24字节checkpoint仅有序号/时间/streamOffset；它们不足以恢复完整VT。迁移保留旧文件只读兼容，旧原始中段没有快照时标范围不完整，不静默覆盖原文件或把offset记录宣传成完整checkpoint。新的事件/快照索引使用独立明确formatVersion、长度和完整性校验；格式变更错误与文件缺失分别报告。旧“512KiB触发”未接到当前设置，不再作为必须叠加的固定阈值，频率须服从记录预算和不阻塞实时终端的约束。

| 激活事件标记 | 复验原HistoryId/recordingId/storageRevision及markerId，暂停并选择该标记；cursor定位到其sequence/time、增加loadRevision，读取有效checkpoint推进到该事件。保持当前visibleRange，若标记因其它导航在范围外，则保现有时间跨度平移并夹取；不放大时间窗、不向实时终端写字节 |
| +/- | 以游标为中心调整visibleRange并夹取availableRange；不改变真实记录或播放速率 |
| 播放 | 1×按monotonic推进cursor，顺序在独立VT重建；到可用末端自动暂停，不发送旧命令到远端 |
| 经过gap | 明示无记录，保最近可证明画面；到下一有效checkpoint才恢复画面，不能对缺口插值 |
| 实时源新增输出 | 扩availableRange，不强拉用户正在阅读的cursor/scroll到末尾 |
| 返回实时 | 只激活原SessionId，历史页保留；原会话已结束/不存在时禁用说明，不能新连同名主机替代 |

事件定位完成后，仅在sourceRowId仍可证明对应时将其滚入输出viewport；无行锚就显示该时刻恢复的有效帧，不能猜同索引文本。标记自身存在、但目标时刻落在gap或缺少可恢复起点时，保最近可证明画面并明确缺口，暂停且不将旧画面标成事件时刻的完整帧；到下一有效checkpoint才恢复。环形覆盖/清理使标记失效则清选中并显示当前范围/可用状态，不钳到另一个记录或同名标记。读取错误保事件选择及可重试原因，旧seek结果不覆盖较新选择；不因点击marker重新分析日志或产生新事件。

当前输入行的实时时钟不会在历史页启动；复制/搜索只作用于历史所选源。历史页切主题使用全局主题，但回放VT的原始ANSI/文本事件保持，不改写归档数据。

底栏归档身份、编码、网格及更多复用V0.1.2§3.4的360宽浮卡和StatusProjection。History适配器只提供本Recording的身份、当前回放帧网格/编码与只读状态；历史/导出按钮绑定此HistoryId/RecordingId，不能通过保留原session号获得可写服务。源会话已经不存在也可读归档，返回实时按上表单独门控。

### 6.4 导出与设置页范围清理

导出冻结`recordingId/storageRevision/format/range/selectionSnapshot/targetPath`；txt是实际终端文本、cast是可回放的原时序输出和尺寸事件，二者排除时间装饰、chip和应用浮层。cast导入必须支持所导出的尺寸事件，不能像当前仅处理output而静默忽略resize。txt导出不是带`offset=…`转义字节的诊断dump。选择范围导出不得串入未选记录，缺口/部分记录在提交前说明。

系统选择器打开前捕获源，取消不写文件。临时目标写入、flush、最终替换成功才显示完成；失败保源记录、实际错误和重试位置，不把半文件发布为已完成。已选目标与记录内容不因切tab或后来新输出变更。读取源路径限于记录服务认可的应用记录范围；用户明确选定的导出目的可在该授权位置写入，不能把“源范围限制”误用于禁止用户选择Downloads等目标。`exported` `236:563752`完成反馈提供实际文件名/目录和“在Finder显示”，只在完成发布后启用；reveal绑定这次成功产物、不读取当前tab，不执行文件。`terminal-toast-error` `392:1833035`保源记录与EACCES原因，重试沿原导出源/格式/范围重新选择或验证目标，不能显示假完成。

本版通过全局设置→数据与日志直接提供“会话记录”和“导出与清理”两个分区，复用V0.1.1已交付的设置外壳、同一draft及固定保存栏；不能等待V0.1.8才获得本版清理入口。会话记录分区四行对应§7字段，标准行580×36、gap6、右值164×30；数值Enter校验/Esc恢复最后有效值，Save才提交。V0.1.8接入位置/凭据和诊断导出，并做八页整合；未交付的域不妨碍本版记录字段与清理操作使用。

“导出与清理”的trash入口开启**设置页范围清理**，不是历史列表单条删除。离线`delete-history` `236:571436`明确“有活动会话时禁止清理，此项在数据与日志设置中执行”；`settings-data-clear-confirm` `236:545445`核对所有已结束会话的输出与快照。标准动作行580×36、行末30×30图标；点击前捕获settings draftId/原页面/scroll/focusReturn，不将当前历史列表筛选当清理范围，不把清理写进dirty或Save/Reset副作用。

打开确认前和提交时均检查活动会话，存在活动会话原位显示“请先结束活动会话”；切到历史tab不代表实时会话结束。确认默认焦点在取消；取消/关闭回原设置滚动位置和触发按钮、保草稿且零删除。确认冻结这次全部已结束RecordingId集合，之后产生记录不加入。操作期间锁本次重复清理入口，其它独立设置draft保留；结果原位显示处理中/已删数/失败数与可重试原因，不以清空动画冒充文件删除完成。

清理只删除列明的会话输出与快照，保主机、设置draft、诊断日志和用户原文件。先协调打开视图/导出读引用，再按记录逐项删除；成功才移索引，失败保条目/错误/可重试ID。文件已删而索引提交失败保“文件缺失”诊断条目供重试；部分成功显示已删/失败数，不提前清空整列。重试只处理原失败集合，不能顺带清新记录。自动保留策略仅处理已结束且无读引用的记录，不用保存设置触发一次全局危险清空。

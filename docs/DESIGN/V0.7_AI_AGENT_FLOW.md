## 0. 问题总览与根因

当前多智能体通道的问题是一根链条，每一环都在教模型“别用这个工具”：

```
判断标准模糊 ──► 调用摩擦高 ──► 派发后被"卡住" ──► 状态不透明
（何时该派？）  （自造幂等键/   （未收齐报告不得     （上限/排队/复用
                起必填名字）    结束，自己轮询捞）    路况全部不可见）
```

- **派发判断**：唯一的鼓励只有一句 "Proactively delegate independent work"（`session_prompt.zig:83`），"independent" 无可执行定义；工具描述（`child_gateway.zig:32`）约 700 词，九成是约束与失败模式。
- **调用摩擦**：create 必填 request_key + name + text + session_refs（`child_gateway.zig:38-45`），幂等键和名字都要模型凭空编造且每次唯一。
- **收尾惩罚**：`resumeAnswer` 遇未收尾子任务直接 `ChildSettlementRequired`（`task_budget.zig:322`），父被打回后须自己 `wait_events` 轮询（每次最多 8 条，`child_gateway.zig:300`），模型体验为"派发 = 被钉住"。
- **状态不透明**：4 子/根、2 请求/根、4 进程槽全部硬编码；`ChildTaskLimit` 只给裸错误码；`list` 不显示排队与可复用路况。

交互式执行另有一条独立的避难路径：批处理 1 步可完成，交互式要 3–5 步就绪舞蹈且处处禁令（§2.2）。预算刚性是第三个独立问题（§2.3）。

### 3.10 窗口置顶按钮修复（P17）

**问题确认（2026-11-15）**：`WindowPin` 按钮的图标**不随状态变化**——置顶/未置顶都是竖直 pin 图标，仅 tint 从 fg_2 换 accent（`main.zig:16748`）；图形库已有 `pin_off`（斜向 45°，`icons_lucide_generated.zig:107171`）但未使用。通用惯例：**倾斜 = 未钉住，竖直 = 已钉住**（形状即状态，不依赖颜色——色弱可辨、扫视即懂）。

**修复**：

1. **图标随状态切换**：未置顶 → `pin_off`（斜钉，fg_2）；已置顶 → `pin`（竖直钉，accent tint）。切换时换 `icon_asset` 而非仅换 tint；实现上 `Button` 重建或预挂两个 icon 节点按 `self.pinned` 切 display（遵循 §7.4 "相同内容不标脏"——状态翻转才更新）。
2. **a11y 同步**：`a11y_label` 随状态换"窗口置顶"/“取消窗口置顶”，`pressed` 属性保留（`main.zig:16741` 现状已设）。
3. **位置调整**：从 application 组末位（设置右侧）移至 **application 组首位**（AI ✨ 之前）。理由：置顶是窗口行为控制（与 ✨/⚙️ 的"应用功能入口"性质不同，但同属标题栏右侧操作区），组内排序"窗口控制在前、应用功能在后"；不放入 history/transfer 组（跨组挪动改变语义分组）。`test_id = "toolbar.window_pin"` 不变，`zw_window_set_pinned` 调用不变。
4. **回归验收**：置顶后图标为竖直+accent；未置顶为斜+fg_2；VoiceOver 读出状态名；既有依赖 test_id 的回归不破坏。

**归属**：阶段 1 批次 C（纯 UI 修复，与审批队列/通知同批交付）。

P1–P16 全部为宿主侧改造：把模型该做的记账、命名、发现、排队交给宿主，安全语义一条不降（§6）。

## 2. 用户裁决三项的详细设计

### 2.1 子任务命名：编号 + 短名

**裁决**：最终名字 = 宿主分配的编号 + 模型/用户提供的短名；短名不要求唯一。

| 字段 | 来源 | 唯一性 | 规则 |
|---|---|---|---|
| `seq` 编号 | 宿主，父对话内单调递增 | **是**（父对话作用域） | `uint32`，复用（reuse）保留原编号，销毁不回收 |
| `label` 短名 | create 的 `name` 参数，**变为可选** | 否 | 1–32 字符，仅展示与助记；可随时重命名 |
| 显示名 | 宿主拼接 | — | `#3 修日志`；无短名时 `#3` |

**为什么合适**：现状名字"必须起但起了也没用"——必填（"A non-blank child name"，`child_gateway.zig:39`）、代码不查唯一、提示词又禁止按名字猜（复用必须精确 32 位 `agent_id`，`child_gateway.zig:43`）。编号承担唯一性之后：

1. 短名解放为纯助记，create 少一个心理负担（P2）；
2. **编号成为可确定解析的引用**：`send`/`reuse`/`stop` 的 `agent_id`/`task_id` 参数新增接受 `seq`（父任务作用域内宿主查表，唯一命中）；裸短名引用仅当父任务下唯一匹配时解析，多匹配返回候选列表错误——延续"不按名字猜"，但给出人机都可用的短句柄（P3）；
3. `list` 返回 `seq + label + agent_id` 三元组；`wait_events` 每条事件附 `seq + label`，报告块归属不再是一段十六进制；
4. 子任务 UI 列表行与弹窗标题统一为显示名（`ai_children_view.zig` / `child_projection.zig`）。

**迁移**：既有子记录按持久化创建事件顺序补 `seq`；`name` 参数语义降级为 `label`，旧 journal 无需格式变更。

**未来钩子（第二阶段地基，不得砍）**：`seq` 即留言板对等引用（`@3`）与 swarm 面板显示名的稳定句柄。三条规则——父对话作用域内唯一、复用保留原编号、销毁不回收——同时也是板帖 `to` 字段的地址解析规则，A 批实施与验收按此执行。本版仍不做孩子间通信，但寻址语义在本版定型。

### 2.2 交互式执行链路重构

**诊断**：批处理（`run_command`）1 步返回真实回执；交互式要走的路：

```
read_terminal(include_control=true) → 取 Shell ID/revision
  → attach_shell(prompt_evidence, wait_ms=30000)     ← 可能超时/观察过期，需重读再来
  → 确认 prompt_ready → run_in_terminal
```

依据：`session_prompt.zig:120-122` 的完整恢复协议、`host_execution.zig:16` 的工具描述。终端被占用时叠加禁令："Never enter input into an occupied terminal to run unrelated work"，须走 create_group → open_session → 等就绪的长路径；interactive 模式还一刀切 "Never switch to batch execution"（`session_prompt.zig:102`）。模型理性避难到批处理。

**方案**：

1. **run_in_terminal 内置自动 Shell 恢复（auto-shell）**：遇 `ShellPromptNotObserved`/`IntegrationUnavailable` 不再拒绝，宿主在**同一工具调用内**执行 read_control → attach → 有界等待（≤30s）→ 确认 → 提交。整段折叠为单个工具步骤展示（“宿主自动恢复 Shell"），证据照常记录（Shell 集成回执、观察区间）。`host.attach_shell` 保留为手动兜底与嵌套 Shell 场景。模型操作面回到 1 步。
2. **占用策略参数**：`run_in_terminal` 新增 `occupied_policy`（`wait` 默认 ｜ `new_session` ｜ `reject`）：
   - `wait`：命令入队，宿主等前台完成通知（复用 AI_SESSION_EFFICIENCY 的语义等待）后自动提交，审批一次即可；
   - `new_session`：经**现有授权生命周期管线**开新工作会话执行（不是静默换目标），过程折叠展示；
   - `reject`：立即结构化报错。
3. **interactive 模式批处理禁令放宽为配置**：新增 `[ai] interactive_batch_fallback`（默认开）：终端占用时**独立无状态命令**可走 `run_command`；关闭则严格维持现状。提示词规则同步改为"有状态依赖的命令必须交互式；独立无状态命令在终端占用时可走批处理（若设置允许）"。
4. **结构化占用/越权报错**：占用错误载荷含 `{占用者命令摘要, 已等待时长, 可选动作}`；`TargetNotAuthorized` 附当前"已授权 + 空闲"会话引用清单，模型不用第二次猜。

**不降级的安全语义**：auto-shell 只省略模型的中间步骤，attach 仍按真实观察与集成回执记录；`completion_source` 区分与 "shell_reported 非防篡改证明" 的证据规则原样保留；占用排队不绕过任何审批。

### 2.3 任务预算可配置化

**裁决**：当前预算限制太死，改为全局设置约束每个活动 AI 会话的最大活跃子任务数。

| 新配置（`[ai]` 节） | 默认 | 范围 | 替代的硬编码 |
|---|---|---|---|
| `child_max_active` | 4 | 1–16 | `task_budget.zig:224,244` 的 `active >= 4`（每活动根任务最大活跃子任务数） |
| `child_request_concurrency` | 2 | 1–8 | `task_budget.zig:472` 的 `count >= 2`（每根任务并发模型请求数） |
| `model_slots` | 4 | 2–8 | `task_budget.zig:435` 的 `active: [4]`（进程级并发模型请求槽） |

- **默认值保持现值**：放宽的是"可调"，不是默认激进。16 子上限同时是内存护栏（每子 = Worker 线程 + backend + 独立对话），不可配置突破。
- **生效语义**：进程启动时按冻结配置初始化 `Slots` 数组（`active`/`queue` 由固定数组改为按配置分配）；运行中修改仅对新根任务生效，与 V0.4 冻结配置一致性原则一致。
- **公平性保留**：`last_root` 反垄断选择（`task_budget.zig:474`）与队列 FIFO 语义不变；数值放大后按比例保持。
- **设置 UI**：`settings_ai.zig` 子 Agent 卡新增三个数字字段，含范围校验与超限错误定位（遵循 DESIGN_STANDARDS §8 输入域规则）。

## 3. 其余问题方案

### 3.1 派发判断标准（P1）

把 "independent work" 替换为可执行触发条件，写入 session prompt 的委派段：① 任务涉及 ≥2 个可独立检查/修改的目标（不同文件、不同会话、不同主机）；② 一段只读调查可与当前写操作并行；③ 用户话语出现"并行／同时／另开／顺便"。同时明确反例（一句话可答、强顺序依赖、需要当前 Shell 状态的修正类请求不派发）。

鼓励基调采用 Codex 式强鼓励写法："只要并行委派能节省时间或提升质量，就应当委派"——委派是默认选项而非例外；约束集中到 §4 的硬边界段，不再散布在工具描述里压过鼓励。

### 3.2 create 摩擦（P2）

- `name`（即 label）变可选（§2.1）。
- `request_key` 变可选：省略时宿主按 canonical(text + targets + 父任务) **内容派生**——相同参数的失败重试自动命中幂等去重；要重复执行相同内容时才需显式新键。显式键语义与 `ChildRequestConflict` 检查不变（`child_gateway.zig:152-155`）。
- create 因 `session_refs` 越权被拒时，报错附可用会话清单（与 §2.2.4 共用）。

### 3.3 收尾自动交付、报告抢救与事件游标（P8/P9）

- **强制续行轮自动投递子事件**：`resumeAnswer` 打回父任务的那一轮（`task_budget.zig:322` → `turn_manager.zig:300-314` 强制等待），宿主直接把"已 settle 未收集"的子报告正文组装进续行输入，并原子推进已投递游标。模型体验从"被打回+自己去捞"变为"下一轮自动收到结果"。投递单位是**类型化任务事件**，字段结构 `{kind, origin(#seq), text, ts, extra}`（与 §9 G8 常量表一致）：本版仅实现 `kind=settle_report`（报告正文）一种；管道按枚举开放设计，第二阶段新增 `post`（留言板帖）等类型时只加类型、不改管道。
- **报告抢救与未收齐披露**（本版唯一安全语义修订，用户已批准 2026-11-15）：父任务被打回、失败或被停止时，已 settle 的子报告**不丢失、不清除**——持久化保留并在子任务面板"最近结束"组可读；父恢复或收尾时自动投递。`ChildSettlementRequired` 从"硬门禁"修订为"**未收齐清单披露**"：父终局回复必须列出未收齐子任务的 `#seq label` 清单，已投递报告的结论照常汇入。语义：不隐藏任何未收齐事实，但已交付部分不再被阻塞。
- **三态分离（2026-11-15 评审裁决，取代以 `unconfirmed` 笼统标注全部未收齐项的写法）**：`unconfirmed` 只表达**结果核验状态**，不表达任务活跃度。父终局回复与面板对每个子任务区分三件事：

  | 维度 | 取值 | 来源 |
  |---|---|---|
  | **交付状态** | 已交付 / 未交付 | 该子报告是否已进入父上下文（G2 游标） |
  | **活跃状态** | 执行中 / 等待用户 / 排队 / 已终态（succeeded·failed·cancelled·interrupted·outcome_unknown） | 现有 `Fact.status` 状态机，零新增 |
  | **核验状态** | 已核验 / 结论未核验 | 仅当结论被 verify/challenge 复核后才标已核验；否则"结论未核验" |

  - **部分交付示例**（三台巡检、两台出结果、第三台等审批）：父可先交付两台结论；主对话保留第三台的审批入口与"等待审批"活跃状态；第三台不是 `unconfirmed`——它是**未交付 + 等待用户**。
  - **用户停止后的晚到报告**：按 V0.4 §"晚到报告"既有规则保存到原任务记录；恢复父助手须用户明确继续（现状语义不变）；晚到报告在面板"最近结束"组可读，标注其到达时间晚于停止时刻。
  - **验收断言**：上述三台巡检场景中，两台已交付结论无 `unconfirmed` 标记（其核验状态另列），第三台显示"等待审批"而非任何核验措辞；用户停止父任务后，已交付结论与晚到报告均可在原任务记录读回。
- **wait_events 游标默认**：宿主按父任务记录已投递水位；省略 `after_sequence` 时默认返回"上次投递之后的新事件"。显式水位分页语义保留（`TaskReportTooLarge` 减半重试逻辑不变，`child_gateway.zig:318-323`）。

### 3.4 复用路况（P10）

`list` 为每个子记录附状态标签：`reuse_ready` / `needs_verification`（旧副作用未收验，对应 `ChildNeedsVerification`）/ `busy` / `cleanup_pending`。两步复用流程（先 list 再精确选）保留——这是安全属性；改的是第一步就能看清路况。同时将 `list` 返回结构一次定型为**面板就绪行**：`{seq, label, agent_id, status, queue_position, targets, usage{requests, tokens}, flags{reusable, purpose}}`——该结构即第二阶段 swarm 面板成员页与审批队列的数据源，UI 层不得另设查询接口（§9）。

### 3.5 错误载荷（P11）

`ChildTaskLimit` 等预算错误的载荷含 `{active 计数, limit, 占用者 [#seq label 列表]}`；`list` 增加每子任务 `running / queued_model_slot` 真实状态。模型可据此决定"停一个"还是"等"。

### 3.6 子任务审批透传（P12）

子任务内 `human_wait` 的待审批命令**透传到主对话**：审批卡出现在父对话 composer 交互区（现状 `main.zig:9242-9267` 的聚合路由已实现单卡透传，标题带子名标注如"确认执行命令 · #3 巡检华东节点"）。审批决策仍走原 Broker，父模型不能代批（现状语义保留）。

- **主对话是唯一审批操作入口**：批准/拒绝只在主对话透传卡上操作。
- **聚合从单卡升级为审批队列**：多个子任务同时待批时全部可见、逐张处理（现状一次只提升第一个待审批子）；队列顺序按待批时间先后。
- **子任务列表/面板只做状态行**：显示"等待审批"状态与所等命令摘要（只读），**不放批准/拒绝按钮**——审批操作不复制到列表入口，避免同一票据双入口产生分歧；点击状态行跳转主对话对应审批卡。
- 子任务待审批纳入桌面通知（现状 `observeApprovalNotification` 仅轮询父 broker，`main.zig:10089`；扩展覆盖子 broker 队列）。
- 三态分离（交付/活跃/核验）见 §3.3。

### 3.7 verify 角色与模型分层（P14/P15）

- `purpose=verify` 从"仅 reuse 可指定"放开到 create 也可指定（`child_gateway.zig:41` 的 schema 枚举同步）；只读核验语义（禁止写入、禁止重放）不变。
- 模型分派升级为**角色模板**体系（替代原单值 `child_model` 枚举），阶段 1–2 只交付存储与回退解析，阶段 3 起全量启用：

  **模板结构**：命名的角色→槽映射，每槽 `{model+effort, skills 掩码, tools 掩码}`。角色枚举 `parent/planner/verifier/worker/batch`（与 create 的 role 参数对应，阶段 1–2 仅实现 worker 默认槽，其余槽在阶段 3 启用；枚举值域本版定型）。

  **回退链**（四层，槽未配置时逐层回退）：

  ```
  create 显式 model+effort（最高，用户/父模型亲口指定）
   └─► 活动模板的对应角色槽
        └─► 同模型·effort 适配（batch=low、worker=medium、planner/verifier=high）
             └─► inherit（父会话模型 + 会话 effort）
  ```

  **能力掩码**：skills/tools 字段是允许清单，**只能收窄不能扩权**——实际能力 = 父授权投影 ∩ create 参数 ∩ 模板槽掩码，经现有 `plugin_tools.zig` 目录裁剪机制实现（与 `purpose=verify` 的只读裁剪同路）。缺省"全部"，此时模板只有模型意义；掩码同时控制 skill 目录是否注入子任务上下文（未释放的 skill 不出现在目录，节省 prompt token）。典型配法：verifier 槽=只读工具+全部技能；batch 槽=无技能+基础工具。

  **默认模板**：出厂内置"均衡"（全部槽 inherit、无掩码），标记为默认；新会话自动套用，等价于现状行为。设置 UI 增加模板管理（AI 卡：列表/新建/编辑/复制/删除，每槽选模型+effort+可选掩码编辑）。模板解析失败（槽指向的模型不可用）时惰性降级为 inherit 并在子任务列表行黄色提示，不阻塞任务创建。

  **生效语义**：模板对**所有子智能体 create 生效**（含普通单父多子模式）；swarm/boost 只是阶段 3 叠加在上面的角色提示与默认参数包，不独占模板。运行中修改模板仅影响新 create。**模板选择入口在模式菜单内**（§10.1.4：模式芯片展开菜单含模板子菜单），不设独立模板芯片——模式与模板是同一决策链（编排方式+成本档位），一次选完。

### 3.9 模型与推理强度中途调整

任何智能体（父/子）在任何时刻可切换 model 与 effort，**下次模型请求生效**：

- **上下文预算校验闸**：切换前校验目标模型上下文容量 ≥ 该会话当前已用 token（含历史+技能+附件）。容量不足则拒绝切换，错误载荷含当前已用量与候选模型容量，会话保持原模型继续执行；历史不裁剪、不压缩。
- 用户可通过自然语言要求调整（"把 #3 换成 X 模型"）——父模型发出 create/update 调用；用户也可直接在子任务列表浮窗/弹窗的配置区手动调整。
- 校验闸同时覆盖 effort 调整（部分供应商 effort 影响实际可用窗口）。

本节同时是单对话分层执行（Antigravity Orchestrator 式"贵规划+廉执行"）的机制基础：父在规划轮用高 effort、执行段切低档，无需专门模式。

### 3.8 子任务用量可见（P16）

`context_usage.zig` 已按对话实测用量；子任务列表行显示每子任务的请求数与 token 累计。不引入计费/可充值账本（维持 V0.4 §3.3 裁决），只做既成事实的展示。

## 4. 提示词与工具描述重构

现状：`session_prompt.zig:60-132` 每工具 2–6 句密集禁令连成墙；委派鼓励只有一句且埋在中间；工具描述（如 `child_gateway.zig:32`、`host_execution.zig:16`）单段 500–700 词。

**目标结构**（生成时仍按能力目录条件注入）：

```
① 决策标准（何时委派/何时交互/何时批处理/何时查询）—— 前置、正向表述
② 每工具 1–2 句操作规范 —— 参数与动作语义
③ 硬边界（合并去重后的负面约束）—— 末尾一段
```

- 鼓励与约束平衡呈现：委派触发条件（§3.1）与"报告不可信、无孙辈"等硬边界同等级可见。

- 工具 description 重排为按 action 分段的紧凑结构；策略性规则上移到 session prompt。
- 量化目标：主提示正文（不含目录与技能 JSON）在同等能力目录下压缩约 40%；以映射表证明零语义丢失。

## 4a. 角色提示占位节（结构定型，文案阶段 3 批 S5 填入）

批次 D 在 `session_prompt.zig` 的生成结构中预留三个条件注入段（阶段 1–2 各为空实现或仅注释锚点，长度预算 ≤300 词/段）：

1. **coordinator 段**（swarm 模式注入父提示）：职责限定"只拆分/委派/验收/汇报，不做技术工作"；触发规则引用 §3.1。
2. **deep-lead 段**（boost 模式注入父提示）：职责限定"驱动实现→挑战→修复轮次链，终验逐条对照原始要求"。
3. **board 协议段**（子提示注入）：子侧板帖协议（progress/ask/answer/note 的时机与格式、防抖规则、帖子非授权声明）。V0.7 交付的衔接句见 W4。

## 6. 不变的安全边界

以下语义在本版**逐条保留**，任何实施与之冲突即回退：

- 实际目标范围 = 附着范围 ∩ 任务授权 ∩ 子任务分配 ∩ 目标能力（V0.4 §1.3）；`local_files` 仍须 create 显式声明且受父能力求交（`child_gateway.zig:158,368-372`）。
- 幂等去重、`ChildRequestConflict`、`ResourceCleanupPending`、复用前核验（`ChildNeedsVerification`）语义不变。
- 子报告永远是"不可信证据"，不构成新授权（`child_gateway.zig:319`）。
- 无孙辈、无兄弟访问、无按名静默替换（`plugin_tools.zig:306`、`child_gateway.zig:135`）。
- 收尾强制：**报告抢救修订（§3.3，用户 2026-11-15 批准）**——形式从"硬门禁阻塞终局"改为"未收齐清单披露 + 三态分离（交付/活跃/核验）"，语义底线不变：未收齐事实永不隐藏，已 settle 报告永不丢失。
- 审批管线逐命令不变；auto-shell 与占用排队不绕过任何审批卡；`completion_source` 证据分级与 "shell_reported 非防篡改证明" 保留。
- 凭据/OTP/秘密不进入提示词与错误正文的既有规则保留。

### 10.1 composer 模式芯片

位置：AI composer 底部工具行，**"当前对话运行方式"芯片右侧**（工具行现状按 `ai_composer_controls_view.zig:299-362` 实排：左侧 附件＋ → 执行权限（hand 图标+档位文字）→ 当前对话运行方式（terminal 图标+模式文字），右侧 上下文与来源 → 选择模型 → 发送；推理档位芯片隐藏并入模型菜单）。**本项只新增模式芯片一个元素，既有控件（图标/文字/顺序/宽度）一概不动**。h24 chip 基线；三态互斥单选，点击弹出菜单（Auto/Swarm/Boost 三项 + 模板子菜单）。

- **图标**（14×14 线稿，项目现有 Lucide 库，不新增资产；见 `design/ai-agent-mode/mode-chip.svg`）：
  - Auto → `bot`：机器人轮廓——"宿主自动决策"；
  - Swarm → `network`：多节点连线网——"多子并行、彼此通信"的 Graph 缩影；
  - Boost → `flame`：火焰——"深度攻坚、火力全开"。

- **芯片文字**：随档位显示 "Auto"/"Swarm"/"Boost"；右侧 chevron 指示可展开。
- **键盘等价**：`/swarm`、`/boost`、`/auto` 命令与菜单等价（切档+对当前输入生效）。

### 10.1.4 模板子菜单（并入模式菜单）

模式菜单下半区为**模板选择**：列出全部模板（名称+简述+当前活动模板选中态）；选择即切换会话活动模板（§3.7），立即影响后续 create 的槽位解析。**不设独立模板芯片**——模式与模板同属"编排方式+成本档位"决策链，一次选完；Auto 档也可配非默认模板（正交）。

### 10.2 档位判定与切换语义

- **Auto 档**（默认）：宿主按"**信号 + 实质**"两步判定（2026-11-15 评审裁决，取代纯关键词触发）：
  - **信号**（任一）：用户话语含"并行/同时/各自/分别/另开/顺便"，或请求涉及 ≥2 个已授权目标。信号仅开启判定，**不足以单独升级**——"顺便解释一下"这类假阳性不得触发。
  - **实质**（须同时成立）：请求确有**可独立执行**的工作（≥2 个互不冲突的目标，或一段可并行的只读调查）、且在**已授权范围内**、且**可独立验收**（每个子块有独立完成标准）。宿主按会话/目标/工具目录机器可判；无法判定实质时**不升级**（保守默认普通助手），父模型仍可按 §3.1 自主委派。
  - **可见反馈**：信号+实质均成立、本次按 Swarm 执行时，面板与主对话显示一次"本次并行执行"标记（任务开始时）；未升级则无任何提示。Auto 升级只作用于当次请求，请求间不记忆。
  - **可解释**：升级判定记录于任务事件（触发信号 + 命中的实质条件），面板可查——用户能知道"为什么这次并行了"。
- **Swarm 档**：会话级锁定。父提示注入 coordinator 段（§4a 占位节 1），create 默认参数包（role=worker、reusable=true 常驻优先复用）。
- **Boost 档**：会话级锁定，仅手动进入。父提示注入 deep-lead 段；首次派发时宿主推荐"攻坚"模板（planner 强/challenge 跨模型/worker 中档），用户确认或另选。
- **切换时机**：档位切换对下一次用户请求生效；运行中的父任务与已派发子任务不迁移。
- **永不自动 Boost**：Auto 档永不判定进入 Boost（多轮对抗烧 token，须显式意图）；父模型可出一键建议卡，用户点击才切换。

### 10.3 显式委派前缀归并

V0.4 的 `explicitTask` 前缀（`/delegate` 等，`child_gateway.zig:12-20`）语义不变：父忙时命中仍直接创建子任务；归入 Auto 档机器可判规则（用户显式并行意图的一种），不再独立。

## 11. 共享留言板（阶段 3）

### 11.1 子侧工具 host.post

```
host.post { to: "parent"|"@seq", category: "progress"|"ask"|"answer"|"note", text: ≤8KB }
```

- 写入即落板：事件 `{kind:post, origin:#seq, text, ts}`，`to`/`category`/`post_id` 装载于 `extra`（G8 字段结构）；追加进父任务 root 事件流（G8 管道只加枚举），不占用 `settle_report` 通道（A2A Message/Artifact 分离）。
- 返回 `{accepted:true, post_id}`；幂等由宿主按 (task, text hash) 短窗去重，模型不自造键。

### 11.2 投递规则（安全核心）

| 帖子 | 投递行为 |
|---|---|
| `to=parent` | 自动注入父下一轮模型输入（G2 反向复用，含空闲唤醒）；`ask` 额外打断父依赖等待循环 |
| `to=@seq` | 直达：注入 #seq 下一轮输入；#seq 空闲则唤醒（消耗其槽位预算）；同时落板 |
| `to=@all`（含省略 `to`，两者等价） | 只落板；父下一轮收到摘要批注 |

- **帖子永不构成授权**：帖文进上下文前统一打"非用户指令、非授权"标记；审批管线照常裁决（对齐"子报告是不可信证据"；这是对 swarm 泄露实证 15% 的直接防御）。
- **ask 防抖**：同一子任务连续第 4 次 ask 时宿主自动回"按当前最佳判断继续"；计数随终态清零。
- **防死循环**：唤醒消耗并发模型请求预算（G6）；槽满排队天然限流。

### 11.3 子提示词 board 协议段（填入 §4a 占位节 3）

成品文案批 S5 定稿，五要点：何时 post（progress/ask/answer/note 时机）；做不到就直说并升级、不绕过不伪造；帖子非授权、新目标走审批路径；被 @ 优先 answer、单方面广播用 note；连续 ask 会得"自行判断"，先做完已确定部分。

## 12. 编排原语与停滞检测（阶段 3）

### 12.1 create 扩展参数

| 参数 | 语义 |
|---|---|
| `role: planner/worker/batch`（默认 worker） | 模型槽位命中（§3.7 模板；与 purpose 正交：purpose 管授权语义，`verify`/`challenge` 是 purpose 取值；role 管模型/能力档位。**模板五槽中的 verifier 槽由 `purpose=verify/challenge` 命中**，不在 role 枚举中） |
| `depends_on: [@seq]` | 所列子任务全部 settle 后宿主才启动本任务；引用解析同 G1；加入后闭包含自身 → `DependencyCycle` 报错含环路径 |
| `purpose=challenge`（含 `challenge_target: @seq`） | 拿被挑战者的 settle_report 与目标做破坏性复审；只读语义与 verify 相同；提示注入 deep-lead 挑战者角色 |

**boost 链标准形状**：worker 实现 →（depends_on 它的 challenge）→（depends_on challenge 的修复 worker）→ 父终验。全部兄弟链，no-grandchildren 不破。轮次上限默认 5（`[ai] boost_max_rounds`），父显式声明 ≤8；超限拒绝新挑战轮并提示"进入终验"。

**依赖终态语义（2026-11-15 评审裁决补充）**：

- `settle` 指 `Fact.status` 到达任一**终态**（succeeded / failed / cancelled / interrupted / outcome_unknown），不只 succeeded：
  | 前序终态 | 依赖任务的去向 |
  |---|---|
  | succeeded | 正常启动（原语义） |
  | failed / outcome_unknown | **不自动启动**；宿主向父投递"依赖未满足"事件（含前序 `#seq label`、终态、原因摘要），由父决定改派、串行降级（去掉该依赖重新 create）或放弃分支 |
  | cancelled / interrupted | 同上不自动启动；用户中断语义优先，父收到事件后决定 |
- **等待依赖的任务计入活跃额度**（`child_max_active`，现状 `task_budget.zig:235` 计数口径）：创建即占位、未启动也占位——保证"分阶段建链"与"提前提交整链"行为一致（不存在整链绕过额度提前挂满）。整链长度受 `child_max_active` 上限约束；超限时 create 返回 `ChildTaskLimit` 载荷（§3.5），父可提高并发档或缩短链。
- 依赖任务在等待期间可被 stop（释放额度）；停止即取消其未启动的下游依赖链（下游全部转 cancelled，各投递"依赖未满足"事件给父）。

### 12.2 宿主停滞检测（零 token）

宿主每 5s 扫描活动 root 账本（确定性判定，无模型参与）：

| 检测条件 | 动作 |
|---|---|
| 子 settle 报告未投递 | 自动投递父下一轮（G2） |
| 全部子 human_wait | 审批队列浮顶主对话 + 桌面通知（§3.6） |
| 全部子终态、父未收尾 | 注入"全部子任务已结束，请汇总"事件唤醒父 |
| 全部子空闲、无未投递事件、任务未完成、板上无新帖 ≥N 分钟（`swarm_stall_minutes` 默认 3） | ①注入"集群停滞，请检查"事件唤醒父；②父被唤醒 M 分钟（`swarm_stall_parent_minutes` 默认 2）无动作 → 面板警示条+桌面通知，附"催父/停全部"一键动作 |
| 子 running 但 counters 无变化 >10 分钟 | 面板该行标"疑似卡住"；不自动干预 |

"催父"= 宿主向父注入 user 属性 steer（走现有通道，非模型消息）。

### 12.3 新配置（`[ai]` 节，设置 AI 卡"多智能体"分组）

| 配置 | 默认 | 说明 |
|---|---|---|
| `swarm_mode_default` | auto | 会话初始档 |
| `swarm_auto_rules` | 内置 | Auto 判定规则集，`none` 关闭自动切换 |
| `swarm_stall_minutes` | 3 | 停滞第一级阈值 |
| `swarm_stall_parent_minutes` | 2 | 第二级（通知用户）阈值 |
| `boost_max_rounds` | 5 | 单链轮次上限 |

## 14. Swarm 面板（阶段 4）

入口：AI 助手头部"子智能体"按钮；点击从 Popover 列表升级为**常驻浮层面板**（与其他面板共存）。面板形态随当前会话模式：

### 14.1 普通模式：成员列表（升级现有形态）

- 数据源：`list` 面板就绪行（G3），不另设查询接口。
- 分组：**待审批置顶**（含"在主对话审批"提示，点击跳转主对话审批卡）/ 待处理（ask 挂起/停滞升级）/ 进行中（运行/等待模型/等待用户/排队 细分状态，排队任务计入"等待"而非"运行中"口径）/ 最近结束（核验状态、用量）。
- **计数口径**：头部"运行中"计数仅含执行中与等待用户任务；排队等模型槽的任务单独计"排队"（`#2 等待模型` 不再算入"运行中"）。行的图标与文案不得冲突：结论未核验的完成行用中性图标，不得同时显示绿色完成勾与"结论未核验"文案。
- 行内容：LOGO + `#seq label` + 状态字 + 摘要 + 用量 + 角色角标。**审批等待显示为状态行**："等待审批 · <命令摘要>"（只读，点击跳主对话审批卡，不放操作按钮，§3.6）。
- 行点击 → 子弹窗（现有 ChildDialog，零改动）。
- 配置区（行展开/弹窗内）：改 label、切换常驻、调整模型/effort（§3.9 校验闸）、停止/清理。

### 14.2 Swarm 模式：Board + Graph 双页签

**Board 页签**：板帖时间流（G8 事件流游标分页）：`from #seq → to` + category 图标（progress=箭头环/ask=问号圈/answer=回复箭头/note=便签）+ 文本折叠 + 时间；筛选按成员/类型/仅看 ask；审批帖以状态行呈现（跳主对话操作，§3.6）；`settle_report` 与 post 以不同图标区分。

**Graph 页签**：父居中、子环形排布的确定性径向图（≤16 子，固定环形坐标，无物理模拟；节点增删仅位置过渡 200ms）。节点=状态色环（运行 accent/等待用户 warn/等待模型 fg-3/收尾 group/终态 ok·danger/结论未核验 虚线 fg-3）+ LOGO + `#seq label` + 模型微标 + 请求数；点击→**既有子弹窗**（ChildDialog，复用现状 `childSelected` → `processChildren` → `ChildDialog.mount` 链路，零新增组件；事件流/引导消息/模型调整/常驻开关/停止均在其内）。边=板帖累积（宽度 1/2/4px=消息量、箭头=方向、accent 半透明）；hover 边→最近帖摘要+"只看这对"（跳 Board 过滤）。空态：≤1 活跃子自动隐藏 Graph 页签；**普通模式无 Graph**。

### 14.3 Boost 模式：Rounds + Board 双页签

**Rounds 页签**：纵向轮次时间线：每轮=轮次名（"第 1 轮 · 实现/挑战/修复"）+ 该轮子任务节点卡（`#seq label`+状态+摘要+模型档位）+ 轮间依赖箭头；挑战轮附挑战结论摘要；失败轮 danger。底部固定父终验状态条（进行中/已通过/未通过+原因，点击展开逐条对照清单）。Board 页签与 swarm 共享同组件。

### 14.4 面板通用规则

- 宽度：窄形态 360px、宽形态 560px；受视口约束，860×480 取窄形态。
- 停滞警示条（§12.2 第二级）置面板顶部。
- 面板入口按钮红点=待审批子任务数（§3.6 队列长度）。

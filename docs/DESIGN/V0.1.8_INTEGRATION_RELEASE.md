## 2. 快捷键表与事件路由

### 2.1 完整动作范围

原型页签/分栏16动作与终端/应用11动作必须全部映射到V0.1.1§2.3已建立的同一命令目录。27是展示动作数：实时节点将`keys.recent_tab · ⌃Tab`与`keys.accept_completion · →`标为`fixed remote-key boundary`，其余25项为`record one action`。本版25项可录制，2项固定边界仅展示/焦点说明，不把固定项做成无依据的录制入口。按稳定action_id保存允许编辑的用户chord，标签不是存储键；本版本不延后前序功能的出厂快捷键，场景的冲突编辑值不是新的默认值。

| 分类 | 必须支持编辑的动作 | 业务归属 |
| --- | --- | --- |
| 页签 | 新建、关闭、直达1–9、前一/后一；最近使用⌃Tab固定展示 | V0.1.1；新建的真实插件路由随V0.1.2–V0.1.4 |
| 分栏 | 垂直、水平 | V0.1.6，不创建第二个指向同一可写输入槽的视图 |
| 文本/搜索 | 复制、粘贴、搜索当前终端 | V0.1.2/V0.1.5；编辑器与终端无选区复制语义仍各自正确 |
| 候选 | 补全菜单可录制，采纳→固定展示 | V0.1.5，采纳仅可信行末无选区；普通Tab/Control走shell |
| 连接/呈现 | 快捷连接、重连、侧栏、AI | V0.1.1/V0.1.3/V0.1.7；同一动作捕获同一owner |
| 传输/广播 | 上传、组广播 | V0.1.4/V0.1.6，分别保原目标/显式确认集合 |

终端自有键、文本编辑器键及应用快捷键按可信上下文仲裁，不能把任意Control或Tab当应用命令。新键仅在保存成功后发布整张映射；已捕获的手势按开始时版本结束，不一半使用旧表一半新表。

### 2.2 行内录制、冲突和恢复

`ShortcutDraft{action_id,raw_modifiers,key,normalized_chord,previous_chord,capture_state,error}`。点击行内键位进入捕获，显示“按下组合键…”，Esc取消本行录制并回原值，单修饰键不可保存。用统一规范化规则处理修饰键顺序/同义键后，与整张表判冲突；冲突显示占用动作，例如把搜索录成⌘J时提示“⌘J已用于AI浮窗”，保留raw并禁保存，不能暗改另一个动作。

捕获令牌属于settings draftId/action_id，同一时刻只录一行；开始时保previous_chord，捕获完成/取消后才释放令牌。固定两项的BeginCapture直接返回只读原因，配置加载/保存也复验其边界，不能借旧自定义配置重绑→/⌃Tab而破坏原型输入语义。录制层先处理IME组字，消费的物理键不得再触发应用动作、终端字节或广播；切分类/关闭设置会按同一事务取消未完成录制并恢复该行，其他分类dirty保留。冲突时实际运行映射继续旧revision，不能因raw已显示新键便生效；Save成功后原子替换整张表，菜单显示、tooltip与动作路由订阅同revision。原型27项只是设置展示集合，重命名等其它菜单动作仍采用CommandCatalog，不能被这27项列表静默删除。

行内恢复默认只改该action的draft，恢复全部经设置Reset协议；冲突/捕获/取消均保其他分类编辑。系统保留或当前平台无法接收的chord显示不可用原因，不宣传已成功注册。输入录制先尊重IME，捕获层消费的事件不能再进入终端。

## 3. 通知、注意标记与系统权限

### 3.1 事件和状态

`NotificationEvent{event_id,kind,owner,operation_id,attempt_or_turn_id?,summary,result}`由对应服务发布终态；`NotificationPolicy{enabled_kinds,bell,tab_dot,quiet_hours,timezone,system_authorization}`决定呈现，不能从UI重绘推断新事件。

| 字段/事件 | 默认与动作 | 保留语义 |
| --- | --- | --- |
| notify.transfer_done | true，Job真实完成事件 | verifying/100%字节不通知成功；失败保任务内状态 |
| notify.reconnect | true，断线与重连结果 | 区分失败跳与恢复，不把重试每帧当新事件 |
| notify.ai_ready | true，成功形成最终答复的回合终态 | 工具等待/单轮流done不等于最终答复完成；失败/取消/远端待核实只保对应业务事实，不伪发回答就绪 |
| notify.bell | false，真实VT Bell事件 | 限制重复打扰；关闭声音不吞终端状态 |
| notify.tab_dot | true，后台输出注意 | 阅读所属内容后按实际阅读清除，不每行弹系统通知 |
| notify.quiet_hours | 默认22:00–08:00 | 本地时区，跨午夜；本页按已画时段输入实现，不另加无原型依据的开关 |

同一event/operation终态去重，切tab、刷新列表和重建控件不重复通知。后台来源按稳定owner显示；点击事件只激活原owner或已有历史/任务记录，不新建同名连接代替。任务/AI/断线状态属于应用事实，系统通知拒绝、勿扰或声音关闭不使其消失。

勿扰输入为HH:mm–HH:mm，小时00–23/分钟00–59；25:00等保raw错误。区间起含终不含，跨午夜为[start,24h)∪[0,end)，同起止为空时段而非隐式全天并给说明。系统时区变化重新计算后续事件；已发生事件不因时间调整重放。勿扰只抑制配置对应系统通知/Bell，保留错误、待审批及应用内标记。

时段编辑保`raw/lastValidTyped/startMinute/endMinute/policyRevision`，Enter只验证字段，Esc回最后合法值；invalid raw跨折叠/分类仍保留并阻整份Save，runtime继续已保存policy。Save不补发已被勿扰抑制的旧事件。通知点击以原event owner与record/operation ID定位已有内容；owner结束则开相应已有历史/任务记录或说明已不可用，不自动重连/创建同名目标。后台注意标记按可见且实际阅读的所属内容清除，不因切到任意tab或重建节点就清全局未读。

### 3.2 权限与UI反馈

保存事件开关保存用户偏好，系统授权另由真实通知能力报告；仅明确启用所需通知流程请求macOS权限。拒绝/受限状态如实显示并保应用内反馈，不写“已授权”。通知失败不会回滚已成功传输或AI答复，也不能让设置保存假失败；配置结果与平台权限/发送结果分别建模。

事件提醒、注意标记/勿扰为设置内独立卡片，遵循统一开关/输入/错误/tooltip规格；quiet-hours编辑及非法时间状态必须可达，不只保留折叠摘要。

## 4. 数据位置、凭据和诊断日志

位置页显示实际配置/记录/诊断路径，不把`~/.zerowork/`原型文字硬编码到不同实际路径；加载与保存使用同一解析结果，不读取可执行目录却写cwd。保留数据格式/权限事实与兼容来源，迁移旧路径须可恢复并显示真实结果。

凭据页区分“当前明文·权限600”“新输入仅内存”“凭据库/Keychain待接入”；不要把文件权限或模型已配置解释成加密、系统钥匙串已可用。可见路径/打开位置只作用于已授权的应用数据目录，不暴露secret正文。V0.1.3/V0.1.7的实际secret生命周期不被整合页覆盖。

用户已明确裁决：原“全部日志 · tar.gz”入口**只导出应用诊断日志**，不包含会话输出或快照；原型同步为“应用诊断日志 · tar.gz”。会话记录仍经V0.1.5的`.txt/.cast`独立导出。诊断导出与会话清理互不扩大范围；活动会话阻断清理，不阻断用户主动导出诊断日志。该内容范围已冻结，不再待决，也不新增范围选择或预览页面。

**来源和内容契约**：`DiagnosticExportPlan{operation_id,source_revisions,files[{file_identity,relative_path,read_handle,frozen_byte_length}],redaction_policy_revision,target_path?}`只枚举实际`AppPaths.diagnostic_dir`内应用产生的当前和轮转诊断文件。记录可含应用版本、时间、模块/错误码、连接阶段、任务/资源生命周期、脱敏后的故障事件；不加入终端正文、用户命令正文/命令历史、VT快照、AI问答/工具参数正文、附件、主机/设置原文件、凭据/API key/OTP/私钥或私钥口令。不扫描用户目录，不沿符号链接越出诊断根。导出是已有诊断记录的受控收集，不为了导出启动终端截屏、重新执行命令或额外采集用户内容。源日志中的敏感片段仍需脱敏，不能认为写入诊断目录就可无条件归档。

**触发与流程**：只有用户点击或键盘激活“导出应用诊断日志”才开始本次独立operation；启动、打开/展开设置、Save/Reset、记录快照、保留期清理均不生成归档，无后台预生成/自动上传。流程为显式激活入口→短暂刷新诊断写入并捕获文件身份/读句柄/字节边界→原生目标选择器→冻结本次目标→只读取捕获边界以内的诊断内容并脱敏→生成临时tar.gz→flush并原子发布→成功回执。捕获之后新增日志不隐式扩大本次集合；轮转不按同名新文件偷换来源。tar.gz可含来源索引manifest（应用版本、导出时间、脱敏策略及相对文件清单），索引也不写secret或会话正文。无诊断文件时显示“暂无可导出的诊断日志”，不回退去打包会话记录。此处归档与§7工程.app/DMG发布打包分开。

**取消、失败和验收**：导出不使settings dirty、不随Save/Reset执行；原生选择取消不生成最终包，不改变日志/会话记录/草稿。写入中取消待当前有界IO退出后释放读句柄、清除本次临时产物，既有目标文件保留。源读取、脱敏或发布失败须报告真实阶段及来源；不能静默漏文件后以“全部诊断日志已导出”成功，也不将半包发布成最终文件。显式重试重新冻结并说明当前来源，不后台自动重试；已有目标遵守原生覆盖确认，成功发布前不破坏旧文件。验收解包比较源清单及冻结边界，验证仅含诊断文件/安全索引，终端输出、快照、历史、AI内容和凭据均未进入包；覆盖取消、源轮转、源读取失败、磁盘/权限错误和新日志并发写入，原记录始终不被删除或改写。

会话txt/cast导出与清空已归V0.1.5；此处只提供其入口并消费同一RecordOperation，不重做删除算法。清空保活动会话门控、范围冻结、逐项结果、打开读引用与部分失败；诊断日志独立保留。导出/清理不能借当前筛选或新产生记录扩大目标。

## 7. 构建、打包与发布门槛

现有本地入口为`zig build`、`zig build test`、`scripts/verify_source_gate.sh`；该gate会验证tracked Zenit、重建SSH依赖并清理生成物，按代码变更与提交约束执行，不因本轮纯文档重组运行无关全套构建。

打包以实际`scripts/package_macos.sh`为入口：验证vendor→构建SSH静态依赖→ReleaseFast→生成.app的Contents/MacOS/Resources/Info.plist→ad-hoc签名→UDZO DMG→codesign校验。不存在可照抄的`zig build bundle`目标，产物大小不以旧8–15MiB估计作保证。Ghostty重编使用ReleaseFast、固定依赖和项目工具链；test-mode构建不得交付。

安装图标沿用设计规范§4.5同源Logo并核对.icns各尺寸。打包脚本目前版本号固定0.1.0，最终发布应从选定发布版本注入Info.plist/产物，且验证macOS14+/arm64及依赖许可。文档实施子版本顺序不自动创建tag、commit或发布；正式签名身份、干净机器安装、权限拒绝、启动/退出、卸载后用户数据边界均需实际验收。通过构建/签名只证明产物环节，不证明产品所有状态完成。

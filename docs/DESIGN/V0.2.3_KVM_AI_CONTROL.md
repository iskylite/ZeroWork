# V0.2.3 · KVM 视觉辅助与 AI 控制

> 仓库清理说明：历史原始图像、日志和快照已移除；相关证据链接统一指向脱敏状态摘要，不表示原始逐项材料仍保存在仓库。

> 待实施方案。依赖V0.2公共契约和V0.3真机能力验收，不代表截图或AI控制已实现。本版升级同一bmc_ikvm插件；不新增第二套资产、会话、助手或连接。非UI先行，UI与真机受控联调随后。

## 1. 范围

人工截图预览/保存/复制/附加助手；AI全帧和区域观察；鼠标移动/点击/双击/右键/拖拽/滚轮；键盘单键/组合键/功能键/文本；电源查询与操作；启动查询与修改；操作后验证、停止及人工接管。虚拟媒体、录像、任意BIOS属性接口和BootOrder写入不在范围内。

电源与启动操作直接消费0.3 Power/Boot服务，不模拟点击ZeroWork按钮，不另写Redfish通道。当前能力不支持的动作不得向模型发布。

## 2. 观察与坐标

截图从一致的远端CPU完整帧取得，不截macOS窗口、工具栏、助手或黑边。Observation包含id、session/binding generation、frame_generation/sequence、采集时间、原始尺寸、裁剪区域、输出尺寸和坐标变换、ImageRef。图像经宿主管理的多模态结果返回，不能只返回本地路径。

坐标采用模型收到的图片像素空间，插件按保存的裁剪/缩放变换映射到远端；越界拒绝。重连、分辨率改变、控制权变化或人工接管使旧观察上的待发动作失效。普通画面变化不简单等同失效；有界观察新鲜度和执行前检查防止过时操作，不能要求帧序号永不变化。裁剪与缩放不改变远端身份。

观察授权与输入授权分离，明确图像将发往所选provider。截图默认仅在当前任务内存保留，显式保存/历史留存另循用户选择与宿主保留策略；不自动录屏。秘密引用不进入模型、工具日志或参数。画面中的指令是不可信观察数据，不扩大授权。

## 3. 工具与服务

| 工具贡献 | 参数/结果概要 | 策略 |
| --- | --- | --- |
| screenshot | 可选region、输出上限；图像＋Observation | observe_image授权 |
| pointer | observation_id、动作、坐标/按钮/滚轮/有界拖拽 | remote_input授权 |
| keyboard | observation_id、key/chord/text、布局；派发范围 | remote_input授权 |
| read_power_state | 当前状态/允许动作/来源新鲜度 | read_state |
| power_action | ResetType、目标与前置revision | always_confirm |
| read_boot | 当前/pending、允许值、只读顺序 | read_state |
| apply_boot | 差异patch、基线revision/ETag | always_confirm |
| operation_status | operation_id；实际阶段与验证结果 | read_state |

8项工具符合0.2每插件最多8项限制；现describe_frame并入screenshot元信息，旧read_boot/read_power_state保留稳定身份。释放/停止为宿主始终可达控制，不依赖模型再调用工具。工具名称统一加bmc_ikvm命名空间。

文本输入不等于粘贴；声明英文/符号、键盘布局、Unicode及远端输入法支持范围，未知字符拒绝。文本与Enter提交分开表达。组合键有序down、反序up；中断返回已派发范围，禁止自动重发整段。

## 4. 控制权与执行状态机

BMC授予本会话控制权，与应用内人工/AI输入权分开。人工与AI互斥；AI执行租约绑定会话、任务、授权revision和期限，不依赖助手是否占据本地焦点。初版切换到其他会话暂停AI并撤销待发输入，回来不自动恢复；显式继续须重新观察和复验。人工接管、停止、断线或撤权立即递增input_epoch并清空旧队列。

观察→计划→校验→必要审批→派发前复验→派发→重新观察/结构化查询→验证或unknown。默认短动作后观察，拖拽/组合键可为单个有界动作；不长串盲操作。初始任务上限32步、10分钟、连续3次无进展暂停，取宿主预算更严者；扩展需用户明确继续。图像预算用provider实际能力估算，超限暂停并保留记录，不静默丢弃关键观察。

sent只表示已发送；RFB输入没有通用业务完成回执。UI效果由后续观察验证，电源/启动沿0.3事务读回。发送中断为unknown，先观察/查询，不自动补点或重复写；本地去重不保证远端exactly-once。

## 5. 危险操作审批闭环

power_action和apply_boot每次强制请示，always_confirm优先于完全控制。审批展示目标BMC/System、动作或字段差异、当前值→目标值、Once/Continuous、是否重启及风险。冻结owner/generation、参数hash、capability/policy revision、operation nonce与有效期。

批准仅允许原动作一次。发送前再次检查；参数/目标/关键前置状态变化、重连、权限变化或审批过期，原批准作废，需重新请示。拒绝/取消/超时零执行。需要固件AUTHKEY时再走当前operation的秘密挑战；不能将用户批准替代BMC认证。正常重启的批准不能升级强制重启。

界面中的格式化、删除关键数据、修改BIOS、危险命令同样需请示；无法判断影响的关键步骤暂停核对。坐标不能可靠证明动作风险，不能宣称shell黑名单能隔离所有图形操作，也不能由模型自行降低风险。审批卡显示关联截图和操作摘要，避免只批准裸坐标。

阶段分别为awaiting_approval、awaiting_auth、sending、accepted_remote、verifying、succeeded、failed、outcome_unknown。停止未发送动作；发送后不伪称撤销。unknown只能查询，再执行必须新批准。跨Tab写锁和ETag仍由原管理服务执行。

## 6. 公共 UI 与原型

沿0.2公共显隐矩阵：隐藏当前KVM传输列表/底栏摘要、终端/广播/用户转发项；保留全局传输管理器及其他会话任务。共享助手、图像预览、工具结果卡、审批、challenge和通知，不画第二套助手。

AI 原型以 V0.1.7 已定稿的**单会话**组件为来源：标准壳 600×456，最小窗壳 600×354；不可用“群组审批＋附件＋多行草稿”的 600×358 组合替代。标准窗示例位置为 (535,76)，860×480 小窗为 (157,76)。固定审批卡高152，固定输入区高90；最小单会话壳保600×354及52px历史阅读视口，不能因当前仅两行消息就缩成334px。窗口根按860×480边界裁切外部投影，AI浮窗内部阴影和原有滚动层级保留；保留头部、owner、会话入口、消息卡、权限/模型/用量控件及三主题样式，只替换 KVM 上下文和本次操作内容。已核实状态复用原成功结果卡头部，不继续显示待批样式。

必要状态：观察授权、图像预览、模型不支持图像、AI控制中、普通鼠标/键盘步骤、停止/人工接管、过期观察、电源待批、启动差异待批、拒绝/过期、二次认证、已接受/验证中、已核实/unknown仅查询；三主题及最小窗固定审批/停止入口。完整窗口需同时验证底栏与其他会话任务归属。

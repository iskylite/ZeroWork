## 1. 产出、前置依赖与范围

产出是能真实请求Provider、按明确owner管理对话和草稿、附加文件/选区/图片、校验/审批/执行四个工具、多轮回灌、停止与恢复的原生AI助手。正常、失败、取消、忙、超限、未知远端结果、关闭再开和混合组均属首版必做状态。

依赖V0.1.1的配置/事件/服务查询和原生外壳；[V0.1.2](V0.1.2_LOCAL_TERMINAL.md)的Local终端上下文、独立本机exec与系统文件选择；[V0.1.3](V0.1.3_SSH_CONNECTIONS.md)的SSH上下文、独立exec channel、身份与generation；[V0.1.4](V0.1.4_SFTP_TRANSFERS.md)的显式远程文件服务；[V0.1.5](V0.1.5_TERMINAL_HISTORY.md)的记录/只读视图隔离；[V0.1.6](V0.1.6_GROUPS_FORWARDING.md)的成员快照、pin排序及组工作区。服务“具备能力”与用户“批准这次调用”始终分开。

需求组覆盖I1容器22态、I2模型/权限/预算12态、I3附件/来源38态、I4回合/工具38态、S6设置11态，以及T2的`@ai`、Local助手与混合组衔接。原索引121个canonical状态三主题363根已通过Bridge逐根只读回读；本轮用户裁决新增的紧凑组审批组合另列§15.6并由根审计补入新节点证据。另有38个实际AI局部标本/主题、114辅助根，见§16与的来源路径/hash。这是确认页数据与契约核验，不表示原生已实现、Present真实手势或全部逐像素验收。

## 2. 所有权、入口与恢复

`AiOwner = session(SessionId) | group(GroupId)`，ID域互斥。每个owner独立保存对话、草稿、模型/effort/权限、附件、卡片、阅读锚、窗口矩形与调用。头部owner只读，不提供“当前/组”或人为改执行目标的下拉。

| 入口 | 结果与门控 |
| --- | --- |
| pane顶边浮条、⌘J、AI入口 | 打开/收起捕获owner助手；无session空态或SFTP文件页不伪造终端助手 |
| 终端中键菜单“询问AI” | `term-context`根223:330803/动作358:1388718、`terminal-group-menu`根342:1254554/动作358:1497199；复用同一打开控制器，捕获点下pane/视图owner和选区来源。真正组视图打开group助手，独立成员tab打开session助手；有选区按已有选区预览→附加草稿，不自动发送，不在关闭菜单后重取active tab |
| `@ai`无参数 | 仅打开原owner；不自动采集文件、请求模型或执行 |
| `@ai <问题>` | 复用composer提交控制器，捕获文字/owner；无模型/忙/超限保留问题及原因，不丢输入 |
| 概括终端报错 | 只填问题；明确发送后使用原选区或最近输出，不自动发请求 |
| 分析应用日志 | 先明确选择日志、预览附加回草稿，再由用户发送；不暗读某个默认路径 |
| 打开独立成员tab | 恢复该session助手，即使它属于某组 |
| 进入真正组工作区 | 恢复group助手，摘要覆盖所有有效成员；pin只排序，不决定执行/文件来源 |
| 切tab/收起/拖动/放大 | 呈现改变，原回合继续；结果回到发起owner，不投到后来选中的tab |
| `×`关闭 | 请求停止原owner当前turn，旧审批失效、历史保留；再开恢复原owner历史，新提问用新turn |

混合组显示本机/远端身份；本机执行卡必须标“本机 · zsh”、捕获cwd、完整命令与影响。Local不能回退到活动SSH；`terminal=true`不自动授予exec/文件能力。独立SFTP拥有文件服务也不因此获得终端助手或exec。

## 4. 模型、Provider、权限和上下文入口

### 4.1 模型与effort选择

2026-10-23 用户最终裁决：模型与推理共用一个composer锚定浮层，宽336、外padding8、区域gap6。顶部是24高的普通“模型列表”标题与22×22关闭X，不做卡片，不含搜索。中间只有一张模型列表卡，按provider分组，每组可以有多个模型，全部直接展开，不含折叠；provider头和模型行各30高，卡片最大180高，内容超过后独立滚动。底部是另一张40高的推理滑块卡，内padding6，滑轨/刻度区域28高，不再加入标题行、说明行或独立开关；不支持时按内容收缩为30高说明。整个浮层最大272高，并按窗口边界翻转/平移。

滑块仅显示当前模型实际可用项：档位模型显示合法离散档位，开关模型显示“关闭/开启”两档；同时支持关闭和档位的模型把“关闭”列为首档。选择模型后面板保持打开，可直接调整滑块，composer chip立即在宿主确认后显示选值。箭头/Home/End与指针均只选择有效档。没有搜索、折叠或独立switch，不采用之前讨论中的三卡片和多次操作方案。

模型发现先按实际协议读取：OpenAI兼容GET base/models，Anthropic GET base/models并处理分页，Ollama GET /api/tags加POST /api/show。能力字段优先采用接口信息，缺失项由models.dev公开JSON补齐，24小时刷新；provider+模型优先，provider未知时使用模型名、命名空间去除和最长边界前缀匹配，冲突不任意选。目录只补能力，不能改变接入协议。MiMo Chat Completions开关为thinking.type=enabled/disabled；OpenRouter为reasoning对象；Ollama为think；Anthropic已验证元数据声明的effort使用output_config.effort。后台拉取不阻塞UI、不向公开目录发送接入密钥，配置revision变化丢弃旧结果；运行turn保冻结快照。

`ai_effort_limited`只允许所声明子集的刻度，键盘箭头/Home/End与鼠标均跳过不支持档；保留刻度文字不等于每档可选。`ai_effort_fallback`明确显示“中 · 已回落”，因此能力变更后的合法回落必须可达，不能把“不可静默猜测能力”扩大成“永不回落”。实施规则：下一请求当前档失效且合法集合非空时，按`low < medium < high < xhigh < max`取不高于原档的最高支持档，无此档取最低支持档，记录旧档/新档/原因并显式提示；当前运行turn不变。能力未知或合法集合为空则禁用并说明，不用回落掩盖错误配置。滑条pointer-down冻结起始档，拖动预览，松开提交合法档，Esc/失焦回起始档。

| adapter种类 | 请求协议和能力边界 |
| --- | --- |
| anthropic | Messages流式adapter；effort按具体模型与已验证adapter能力映射，不固定全型号预算表 |
| openai_compat | Chat Completions兼容流；网关/模型显式声明支持字段，兼容协议不代表vision/effort全部可用 |
| ollama | 本地chat adapter；无声明推理能力则禁推理入口，本地端点仍需合法配置与实际可用性判断 |

应用接口为`Provider.chat(ChatRequest, DeltaSink) -> ChatStats`及`models -> ModelInfo[]`。ChatRequest冻结model、effort、system、messages、输出预算和timeout；现有默认max_output4096、provider请求timeout60秒属于实施默认，不是原型性能保证。具体API字段/endpoint拼接由adapter实现时验证，不通过修改UI默认值假装所有协议统一支持。

### 4.2 两种权限与分类

权限chip只有“确认后执行/完全控制”。前者可靠证明只读的调用可自动、写操作逐调用确认；后者仅当前单session scope、插件能力和策略允许时自主写。group写即使只指定一个成员仍逐调用确认；禁止项任何模式都不能执行，只可复制。UI批准的是具体call，不能选择另一目标。

管线为`工具/参数/scope/能力合法 → 禁止规则 → 可靠只读分类 → 模式/组判定 → 审批 → 派发前复验`。禁止项至少覆盖毁根/home、格式化设备、向块设备写、fork炸弹、shutdown/reboot/halt、递归全权限等已有策略；不能只靠首个只读单词白名单放行`cat...; rm...`、重定向、管道或子命令。不能可靠分类的内容按需确认/拒绝，不当成已证明只读。尚未接通的用户白名单模板编辑器不属于首版新增入口，也不能被描述为已有授权机制。

审批固定显示原owner、完整命令、cwd已知/未知、每目标身份及本机/远端、风险与影响，提供批准此调用/拒绝/复制。批准不等于执行完成，exit0不等于远端业务已收敛；失败分析属于同助手后续回合。

### 4.3 预算与来源分解

用量popover按历史、引用、终端选区/最近行、身份/工具摘要分解；保存modelWindow、各来源estimate、预留输出、usageActual和overLimit。总预算为`历史+系统/工具声明+本次文字+显式附件+终端/身份摘要+预留输出`；文本bytes/4仅估算，provider真实usage另记。新自动采集上下文预算为窗口5%、最多4k tokens，不是“窗口5%行数”，也不是裁显式引用/总历史的授权。

示例数值的口径须可复算：`42,000历史 + 1,024引用 + 2,560终端 + 416身份/工具 = 46,000`，“本次4,000”是后三项小计，不能再加一次；超限例同理为`197,200 + 4,000 = 201,200`。用量主值显示当前输入估算/模型窗口，输入本身超限显示1,200；发送门控还须把预留输出计入完整请求预算，因输出预留才超限时在同一原因区明确输出预留及缺额，不把输入占用谎报成已含输出。各来源去重后归到一个分项，系统/工具声明与本次文字若并入摘要须有内部明细，不重复统计。

来源优先为明确附件/引用→原选区→最近纯文本行→cwd/主机身份→全部有效组成员摘要，pin只排序。去控制序列和时间/状态装饰，不改变原终端。可选脱敏按保存配置执行，IPv4/IPv6/host/user等相同原值同次文档映射同占位；秘密/OTP/API key从不作为普通上下文。

窗口未知显示未知、禁发并引导补配置，不能画0%安全；超窗禁发保草稿与附件，显示实际分解/超出量，管理引用或新对话，不能自动删最远历史继续。图片估算用adapter能力，不能把PNG压缩字节/4冒充图片token。用量示例201200/200000和23%不是固定显示值。

## 5. 四类附件与来源流程

统一附件184×44/r8，28×28预览位于8,8，两行身份/元信息及22×22移除位。附件区高56、横padding14/竖6、距输入4，多附件单行独立横滚。选取/替换/移除在同一行；预览104高，长内容内部滚动，不撑外壳。路径、来源与截断常显；重名附件按stableId，不按文件名误删。

| 来源 | 完整流程/状态 | 限制与异常 |
| --- | --- | --- |
| `/`或＋远程文件 | 原owner→可读来源session→绝对路径/目录下钻/上级/过滤→选文件→读取预览→加入原draft | 默认4096、最多65536字节；显示原大小/实读/截断。只列group实际可读成员；离线禁选并说明；来源选择不改工具目标 |
| 本地文本 | 原生文件选择→内容UTF-8/大小校验→预览→附加 | ≤64KiB；不只看扩展名；ZIP/NUL/格式/权限/96KiB超限拒绝且不加入；BOM规范化需有说明；取消保草稿 |
| 终端选区 | 捕获原session/generation/时间/纯文本及行数→预览→附加 | 不读取后来active选区；移除不清终端选区；发送后不可变 |
| 本地图片 | 本地选取/粘贴/drop→来源预检→读取解码processing→ready/error→发送后历史 | 宿主每draft最多4张图片、单张10MB；vision与adapter更严限制再取交集。处理中不可重试，可移除/等待；已接受附件的error才重试；真实mime/格式/尺寸/字节均校验并显示实际限制 |

远程目录`idle/loading/ready/empty/error/disconnected/cache`与文件预览`selected/reading/ready/error`分开。换来源立即增加sourceRevision、清旧路径/选择/缓存投影，切该来源已知目录；原问题保留。目录失败和文件读取失败各在原控件反馈，可重试；缓存注明来源/采集时间/新鲜度，不能当实时。路径不合法、无结果和无文件记录不能合成空成功。

资源入口与状态的连续行为如下，均在原owner内完成。单个`/`作为独立当前词（行首或空白后）触发资源候选；普通路径内部斜杠不触发，采纳只替换本次triggerRange，Esc恢复原草稿/插入点并抑制同revision重开。＋的四项为选择图片、选择本地文本、引用远程文件、粘贴图片；菜单/选择器取消均不读取未选择文件、不创建附件。资源popover中Esc/外点只关闭并回composer，不停止原turn。

目录项选中不等于读取或附加：点击文件进入`selected`，路径箭头才读取默认4096字节预览，`ready`后附加；上级/换路径/清除先清选中文件与预览。目录搜索是当前目录过滤，`no_results`保query并提供清除，不冒充空目录；相对路径`logs/worker`保raw并报绝对路径错误，不自动补`/`。目录EACCES只重试list，文件预览EACCES只重试原source/path/readLimit；重试不暗切来源、不提权、不重连其他会话。缓存键至少含SessionHandle/sourceRevision/规范化路径/读取上限与采集时间，过期结果不能覆盖新的目录或预览。

本地文本选择器读取真实用户所选文件；原型虚拟文件名不是可直接内置的产品内容。服务先检查或有界读取到上限+1以判超限，不无界读完整文件再只裁UI；64KiB合法、64KiB+1拒绝，96KiB示例不自动截断附加。附加后预览使用已捕获contentRef，关闭预览只释放视图引用，“保留附加”不再新增同一附件。发送历史独立持有原内容；终端选区中的真实日志时间属于VT文本可保留，旁路UI时间槽须剔除，移除附件不清原终端选区。

独立局部标本`359:1538484`把“最多4张图片 · 单张10MB”明确为宿主附件上限，不是可省略示例。实施将UI的MB按十进制`10,000,000`字节解释（这是字节口径补全，原型未标字节数）；draft内ready/processing/error图片槽均计数，已发送历史不占下一draft名额，文本/远程引用不计图片张数。Provider更严的图片数量/字节/尺寸限制取交集，须说明当前限制来源，不能因支持vision就忽略上限，也不能把识图能力当通用无限图片能力。

数量超限/所选来源已能判定的格式损坏进入`Attachment validation`拒绝态，**拒绝的新来源不加入draft**，显示“管理附件/重新选择”，原文字和既有附件保留。选择一次多图先预检本批数量/基本类型/字节，整批不合法则不暗中只加前几张；选定并接受为processing后才出现的异步读取/解码错误则保error chip，按现有错误态重试或移除。两种错误阶段不能合并成“所有坏图自动删掉”或“所有被拒图都留下不可发送chip”。管理附件只定位原draft附件横条及其移除/详情，不另开任意文件管理器；重新选择显式回同一来源选择器，取消不改变既有draft。

文件加入draft时保存内容快照或能稳定重读的不可变contentRef，不能只存路径、发送时无提示读取被替换的新文件。选择器/读取/解码都捕获owner、attachmentId和revision；取消/移除/换源后晚到只释放，不复活附件或写新owner。发送前仍读取中/失败/不兼容禁发保文字、原model与其他附件，用户显式移除或换识图model，不自动换模型。

草稿和已发送message分别持有引用；移除draft只释放其引用，不破坏发送历史。采集失败不能静默删用户附件后提交剩余问题。Local文本/图片经宿主明确选择，AI模块不直接import任意本机文件API；remote-files工具不能改名后读本机路径。

## 6. 四工具schema、能力与结果

模型只能选宿主提供scope内SessionId，不能传generation/插件裸句柄。每工具独立schema，拒绝未知字段、错误类型、NUL、空/重复/越界session_ids；最大目标数为当前声明的16，不截断大组，不暗拆成沿旧批准的新调用。

| 工具 | 参数与校验 | 最小结果 |
| --- | --- | --- |
| `read_terminal` | `session_ids`必需；无command/path；每目标terminal_context能力，读真实输出快照 | session/generation、采集时间、行数、纯文本、truncated/error |
| `list_remote_files` | `session_ids,path`必需；绝对远程path、无NUL；每目标remote-files能力；非递归有界列表 | 来源、请求/规范化路径、条目/类型、缓存或读取时间、分页/截断、错误 |
| `read_remote_file` | 同上，max_bytes可选默认4096，整数1–65536；拒目录/设备/不支持二进制 | 来源、请求/实际路径、原大小、实读字节/编码、truncated、时间/error |
| `run_command` | `session_ids,command`必需；trim非空/无NUL，完整程序；只走独立exec，捕获cwd或明确未知 | 每目标transport/cwd、状态、stdout/stderr、exit?/signal?、elapsed、truncated、清理/unknown |

Local的read_terminal可用；run_command要求显式local exec，使用独立本机进程，不向交互zsh模拟按键。SSH exec用独立channel，不注入用户shell；remote-files经对应服务，路径中的空格/引号是数据，不拼接裸cat/ls。SFTP-only不因文件服务被授予终端或exec；无能力拒绝，不换最近会话代办。

宿主捕获`TargetSnapshot{SessionId,generation,pluginId,capabilities,displayIdentity,cwd?}`支撑卡片/审批。每目标仍须属本owner；会话助手仅自身，组助手可选一个或多个实际成员，不强制全组。删除成员/新generation使快照失效；用户不能在审批下拉中改模型指定目标。

AI调用的宿主执行默认deadline为60秒、stdout+stderr合计64KiB，冻结到请求；60秒是实施补全值，覆盖`ai-tool-long-output`/`ai-resize-reading`已画的48秒仍运行状态，并非原型标注。V0.1.2/V0.1.3基础Exec原有30秒默认可保留，但ExecRequest必须允许宿主传入本次有界deadline，不能把基础默认当产品硬上限而删掉48秒状态。模型schema不接受任意timeout/cap，Provider每轮60秒网络预算与exec执行deadline分别计时；等待工具不消耗尚未开始的下一轮Provider网络请求预算。达到输出上限先标截断并按执行服务策略停止/清理；SSH command还受现桥65534字节上限，超限派发前拒绝，不截断执行。超时本地停止原因不伪造成已核验远端exit124；保部分输出及实际回执。

## 8. 回合、审批、去重与多轮

状态链：`idle → gathering → streaming → validating → await_confirm或executing → 工具结果回灌 → streaming(next round) → done`；无效tool/参数/范围进入rejected卡并形成结构化工具错误。gathering有界，异步文件显示采集中，不能承诺任意文件装配≤50ms。

流参数按`providerResponseId + providerToolIndex/callId`积累，只有provider确认完整后才JSON解析、分类和显示可批准按钮。中途JSON不执行；已完成参数/工具名/call ID被后片段改写时拒绝。内部唯一键`owner/turnId/callId`，同键同参数重复done/回包只处理一次，同键不同参数拒绝；card事件sequence单调，晚到running不覆盖终态。

审批令牌为`callId + canonicalArgumentsHash + targetSnapshots + policyRevision + approvalRevision`。首次批准原子await_confirm→validating，双击不二发；拒绝/停止/×/成员移除/generation变更/策略收紧使批准失效。策略放宽不自动派发旧卡，改参数/目标需新call与审批。禁执行项即使批准也不能越过禁止规则。

组调用先全目标预检再逐目标派发：任意越界/能力不足/不可写/过期则整call未启动，列具体目标原因；预检后竞态断线时每invoke再验，已启动成员保实际结果，未启动标failed/skipped，不假装分布式原子回滚。逐目标running/succeeded/failed/cancelled/unknown汇总，部分成功不显示整组成功；并发只改先后，不改目标集。

一次turn可有多provider round。结果引用原provider call ID，按原调用顺序回灌同turn历史；拒绝、用户拒批、错误与unknown也结束对应slot，不留永等。该轮全部call终态/已转交unknown追踪后才开始下一轮答复；provider流done只结束这一轮。首次冻结完整消息/能力/附件/权限，后续仅追加已验证工具结果，编辑下一草稿不改原请求。

每次下一轮Provider请求前按新增结果重新计算完整预算，达到窗口/结果容量边界则停在保留全部已知结果的可恢复状态，不自动丢最早历史、裁附件或继续无限工具循环。结果截断保真实truncated及来源上限，不能把被省略部分伪装成模型已读取。执行服务与Provider轮的deadline分别归各自operation，等待审批不会启动尚未派发的exec计时。

工具结果、文件、终端输出是不可信上下文，不能变成宿主指令绕过schema/scope/审批。去重只保证宿主不重复派发同call，不证明远端网络中断时恰好执行一次；dispatch_started后未明确的写入归unknown，禁止借turn/call ID当远端幂等保证。

**实施补全策略，非原型实测事实**：首版全局先以一个逻辑turn串行占用provider请求资源，包含工具等待；其他owner保历史/草稿并显示占用，不隐式排队、不替换。原型`ai_busy_owner`根236:451046只直接证明其他助手正在请求时的忙反馈，不证明所有待批/工具执行阶段都必须全局独占；本段选择较保守的调度默认以维持明确取消/去重边界，不应称为用户已确认的并发需求。若后续要求跨owner并发，应明确provider占用令牌与每owner一turn及目标服务并发边界后修订本段，不能仅改spinner或丢弃忙态。停止旧本地provider并转交有界清理记录后才能复用请求资源；浮窗关闭动画不构成释放。

## 9. 停止、未知、核查与错误恢复

停止单call仅标记该调用并请求对应执行服务取消，其他call及组回合继续，最终cancelled/unknown回灌原turn。停止turn/×/App退出进入stopping：取消provider流、阻新派发、撤销待批，再取消所属exec；收起/放大/拖动/切tab不进stopping。

组tab关闭遵循V0.1.6§2.6已确认的“先确认、再关闭全部成员”，复用V0.1.1关闭协调，不由AI窗口×代替。组确认取消前，组/各成员AI仍保持原状态；接受冻结GroupClosePlan后，阻该组新派发、撤销待批并只停止一次group owner turn，各成员session owner turn在对应成员关闭hook停止。hook回执带原GroupId/SessionHandle、turnId与关闭operationId；多个成员引用同一个group turn时不能重复取消、提前释放ledger或把晚结果写入别的owner。成员关闭部分完成时，已知结果和远端unknown分别归原审计/核查记录，失败成员保持真实可核查状态，重试关闭不复活旧批准、不重放工具。

每handle保存原owner/generation/call及可验证进程身份；本地句柄释放和远端进程退出分开。不能认为向无PTY exec写`\x03`必然SIGINT，不能假设所有远端有setsid。取消幂等，等退出/close回执再释放fd/channel/缓冲；无法核验显示“本地已停止 · 远端状态待核实”，保部分输出。只有证据确认才标相应资源已清理，已提交业务修改不回滚。

无回执远端记录转为不持有本地handle的诊断追踪，避免UI关闭丢worker引用。重连后可只读核查，不自动补杀旧pgid或重放写入；显式清理也重新验证进程身份/授权，防PID重用。核查仍绑定原目标，scope/generation失效说明不可核查，不连接另一个同名主机冒充。

| 异常/用户动作 | 界面与恢复 |
| --- | --- |
| 未配置Provider | 面板内去设置/本地Ollama引导，终端继续可用 |
| 网络/超时/429 | 保部分答复、错误和重试次数；自动退避遵守Retry-After与总timeout，不无限等待 |
| 重试已有文本 | 新attempt显式分开，不把两个开头拼接成一句；已有工具计划/派发的round不能从头自动执行 |
| 仅重试答复 | 同owner/turn快照及call ledger延续，复用已知结果，已完成工具不重放；新写建议只能新计划验证/审批 |
| 编辑问题 | 保原turn/部分输出并回填draft，不自动发送 |
| 重新生成计划 | 新turn/new call ID，重校验/新批准；未知写入先只读核查 |
| 断线/目标退出 | 已有上下文只读可看；对应工具不可执行/已发结果unknown，本地资源取消；其他组目标结果保留 |
| 参数不全/未知tool/越界 | 原call卡原因、禁止派发，不退回普通文本当命令执行 |
| 附件失败/不兼容/预算超限 | 保文字/附件/model，原位修复/管理引用，不自动换模型/丢历史 |
| 关闭再开 | 恢复原owner历史、已提交调用结果、失效旧审批和unknown标记，提供只读核查/新问题 |

请求失败的实施重试预算与原型`3/3`、`1/2/4s`保持一致：初次请求后最多3次自动重试，基础等待依次1/2/4秒，所有尝试/等待共享本轮60秒；仅重试适合继续的瞬态Provider错误，不重试参数错误、无权限等永久失败。429还受真实Retry-After约束，取更严格等待；超过本轮剩余预算就结束该轮并保冷却deadline，冷却结束后仅恢复手动按钮，不自动排队请求。倒计时以monotonic计算，不把示例30秒硬编码为所有429。手动“仅重试答复”生成新attempt预算但保同turn快照/已完成call账本；“编辑问题”只回填draft；“重新生成计划”才创建new turn/new callId并重新校验/审批。三者不能共用一个会重放写命令的重试函数。

## 10. AI设置字段、事务与生效

设置面板/保存栏/跨分类草稿来自V0.1.1，AI新增域包括Provider卡、连接配置、model列表、权限、上下文、附件和其他行为。首个Provider卡默认开、连接配置折；每model默认一行摘要，仅新增/编辑项展开，原位新增模型而非另弹独立设置窗。字段原始输入/最后有效typed值与错误都保留。

Provider卡的“已配置/禁用/待保存”是配置资格投影，不当网络状态或额外连接开关；不据schema字段另加原型没有的按钮。内联字段Enter只校验/提交该字段draft，Esc回其最后有效值，不保存整份Config。新增Provider保已有卡/默认值并可折起“已有Provider”；新增model取消只撤该新行。新模型未保存不进入请求可选列表、不替代已保存默认；保存并成为合法配置后方能参与默认选择。删除最后/当前默认前须在draft指定已有合法替代，未提交前原baseline和活动turn继续可用，不能因卡片编辑立刻丢失默认。

| 字段 | 校验与生效 |
| --- | --- |
| Provider id/name/kind | 稳定providerId不随显示名改；kind仅anthropic/openai_compat/ollama；启用需合法endpoint及至少一个有效model |
| endpoint | 带host的http/https绝对URL，无内嵌账号/口令、fragment、NUL；Ollama本机http可用；adapter处理base path避免重复`/v1` |
| api key/凭据 | 按adapter是否必需校验，不能一律要求本地Ollama有key；不进日志/tooltip/AI上下文；存储能力与600/Keychain标签如实 |
| 默认Provider/model | 已配置启用；model属于该Provider且有效；删除/禁用默认先在draft指定替代，删最后model需禁用Provider或补model |
| modelId/window | ID trim后非空、同Provider唯一，保存完整ID；window正整数且在adapter可表示范围内，0不是无限 |
| reasoning/efforts/vision | reasoning与vision独立；开启reasoning至少一档且与adapter支持交集非空；关闭保草稿档位但不发推理字段；只五个合法离散档位 |
| permission | confirm/auto内部值对应两种明确UI语义；组写仍确认，禁止优先；未派发授权遇策略收紧作废 |
| 脱敏/来源/附件行为 | 保存明确配置，下一次装配生效；只支持真实接通来源/adapter，限制/禁用有原因，不伪造通用图片上限 |

“已配置”只表示本地参数合法，不证明联网、model存在或配额可用；保存不自动发Provider请求。未配置禁用槽不阻其他页保存；全无Provider可保存外观，AI入口引导，不暗选未配置项。保存失败保本域/其他页draft与有效预览；不因卡片显示“待保存”就已改变运行Provider。

运行turn用原配置/模型/权限/附件快照；选model、effort、配置保存只影响下一请求。策略收紧可以撤销未派发批准，不能扩大旧授权。脱敏不回写历史消息；删除draft附件不影响发送历史。OwnerStore运行期草稿/矩形和历史分别保留，不能声称重启自动恢复活请求或旧批准。

默认值与owner选择的优先级须显式保存：`nextModel/nextEffort/nextPermission`分别记`origin=default|owner_explicit`和来源配置revision；新owner从已保存默认初始化。全局默认保存后，仅仍跟随default的owner更新下一请求；用户已明确选择且仍合法的owner值保留。显式模型被删除/禁用或变不兼容时保问题/附件并显示不可用、禁发，用户修复选择，不暗跳到另一Provider。effort因合法能力子集变化的显式回落按§4.1反馈；当前turn始终不变。权限默认是后续请求的初始选择，禁止规则/组写约束是不可由owner模式绕过的策略；两者的revision与失效原因不能混写。

审计按turn记录时间、owner、call、目标、完整命令判定、策略revision、审批和结果摘要；API key、密码、OTP、认证回复不写普通日志。附件内容保存引用，不在每条事件重复无界落盘。审计失败/Provider错误/执行清理错误分开呈现，不能用日志落盘失败杀交互终端。

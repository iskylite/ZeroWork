### 0.1 本版最小交付闭环

用户在当前助手发起任务 → 按需新建／复用子对话 → 父子各自串行接收输入、按实际能力执行 → 父级收到有证据的报告并汇总 → 任务结束不再调用模型或持续重绘 → 解绑保存并销毁 Worker。技能与 MCP 都是此闭环中的受控能力来源，独立安装／连接成功不改变 Agent 身份和附着范围。

先复用已经落地的对话、显示快照、用量、查询／执行、输入和关闭服务；只新增无法由这些机制表达的子关系、任务门禁和能力适配。父级能直接完成的简单工作不必创建孩子，设置和工具仅决定需要子 Agent 时的上下文／复用方式，不新增“所有任务必须多 Agent”的模式。

## 1. 产品模型与不可变边界

### 1.1 一种附着主体，按工作需要协作

| 对象 | 职责 | 范围与生命周期 |
| --- | --- | --- |
| 单会话 Agent | 当前连接的查询、分析和执行，可派生明确子任务 | 只附着当前连接；不管理其他会话／组 |
| 会话组 Agent | 组内直接执行、分工、依赖协调及汇总，可派生明确子任务 | 只附着当前组；没有启用集群或第二套纳管关系 |
| 子 Agent | 在独立对话中完成父级分配的工作，可被用户继续交互、按策略复用 | 唯一直接父级；范围为父任务子集；第一版不能再派生子 Agent |

单会话与组是附着范围差异，不是两种需要转换的角色。组成员是业务连接，不要求每个成员同时常驻一个后台 Agent。一个子任务可负责组内一个或多个获准成员，不按机器数量机械创建 Agent。简单工作直接执行，同类多目标检查复用原工具；仅为独立上下文、可独立验收或并行收益拆分任务。

“会话组 Agent 承担集群协调”仅是职责描述。没有 ClusterId、集群成员表、单集群归属、集群页面或跨组路由；用户先通过已有界面组织会话组，Agent 只消费当前真实范围。

### 1.2 配置、上下文与 Worker 分离

- **逻辑记录**：Agent 身份／父级、模型偏好、上下文模式、复用策略、技能和 MCP 选择。
- **对话记录**：ConversationId、历史、草稿、附件／摘要、输入回执和必要任务／执行证据。
- **Worker**：执行模型和工具循环的临时运行对象，含 Manager、请求现场、取消、Broker、运行期工具表与服务引用。

首版只强制**成功解绑后销毁所属 Worker**；已绑定但空闲时允许保留现有运行对象，不强制另做空闲回收策略。若实现空闲回收，必须保留现有停止后只读核验／回答恢复所需事实，不能因释放 Manager 静默丢失这些入口。再次工作按需创建 Worker，不复用旧线程、Provider binding、输入租约或批准。

现有 `Runner` 同时承担稳定控制槽位和运行对象，后台 AiHost 还持有其他执行资源。最小改造是让稳定槽位保存 AgentId、轻量 backend 工厂／窗口登记及 `worker?`，把 Manager、Broker、请求快照／桥等移入可释放对象；不必删除整个槽位后重做现有命令查找。`runnerFor`、`managerRef`、Bridge pump／released／destroy 和 UI 绑定同时适配空 Worker 状态。保留小型登记不等于保活 Worker；不能只清 thread、或仅释放 Manager 后留下后台 AiHost 继续持有请求和回调。

### 1.3 统一权限硬边界

所有 Agent 均不具备发现、读取或管理其他连接会话／组的能力；不存在工作区 inventory 扩权、跨组委派或一次允许的旁路。用户的全局导航和历史回看权限不授予模型。静态主机配置与真实连接保持不同实体：已有受控静态 source／组内新建路径继续有效，不由此开放其他运行会话或全局配置修改／删除。

实际目标范围 = 当前附着范围 ∩ 当前任务授权范围 ∩ 子任务分配范围 ∩ 当前目标能力。权限模式、上下文继承、复用、技能、MCP 和用户对子 Agent 的输入都不扩大该交集。历史可读不等于历史目标可再次执行。

## 2. 子 Agent 的上下文与复用

### 2.1 新建时的上下文模式

| 模式 | 初始化内容 | 默认 |
| --- | --- | --- |
| `independent` 独立上下文 | 当前系统约束、获准技能／工具目录、任务说明和明确交付的必要材料；不复制父对话历史 | 是 |
| `inherit` 继承上下文 | 上述内容，加父对话在创建时的可用稳定快照；记录源 ConversationId／内容 revision／截止事件 | 否 |

继承是一次快照，之后父子各自增长，不持续镜像。只复制合法闭合的工具对或可证明的稳定前缀，当前未闭合调用和秘密不进入新模型历史。历史工具／连接引用标记为历史环境，不签发权限；任务需要的当前事实重新查询。快照超过上下文预算时使用有来源的有界材料／摘要或明确拒绝，不能无提示截去关键约束。

模型在当前 Turn 调用创建工具时，`Record.history` 可能仍是上一轮 checkpoint。继承应由拥有当前 Loop 的执行端冻结已经消费的用户输入和已闭合调用前缀，再交给控制端保存；排除包含本次创建调用的整个未闭合 assistant 工具批次，不从 UI 消息拼接，不等待包含自身的回合结束，也不悄悄继承成过时 checkpoint。沿 `wire_history.History.copy` 的合法性与图片引用规则，按子任务交付范围投影；无法安全拆分的原文由父级提供明确材料。

设置提供默认模式，创建工具可由模型显式覆盖；省略参数才使用保存的默认值。设置是默认策略，不是禁止覆盖的权限开关。生效值和快照来源写入创建回执，子 Agent 详情可查看。

### 2.2 复用与新建分别表达

| 参数／设置 | 含义 |
| --- | --- |
| 默认复用策略 `new`／`prefer_reuse`／`model` | 每次新建／优先复用／由模型决定；默认 `new` |
| 新建参数 `reusable` | 本子 Agent 是否可被模型在后续任务中选作复用对象；缺省依默认策略，`model` 且模型未决定时保守按 false |
| 复用参数 `agent_id` | 精确选取已有子 Agent，保留原配置和原对话上下文，建立新任务；不能按名称猜测 |
| 新建参数 `context_mode` | 仅用于新建初始化；复用时不接受重新初始化历史 |

`prefer_reuse` 提示模型先查询合法候选；由模型使用稳定 ID 明确选择，宿主不按任务文字相似度自动匹配。无匹配才新建可复用子 Agent。`new` 为默认创建不可自动复用的记录；模型可以明确覆盖默认值。复用前检查同一父对话的子关系、当前合法父绑定、候选标记、无活动任务／清理，以及新任务的 scope 和模型能力。忙碌对象返回明确状态，不静默并发写其对话或另建副本冒充复用。

复用不恢复旧任务，不沿用旧预算／批准／租约。新任务使用原上下文并带入本次任务材料，创建新的 Worker generation。若模型希望新的独立／继承上下文，应新建子 Agent；补充父级最新信息走有来源的任务材料，不覆盖旧历史。

本地工作区按 [V0.4.3 PATCH §6.2](V0.4_PATCH_AI_LOCAL_WORKSPACE.md#62-子对话新建复用与继续)：新建时捕获父级目录，复用／用户继续时保留并重新校验子对话自己的目录；父级后来更换目录不自动改写孩子偏好。创建／复用回执返回实际目录，本次任务若要使用其他目录须提供明确基准。文件能力按当前宿主、父任务与子分配重新求交，不沿用旧批准。

候选只属于同一父 ConversationId，不建立全局池。子记录分别保存不可变的创建父 AgentId 和父 ConversationId，当前执行父级从该父对话的有效 binding 获取。现有 replay 后原 Agent 不再可执行，恢复原对话可能产生不同 AgentId，因此不能强制其等于创建父 ID，否则重启后永远无法复用。

用户显式恢复原父对话后，子配置／上下文可重新列为待校验候选；只在明确新任务时取得当前父身份和范围，不继承旧目标／子绑定或自动运行。换到不同业务环境的历史引用仅作记录，精确目标必须在当前范围重新选择。复制父对话不复制子 Agent 身份、活动任务或控制关系，必要已交付摘要可作历史；普通恢复／复制命令不能单独把子对话提升为主对话或挂到另一个父 ConversationId。

### 2.3 用户继续交互

`reusable=false` 限制模型自动分配后续任务，不限制用户在子 Agent composer 明确继续。当前任务活动时，输入按该子对话的 queue／steer 规则处理；已结束时，明确发送建立新任务并沿用原上下文，不复活旧 Task。

继续任务仍须有有效父对话及当前范围。原根任务已终结时，宿主登记新的用户来源根任务／子任务关联，保留历史父级而不重开旧根任务。父对话未绑定时只读查看；先通过父对话现有恢复流程建立合法绑定，不因子弹窗发送而隐式接管连接。超出已分配子范围的要求须由用户／父级明确修订分配，不能直接获得整个父范围。

### 2.4 配置解析、复用检查与保留

新建时按“工具显式参数 → 当前已保存默认值”解析 context_mode／reusable；模型／effort 未指定时冻结父助手当前有效生成选择，指定时仅允许已配置且具备所需能力的模型。`prefer_reuse`／`model` 是给模型的分配策略，不由宿主暗中替换 create 为 reuse；最终选择和来源写回执。父级后续切模型不重写既有子配置，失效模型要求重新选择，不静默更换。

复用除身份／空闲检查，还核对上次任务是否已保存、未决执行是否只允许核验、当前模型／工具能力和上下文容量。旧上下文超过窗口先沿原压缩／有界材料机制处理，不能通过清空历史冒充复用。权限收紧立即对新派发生效，旧上下文文本并不因此消失。

控制资源清理未知时不复用；仅远端业务效果未知而本地已释放时，保留原尝试的禁止重放门禁，允许明确的只读核验或与旧副作用无重复的新授权工作，不永久封禁整份上下文。原任务不能因此改为成功，新任务的结果也不能覆盖旧未知事实。

“不可自动复用”仍可保留历史并供用户继续；完成时不自动删除配置或上下文。父对话显式删除时，对子记录检查无绑定、无活动任务、无未核对交付及必要记录引用，再按同一删除计划清理子记录／附件引用；保留的审计／执行记录仍沿原保留规则，不为避免孤儿记录保活 Worker。没有额外全局子 Agent 仓库或独立保留策略设置页。

父对话删除入口须在原影响说明中包含所属子记录数量及处理结果；不因主记录当前未绑定就直接删掉仍有任务／输入待核对的孩子。不增加普通停止／解绑时的额外删除确认。

## 3. 任务、输入与协作

### 3.1 任务与工作项

根任务维护目标、子任务列表、授权依据、预算和交付条件；首版只实现父级等待直接孩子、汇总和明确改派，不增加通用工作项平台／任意依赖图。子 Agent 可串行承担多次 Task；每次任务有唯一直接父任务与 root_task_id，Task 的终态不因 Agent 再次工作而改变。

每份委派以 TaskId／父任务内委派键确定唯一负责人，重试沿原键返回既有记录，复用现有 HostOperationId／ExecutionId 和真实目标身份保存尝试，不另建 target_slot_id 系统。改派先冻结旧执行、取得收尾／完成证据，再建立显式续接任务；原未知尝试仍有门禁，不得通过新 Worker、重连或新 request_key 绕开而重放副作用。

每个对话同一时刻只有一个活动模型／工具循环。父子独立 Worker 可以并行，冲突目标仍按现有租约仲裁；不把某个 PTY 的等待扩大成全局 AI 锁。首版只允许父子通信，子 Agent 之间不直接互发或控制；需要协作由父级审查信息并重新分配。

### 3.2 输入与任务事件分流

用户输入继续沿现有 SubmissionId、binding／environment fence、接收回执和 queue／steer。引导只进入目标对话当前任务，不自动广播到所有子 Agent；父级消费后按需要修订计划、发送明确的子任务引导。用户直接操作子 composer 的事实和任务变更向父任务发布摘要，父级不共享可写历史。

子结果是带来源的任务事件，不伪造为用户消息、system 指令或授权。事件至少包含 event_id、父子 TaskId、执行 generation、报告序号、状态、简要结论及证据引用；重复事件去重，旧代次只补原任务事实。父级只读取交付范围内的结果和必要记录，不默认把全部子对话塞入模型请求。

父级等待使用有界事件订阅。订阅前检查结果水位，登记后再次核实，避免先完成后等待丢唤醒；首版允许 `wait_events` 在当前 Worker 上做可取消的有界事件等待，事件／超时返回真实工具结果，沿原循环继续。模型槽只包围实际 Provider 请求，不包围整段 Worker 生命周期，所以等待可以保留 Worker 而释放模型槽；不要求先实现任意工具／整批 slot 的通用 suspend 平台。批次工具对闭合前不发下一请求。`resumeAnswer` 继续只做原无工具回答恢复，不用来恢复协作或补满预算。

这是新增接缝：当前 Manager 是同步工具循环，`Service.pollRunner` 在线程完成后直接 finish inbox 并 pump 下一条输入。增加任务级 waiting／settling 门禁：父级请求等待或模型先返回时，只要所属子任务未收尾就不终结根任务、不消费下一条 queue；用户 steer 仍按原 Task 接收。父模型已返回后需要再汇总时，在已闭合工具批次与已保存历史的边界，以同一 Task 的后续请求继续，不能走 `Service.start` 新建 TaskId。跨请求的计时／次数／结果水位由任务对象拥有，不保存 `RequestBudget` 栈指针或已释放 CancelToken。正常应用退出只保存上下文／事实，重启不恢复内存续行现场。

任务等待与 Provider 流分开：父级无活动模型流但仍等待孩子时，新 steer 先记为原 Task 的待消费输入，在下一合法请求中消费，不向已关闭流插入、不为引导重放旧请求。queue 仍等根任务收尾后开始。已停止／失败／解绑时，晚到子报告仅更新原任务记录，不自动触发父模型；只有当前有效等待或明确新输入可以调度后续请求。等待孩子需要父级创建工作会话等协助时，控制事件先交父级在原权限内处理，再继续等待，不能形成父等子、子又等父的死锁。

用户在已结束子对话中继续输入而父助手正执行其他根任务时，登记子定向的用户来源新工作，仍受父 ConversationId 的当前授权和根任务配额约束；不抢占父正在写的主对话，也不将其结果合并成父当前根任务的成功。父主任务的停止只取消其任务树；结束父对话则关闭该父对话下所有用户／模型来源子工作。首版不做跨根任务结果自动合并或共享执行。

子定向用户工作由控制端登记根任务事实即可，不为此强制调用一次父模型；展示用户直接发起及所属父对话，父级获准查看时可查询摘要。根任务和子任务的建立、输入接收与实际请求启动分别记录，不把排队时间或打开弹窗算成模型处理用时。

### 3.3 预算、完成与取消

现有上限主要是每轮请求时间、工具 round／call 和输入队列；当前没有根预算账本或全局模型槽配置，不能写成已经可直接复用。新增有界共享调度，首版工程默认同时最多 4 个模型请求、每根任务最多 2 个、每根最多 4 个未收尾子任务，均为待实现上限，不新增用户调参页。排队／等待不占模型槽，实际请求结束才释放；不同父任务公平推进，排队取消无需先取得模型槽。

任务级预算从现有请求时间和工具 round／call 限制延伸，父子共同受根任务门禁约束，不能各领一份完整默认次数。记录实际 Provider usage，但不把没有报告的 usage 记成零；首版不增加计费／可充值 token 账本。新增持久记录保存已消耗计数、有效 deadline／人工等待区间和子任务预留，真实收尾后才归还未用额度。Worker 重建、暂停恢复或 handoff 不补满同一 Task 预算；复用子 Agent 创建新 Task 才取得新的预算。

人工等待沿当前暂停计时规则；仅等待的分支暂停，不因为某个孩子待审批就暂停其他仍在执行的机器分支。根任务预算时间不简单累加并行孩子用时。明确新任务可以有新的预算，但保留历史消费和创建来源，不伪装为旧任务自动续行。

根任务若只剩等待用户的孩子／由这些孩子形成的父依赖等待，暂停根自动执行计时；仍有模型、网络、命令或其他机器分支推进时继续计时。状态转换核对当前任务版本并沿原规则结算，迟到计时器不能终结已进入人工等待的现场，也不能借反复进入等待补满已消耗额度。网络／执行操作自己的超时继续独立有效。

成功必须满足交付物、必需依赖和资源收尾。默认继续收集独立工作结果；依赖失败的后续步骤记阻塞／失败，不能继续有前置要求的变更。用户取消立即关闭该任务树的新派发，再沿直接父子关系取消；只影响所属工作。总结逐项保留成功、失败、取消、未授权和未知项。模型回复完成、取消请求受理、Worker 退出都不能单独证明远端业务成功或停止。

首版不引入“父已完成但子继续后台服务”的模式。属于该根任务的已创建孩子都必须纳入收尾；可选只表示失败是否影响交付，不表示允许脱离根任务。需要以后继续使用的是保存的子上下文，不是保持活动的旧任务。创建／复用被重试时返回原 Task 和回执，不重复计入运行数、报告或额度。

### 3.4 状态与用量的统一语义

对话绑定、任务进度和执行结果分别记录。主助手现有 idle／running／approval／done／failed／stopped 展示继续复用，子任务只增加必要的 waiting／settling 原因；不因新增一个状态就扩展对话绑定枚举。

| 情况 | 展示及调度含义 |
| --- | --- |
| 模型或明确工具正在运行 | 计入运行角标，完成前保留真实控制状态 |
| 待审批／用户／依赖 | 显示明确等待原因，不占模型槽；仅仍有实际执行活动时计入运行数 |
| 正在取消／保存／释放 | 不能显示已完成或允许复用；详情列真实清理进度 |
| 控制已释放但远端效果未知 | 显示待核实／结果未知，不持续转圈冒充执行；禁止重放，等待明确核验 |
| 任务已终结，记录可继续使用 | 显示完成／失败／已停止及复用资格；不启动模型、保活定时刷新或递增运行时长 |

用量分为三类：composer 的**当前上下文占用**、本对话各 Turn 的**实际请求消耗**、根任务的**父子累计消耗**。上下文占用不能把孩子的占用相加到父 composer；父子累计按各真实请求唯一结算，向父报告结果不能再次累加孩子用量。结果摘要进入父请求后产生的父输入 usage 是新的真实请求消耗，单独记录，不与子累计混写。未报告用量保持未知，不能把估算显示成实测。

沿 `context_usage.Fixed/Sample/Stored` 与 `composer_usage_cache` 验证模型 key、system／工具目录指纹和消息前缀。新建／继承子上下文不复制父实测 baseline；复用原子对话仅在全部条件仍匹配时保留自己的 baseline。技能正文、MCP schema、角色提示、压缩或模型变化导致指纹／前缀失配时回退估算。重启恢复的可验证基线继续复用，不重新请求模型校准，也不把 Provider output_tokens（可能含未回放推理）当作新增上下文长度。

沿当前 `request_usage_fixed`／缓存保留标量用量信息，不能为显示 Token 而保活请求表。`attachedReleased`／Bridge.clear／Worker 销毁前撤销 `request_tools` 的有效切片，UI、压缩预算及延迟回调不得再遍历旧表的名称／schema。需要重建提示或目录时取得新的拥有型快照，不能用缓存数值证明旧能力仍可执行。

## 4. 目标、工具与附件范围

### 4.1 复用现有授权路径

保留真实非零 session／group Owner、Context 和宿主 controller。子 Agent 具有独立 AgentId／ConversationId／TaskId，但其执行上下文还携父级 fence、授权 scope 和 Worker generation；宿主验证父级仍有效，再以该子任务身份进入同一执行服务。不能只验证借用的 owner，也不能将子调用伪记成父 Task。

当前 `host_tools.Context` 只有对话／Task／binding／revision，没有 AgentId、父 fence 或 scope_subset；`Controller.inBinding` 也只检查完整会话／组。实施时增加宿主内部、不可由模型填写的子执行来源和有效目标集合，贯通 RequestTable、Bridge、controller、查询与执行服务。成员列表、终端／附件／记录读取也按子集合投影，不能只限制执行却把父组全部成员返回给孩子。主路径未携子来源时保留原校验，不能因可选字段缺失而把子调用降级为主调用。

逐工具 schema 沿已有 `Contribution.session_targets` 继续投影“父当前范围 ∩ 子获准范围 ∩ 该工具实际能力”。读取、PTY、Shell 接入和内置显示动作分别取集合，不能用任意一种可读能力推导其他能力；明确空集合禁止回落为全组，`null` 的旧兼容默认不得用于子范围缺失。schema 投影减少错误调用，但服务派发前仍复验。对有效缓存事实直接复用，只在范围／代次失效或目标不明时查询，不要求每次调用前重复 list/get。

需要实时 session_ref 的工具若无有效目标，则不发布该定义，不给 Provider 发送空 enum 或含义为“任意目标”的占位 schema。技能加载／材料处理型 MCP 不需要实时连接目标，不为进入旧解析路径而伪造 SessionHandle。

`session_lifecycle.attach` 和 `assistant_store.active/select/get` 都按 owner 选择主助手。须显式区分主附着与子身份／索引，保留主路径 owner 唯一，仅对子记录按 AgentId／ConversationId 定位；新增子对话不得取消父 selected 状态或混入普通全局会话列表的恢复／复制入口。每个子 Agent 只写自己的当前对话，额外验证父对话 fence。

首版改变父级绑定／成员的 create_group、rename／add／remove_group_member 等生命周期操作只由父 Agent 执行；子任务默认取得获准读取／执行能力，需新增工作会话时向父级提出请求。父级完成组内创建、冻结新增 scope 后再分配，避免子会话调用现有 create_group 把自身对话交接成组并脱离父关系。borrowed_user／created_task／handed_to_user 和自动清理资格继续由原资源服务管理，子任务不得关闭父级或兄弟借用的连接。

请求捕获、解析、审批、执行、回执、下一轮刷新均绑定这一身份。去重键须包含真实对话／任务及原 turn／call，避免父子重复 call_id 冲突；旧回执只能写原记录。Broker 按子任务隔离，不能覆盖主助手或另一孩子的待决审批。每次输入、读取、租约续期和副作用派发复验当前 scope，而非仅在创建时检查。

成员增加后不自动扩大旧 Task 的目标；成员移出／能力失效立即禁止新操作，受影响尝试按原身份安全收尾。组 revision、连接 generation 和绑定／环境 revision 分别维护；重命名、Tab 排序和窗口移动不扩权。离线目标可读取合法历史，实时工具明确不可用。

成员和绑定不变时，服务就绪／撤销、连接 capability revision 或原生执行／Shell 接入 API 的变化也必须经已有 `capabilityFingerprint` 路径触发下一安全边界刷新。仅原已分配目标及动作集合内的可用性变化可更新目录，不自动增加子任务目标、恢复旧批准或授予新操作。插件只读／文件／KVM 能力与终端执行仍分别取真实服务，不能只看“连接在线”。

### 4.2 附件、数据与能力

继承既有附件来源／路径／时间／快照／截断契约，切换 Tab 或复用子 Agent 不改变附件目标。秘密只走宿主凭据和敏感输入服务，不进入普通上下文、技能包或 MCP 日志。继承上下文与交付任务材料分别记录来源，引用只提供定位，不携执行权。

Local／SSH／SFTP／KVM／未来网页只提供实际服务能力；没有 exec 的连接不获得 Shell。`fetch_url` 沿其独立网络读取边界，不成为远程技能安装器或组外连接访问通道。传给外部 MCP／Provider 的数据必须在获准交付范围内；配置存在不等于允许发送当前日志和文件。

`host.run_builtin` 已提供 @dots／@help 的受限本地显示动作，只能作用于其 schema 中的当前终端引用，不发送 Shell 字节，也不要求 Shell 就绪。子 Agent 和技能不把 @ 指令包装成 shell 命令，其他未开放指令仍由用户手工操作；新增网关也不能把 conversation_context 一概当成“无影响”的只读操作。

### 4.3 统一有界工具目录

技能加载、子 Agent 管理及 MCP 适配复用现有注册／RequestTable／权限／调用回执。源码当前上限为插件工具 16、宿主工具 32、目录 96 KiB，单插件工具 8；本版不直接提高常量。宿主代理命令进入宿主配额，MCP 工具不是连接插件贡献，不伪装成额外无限配额。

首版将 §6 的逻辑动作收敛为少量 `host.*` 贡献，例如 `host.agent_tasks`、`host.skills`、`host.mcp_catalog`、`host.mcp_call`，具体通过有界 action schema 和能力引用区分。当前 `initWithHost` 只接受 `host.` 前缀且 `encodeName` 限制字符／长度，不能直接注册表中的 `agents.*`／`skills.*` 或拼入任意 MCP 原名。远端能力用稳定短 ID 映射，原名保存在适配记录中。

目录返回可调用能力的有界 schema 与 revision 引用；调用网关须按请求捕获的精确服务／工具定义再次验证远端参数，不能只通过外层 JSON object 校验。主机网关的只读／管理／副作用按实际 action 决策，不把整个入口标成只读。批准绑定内层能力、参数哈希和目标，新增审批 subject／renderer 使用同一 Broker，而非复用只能表达终端命令的票据。

每请求冻结目录和 schema／服务 revision；目录变化下一安全请求才生效。实现前核对现有全部贡献与新增网关的最坏组合，超过 16／32／96 KiB 时用明确阶段目录缩小能力集或发送前拒绝，不静默丢工具、不将新网关插进执行时的隐藏目录。

在最终目录投影完成后沿 `session_prompt.build` 生成主／子提示，再加入当前任务说明、所选技能和扩展能力说明；权限刷新时目录、提示和用量固定指纹一起更新。子提示明确只能处理分配范围、不能再派生孩子，不能复制父完整 system 从而广告自己没有的工具。技能／MCP 的加载内容不能覆盖宿主边界；模型看到的可用能力来自同一请求表，不另维护按协议名／Agent 名称判断的能力白名单。

当前 `AuthorityRefresh.system` 可在工具批次闭合后替换 system。V0.4 的首次请求与刷新必须共用完整提示组合入口，保留当前子角色／分配范围／已固定的技能 revision／MCP 选择；不能只调用基础 `session_prompt.build` 就把子限制和已选技能丢掉，也不能叠加重复正文。刷新结果在替换旧 Bridge 前后均有清楚所有者，新 RequestTable、目录、system 和用量固定指纹一致发布；失败不带着半张新目录继续下一请求。旧调用仍按旧捕获身份收尾，不追改历史。

## 5. 建组、结束、解绑与 Worker 销毁

### 5.1 沿现有会话组行为交接

| 操作 | 本版要求 |
| --- | --- |
| 单会话助手受控 create_group | 保留现有 AgentId、ConversationId 和当前 Task，更新 owner／绑定及环境版本，在安全边界刷新权限与工具表 |
| A 拖到 B 新建组 | 按已有规则交接 B 的当前对话，A 的活动结束归档；不合并两边历史 |
| A 拖入已有组 | 保留组当前对话，结束 A 来源活动；刷新组成员，不将 A 助手纳管为后台孩子 |
| 改名／布局／Tab 排序 | 不改变主体、对话、任务归属；不启动模型 |
| 组只剩一个或零个成员 | 继续作为组；零成员只读历史可用，没有实时执行目标 |

受影响的运行子 Agent 不随 handoff 迁移。提交前冻结其新派发，收齐取消和资源释放证据，保存上下文并销毁子 Worker；触发建组的父调用不等待自己结束。原根 Task 的预算与历史不重置，原子任务保持真实终态。父级交接成功后可在原授权内明确创建新子任务，重新验证复用记录及新 scope。不能把仍活动的孩子挂到新 binding。

已有 `tab_grouping.commit` 是同步发布路径，不能直接在其中等待新增子任务。有活动孩子时先保存拖放意图并关闭受影响域的派发，在宿主控制循环收尾后复验 source／target／组 revision，再提交成员与对话交接；取消或前置失败不发布新布局／归属。模型 create_group 也通过宿主等待接缝处理。UI 线程不持组／Bridge 锁等待，已有无孩子路径继续使用原短事务。

### 5.2 界面动作与运行行为

| 动作 | 效果 |
| --- | --- |
| 收起主助手／关闭子列表气泡／关闭子 Agent 弹窗 | 仅关闭界面呈现；不取消、不解绑、不因重新打开而启动模型 |
| 主窗口红色关闭按钮／普通关闭窗口动作 | 沿当前 `.window → hide` 行为隐藏窗口，父子任务和连接继续；不调用 End 或释放执行域 |
| 停止当前任务 | 关闭本次任务树派发、暂停自动输入消费、收尾；对话仍绑定 |
| 结束父对话并解绑 | 停止所属父子任务，保存上下文与暂停输入，销毁所属 Worker 后提交解绑；不默认关闭业务连接 |
| 关闭业务连接／组 | 沿既有影响预检、关闭和应用协调器处理；相应执行失权与 Worker 收尾不得遗漏 |
| 恢复／复制对话 | 沿 0.3 原 ID 恢复／新 ID 复制事务；不恢复旧 Worker、审批或自动执行队列 |

“界面呈现”只指主助手面板、子列表气泡、子 Agent 弹窗等，不是新的业务实体。主助手现有 × 若表达结束，继续使用原结束确认；子弹窗 × 明确标为关闭窗口，结束操作单独表达。

窗口隐藏、真正 dispose、结束 AI 对话和应用退出分别路由。隐藏期间继续通过现有应用控制循环接收执行／子报告／审批事件，不依赖窗口绘制帧；显示恢复只刷新投影。真正销毁附着宿主或退出才进入原 `closeWindow/releaseWindow/shutdown` 收尾，不能因函数名带 close 就把原生 hide 误接成取消。待批继续待批，隐藏不会批准、暂停或自动选择模式；通知沿现有应用服务按同一事项去重。

### 5.3 解绑提交屏障

1. 按原 fence 接受幂等 End 操作，关闭父子新输入派发及自动消费。绑定仍为已绑定，界面可显示停止进度。
2. 撤销未消费审批，取消模型、工具、等待、压缩和后台附件工作；收集已派发执行的取消／接管／ownership 交接回执。
3. Worker 发布不再运行后，在控制循环安全点 join，完成原 `pending_commit`／`pending_notify`、结果捕获和执行收尾。不得在 UI handler、工具回调或持锁时等待自己；不能把 join 留到最终上下文保存之后而遗漏最后结果。
4. 冻结最终内容与输入版本，保存已接收消息、草稿、完整工具对或真实中断尾部、任务状态及执行／未知证据，再释放 Manager、Broker、Provider 运行 binding、工具桥／请求表和服务引用。未赶上屏障的编辑归原票据恢复草稿；结束操作和可重试的最终数据由持久记录／轻量槽位拥有，不能只存在已释放对象中。
5. 持久提交结束回执、双向绑定清空及 binding_revision 推进。逻辑配置、对话和父子来源记录保留。保存失败保持已绑定及停止门禁，可重试原操作；Worker 已释放也不自动宣布解绑。

本地控制释放未知时阻塞提交。远端业务效果未知但本地已失权可保存 unknown 后结束，不要求无限保活 Worker；Worker 销毁不等于远端进程停止。短暂状态中的停止／释放进度不是第三种绑定状态。解绑完成时不能有仍持有效执行入口的子 Worker。

共享不可变配置、模型目录可由应用保留。首版 MCP 默认按对话／执行域持有进程或协议会话，解绑取消请求并关闭无引用连接；不先建设跨 Agent 有状态连接池。后续若共享传输，须证明请求／服务端状态隔离，不能借其保留旧 Worker 或旧执行权。

## 6. 子 Agent 工具契约

以下名称是内部逻辑动作的设计名称，不是可直接注册的 Provider 工具 ID；线上的 `host.*` 网关映射见 §4.3。按钮和模型工具调用同一宿主命令。

| 工具 | 关键参数与行为 |
| --- | --- |
| `agents.create_child` | name、task、deliverable、scope_subset、context_mode?、reusable?、model?、effort?、skills?、mcp_tools?、request_key；同一提交保存身份／上下文快照／首任务／预算预留，返回实际选择和任务票据 |
| `agents.list_children` | 只查询当前父对话的孩子，支持状态和有界分页；返回身份、时间、任务摘要、复用资格，不返回其他附着域 |
| `agents.get_child` | 精确 ID 查询获准详情、报告／证据和必要上下文，按范围和长度限制读取 |
| `agents.reuse_child` | agent_id、new_task、deliverable、scope_subset、request_key；验证候选后创建新 Task，保留原上下文；与 context_mode 同传则拒绝 |
| `agents.send_input` | child_id、TaskId／预期活动轮、submission_id、queue／steer、材料；仅直接父级输入，不以消息文本替代停止 |

创建失败不留下意外 Worker 或重复任务；重试同 request_key 返回同结果。停止／列表／详情均不能绕过父级和当前 binding。用户对子 Agent 的操作走同一服务，但标记 user 来源，不伪装为模型委派。

## 7. SKILLS：仅本地导入

### 7.1 设置入口与导入事务

在设置 → AI 辅助增加“技能”卡片：拖放区、“选择本地文件／文件夹”、已导入列表、名称／描述／启用状态、查看内容、重新导入和移除。拖入本地 `SKILL.md` 或含该文件的技能目录；目录保留配套 references／assets／scripts。也可选择包含多个技能的父目录，递归发现 SKILL.md 后按独立技能导入，全部校验成功才更新设置草稿；不自动替换同名技能。忽略 .git、.DS_Store、__pycache__；脚本配套的 node_modules、.venv 保留。首版不要求压缩包格式。

只支持本地导入，不提供 URL、Git 仓库、远程市场、订阅更新或自动下载。正文中的远程链接不能触发技能资源自动抓取。先复制到应用受管暂存目录，解析 name／description 和正文、检查引用，再提交包及索引；不执行文件。路径规范化后不得逃出包根，外部符号链接拒绝，不顺带复制包外文件或凭据。

技能文件、资源、整个技能包及导入数量不设应用级大小或数量上限。配套 scripts／assets 按块复制与哈希校验，不作为正文解析或自动发送给模型。文件大小显示 B／KiB／MiB／GiB 等单位；导入错误在所属设置卡片内使用主题错误色，显示实际文件路径。SKILL.md 与文本资源经 host.skills 按字节 offset 分页读取，返回 next_offset，保留 UTF-8 边界及版本校验。正文中的 ../其他技能/... 链接只保留引用，不复制或读取包外文件；使用时另选已启用且获准的技能。单文件缺少配套资源、格式错误和同名冲突分别提示。更新同一技能要求明确替换，保留稳定 skill_id 并产生新内容 revision；失败保留旧版本。导入的包不依赖原路径持续存在，原文件移动不会损坏已导入内容。技能索引、启停和设置沿原保存／放弃语义提交；暂存包在保存成功前不可被模型加载。

### 7.2 按需加载与执行边界

默认只将获准技能名称和描述放入有界目录；模型选中后读取正文，再按需读取包内资源。主 Agent 与子 Agent 共用技能存储，子级仅取得父级获准技能子集，独立上下文不意味着丢失已分配技能。

用户点名技能时核对本地已启用目录，缺失／停用／不兼容明确说明；不凭同名标题虚构技能，也不转为远程安装。未点名时模型根据有界描述选择任务需要的技能，记录实际加载项；不把所有正文一次性注入。metadata、正文、包内资源有同一 skill_id／revision，不能在分步加载间混入刚替换的新版本。子配置中的技能选择是上限，继续交互时也不自动纳入后来新增的全部技能。

技能是工作指引，不是宿主规则或授权。导入不会启动脚本；技能要求的命令必须经当前附着目标的已有执行服务、能力检查和审批。应用本地技能目录由专用只读加载器读取，不新增绕过附着范围的本机文件系统／Shell。当前附着为真实 Local 终端时，可按正常授权在该终端执行；附着为远程连接时不能用技能脚本退回宿主 Shell。若需交付脚本到当前远端目标，必须走实际已有且获准的文件／执行能力，缺少能力时明确不可用，不为技能另建上传／脚本执行引擎。

每次使用记录 skill_id／revision／内容引用。更新不改写历史、不替换当前请求已冻结内容；保存停用后禁止新加载，已进入上下文的文本保留历史属性，不能承诺从模型中撤回。技能启停本身不撤销已经取得的普通连接操作授权；实际权限收紧仍由宿主工具门禁执行。删除先检查读取引用，旧历史引用有明确保留或缺失状态，不假装仍可完整重读。

## 8. MCP：配置、能力接入与作用域

### 8.1 配置与协议边界

设置 → AI 辅助增加“MCP”卡片：服务列表、新增／编辑、启停、测试连接、移除；显示状态、工具数量、最近错误及能力详情。首版采用表单配置，按传输类型校验；不额外要求另一套原始 JSON 编辑器，不把原始错误或秘密直接铺在列表。

| 传输 | 配置 |
| --- | --- |
| 本地 stdio | name、可执行程序、参数数组、工作目录、环境变量及秘密引用；直接启动指定程序，不经隐式 Shell 拼接 |
| Streamable HTTP | name、endpoint、认证配置、必要 headers、超时；请求与重连沿协商版本 |

标准传输依据 [MCP 2026-07-28 传输规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports)，以该当前正式版本为兼容基线，同时保留 2025-11-25 及更早版本的握手兼容路径；不自动跟随 draft。旧 HTTP+SSE 不作为隐式兜底。技能仅本地导入不限制用户配置远程 MCP。

API Key／token／敏感环境变量复用既有秘密存储事务，普通配置仅存引用，编辑和日志脱敏。当前保存／加载／清理只遍历既有 Provider 和连接引用，MCP 必须补入这些路径，不能假定新增引用自然受到保护。首版支持显式配置的认证 header／秘密环境变量；不把完整 OAuth 流程作为必需前置，服务要求未支持的交互认证则明确不可用。

测试连接只做初始化与能力查询，不发送业务 tools/call；stdio 启动第三方程序本身会运行代码，不能宣传为“完全无副作用”。仅用户明确测试或获准任务按需使用时启动，纯配置校验／保存／应用启动不自动执行程序。测试使用隔离的临时会话、脱敏记录，结束即释放，不进入 Agent 任务历史或复用旧授权。配置及停用影响通过原保存事务生效，并发调用使用明确的原配置 revision。

### 8.2 首版工具调用与可选扩展

首版必需初始化／版本协商、tools/list（含分页）与 tools/call、取消／关闭及真实结果展示。resources／prompts 在确有读取适配且同样受 scope 检查时才声明客户端支持，不作为本版工具主链验收前置；未实现时明确不可用。资源内容、模板和服务消息均不是用户授权，连接成功不等于每个工具允许当前 Agent 调用。

宿主生成稳定且带服务命名空间的能力 ID；每次请求冻结 server_id／配置 revision／能力定义及 schema hash。调用前后复验；变更影响当前批准则撤销原批准，下一安全边界刷新。已派发请求保留原归属；断线后先对账原请求，结果未知的副作用不自动重发。

统一展示真实目标、远端能力名、参数影响、状态、结果与错误；结果有大小／分页限制，文本、资源和图片沿现有有来源内容／附件机制处理。工具注解仅供提示，不作为只读／安全证明。服务发起的 sampling、elicitation 或 roots 等客户端请求，只有显式实现并进入同一用户／scope 门禁才接受，否则按协议返回不支持；不借其发起额外模型或本机访问。

### 8.3 当前附着范围的实际执行保障

MCP 按用户配置的工具名白名单开放，支持多字段、嵌套对象、数组等参数；不再要求唯一必填 text 字段。目录返回工具实际 input_schema，调用使用 arguments 对象，由嵌入式 Ajv 校验 JSON Schema 2020-12、2019-09 和 draft-07 的输入及结构化输出，支持引用、组合、可空类型、模式及对象约束。无效 schema 或未提供的外部引用明确显示不可用，不跳过校验。工具目录及大 schema 分页返回。

调用仍检查当前任务选择、服务启用状态与配置 revision，并走原审批流程；派发前重新发现工具并核对 schema hash。外部工具不获得应用内部连接、历史、凭据或服务容器；参数格式不作为服务隔离或只读证明，外部程序实际权限由用户配置的服务和运行环境决定。设置区分协议连接与已授权可用工具数，未选工具保持不可用。启用新服务不会自动加入旧子任务。

父子请求须隔离路由、任务、审批和服务端可见状态，首版默认独立协议会话／本地进程，避免建立有状态跨域池。单独会话也不自动证明服务内部数据隔离，仍须满足前述具体能力边界。解绑取消其请求、撤销路由并释放租约；晚到消息只补原事实，不能唤醒新 Worker。外部业务效果仍未知时保存证据，不因断开 MCP 就标记业务取消成功。

## 9. 子 Agent 入口、列表与详情弹窗

### 9.1 主助手顶部入口与角标

在 AI 助手顶部按钮区靠左加入助手图标，使用项目现有图标／tokens，保持其余入口相对位置。角标显示当前父对话下**实际正在运行的子 Agent 数量**，零时隐藏数字但图标可用。模型推理和已派发工具执行计数；排队、等待用户／审批／依赖、空闲、完成、失败和仅保存上下文不计入。状态混合时按有活动执行的真实状态判定，不由文字推测。

计数来自宿主事件，同一 Agent 不因多个任务记录重复计数，多个窗口一致，不触发模型查询。Tooltip／可访问名称给出“子智能体，N 个运行中”；待处理事项在列表明确呈现，不改变角标数字含义。

### 9.2 小气泡列表

点击入口打开可聚焦、可滚动 Popover，默认按状态分组，同组按最近活动时间倒序，稳定 ID 为同时间兜底：

1. 待处理：等待审批／用户输入、需要人工处理的失败或未知结果。
2. 进行中：运行、排队、等待依赖。
3. 最近结束：完成、已停止及可复用空闲项。

每行使用 LOGO + 内容 + 状态三列：32×32 的确定性机器人 LOGO、名称／任务摘要／时间和必要复用标记、固定 24×24 状态槽内的 16×16 图标。LOGO 由稳定 AgentId 派生，改名不换图。标题、分组名与内容名称对齐；状态完整文字保留在 Tooltip 和可访问名称中。状态优先级在一处实现，排序与计数使用同一查询；空态为“暂无子智能体”。更新保留滚动、焦点和选中项，避免运行项频繁跳动导致点击错误。长名称省略但可查看完整名称，状态不只依赖颜色。Esc／外部点击关闭，不停止工作。

排序时间使用任务创建、状态转换、完成或用户交互时间，不随每个流式字符、计时显示或列表打开而更新。按压／键盘选择捕获稳定 child_id 和行 revision；状态变化可更新行内容，必要排序延到本次交互结束，避免同一位置被替换成另一孩子。未知结果进入待处理区，真正完成且可复用才显示空闲复用资格。

### 9.3 可继续交互的详情弹窗

点列表行关闭气泡，打开对应子 Agent 弹窗；同一子 Agent 再次打开定位原弹窗，不新建 Worker／Agent。多窗口只订阅同一权威记录，不产生第二写入者。

复用主助手的消息时间线、思考／工具步骤、审批、附件、模型／推理／权限控件、composer 和 queue／steer。控件作用于子 Agent 自己，默认配置可继承父设置，当前执行保持请求快照；不能直接修改父助手的输入、模型或权限。权限菜单仅能在父级允许上限内选择，子 Agent 不显示再派生入口。

当前可写助手仍由 `main.zig` 的 AiHost 组合，`ai_sessions_view` 的历史弹层没有可写 composer，不能直接改为子执行窗口。仅提取本次需要的会话渲染／输入组合与具名回调，以子 ConversationId／AgentId 绑定，不切换父 `display_conversation` 或临时改写 `execution_host` 来模拟独立窗口。窗口订阅用稳定 ID／generation，不持裸 Worker 指针；关闭后草稿／附件仍由子记录持有，不保留 UI Node／Scope。主助手现有步骤折叠、恢复、图片与输入行为继续复用，不为该弹窗重写整套 AiHost。

“组件一致”不等于直接复用主助手动作的副作用：当前主 composer 的 permission／execution_mode 动作还会写全局默认值。子弹窗必须使用子身份回调，只改子配置／当前任务，不顺带改父助手或应用设置；全局默认仍由原主入口／设置管理。子级有效权限取自身选择与当前父级授权上限的较严者，父级收紧即时限制未派发调用，放宽不自动提升孩子；已发生操作保留原回执。生成模型／effort 变化沿原下一次请求生效规则，不改写已执行请求。

复用 `conversation_presentation` 恢复消息、思考、工具步骤、附件、时间线和展开状态，使用同一来源跳转及历史失权规则。子记录分别保存生成偏好引用和展示数据，不能只保留依赖全局默认的临时 Controls；恢复时验证模型仍存在，凭据始终从配置服务解析。未改变的消息节点保持原位，终态后停止 spinner／耗时定时器／无变化全树重建，不因“可复用”持续刷新空闲弹窗。

主、子对话共用标题栏组件和对话样式，默认均为 600×456；子名称进入原 owner pill，新增设置图标使用原窗口按钮 recipe。直接父级、当前目标、独立／继承及快照来源、可复用性、技能／MCP 选择和任务记录进入独立设置气泡，不另造聊天标题布局。设置宽 320、自然撑高并限制滚动上限，名称与输入同行，字段 KEY 使用主题主前景色，任务记录默认折叠；列表、气泡和对话使用原浮层阴影。composer 支持继续提问、附件、引导／排队和停止。用户直接补充产生真实 submission 记录；父级收到必要摘要，不将其当成新的系统指令。

未绑定父对话的历史详情只读，显示恢复父对话后继续入口；不能把普通查看变成自动恢复。关闭弹窗仅销毁 UI 节点和订阅，草稿保存，工作继续；Worker 销毁后弹窗仍可读取已保存内容。有新输入且绑定有效时按需创建新 Worker。

### 9.4 时间线与原生实现

正文、思考、子任务／工具事件按真实顺序追加；状态只更新原条目，不因排序或结果到达重排聊天。审批在原调用位置转换为执行步骤，父助手汇总只保留必要进展和可定位结果，不重复倾倒子完整对话。待处理项可从父子入口定位同一精确票据，跨窗口只消费一次。

沿 `zenit-html-ui`、现有助手／设置组件和 Refactoring UI 层级设计。后续视觉实施先扩展可编辑本地 HTML/CSS 基准，测量计算样式与布局，复用 tokens 和 `ui.widgets.*`，再实现原生；不新建视觉体系、WebView 或截图式替代。图标角标、空／长列表、排序、详情交互、待批、运行、完成和未绑定只读为必要原型状态。设置使用顶部图标触发的独立 Popover，不在聊天区域展开表单。验证时保存原型测量、原生截图与交互证据，生成物不纳入版本管理。

## 11. 实现接缝、持久化与恢复

### 11.1 沿现有模块扩展

```text
附着 Agent／子 Agent 记录 + ConversationRecord（可持久保存）
                 ↓ 有效绑定 + 明确新输入／任务
      按需 Worker（Manager、Broker、工具目录、取消）
                 ↓ 同一 scope／审批／调用链
   现有连接、执行、记录服务 + 受控技能／MCP 适配
                 ↓ 收尾与内容保存
       释放 Worker；解绑后仅保留记录
```

`session_lifecycle` 管身份／绑定／父子关系与持久事件；`session_runtime` 管按需 Worker、输入和任务调度；`assistant_store` 管既有内容呈现及草稿投影，不能另建第二份权威绑定。子记录复用现有对话存储，不让按 owner 唯一的主 Agent 索引吞掉孩子。必要类型／文件名以实施实际代码为准，不要求新建独立 AgentRuntime／工单平台。

最少区分 AgentId、ConversationId、TaskId／root／parent、SubmissionId、Worker generation、HostOperationId、ExecutionId／RecordingId、真实 SessionHandle 与组 revision。子记录保存直接父 Agent／父对话和 context_source，Task 保存负责人／scope／预算及 attempt。Worker 指针、线程和 UI 对象不写持久记录。

`Record.parent/source_revision/fork_turn` 当前专用于复制来源；子关系另存 owning_parent_conversation／created_by_agent 等明确字段，不能重用它导致列表误判为副本或恢复错误。Agent 增加 attached／child 的内部区别，attach、handoff 的 owner 唯一性仅约束 attached；子绑定仍写真实 owner，但必须经父关系和有效 scope 复验。回放、orphan 收尾、列表投影和删除条件同步识别此区别，不放宽原主助手约束。

生产接线沿 `attached_service.Host` 的应用级 pump／closeWindow／shutdown。父子 Worker 的依赖 token／预算对象活到所有消费者收尾，先收孩子再释放父对象；`pending_notify`、`task_finish` 和 `execution_driver` 未结束时不能销毁后台 AiHost。`destroyAttached`、Runner deinit 及 UI teardown 对每项资源确定唯一释放者，保留轻量 Bridge 或注销旧 Bridge 后按需重建，禁止旧 Bridge.pump 访问已释放 context。不把此局部拆分扩展为所有主程序模块重构。

子执行域在创建任务时即登记到应用运行表和父窗口真正销毁域，不依赖首次打开子弹窗；全局 pump／退出／更新检查必须覆盖没有 UI 的孩子。子弹窗关闭只释放显示订阅，主窗口 hide 保持执行；真正销毁附着宿主／关闭业务对象才通过原协调器收尾，不留下没有 Bridge 却仍运行、无法被 shutdown 枚举的执行者。

SKILL 受管目录／内容索引和 MCP 配置／秘密引用进入应用既有数据位置及设置服务；不把技能文件写入连接资产或把 MCP 服务伪造成业务会话。插件 API 2、现有 manifest／typed service 边界继续有效；本版不以 API 3、双贡献或通用 FeatureHost 为前置，不要求改写 Local／SSH／SFTP／KVM 清单。

### 11.2 持久化提交与容量

复用现有单写事件／原子提交与操作日志；跨内容文件使用先准备、验证引用、再发布元数据的顺序。子创建／复用的 Task、首输入、父引用和预算预留必须具备一致提交／恢复路径，失败不派发孤立 Worker；不能声称若干独立 JSON 原子替换构成跨文件事务。

当前 `session_journal` 只接受 schema 1，已保存 presentation／context_usage 及原消息／输入，但尚无本版子关系和任务树／预算事实。新增子关系／Task 事件采用明确的新 schema，新版兼容读取同一日志中的旧 schema 1 行，保留原 ConversationId、fork 来源、队列、展示快照和用量校验，不要求先整库迁移。未知版本和坏记录明确诊断，不忽略字段继续派发；旧程序不支持新事件时报告不兼容，不降级删除。新增字段不混入 `Record.parent`，也不把已有 presentation 支持误记为尚未实现。

模型 wire history 与展示快照继续分开：前者可压缩，后者已通过 `conversation_presentation` 保存原消息、思考、步骤、时间线、附件及展开状态。子详情复用这套 capture／restore 和 `savePresentationWithUsage`，解绑最终保存屏障同时覆盖 wire checkpoint、展示快照、草稿及输入回执；不能只保存压缩后的模型上下文而丢掉用户已看到的过程。仅对旧记录无快照或确有缺失时采用现有文字回退并标明缺失，不伪造时间／步骤，也不另建第二套子消息格式。

子创建继承只取合法模型前缀，不复制父展示快照伪装成子产生的过程；可显示明确的继承来源，子时间线从本次任务开始。复用子 Agent 保留自己的展示历史，新任务追加。保存展示与实测 baseline 使用原同一事件接口，但 baseline 是否可用仍由模型／请求指纹验证，不能因快照恢复成功就当成有效执行授权或精确计数。

任务接纳前检查有限队列、内容和收尾记录容量，保留取消／结束必要写入空间；满额拒绝新工作，已有工作仍可保存与收尾。附件／技能版本／任务证据按引用管理，当前读取和未决操作引用不可回收。缺失或损坏内容进入明确诊断，不以空历史自动覆盖或启动模型。

### 11.3 恢复矩阵

| 状况 | 必须行为 |
| --- | --- |
| 应用重启或 Worker 异常退出 | 加载配置、上下文和必要事实；无恢复出的执行 Worker，旧绑定按 0.3 orphan 对账／恢复门禁处理 |
| 父／子对话恢复 | 明确动作重建当前绑定／环境；再次发送才创建 Worker，旧子任务不自动运行 |
| 解绑前保存失败 | 保留已绑定和停止门禁，重试同操作；不得已解绑后丢历史 |
| 释放后解绑提交失败 | Worker 保持已销毁，记录仍绑定且禁止自动派发，重试原持久提交 |
| 解绑成功后旧消息到达 | 只补原请求事实／去重消费，不更新新草稿、重开模型或恢复旧批准 |
| MCP 调用已派发、响应未知 | 保存原请求与未知效果，按服务能力对账；不自动重放副作用 |
| 技能导入中断 | 未发布暂存可清理，已发布包保持索引一致，原技能版本不被半成品替换 |
| 根任务已结束后复用子 Agent | 明确新 Task／账本／scope，新 Worker；旧根任务状态和消费不重写 |
| 原父对话在重启后恢复到新 AgentId | 按父 ConversationId 找到原子配置／上下文，验证当前父绑定和新任务范围后按需使用；不要求旧 AgentId 复活 |

应用退出、更新关闭、连接关闭、睡眠／断网均遍历所有父子 Worker 与 MCP 租约。正常退出保存后释放；唤醒不默认批准或重发。不确定业务效果保留原证据和禁止重放约束，不能靠重建 Worker 清除。

## 12. 实施阶段

**2026-11-06 开始实施首个基础增量：Worker 回收。** `session_runtime.Runner` 保留身份、backend 工厂和持久提交状态；可选 `Worker` 持有 Manager、取消、审批／问题 Broker、stream 与运行历史，仅在明确输入时创建。End 在 join、checkpoint、完成投影及本地释放之后，通过生产 `releaseAttachedWorker` 保存最终展示、等待 TaskFinish／通知／执行驱动收尾并释放后台请求资源，然后销毁 Worker、提交解绑。释放后持久提交失败保留原绑定及停止门禁，以原票据重试；恢复／查看不创建 Worker，再次输入才推进 Worker generation。正常清理等待由控制循环继续推进，不显示为保存失败。

**2026-11-06 后续基础增量：子记录与范围接缝。** 新增独立子 Agent 身份、不可变创建父级／父 ConversationId、独立／继承来源、可复用配置和精确当前父 fence；主 owner 索引仍唯一，子对话不混入主会话的选择、普通恢复／复制或列表。子事件使用 session journal schema 2，混合读取旧 schema 1；普通事件保留原字段形状，重启先收尾旧子绑定再收尾父绑定。父对话恢复到新 AgentId 后，子配置仍按原父 ConversationId 校验。家庭删除提供有版本和数量预检的单次持久提交，活动／未知输入不被绕过。

当前 Loop 的继承冻结入口排除包含自身的整个未闭合工具批次，保留本轮已消费输入和更早闭合结果；无法安全投影到较小范围时明确拒绝。子运行使用独立 Runner／Worker 和审批器，宿主 context 带不可由模型填写的子来源，读取成员和逐工具目标按子集合投影，明确空集合不回退为父范围。父级 End 先收尾孩子，Stop 只沿当前 Task 关联取消；活动孩子尚未收尾时关闭新派发，持有原 fence／操作标识并由控制循环取消和收尾孩子；完成后复验再交接，见下述后续增量。

**2026-11-06 工具网关、同 Task 续行与共享预算增量。** 主助手的实际工具目录发布 `host.agent_tasks`，支持 `create`／`reuse`／`list`／`send`／`stop`／`wait_events`。创建必须提供请求键、名称、任务材料和明确的 `session_refs`；空集合表示仅处理材料。创建的模型／effort 冻结父级当前有效选择，显式覆盖先验证已配置能力；复用保持原配置，以新 TaskId／Worker generation 开始。子级目录不发布该网关，宿主仍拒绝伪造的子级调用及越界目标。创建键在当前根任务内返回原回执，不因响应重试启动第二个执行者；重启后不借旧键复活旧任务。

`child_launch` 一行提交子身份或复用绑定、精确目标、首条输入和任务事实；持久化或分配失败回滚，提交后启动失败保留明确失败事实并收尾。新增任务事实使用 journal schema 3，兼容读取原 schema 1／2；旧 schema 不能伪装携带任务扩展。任务保存父／根 ID、generation、消费计数、有效执行时间、usage 完整性、状态和交付水位；恢复把未终结事实写为 interrupted，不恢复 Worker／计时器／模型请求。已预留但未收到 usage 的请求保留未知标记，不能按零消费汇总。

父级 Provider 提前返回时，原 Manager／Loop 等待孩子清理并保存结果后继续请求，保留 TaskId、Turn、已闭合工具账本与预算，不调用 `Service.start` 或 `resumeAnswer` 伪造续行。报告只通过真实 `wait_events` 工具结果读取，按事件水位分页；整批 call/result 接受后才确认交付。预算记账和交付确认不会自行制造新的报告事件。等待期间 steer 可唤醒父级在原 Task 消费；queue 等根任务收尾后再启动。孩子等待人工决定时，未读控制事件可交回父级处理，但模型不能代替用户审批；子审批／提问通过独立可写子对话处理，消费原子级票据，不借父 composer 代替用户决定。

模型槽只覆盖实际 Provider 请求，工程上限为进程级 4、每根任务 2，按就绪根任务轮转；排队取消无需先取得槽。每根最多 4 个未收尾孩子，清理／最终事实提交未完成也占该名额。父子共享原请求时间及 round／call 上限，重试、同 Task 续行和自动上下文压缩同样记账，不各领完整预算；排队及依赖等待不占模型槽。有效时间按仍有机器分支推进的墙钟计，不能累加并行孩子时间，也不能因单个孩子待人工就暂停其他机器分支。明确的回答重试沿旧任务消费剩余额度，不补满计数。Worker 已解绑而最终任务事实保存失败时，保留收尾门禁并以原 End 回执重试，父级不能提前结束或删除家庭记录。

**2026-11-06 默认策略、异常复用与异步交接增量。** `ai.child_context_mode`／`ai.child_reuse_policy` 接入配置解析、格式化、全局草稿保存／撤销、搜索和原生 AI 设置卡片。创建按父任务捕获的默认值解析，显式参数覆盖；修改默认值不撤销旧任务。优先复用提示模型先查询并明确选择候选，不由宿主静默替换创建。`model` 默认保守，仍可显式指定复用与可复用配置。

`reuse purpose=verify` 为旧子上下文开启一个宿主强制只读的新 Task：目录按 effect 筛选，伪造写调用在派发前拒绝，自动权限模式同样受限。普通新工作仅允许与尚未核验的旧终端目标不相交的明确范围，或仅材料任务；同 session 的新 generation 仍视为重叠。旧记录缺少精确目标时保守限制非空工作范围。旧 unknown／interrupted 不因新 Worker 或核验任务成功而改为 succeeded；门禁同时检查恢复索引和当前进程保留的所有根账本，MCP 原有语义防重放门禁保留。任务事实的只读标记与目标快照持久化、回放校验且不可在后续事件中改写；新首任务事实必须与同一原子行的授权目标一致。

交接分为意图、关闭派发、子任务收敛、复验和发布。标签拖放保存原 TabId／SessionHandle／父 fence／目标组成员版本，等待期间不分配或发布半成品组，版本变化即撤销意图并释放门禁。模型 `create_group` 在锁外短时等待控制循环，保留原审批、父 Task 和共享预算；UI 轮询区分过渡门禁与真实失效，避免撤销本次交接审批造成自取消。停止、失败或释放计划会清除本操作的门禁，释放旧操作不能清除新操作。真实原生验证覆盖活动子 Provider 请求被取消、子 Worker 解绑早于 handoff 持久化、父级收取报告并以原任务结束。

**2026-11-07 子对话与配置补齐。** 主助手顶部新增子智能体图标和真实运行计数；统一投影负责状态、分组与活动时间，等待人工不计入运行数。列表保留稳定行身份和焦点，交互期间不重排行，重新打开应用最新分组顺序；长名称省略并保留完整可访问名称。历史父对话的只读查看提供子智能体入口，不恢复执行。

子弹窗复用主助手同一消息／思考／步骤／审批／提问／附件／composer 组合，按子 ConversationId 保存草稿、图片和本地／远程材料。设置图标打开独立气泡，包含名称、复用、目标、技能／MCP 选择及上下文／任务信息；模型、推理、权限与执行方式复用 composer 控件，但只写子偏好。`child_config` 单独持久化且校验 revision 和父级授权，保留不可变创建来源。父级收紧即时限制未派发调用，不能从子菜单提升父权限。

用户明确续行可用于不可自动复用的子对话，创建新的根任务／Worker；活动中的 queue 等当前任务收尾后继续，保留冻结输入、配置与附件，steer 留在原 Task／Turn。受父委派的排队任务在原根锁内切换到下一 Task，保留共享预算，防止父级观察到虚假的子任务空档。关闭子弹窗只释放呈现，任务继续；再次打开不启动请求。父未绑定时历史子对话只读，显式恢复父对话后才允许新输入。

**2026-11-07 共享设计与列表对齐修正。** 子对话标题栏、尺寸和消息／composer 使用主助手同一组件；列表仍由主顶部图标触发，标题、分组和名称对齐，采用稳定 LOGO、内容、状态图标三列。设置收紧为 320 宽的自然高度气泡，名称同行、字段高对比、开关靠右、任务记录折叠。

本地技能、MCP 主链、对应设置、默认策略、异常只读复用及异步交接已接通，沿已有专项验证；没有待实现的子对话占位入口。不提供任意“标记已核验”来清除原未知事实的旁路。真实商业模型、外部 MCP 认证与远端业务结果不由本地受控验证代替，仍保留原能力和权限限制。

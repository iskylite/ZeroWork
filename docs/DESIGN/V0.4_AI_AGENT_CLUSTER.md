## 1. 角色与不可变边界

| 类型 | 产生方式 | 归属与职责 | 子 Agent |
| --- | --- | --- | --- |
| 独立 Agent | 从 AI Agent 连接入口新建，每次创建一个独立实例 | 不绑定连接会话；独立内容页；在用户授权后可选择任意会话/组并直接使用工具 | 可以派生 |
| 集群 Agent | 独立 Agent 经显式操作转换；可以有多个互不混同的集群 | 独立内容页；自身仍具备普通 Agent 能力；仅纳管会话 Agent，负责协作调度 | 可作为直接父 Agent 派生自己的子 Agent |
| 会话 Agent | 支持附着能力的连接会话/会话组建立时登记，使用时按需启动 | 一个逻辑会话或组对应一个 Agent；单会话严格限本会话，组严格限组内成员 | 可以派生，权限限父任务范围 |
| 子 Agent | 上述父 Agent 为明确任务派生 | 独立任务上下文，唯一直接父 Agent；不能作为集群成员、不能独立迁移 | 不可再派生 |

四类角色不是强制四层调用链。集群结构为“集群 Agent → 会话 Agent → 各自子 Agent”，集群 Agent 也可以有自己的直接子 Agent。普通独立 Agent 及其子 Agent 存在于集群之外。

硬边界：

- 新建 AI Agent 连接只创建独立 Agent；不提供绕过转换的新建集群入口。恢复既有集群是恢复记录，不是新建独立 Agent。
- 集群不纳入独立 Agent、其他集群或子 Agent。会话 Agent 同时最多加入一个集群。
- 独立 Agent 转换成功后永久终结，不存在退回、撤销为独立或恢复旧独立实例的操作。
- 会话 Agent 不能跨绑定范围；用户授权、加入集群、消息转发都不能扩大这一硬边界。只有绑定会话组的 Agent 能直接操作多个组内会话。
- 子 Agent 只与直接父 Agent 通信。集群 Agent 不得直接查看成员子 Agent 的私有对话、发送消息、委派、打断或控制它；控制请求必须交给该成员执行。
- 选择执行目标与纳管 Agent 相互独立。独立 Agent 无需建立集群即可在授权后操作任意会话/组；选择目标本身不建立成员关系。
- 所有主体共享基础 Agent 实现、Provider、附件、审批与工具结果组件；权限和生命周期由宿主检查，不以提示词代替。

## 2. 创建入口、转换与成员管理

### 2.1 从 AI Agent 连接开始

新建菜单/连接入口提供“AI Agent”，经标准插件创建入口建立独立内容页，不要求主机资产、SSH 或本地终端。模型未配置时仍可进入页面并配置，发送前提示准确缺项。

页面提供“启用集群”动作，以及自然语言路径，例如：“把生产 SSH 和测试组的助手加入，协同检查故障。”模型先解析实际对象、查询归属，再调用结构化工具。明确请求已构成相应授权时不重复确认；对象重名、范围不清或需超出授权时才要求补充。用户所选权限策略要求审批的操作仍经过统一审批。

两条入口调用同一宿主命令，不在按钮和模型工具中维护两套转换逻辑。UI 文案使用“启用集群”，避免用“启用 AI Agent 模式”描述一个本来已经是 Agent 的页面。

建议工具契约：

| 工具 | 关键输入与行为 |
| --- | --- |
| `agents.list_session_agents` | 按名称/状态/所属会话/组查询，返回稳定 Agent ID、绑定与当前集群归属；可见不等于可纳管 |
| `cluster.enable` | 当前独立 Agent、预期 revision、请求幂等键、初始会话 Agent ID 集合、明确授权范围；原子转换并纳管；返回新的集群 Agent ID 与交接回执 |
| `cluster.add_members` | 已存在集群、成员 ID、预期归属/权限 revision、幂等键；仅接受会话 Agent |
| `cluster.remove_members` | 集群、成员 ID、任务处理方案与预期 revision；撤销该成员协作授权并移除 |
| `cluster.get` / `cluster.list_members` | 返回允许公开的集群/成员状态、数量和任务摘要，不泄露私有对话 |

显式“启用集群”可不选择成员，创建空集群；自然语言要求加入指定成员时，转换和首次纳管为同一事务，不能失败后留下意外空集群。成员增减可以通过按钮或模型工具完成。成员数量变为零时仍为集群，显示“尚无成员”，不自动退回。

### 2.2 转换是单向交接，不是可逆标记

建议使用独立的旧、新 Agent ID，使“旧独立 Agent 已终结”具备可审计事实：

1. 校验当前独立实例、权限、初始成员、单集群归属及插件能力。转换前置失败不改变旧 Agent。
2. 进入 `converting`，冻结旧 Agent 新任务。旧 Agent 其他运行回合、待批操作和自己的子任务必须完成或按明确取消方案停止；存在清理未知时阻塞转换，不重挂仍运行的子 Agent。
3. 准备新集群记录、权限快照与 AI 对话续接记录。转换工具返回内部 `handoff_pending` 后将本回合停在宿主交接点；等待集合排除这个调用本身，不能在 controller/UI 线程等待自己结束。释放事务锁后等待其他任务清理，回到提交点重新校验 revision。
4. 按§11.2的单一持久化提交点提交：旧 Agent 标为 `converted`，记录 `successor_agent_id`；建立新集群 Agent；登记初始成员独占归属；建立新的对话续接记录和 Tab→Agent 引用。持久化成功后，当前及其他窗口更新投影。
5. 宿主将成功回执写入旧对话结束事件及新对话交接事件，只由新 Agent 继续后续工作。旧运行 generation、待批令牌、回调和执行入口全部失效。

旧独立 Agent 从活动列表和可恢复列表消失；历史审计记录只读保留并可跳转后继集群，不具备恢复旧 Agent 的入口。当前内容页位置保持，Tab 标题、图标和状态随事务一起切换。历史上下文可通过不可变引用续接，不复制正在运行的任务和执行权限。

事务提交前失败可撤销准备状态并保留原实例；提交后失败只能恢复集群记录，不能复活旧独立 Agent。崩溃恢复、重试和多个窗口重复点击用同一幂等键及唯一后继约束，保证只有一个后继实例。

### 2.3 成员归属

纳管时绑定具体 `AgentId`，不能按名称或当前活动页签定位。已在另一集群的成员返回明确冲突，不能静默抢占。转移必须先处理原集群任务、撤销协作授权并移除，再加入新集群。

成员退出仅停止/撤销原集群来源的任务权限，不删除 Agent、AI 对话、连接配置或底层连接。任务清理未知时保持“退出中/阻塞”，不能把同一成员交给另一个集群继续执行。

单会话 Agent 和包含该会话的组 Agent 是不同主体，可以分别加入不同集群；这不会产生双重 Agent 归属，但会产生资源重叠，须经过§8的统一目标仲裁。

### 2.4 与 PATCH 的 session→group 交接明确区分

| 项目 | 已有附着对话建组 | 本版启用集群 |
| --- | --- | --- |
| 触发 | 附着助手经 host.create_group 受控建组 | 独立 Agent 经 cluster.enable 启用集群 |
| 对话 | **保留同一 ConversationId**，initial_owner 不变，owner=session→group，binding_revision 递增 | 旧对话关闭；**新的 ConversationId** 通过 continued_from 续接 |
| Agent | 源 session Agent 留存；为新组登记 group 会话 Agent，当前对话归给它 | 新建集群 AgentId，旧独立 Agent 永久 converted |
| 集群关系 | 源 session Agent 的既有成员关系不动，新组 Agent 默认未加入；必须单独显式纳管 | 初始成员与角色转换同一元数据事务提交 |
| 历史与授权 | origin_agent_id/origin_binding 保留；旧批准与旧 binding 回调作废，组内目标重新冻结 | 旧 generation/批准/回调作废；历史引用不携带权限 |

会话 Agent 的绑定身份自身不改为另一个对象；变化的是当前对话的承接 Agent。源 session Agent 之后仍可新建自己的对话，不复制或抢回已交接对话。session→group 不可逆，不提供把该对话再改回 session 的操作。不得把它实现成 cluster.enable，也不得随着对话移动自动迁移集群归属。用户来源任务可在原建组授权覆盖的范围内以新 binding revision 续行，但须重新签发执行 scope。若被交接的是集群来源任务，对话移动不把该任务的协作授权带给未纳管的新组 Agent；交接后暂停该来源任务，需明确纳管及重新委派，原 TaskId/来源记录保留供对账。

组建立仍由现有 lifecycle controller 完成。V0.4 对 `prepareHandoff/commitHandoff` 增加 Agent 关联投影，持久记录 group、原/新 Agent 和同一 ConversationId 的交接意图；只有宿主组提交回执已核实，才能发布新 owner。恢复按原 HostOperationId 对账，不能因元数据未补全再次创建组；宿主结果未知时保持交接待核实并禁止旧绑定继续执行。不得宣称不同存储文件间已有原子提交。

## 3. Tab 名称与 AI 对话属性

### 3.1 Tab 命名

- 默认标题分别为“独立 Agent”“集群 Agent”；同类多实例由宿主提供稳定序号消歧，不因关闭其他 Tab 重新编号。
- 支持别名，采用“独立 Agent · 排障”“集群 Agent · 排障”等类型前缀形式。自动生成标题只更新别名；类型标识不能被覆盖。
- 转换提交时同一 Tab 更新类型前缀与图标，保留别名/位置/用户设置；其他窗口的导航、切换器、任务链接同步。准备中可显示“转换中”，不能提前显示成功。
- 会话 Agent 附着面板不修改其底层连接 Tab 名称。AI 对话标题、Agent 内容页标题、连接 Tab 标题分别存储。

### 3.2 对话来源与当前归属

AI 对话至少记录：

| 字段 | 契约 |
| --- | --- |
| `ConversationId` | 独立于 AgentId、连接 SessionId、TabId |
| `origin_agent_kind`、`origin_agent_id` | 创建时来自集群/独立/会话/子 Agent，创建后不可改写 |
| `owner_agent_id` | 当前承接 Agent；session→group 交接可改变，创建来源不变 |
| `origin_binding` | 创建时的会话/组绑定快照；独立与集群为空，不伪造连接绑定 |
| `cluster_at_creation` | 可选创建时集群来源；成员后续退出不篡改历史 |
| `initiator`、`task_id` | 用户直接发起或某个父级/集群委派；不与 Agent 类型混用 |
| `continued_from` | 转换时续接的旧对话 ID，可空；不是迁移旧权限的通道 |
| `state` | active/closing/closed/archived；关闭不等于删除 |

列表/属性浮窗显示“来源：独立 Agent / 集群 Agent / 会话 Agent”；子 Agent 显示自身类型及直接父 Agent 来源。当前所属集群单独显示，不覆盖创建来源。

独立→集群转换时旧对话关闭，新对话来源为集群，使用 `continued_from` 续接必要历史。session→group 则按§2.4保留同一对话，不创建伪续接记录。用户可连续阅读，但不能把转换前的消息伪标为集群产生。子 Agent 记录明确父主体，不将成员子 Agent 直接标成集群的子 Agent。

### 3.3 会话助手的 ×

会话 Agent 面板的 × 是“关闭当前 AI 对话”，不是销毁 Agent、退出集群、断开连接或删除历史。

关闭过程先将当前对话置为 closing，禁止新回合，取消当前对话尚未派发的步骤，并停止其运行回合与子任务；收集真实清理状态后关闭/收起当前对话。存在不确定清理时保留状态提示，不声称操作已全部停止。其他对话或独立委派任务不因本次 × 被取消。

再次打开助手默认新建对话；用户可以从历史查看/显式继续旧对话，但旧审批不会恢复。后台获准的集群委派使用该 Agent 的任务对话，不自动弹出或重新打开用户刚关闭的对话。Agent 身份、会话绑定、集群成员关系始终保留。

AI 内容页的 Tab × 是关闭该内容页运行实例；其内部对话的关闭动作另行定义并标注。关闭集群内容页停用该集群协调，不将它变成独立 Agent；允许之后恢复集群本身。

## 4. 目标、工具与附件范围

| 主体 | 可直接操作的范围 | 扩展规则 |
| --- | --- | --- |
| 独立/集群 Agent | 用户授权的任意现存会话/组及明确授权的本机能力 | 选择并冻结本次目标；不以集群成员名单代替授权 |
| 单会话 Agent | 仅绑定会话提供的能力 | 不能发现/操作绑定外既有会话；可按 PATCH 受控建组交接，跨范围任务可交给所属集群 |
| 组会话 Agent | 仅绑定组内冻结成员 | 可选择组内一项/多项；组变化重验，不自动扩入新增成员 |
| 子 Agent | 直接父任务授予的目标和能力子集 | 父为单会话则单会话；父为组则限定组内；不能借消息或转交扩权 |

“会话 Agent 不跨会话”覆盖执行、终端上下文、远程附件浏览、会话管理和模型工具，不只是命令执行。通用用户本地附件不自动提供额外连接能力；会话 Agent 不因运行在本机而获得操作宿主 shell 的兜底通道。

独立/集群 Composer 的目标选择器支持授权会话/组及具体成员。会话 Agent 的选择器固定本会话，组 Agent 仅列组内成员。目标选择和参考上下文分别记录；选择不意味着自动读取全部日志。

工具参数必须明确目标，宿主捕获会话 handle/generation、组 revision、权限 revision、调用来源与完整参数。多目标先预检后派发；前置不满足给出逐项原因，不擅自跳过目标。批准后的组成员或连接代次变化使批准失效。执行中失败允许部分结果，不能谎称分布式原子回滚。

远程文件 UI：选择允许范围内的会话/组 → 具体成员 → 目录/文件 → 捕获附件。单会话自动填入来源但仍可见身份；不同主机同名文件不能混淆。附件保留来源、路径、时间、截断信息和内容快照。切换当前 Tab、目标选择或连接重连不会重定向已附加内容。

已关闭 Agent 面板不影响在线连接选择；连接断开时可查询/引用快照，实时能力不可用；关闭的连接会话作为历史来源选择，重新执行须通过显式打开/重连取得新运行身份。保存配置与运行会话在选择器中分组，不把离线配置伪装成在线目标。

### 4.1 独立授权入口与执行适配

新增宿主私有的 `AgentAuthority`，包含 AgentId/kind/generation、ConversationId、TaskId、initiator、grant_revision、可选 parent/membership/coordinator revision。`ExecutionScope` 保存本任务实际授权的 SessionHandle 集合、group revision、能力集合、权限/执行模式与来源；scope 是宿主签发的不可变引用，不接受模型自报角色、成员或授权值。子任务只能取父 scope 的子集；附着主体还必须与其实时绑定求交。

保留 `host_tools.Context` 的 session/group 非零校验，以及 `host_queries`、旧 inventory、附着 UI 的原有拒绝路径。独立/集群通过新的 agent 工具网关验证 AgentAuthority，不能制造 session=0、AI 页面容器 SessionHandle 或临时全局组来满足旧 Context。AI 页面本身不是执行目标。

落地时增加内部 `ExecutionAuthority = attached(Context) | agent(AgentAuthority, scope_ref)`，由 `agent_host_adapter.zig` 连接执行服务；现有附着工具入口仍只接受原 Context。`host_execution` / lifecycle controller 的内部授权钩子和操作日志按该显式判别类型演进，旧分支调用原校验，新分支通过 AgentRuntime 再验。只扩展授权载荷、索引和回调，不复制其命令提交、等待、取消、输入、记录逻辑。旧日志 schema 迁移映射为 attached；不允许反向推导成 agent 授权。

实际派发链为：角色工具入口 → 任务/成员/目标/审批复验 → 现有宿主 controller → typed service → 原 exec 或 PTY driver。每次输入/租约续期/读取执行记录都重验 task、scope 和目标 generation；不得只在第一次 run 时检查。审批新增 AgentId/generation/scope revision 的绑定，保留现有命令规范化哈希及精确目标校验。集群来源任务使用该成员自己的执行身份，不能借集群 authority 越过成员绑定。

独立/集群的目标发现使用单独的授权目录投影；附着 Agent 没有该入口。成员目录只向已获协调授权的独立/集群列出候选，会话 Agent 仅能读取已加入集群公开的成员摘要；摘要不提供对方会话的实时工具引用。

### 4.2 工具目录与上下文预算

§2/§5/§6中的名称是逻辑命令集合，不要求每回合全部暴露。Agent 管理命令由可信宿主贡献，不塞入 AI 插件的 8 个插件工具配额；宿主配额仍是 32。按角色、授权、当前任务阶段选择注册表中的工具集，并固定到本请求的 RequestTable；目录中不存在的调用返回明确不可用，不在执行时临时放大目录。

需要切换“成员管理/任务协作/执行”等目录时，由宿主在下一模型请求边界重建目录并保留授权 revision，既有 tool_call 仍按原表解析。预先计算插件工具数、宿主工具数和序列化字节数；超过 16/32/96 KiB 即在发送前拒绝并提示缩小本次能力集，不静默截断、不直接提高常量。新增 API 与回归用例必须覆盖混合 Local/SSH/SFTP/KVM/网页连接插件目录的最坏组合；目录可见性从不等于操作批准。

## 5. 会话管理与 Agent 管理工具

本版目标是覆盖连接会话查询、创建/打开、修改、断开、重连、关闭，以及连接配置/历史记录的显式删除；组覆盖查询、创建、改名、成员增减、解散。当前 `host_catalog` 只有 list_hosts/get_host/create_host，不能把目标列表写成已具备修改/删除 API。逐项复用现有宿主命令；没有命令或精确影响审批的动作不发布给模型，在§12阶段补齐后才开放。关闭连接、删除配置、删除记录是独立操作，不提供含混的“删除会话”包办动作。

独立/集群 Agent 可在用户授权范围使用这些工具。单会话 Agent 只查询/控制当前绑定的既有运行会话，但可读取静态主机目录，并按现有 create_host 精确审批创建保存配置；保存配置不等于打开连接。它可按 PATCH 明确请求建组、保持同 ConversationId 交接，然后在组内新建获准工作终端；这不是枚举或接管其他既有运行会话的入口。组 Agent 可在授权后通过宿主在当前组内新建工作终端，提交成员变更后重取范围快照，旧批准不自动覆盖新增目标。将绑定外既有会话加入组，仍须由用户或具有独立授权的独立/集群 Agent 发起，附着 Agent 不能先靠 inventory 发现对象再请求扩权。子 Agent 默认无生命周期管理，确需时只授予父范围内具体动作，不能自己扩大父任务范围。

Agent 管理工具与连接管理分开：新建独立 Agent、转换集群、成员增减、查询状态、委派/消息/等待/停止、派生自己的子 Agent、关闭 AI 对话。集群不能用通用 `stop_agent` 等工具绕过子 Agent 边界；所有查询和动作均按直接父级/成员关系校验。

所有副作用操作沿原有宿主命令、影响预检、审批及资源清理回执执行。认证和秘密由宿主受控服务处理，模型不读取凭据明文。工具返回结构化成功/失败/取消/清理未知，保存成功不等于连接成功。

## 6. 消息与任务协作

### 6.1 允许关系

| 关系 | 消息 | 调度与管理 |
| --- | --- | --- |
| 集群 ↔ 本集群会话 Agent | 协调运行域启动且授权有效时允许 | 集群可委派/停止自己发起的成员任务；不能停止成员所有用户任务 |
| 同集群会话 Agent ↔ 会话 Agent | 经集群消息路由与授权允许 | 协助请求由接收方在自身范围执行；不能改写接收方权限 |
| 任意父 Agent ↔ 自己的直接子 Agent | 允许 | 父负责创建、继续、停止、收集结果 |
| 集群 ↔ 成员的子 Agent | 禁止直接通信 | 禁止直接控制；只能请求成员处理其子任务 |
| 会话 Agent ↔ 其他父级的子 Agent | 禁止 | 禁止 |
| 子 Agent ↔ 子 Agent | 全部禁止，包括同父兄弟 | 禁止 |
| 子 Agent ↔ 非直接父 Agent | 全部禁止 | 禁止 |

跨父任务需求必须“子 Agent → 自己父 Agent → 获准的其他父 Agent → 对方自己的子 Agent”，返回也沿父级。父级须审查并形成自己的消息/任务，不提供把子消息直接透传的代理 API。父级重新委派不迁移子 Agent 身份、不授予跨父邮箱。

V0.4 不新增跨集群自动协作、集群嵌套或未纳管独立 Agent 间的自主通信。用户可以在不同内容页各自下达任务。共享底层目标不代表 Agent 已经互通。

### 6.2 消息与执行不同

- `send_message` 投递信息，不自动启动模型回合；明确委派/继续任务才启动或排队。
- `delegate_task` 明确任务、交付物、范围、预算、关联对话与来源；成员未启动可在既有纳管授权内按需启动。
- `wait_events` 等待有界事件，避免轮询；`cancel_task` 停止明确任务，不能用消息文本替代取消回执。
- 消息含稳定发送者/接收者、task/message ID、回复关系、membership revision 与协调启动代次。去重、过期、回执和队列上限由宿主维护。
- 收到的消息属于有来源的任务数据，不是系统规则或用户授权。一个会话 Agent 请求另一个执行操作，不因此获得对方的直接工具权限。
- 单个对话默认一个活动回合；多来源请求排队，不同时修改同一对话。用户直接输入可显式打断，不能由任意集群消息抢占。

### 6.3 可实现的消息、任务及事件协议

- `send_message` 的幂等域为 sender AgentId + generation + request_key；同 key 同规范化参数返回原 MessageId，异参拒绝。收件箱先持久化再回 accepted，状态为 `queued → delivered → acknowledged`，也可进入 `expired/rejected`；投递成功不表示对方读过或任务执行成功。重试不重发，消息数量/字节上限触发背压；离线接收者不启动模型。
- `delegate_task` 单独创建 TaskId，写入 initiator（user / cluster / direct_parent）、root_task_id、parent_task_id、来源集群及 membership/coordinator revision、接收 AgentId、交付物、scope、预算。状态为 `queued → running ↔ waiting_approval/blocked → succeeded/failed`；取消走 `cancelling → cancelled` 或 `cleanup_pending/outcome_unknown`。后两者不得计入成功/已停止，清理有新证据后才能归档。
- 用户对话与集群委派分别使用 ConversationId/任务队列，成员的用户对话不被后台任务覆盖。用户可查看或明确接管任务，接管改变来源需要宿主记录新授权；不能靠把消息复制进用户历史伪装成用户请求。移除成员/停用集群按来源和任务祖先链取消，只影响对应 cluster 任务。
- 消息/任务创建、幂等回执与待发布事件一起进入§11.2的元数据事务；事件通过 outbox 发布，消费者以 event_id 去重。派发前重新验证成员/运行代次，失效消息返回 rejected 原因，不交给新集群或新启动代次。不能承诺网络副作用恰好一次，只承诺宿主接单去重与禁止未知结果重放。
- `wait_events(after_cursor, max_events, wait_ms)` 只返回调用者有权读取的事件，wait_ms 上限 30 秒；返回 next_cursor、has_more、timeout。cursor 包含授权域和 stream_epoch，事件保留已过期返回 gap + 最新快照/续读位置，不以空数组掩盖缺失。超时不代表任务完成，快照不泄露子 Agent 私有邮箱/控制句柄。
- 每个 Agent 的收件箱有界，每个 ConversationId 只有一个运行回合；父等待孩子或等待事件时释放 Provider 并发槽，不持有资源锁等待。父/子任务依赖必须无环；等待自己的转换调用同样禁止。业务状态事件驱动 UI 和 wait，不用模型定时询问状态。

## 7. 运行、退出与停止

集群成员关系持久化，协调运行状态独立管理。显式启用集群并打开内容页后启动协调域；空闲不持续调用模型，切 Tab/最小化不停止。停止当前回复只停止当前任务，停用集群或关闭其内容页才关闭协作门禁。

停用时立即禁止新跨成员消息/委派，撤销当前协调代次；待执行的协作步骤取消，已执行请求按任务树向各直接父级发出取消。成员父 Agent 再停止自己的子任务，集群不直接调用子 Agent。取消失败/远端未知单独记录，不用父任务已取消推定所有进程已停止。

成员由用户直接发起的任务及其子任务不受其他集群任务停止影响。集群停止后会话 Agent 可单独工作和使用自己的子 Agent，但跨成员协作不可用。其他集群不受影响。

恢复集群时换新协调代次，重新验证成员、任务权限及目标；不自动重放旧消息、旧审批和未确认副作用。关闭底层连接时立即撤销该绑定的实时能力，保留 Agent 历史和成员信息，并显示连接关闭。重新打开获得新运行身份，必须明确重新关联，不能按主机名称继承旧批准。

子 Agent 完成后释放模型/工具运行资源，保留只读结果。未完成任务可由同一个直接父级在有效授权内继续；不能换父复活。父 Agent 被转换/销毁前完成或停止其子任务，禁止产生无主执行者。

## 8. 权限与资源冲突

有效权限 = 用户授权 ∩ Agent 角色硬边界 ∩ 任务委派范围 ∩ 目标当前能力。状态可见、内容读取、消息、委派、资源执行分别授权。纳管不等于完整历史共享，也不等于任何命令免审批。

会话 Agent 的单集群约束由宿主原子登记，两个集群同时纳管只能一个成功。成员/权限撤销使未执行调用失效；正在执行的副作用按真实取消能力处理。

连接会话是最终资源仲裁对象：独立 Agent、集群直接调用、成员 Agent 及组 Agent可能访问同一目标。只读操作按服务能力并发；关闭/重连等生命周期操作与冲突写操作需排他或排队。锁定与权限复验发生在实际派发前，不能仅按不同 Agent ID 判断无冲突。外部操作者或不同连接访问同一远端资源仍可能竞争，不承诺宿主锁能覆盖外部进程。

审批绑定原始任务、执行者、目标代次、完整参数和权限 revision，父级转交不能洗掉原来源或升级权限。同一审批事实在授权位置展示并只处理一次；集群 Agent不能代用户批准成员操作。

子 Agent 的私人对话、控制句柄和收件地址不向集群暴露。集群可以读取会话父 Agent 发布的子任务总数、忙碌/阻塞摘要及获准交付结果，但这不是对子 Agent 的直接查询或交互。

## 9. 简洁状态 UI 与详情浮层

主 AI 助手/页面只保留角色、关键状态和数量，不常驻完整成员树、完整任务日志或大量状态列。

| 位置 | 常驻摘要示例 | 点击后的详情 |
| --- | --- | --- |
| 独立 Agent | 独立 · 空闲；子任务 2 | 自己的子任务列表/状态；启用集群入口 |
| 集群 Agent | 集群 · 协作中；成员 4 · 忙碌 2 · 待处理 1 | 成员浮窗、增减成员、授权状态、任务摘要；成员子任务仅父级发布的摘要 |
| 会话 Agent | 所属会话/组；集群名称或“未加入”；子任务数量 | 所属集群是否启动、同级成员公开状态、自己的子 Agent 详情 |
| 子任务详情 | 任务状态、父 Agent、必要目标 | 结果、阻塞、权限与停止操作，仅直接父级或用户有权操作 |

摘要计数从宿主事件产生，不触发模型查询；忙碌、待审批、失败等精确语义在浮层展开。非颜色唯一编码，提供文字和键盘可访问入口。短说明用气泡；有按钮、列表和滚动内容的详情使用可聚焦浮窗，不能只放 hover tooltip。危险操作的目标/影响与审批仍常显在原审批区，不以精简状态为由隐藏。

显示全局应用导航供用户定位多个 AI Tab，不把所有 Agent 的详细状态注入每个 AI 页面。未加入集群的会话 Agent 不显示其他集群内部信息。

视觉实施复用已有组件与 tokens，以可编辑 HTML/CSS 制作必要状态基准，再通过 zenit-html-ui 实现；本文未定义猜测像素，不代表原型/原生 UI 已验收。

## 10. 插件设计：事实连接与附着功能组件

### 10.1 对第 13 条的结论

AI Agent 应作为正式的独立内容页连接接入；会话助手作为附着功能组件接入。这里“事实连接”指宿主真实管理的独立运行实例，不要求必须建立网络 socket。AI 运行实例无需创建假 SSH 或隐藏终端。

插件不宜简单分成互斥两种插件枚举；应允许**同一插件声明两类贡献**，分别是 `StandaloneContribution`（独立内容页）和 `FeatureContribution`（附着功能）。AI 插件同时提供二者，共享 Agent 核心和视图组件。

| 方面 | 独立内容页连接 | 附着功能组件 |
| --- | --- | --- |
| 创建入口 | 新建/连接标准动作 | 宿主对可附着对象提供入口 |
| 身份 | 自己的运行实例与 Tab；关联独立/集群 Agent | FeatureInstanceId + 明确宿主绑定；关联会话 Agent |
| 生命周期 | create/cancel/close、资源回执、恢复 | attach/update_binding/suspend/detach/dispose；对话关闭另行处理 |
| UI 槽 | 标准内容 renderer | 宿主分配的面板/浮层槽 |
| 服务 | 自身声明的运行服务与工具 | 从宿主受限借用所需 typed service，不自行克隆连接 |
| 存储 | 可选创建配置 + 运行状态 | 组件偏好 + owner 绑定状态，不伪造主机资产 |
| 权限 | 与任务目标分别授权 | 受宿主绑定硬限制，再与任务授权取交集 |

“连接插件的复用”是复用注册、服务、工具、配置事务、受限 UI、事件和生命周期基础设施，而非把功能组件包装成另一个实际连接。组附着由宿主组上下文提供成员能力投影，不要求每个连接插件实现自己的组助手。

### 10.2 已有基础与真实缺口

当前 `src/host/plugin_registry.zig` 的 API 为 2，已有 `connection`、`quick_create`、`session_factory`、typed services/tools、AI context 和 renderer 注册。`publish` 当前要求每个 manifest 都有 session factory 与匹配的内容 renderer；`src/host/plugin_ui_contract.zig` 的 ContentMount 绑定 SessionHandle。已有 AI context 是连接向助手提供上下文，不是可挂载功能组件的生命周期契约。

因此，不能声称 API 2 已完整支持功能组件。V0.4 必须补充能力：

1. 按贡献类型校验：独立贡献要求创建/运行工厂和 renderer，纯功能贡献要求 FeatureFactory 与受限面板 renderer，不要求伪造 session factory。
2. 提供 FeatureHost 和 `FeatureBinding = session(handle) | group(id, revision)`；支持资格、唯一性、服务需求及失效通知。
3. 提供 FeatureMount：只含槽位、tokens/主题、功能实例身份、绑定快照、受限服务解析器和事件出口，不暴露全局 App/UI 根。
4. 服务借用显式携带目标 handle/generation/权限 revision；组件持有的是可撤销引用，不获得连接所有权。组按目标解析服务，缺能力成员如实禁用，不扩大或伪造共同能力。
5. UI unmount 只释放视图，不能等同销毁 Agent；suspend 撤销不可用的会话能力；detach 是明确解除功能绑定，完成任务清理后 dispose。×关闭对话不调用 detach/dispose。
6. 插件配置/工具/服务按稳定命名空间注册，依赖和 API 版本在发布前验证，卸载/移除能力不得留下悬空句柄。

目标契约示意（非已实现 Zig API）：

```text
PluginManifest
  metadata, dependencies, settings, service/tool definitions
  standalone?: { creation, runtime_factory, content_renderer }
  features[]: { id, supported_bindings, required_services,
                feature_factory, panel_renderer, attachment_policy }

AI plugin
  standalone: quick_create -> IndependentAgent; page renderer
  feature: attach(session | group) -> SessionAgent; assistant renderer
  shared: AgentRuntime, conversation/composer, attachments, approvals, results
```

本版采用 **宿主 API 3 + API 2 兼容消费**，具体顺序如下：

1. 引入版本化入口与归一化 manifest。保留 API 2 的原字段语义/默认值，将 session_factory、workspace_kind、renderer 归为 standalone；新 feature 只能经显式 API 3 声明。不能让共享默认常量变更把旧声明自动标成 API 3。
2. `plugin_registry.publish` 先按来源版本验证，再统一验证贡献/依赖/服务；纯 feature 路径跳过 standalone 工厂/renderer 要求，但必须验证 FeatureFactory、binding 类型及 panel renderer。混合贡献分别验证，任一失败均不发布。
3. 同步改造 `plugins/linked_plugins.registerAll` 的精确版本检查及 legacy descriptor/registration 默认值，保证 Local/SSH/SFTP 仍经 API 2 适配。新增版本协商函数供所有注册路径共用，未知版本拒绝。
4. `PluginHost.apis` 的 host 依赖解析按兼容表处理 major=2/3，不能在当前按 id 唯一的列表里直接塞两个 host 条目，也不能将依赖 major=2 强改为 3。非 host 服务及插件依赖继续精确匹配各自 major/type token。
5. API 2 的 ContentMount、renderer update/unmount、session factory、typed services/tools 通过适配保留行为；API 3 feature 使用另一个 mount 契约。持久配置 payload_version 与宿主 API 版本独立，升级宿主不触发无关配置迁移。
6. [V0.3 BMC iKVM](V0.3_BMC_IKVM.md) 和 [V0.5 网页连接](V0.5_WEB_CONNECTION.md) 的 API 2 声明继续作为合法输入由兼容层消费。不能要求它们为采用 V0.4 重写协议、frame sink、凭据或执行实现。

兼容验收必须实际走 builtin legacy/API 2 bundled/API 3 standalone/API 3 pure feature/API 3 mixed 五种发布路径，并覆盖 host major=2 依赖、无效版本/缺 factory/错误 service token、renderer 迁移窗口能力校验。只测试 manifest 常量或新 AI 插件注册不算兼容完成。

### 10.3 AI 插件的具体接入

- AI 内容页优先复用 `quick_create` 语义：新建独立实例无需强制保存连接资产。若以后提供可保存模板，只保存模型/偏好等配置，打开模板仍新建独立 Agent，不能保存“新建即集群”的捷径。
- 标准运行容器可以继续采用宿主 SessionHandle 管理插件实例；其含义是 AI 页面实例，并非被 Agent 附着/操控的连接会话。业务 `AgentBinding` 对独立/集群始终为空，AI 对话使用另一 ID 域。
- AI 页面自己不声明会话助手附着资格，避免“Agent 页面再附着 Agent”递归；也不作为远程终端/文件目标或集群会话成员。选择器依据能力与绑定类型排除，而非靠名字判断。
- 支持的连接插件提供上下文/工具服务和附着资格；宿主挂同一 AI feature，连接插件不各画一套 AI 助手。
- 不具备 exec 的文件连接或 KVM不因附着 AI 就获得 shell。功能可用范围取实际服务快照，不绑定到“连接在线”等单一布尔值。
- 转换只替换该 AI 页面关联的业务 Agent，保留同一插件内容容器/Tab；不重建网络连接，不影响被纳管的成员连接。
- 子 Agent 仅为 AgentRuntime 的任务实体，不创建连接资产、顶层 Tab 或附着组件。

## 11. 运行、存储与恢复的实现方案

### 11.1 模块职责及身份索引

应用进程持有一个 AgentRuntime；页面/feature 仅发命令和订阅投影，不各建调度器。至少分离 AgentId、ConversationId、ClusterId、TaskId、FeatureInstanceId、连接 SessionHandle 和 TabId。会话 Agent 的稳定键使用 Agent store 中持久的 binding_id，映射一个逻辑连接实例，不能按 AssetOwner/主机名称去重；同配置打开两次对应不同会话 Agent。在线 SessionHandle/generation 仅为当前能力，重启恢复不直接复用，重新打开后须明确重新关联。组 Agent 使用组身份，组 revision 单独递增；关闭的绑定记录仅保留历史。

Agent 记录包含 role、generation、state、binding（仅 session/group Agent）、唯一 parent_agent_id（仅 child）、successor_agent_id（仅 converted）；成员记录独立包含 cluster_id、member_agent_id、membership_revision、state。会话 Agent 同时最多一个有效成员记录，在宿主单写事务内校验唯一索引。附着 Agent 的初次登记由 FeatureHost 完成并去重，不随打开/关闭 AI 对话反复产生身份。

`assistant_store` 继续负责现有内容、草稿、附件、Provider wire history 等，不把连接 owner 当 AgentId。增加以 ConversationId 查询的对话元数据表，将 initial_owner/origin 与 current_owner/owner_agent_id 分开；现有附着历史按真实来源导入，未知字段保持 legacy/unknown，不猜测集群或任务来源。独立对话允许无连接 owner；这是对话存储模型的扩展，不放宽 attached Context。

### 11.2 具体持久化提交点

第一版采用**单个有界 Agent 元数据快照**（拟定 `ai/agents/state.json`），不新增数据库依赖。由一个进程级 IO owner + 排他文件锁持有；写入校验预期 store revision 与磁盘摘要，禁止各窗口各存一份。快照包含 Agent/绑定/成员/任务/对话头、Tab→Agent 关联、转换回执、幂等索引和待发布 outbox；收件箱保存 MessageId、发送者/接收者及代次、任务/回复关系、状态、过期时间和不可变消息内容块的哈希引用。实际执行命令、凭据、终端输出仍留在现有受控服务/记录中。

`send_message` 先将消息内容块写入并持久化，再将收件消息头、内容引用、发送幂等回执及 outbox 事件在同一次 state 快照提交中发布，完成后才返回 accepted。崩溃恢复从收件箱记录恢复投递状态，outbox 只负责通知；不能仅持久化 outbox 就声称消息已入箱。内容块预写后提交失败仅留下未引用块，恢复不得产生第二条 MessageId。

事务具体执行：

1. controller 解析命令并准备不借用 UI 指针的计划；规范化参数哈希与 `(actor_id, generation, command, request_key)` 一起保存。相同 key 异参拒绝，相同请求返回原 operation/后继 ID；旧主体 converted 后仍能查询其原转换回执，但不能执行新命令。
2. 在锁内校验身份、成员唯一性、revision 及预算，形成 converting 意图并持久化；释放锁，完成获准的旧任务/子任务清理。初始成员不提前对外显示已加入；并发纳管者可先成功，转换提交时若冲突则整体失败，不留下空集群。不得持锁等待 Provider、审批、子任务或宿主 IO 回调。
3. 对话必要历史写成不可变内容块，写完并持久化后得到哈希引用；对话头和引用在最终快照内提交。预写后失败仅留下可回收的未引用块，不能出现已发布的新对话引用未落盘历史。当前草稿、已完成工具结果和完整 tool_call/tool_result 配对按显式续接边界整理，不复制待执行调用或审批。
4. 在锁内重验计划，构造完整 next 快照；写同目录临时文件，sync 文件，原子替换唯一 state 文件，再同步父目录（采用项目实际 Zig/平台 IO API）。成功后更新内存 revision，再发布 outbox/UI。**旧主体终结、新主体/对话、初始成员、Tab 关联和转换回执处于同一个文件的一次替换**，不是多个 rename 的“事务”。
5. 文件落盘/替换前失败保留上次快照；替换已发生但目录同步/结果回传失败则进入 commit_unknown，停止旧主体入口并按原 key 读取恢复，不以“返回错误”回滚成独立 Agent。平台持久化保证必须通过故障测试确认，不能沿用现有原子写函数就声称断电安全。

工程初始限制为 state 快照序列化后最多 8 MiB、各元数据表合计最多 8,192 条记录，其中待发布 outbox 最多 2,048 条；先达到任一限制即背压，满额前停止接收新增工作，回收策略只归档已终结且无引用的历史。converted 墓碑、有效幂等回执和未清理任务不能因队列清理被删除。该方案用于本版本地有界协作，不要求同时改造全部应用配置存储。

现有 `lifecycle_journal` 仍是执行/生命周期副作用的事实来源，它当前的单文件原子替换不能与 Agent state 合并成跨文件事务。Agent state 只关联 HostOperationId/ExecutionId；先保存派发意图，再调用现有幂等服务，再记录回执。两次写之间崩溃按原 operation 对账；副作用已派发但无可靠回执时使用 outcome_unknown，禁止换 request_key 再执行。§2.4的建组交接走这一恢复边界，不冒称与 metadata 同事务。

### 11.3 崩溃、旧回调与恢复矩阵

| 断点/竞态 | 必须恢复出的状态与行为 |
| --- | --- |
| converting 已保存，旧任务还未清完 | 旧 Agent 可显示但入口冻结；原任务先查现有回执，清理未知继续阻塞，不自动提交/重放 |
| 历史块准备完，最终 state 尚未替换 | 权威 state 仍为 converting；可按原意图继续或在安全清理后解除冻结，未引用历史不成为新对话 |
| 最终 state 已持久化，UI/工具回执未显示 | 只恢复新集群；旧 Agent 墓碑定位同一 successor，outbox 重投由事件 ID 去重 |
| 两个窗口同时转换或纳管同成员 | 事务 revision/唯一索引保证至多一个成功；失败者取得明确冲突/原幂等回执 |
| 重启后原协调域/子任务仍显示 running | 恢复为 suspended/recovery_required；新启动代次重验后由明确继续动作启动，不自动调用模型或工具 |
| 旧审批/Provider/文件选择器/执行结果回调晚到 | callback 携带 Agent generation、ConversationId、TaskId、binding/grant/membership revision；只更新原记录或丢弃失效展示，不能写入后继对话或派发新操作 |
| 成员移除与队列派发竞争 | 撤销先落盘；派发复验归属/协调代次，原任务清理未知保留退出中，不允许加入新集群 |

转换工具使用宿主控制结果收尾：提交成功后旧对话写入终结事件，新对话写入引用同 operation 的交接事件；这些事件随权威 state/outbox 可恢复。Provider 后续 completion 只能关闭旧请求，不能重新启动旧 Agent。模型故障、窗口关闭都不能决定 converted 是否回滚。

### 11.4 调度、预算与资源回收

每个 Task 显式保存子任务数量、模型请求/token 上限、工具调用上限、并发上限与 deadline；模型、token、工具调用及 deadline 优先继承现有任务和 Provider 限制，与父任务剩余额度取更小值，不另增一套模型配额或设置 UI。父派生时先预留子预算，完成/取消后释放未使用额度，禁止父子分别花掉同一额度。Provider 未返回准确 usage 时先保守计入已预留预算，不能按零消费继续无限派生。耗尽进入 blocked_budget，不自动扩额；续预算必须来自用户或仍有可用预算的直接父任务。

队列按 Agent/任务来源做轮转并设置等待老化，防单个集群塞满所有 Provider 槽；用户交互优先但不无限饿死后台已授权任务。工程初始上限为宿主同时 4 个模型请求、每 Agent 同时 1 个模型请求、每集群同时 2 个成员任务进入模型执行、每直接父任务最多 4 个未终结子任务；待运行任务每 Agent 最多 32 个、全局最多 128 个。既有 Provider/任务限制更低时取更低值，不能把各成员上限相加当成宿主容量。取消标记先撤销新派发，再沿直接父子链传播；等待清理不占模型槽，不因为超时就声称进程已退出。

收件箱初始限制为每 Agent 最多 128 条未确认消息且内容总量不超过 1 MiB，单条消息内容最多 16 KiB，全局未确认消息最多 1,024 条；任一超限均返回 QueueFull/MessageTooLarge，不静默丢弃。以上数值及§11.2存储上限是保守工程初值，未经过性能实测，先作为内部常量实施；必要调优须以定向测量为依据，不增加设置产品。

执行资源复用现有 SessionHandle/目标 generation、PTY Lease、ownership_revision 与录制屏障。持有执行 lease 才能输入，用户接管撤销 Agent 输入；Agent 完成不能自动关闭 borrowed_user 或 handed_to_user 终端，created_task 资源按保留策略清理。组 Agent/单会话 Agent/多个集群对同一目标使用同一仲裁入口，按稳定目标顺序申请多目标短锁，不在持锁时等待用户批准；派发前再次复验。只读与写入的并发规则由具体服务决定。

保留 exec 与 PTY 不同完成证据、Local private_protocol 与 SSH shell_reported 的区别、session_interval 输出归属及 recording_degraded/outcome_unknown。聚合结果须逐项显示 local_released、remote_effect_unknown 和资源所有权，任务取消、预算耗尽或集群停止都不能把未知远端效果变成“全部已停止”。

# V0.3 应用内更新设计

> 2026-11-02：本功能属于 **0.3**，与 [BMC iKVM](V0.3_BMC_IKVM.md) 共同交付；不新增版本编号。已接入原生更新控制器、任务关闭协调器、独立安装辅助程序及签名发布脚本；HTML/SVG 继续作为可编辑设计基准。原生验证与发布边界见本文末尾。实际构建版本仍读取 `build.zig.zon`。

用户发布新版本后，ZeroWork 可发现更新，用户选择下载；更新包验证通过后，点击安装。存在运行工作时，应用提供 **「结束任务并安装」**：用户一次确认，应用负责结束所有相关工作、保存应用状态、正常退出、替换应用并重启。无需用户逐个关闭任务。

设计基准：[可交互原型](../UI_V3/app-update/index.html) · [状态、主题与原生映射](../UI_V3/app-update/README.md)。本设计替代此前 SVG 中“请先手动结束工作”的流程；旧稿仅保留为聊天历史，不再作为实施依据。

## 1. 范围与可行性

首版支持公开 GitHub Releases、arm64、macOS 14+、正式版通道、完整 ZIP 更新；当前 RC 可升级到较新的正式版。保留 DMG 手动安装。自动检查默认开启，首次启动异步检查，此后按持久化时间戳每 24 小时最多自动检查一次；手动检查可立即重试。后台失败不打扰，手动检查显示失败与重试。下载失败不自动安装。

不实现增量更新、静默安装、提权服务、私有仓库凭据、预发布通道或自动回退用户数据。首次带更新器的版本仍需用户手动安装。更新器只结束 ZeroWork 管理的本地资源，不向远端发送任意清理脚本或终止无关进程。

| 基础 | 设计时基础 | 当前实施状态 |
| --- | --- | --- |
| 发布与身份 | `scripts/package_macos.sh` 已生成固定签名的 App、DMG 与校验文件；包含完整发布版本字段 | 常规打包只生成 DMG 和校验文件，并校验固定信任配置；自动更新所需的 ZIP 和 Ed25519 签名 `update.json` 须另行准备 |
| 下载与签名 | 项目已有 Objective-C 桥接；Zig 0.17 标准库包含 Ed25519；macOS 提供 NSURLSession 与 Code Signing Services | 已接入有界 NSURLSession 下载、原始 payload 验签、SHA256、受限解压与固定签名身份校验 |
| 全局资源关闭 | `SessionHost` 的关闭阶段与 CloseReceipt，`application_task_domain.Domain.shutdownStep()` 的 retained 传输、转发、认证收尾已存在 | 已接入可取消的关闭协调器、生产入口门禁、全窗口与后台清单；保留原关闭操作和实际释放回执 |
| 主题 UI | 现有 V3 语义 tokens、全局材质、Modal/Button/Progress/Switch | 已接入设置页及原生 Modal/Button/Switch，按既有主题语义渲染；实机核对几何与颜色 |

以上支持技术可行性，不代替包体、性能、退出与安装实测。现有 `shutdownStep()` 属于不可逆的进程退出路径，不能直接在可取消的更新对话框中调用；需要先明确可继续运行的关闭屏障与实际退出之间的边界。

## 2. 发布与信任链

一个正式 Release 具备以下附件，资源全部上传并验证后再发布，并按版本顺序明确指定正确的 Latest：

常规打包只生成 DMG 及其校验文件；如需提供自动更新，须另行准备 ZIP 和签名清单。

- `ZeroWork-<版本>-arm64.dmg` 与现有 `.sha256`，供手动安装。
- `ZeroWork-<版本>-arm64.zip`，只包含最终签名的 `ZeroWork.app`，供自动更新；不使用 GitHub 自动生成的源码 ZIP。
- `update.json`，包含签名封装：`key_id`、`payload_base64`、`signature_base64`。签名覆盖解码后的 payload 原始字节，先验签再解析可信内容，避免重新序列化和多附件竞态。

固定发现地址为 `https://github.com/iskylite/ZeroWork/releases/latest/download/update.json`。payload 包含 schema、完整版本、最低系统版本、架构、绑定具体版本的 HTTPS ZIP 地址、准确字节数、解压大小上限、SHA-256、纯文本更新说明和官方 Release 地址。地址须属于内置仓库及允许的 GitHub 附件重定向链；拒绝非 HTTPS、未知 schema、错误架构、不兼容系统、同版本覆盖与降级。版本按语义比较，`0.3.0-rc1 < 0.3.0-rc2 < 0.3.0 < 0.3.1`，不能按字符串排序。

主程序与辅助程序内置同一公钥集，`key_id` 只能选择内置可信公钥。私钥保留在发布端，不能放入仓库或应用。ZIP 验哈希后，解压前检查路径逃逸、绝对路径、文件数、总大小及链接目标；允许 App 合法且限制在包内的相对链接。包内标识固定 `com.zerowork.app`，完整版本与清单一致，并检查 arm64、系统条件、严格代码签名和受信任签名身份。不能只接受任意有效签名。

当前本地自签名身份可用于受控验证，按证书身份约束；正式面向其他用户分发还需 Developer ID 与公证验收。更新清单签名和 Apple 代码签名各自验证。首版不从未受信任清单接收替换公钥；丢失私钥或不兼容身份更换通过手动安装恢复。

## 3. 一次确认结束全部工作

### 3.1 安装前预检与工作清单

更新包必须先下载并验证；先检查应用位置、安装目录权限、可用空间和辅助程序完整性，再允许结束任务。无权限或只读位置直接进入手动安装，避免关闭工作后才发现无法替换。

工作清单来自应用级宿主，覆盖所有窗口、后台域和隐藏工作，不从当前 Tab 或 UI 节点推断：

| 工作 | 应用负责的结束动作 | 完成依据 |
| --- | --- | --- |
| 本地终端、SSH、独立 SFTP、连接中/重连中会话 | 停止新操作与重连，走既有取消/close 阶段；结束本地 owned PTY/子进程组，关闭 SSH/SFTP transport | owner/generation 对应的真实本地资源 released |
| 文件传输及后台 retained 任务 | 取消排队与运行任务，停止读写、保存已有恢复检查点，等待 worker/句柄释放 | producer 停止、清理回执 released；不将请求取消等同释放 |
| AI、审批、工具执行和 probe | 停止模型流与调度、撤销待审批及租约、结束 owned exec/PTy，保留对话、发送边界与未知结果 | 工具循环与本地资源释放；未知远端结果继续保留在记录中 |
| SOCKS/端口转发、KVM | 停监听、关闭 relay；释放 KVM 输入和视频生产者，注销自有会话并释放独立 transport | 本地 listener/worker/channel/sink 已释放；远端注销结果单独记录 |
| 跨窗口、尚未完成创建或已经关闭中的任务 | 加入同一 app scope，按稳定 owner 与 operation 去重并继续等待 | 不能因窗口销毁或 Tab 隐藏而漏计 |

断开 SSH 不保证远端命令终止；取消已发工具或管理动作不等于业务回滚。已发未知结果不自动重放、不冒充成功或取消。远端结果未知但本地资源已明确 released 时，可以安装，并将未知结果写入记录；本地资源为 unknown/awaiting 时不能继续退出或替换。

### 3.2 确认、草稿与更新前快照

没有运行工作时按钮为「安装并重启」。有运行工作时打开确认框，主按钮「结束任务并安装」，次按钮「取消」。确认前不发送关闭请求；取消、Esc、关闭窗口均返回准备安装状态，不改变工作。

草稿检查覆盖全部窗口的设置、连接编辑、AI 未发送输入及其他未提交内容，先于结束工作。只保存产品原本允许持久化的内容，不自动提交配置、不把密码/API Key 等敏感编辑内容写入快照。提供返回处理与明确放弃的选择；没有安全保存出口的内容须由用户决定保留或放弃。取消或保存失败均不开始关闭。

确认绑定不可变 `UpdatePlanId + package_digest + inventory_revision`。主线程先建立应用级门禁，再核对最终清单；新增工作、改变安装目标或草稿内容变化时释放本轮临时门禁、刷新摘要并重新确认。自然结束的工作可剔除。无运行工作的路径也必须经过同样的门禁与复核，不能直接跳过；门禁后所有窗口的创建、自动重连、AI 派发及传输入队均被阻止。

**任何关闭请求之前**，保存更新前的窗口/分栏/资产关联、允许恢复的草稿和布局快照，并取得成功回执，绑定计划与清单修订。快照保存失败显示「工作区快照未能保存」，提供重试保存与稍后更新；此时工作未被结束。不能等 Tab、组成员与挂载被销毁后再采集布局，也不能用关闭后的空工作区覆盖快照。

关闭过程中另行补记操作结果、记录尾部与传输检查点；这属于收尾记录，不替换更新前布局。更新成功、安装失败或取消更新均不重放输入、传输、AI 或远端写入。部分关闭后再次安装时重新采集现存工作、核对修订；已发关闭继续接续，不把旧布局当新授权清单。

### 3.3 关闭批次与取消安装意图

新增目标契约 `UpdateCloseCoordinator`，按宿主依赖顺序停止生产者和释放资源。普通会话关闭可能保留后台传输，更新关闭必须覆盖 retained 域；关闭副作用归原资源 owner，重复点击和重试不重复派发。

**安装计划和关闭批次分开管理**：`InstallIntent(plan_id, generation)` 可撤销；`CloseBatchId + owner + close_operation` 的生命期持续到已发请求收尾完成。关闭回执不因安装意图失效而丢弃，由原 owner/批次更新真实释放状态；它们只能继续清理和刷新清单，不能恢复安装授权。

关闭过程中展示「已结束 / 正在结束 / 等待释放 / 结果不明」，进度只按真实 released 数量累计。UI 与事件循环保持运行，不能在主线程 join worker。

- 在尚未交接辅助程序时点击「取消更新」，立即撤销安装意图，不再派发剩余主动关闭；已经发出的关闭仍继续收尾，已经结束的工作不恢复。
- 主 UI 返回工作区，显示仍在收尾的数量与入口；释放应用级创建门禁，但 closing/unknown owner 保留自身限制。新 owner 的操作不得被旧批次回执取消。
- 再次更新时查询最新清单，接续已有 close_operation，并为新增工作重新确认；不能重新派发已发远端命令，也不能把旧批次的晚到回执误当新安装完成。
- 等待 15 秒显示「仍有任务未结束」，保持真实回执接收；重试仅查询或推进原清理步骤，不伪造 released、不要求用户逐项关闭。
- 全部释放后复核目标、空间与包摘要，补齐收尾记录。无论取消后最后一个回执何时到达，安装意图已撤销就绝不能进入交接。

辅助程序开始准备以后，取消按 §4.1 的确认协议处理，不能仅在主界面清掉计时器或 generation 后就宣称已取消。

## 4. 安装交接与失败恢复

### 4.1 准备、提交与取消回执

主程序在启动辅助程序前，将随包签名的辅助程序复制到 0700 的私有事务目录。辅助程序独立复核清单签名、暂存包、目标 realpath、包标识与签名身份，不使用 shell 拼接命令，不提权。事务与短期通信包含随机事务 ID、计划 ID、包摘要、父进程身份/启动时间和一次性 nonce，校验同一用户及预期进程身份。

`PREPARE → PREPARED` 只表示可安装，**不会授权替换，也不能因为父进程后来退出就自行安装**。主程序只有在安装意图、清单门禁与预检仍有效时，才发送 `COMMIT_REQUEST`。

辅助程序按单一事务串行决定提交或取消，并先持久化决定，再回复；仅允许 `undecided → committed` 或 `undecided → cancelled` 一次终态转换。具体规则：

| 竞争或事件 | 决定与主界面行为 |
| --- | --- |
| 主程序在发送提交前取消 | 不再发送提交；请求取消，等待 `CANCELLED_ACK` 后返回工作区 |
| 提交请求已发出，用户请求取消 | 显示「正在确认取消更新」，保留启动门禁；不能提前显示取消成功 |
| 辅助程序先接受取消 | 持久化 cancelled，回复 `CANCELLED_ACK`；晚到提交被拒绝，之后任何普通退出都不触发替换 |
| 辅助程序先接受提交 | 持久化 committed，回复 `COMMITTED_ACK`；晚到取消得到已提交结果，UI 转为不可取消的安装阶段 |
| ACK 丢失或连接中断 | 按相同事务查询持久决定，幂等重试；不能根据 UI 超时推定取消成功，也不能启动第二个事务 |
| 已提交但父进程未在期限内正常退出 | 不强杀、不替换；辅助程序持久化 `aborted_before_replace` 并撤销本次退出授权。之后退出不能触发旧事务，重试须新授权 |

主程序收到提交成功回执后才正常退出。若提交结果不明而主程序崩溃，恢复入口先核对持久决定和实际包状态；没有有效提交决定的事务只能清理或取消，不能推断用户仍希望安装。

### 4.2 启动门禁与锁

安装互斥覆盖同一当前用户、目标 App bundle 及数据作用域，不能只防两个更新按钮。安装事务锁与现有 `DataScopeLock` 职责分离，避免旧主进程持数据锁等待 helper、helper 又等待数据锁的死锁。

普通启动在配置加载、数据迁移与创建工作区之前，先检查安装/恢复门禁。存在活跃事务时只附着只读安装状态，不启动任务、不迁移数据、不自行运行旧包。辅助程序持有事务唯一决定权；仅为已经验证的目标版本、进程和一次性启动 nonce 发放正常启动许可。旧版退出后数据锁释放，不代表安装门禁解除。

辅助程序已失效或机器重启时，恢复入口先取得唯一恢复所有权、读取持久记录并核实包身份，再处理事务；不能按过期 PID 杀进程，也不能直接把“helper 不在”当作安装成功。替换前还要确认目标没有被其他相关实例占用。事务只有在新版健康确认、旧版安全恢复或替换前明确终止后才解除相应门禁。

### 4.3 事务持久化与中断恢复

事务至少记录目标、旧版/新版身份与摘要、同卷暂存/备份位置、提交决定、替换阶段、数据兼容标记及启动回执。决定与阶段使用原子写入并落实文件及目录持久化；关键记录未成功落盘就不执行下一破坏性动作。记录只描述意图，恢复时必须核实磁盘上实际包及签名，不能只信阶段字段。

| 持久阶段 | 中断后必须核对 | 恢复动作 |
| --- | --- | --- |
| prepared / undecided | 原包身份、辅助程序、是否存在有效提交 | 无提交则保留原包，终止事务；不能自动安装 |
| committed / waiting_parent | 提交决定、准确父进程是否仍在、退出授权期限 | 仍运行则等待或在超时后撤销本次替换；不能强杀 |
| staging_verified | 原包、完整新版暂存及空间条件 | 尚未动原包可安全终止；继续须满足原事务授权与占用检查 |
| backup_verified | 备份有效性、目标是否缺失或部分替换、是否曾启动新版 | 默认恢复已验证旧包；恢复前排除新版仍运行及数据不兼容 |
| new_placed | 目标新版和备份的实际身份 | 核对后尝试受控启动或进入恢复；不能因 rename 完成就显示成功 |
| new_started / readiness_unknown | 新进程身份、数据访问标记与兼容性、是否收到有效就绪回执 | 先查询，不能把 ACK 超时当作进程已停止；满足 §4.4 才允许回旧版 |
| healthy | 事务 ID、版本、进程对应的就绪回执 | 解除安装门禁、清理临时包，保留一份旧包 |
| old_restored_verified | 旧包签名/摘要、数据兼容、新进程已释放 | 显示旧版可用并允许打开，记录失败结果 |
| restore_failed / inconsistent | 包缺失、损坏或身份矛盾，以及可用备份位置 | 保留门禁、备份、事务与诊断，进入独立修复界面，不宣称旧版可用 |

最终替换暂存和备份在目标卷完成，不能依赖跨卷 rename。恢复/替换失败都不能清理唯一可用备份；未解决的事务阻止下一次更新覆盖其恢复依据。缓存清理、用户稍后安装及 helper 错误窗口关闭不删除未完成事务或备份。恢复再次中断仍由同一事务继续核对，不无限自动重试。

### 4.4 新版就绪与数据兼容

新版就绪回执必须绑定事务、目标版本、进程身份及启动 nonce，表示本地配置与必要迁移成功、主事件循环和工作区入口可用；不等待 SSH/AI 等外部服务恢复，不自动重放任务。发起系统启动成功或仅出现进程均不等于就绪。

在授予新版数据访问、任何可能改写持久数据的初始化之前，先持久化“可能已变更”标记。只有受控流程明确证明未改写数据，或已有明确的旧版可读兼容证明时，才可标记可回退；缺失、损坏或未知标记一律按不确定处理，不能把缺少记录解释为没有写入。

回旧版同时要求：旧包验证通过、新进程已完全释放、数据未变更或明确向后兼容。新版可能仍在运行时，先解决进程归属与释放，不能并行打开旧版。若数据已迁移或兼容性未知，仅保留备份、提供诊断与安装兼容版本的修复入口；不提供会直接启动旧版的按钮，不自动回退用户数据。

### 4.5 异常界面与归属

- **交接失败**：主 App 仍运行，尚未替换；重试安装或稍后，说明已结束的工作不恢复。
- **退出超时**：helper 独立界面说明本次替换已撤销、未强杀也未替换；允许返回仍运行的 App。
- **替换失败且安全恢复成功**：只有包、兼容性及进程状态都已验证后，才显示「旧版可以继续使用」。
- **恢复失败**：由包外 helper 显示备份和事务记录的准确位置、诊断与官方修复下载；不能依赖已损坏的主 App 显示此页。
- **新版启动失败、数据未变更**：先确认新进程已释放，再提供恢复旧版或修复安装。
- **新版已写数据或兼容性未知**：保留备份并提供兼容版本修复，不提供启动旧版。
- **安装期间再次启动 / 中断后恢复**：显示只读事务进度或恢复检查，暂不打开普通工作区。

上述窗口消费同一主题语义；helper 缺少快照时用系统外观。用户关闭终态错误窗口只收起界面，未解决事务保持可发现；下次启动必须重新进入恢复，不能借关闭窗口解除门禁。

## 5. 状态与 UI 映射

主路径：`idle → checking → available → downloading → verifying → ready → draft_resolution? → confirm_close? → snapshot_saving → closing → preparing → commit_pending → committing → installed`。失败状态分 `check_failed / download_failed / invalid_package / snapshot_failed / close_blocked / handoff_failed / parent_exit_timeout / install_failed / restore_failed / launch_failed / incompatible_data / recovery_pending / startup_blocked / manual_install`。下载与安装事件携带计划 ID 与 generation，过期结果不能启动安装或覆盖新计划；关闭事件使用独立 CloseBatchId，由原 owner 持续接收，不能随取消安装丢弃。

| 状态 | 主操作 | 取消与关闭 |
| --- | --- | --- |
| 可用更新、下载、校验 | 下载更新 / 后台下载 / 后台检查 | 隐藏详情不取消操作；取消下载删未完成包，取消校验删除未验证包；二者使对应操作 generation 失效 |
| ready，无运行工作 | 安装并重启 | 稍后安装，保留已验证包 |
| confirm_close | **结束任务并安装** | 取消/Esc 不结束任务；默认焦点放取消 |
| closing | 继续接收真实回执，无假进度 | 取消更新；说明已结束工作不恢复 |
| close_blocked | 重试结束 | 取消更新；保留已验证包与关闭记录 |
| preparing / commit_pending | 等待准备或提交回执 | 可请求取消，但只有 CANCELLED_ACK 才表示成功；COMMITTED_ACK 优先到达则继续安装 |
| cancel_pending | 等待取消决定 | 保留门禁，不先显示取消成功；结果不明则查询原事务 |
| committing | 不可取消，辅助程序显示安装状态 | 禁用关闭入口；退出未完成不能替换 |
| invalid_package / manual_install / install_failed | 重新检查 / 打开下载页 / 查看恢复 | 如实显示当前版本与恢复状态 |

入口新增设置「关于与更新」及应用菜单「检查更新…」。设置内自动检查偏好沿既有保存事务提交；手动检查、下载和安装是即时动作，不依赖保存偏好。全部窗口的草稿都按 §3.2 先行处理；既有设置保存/放弃/取消流程继续使用，不能把草稿当已提交配置自动保存。

## 6. 主题与布局

颜色只消费当前主题的语义角色：`surface_1/2`、`overlay`、`well`、`fg_1/2/3`、`accent_ink`、`action_accent(_2)`、`action_danger`、`warn_ink`、`danger_ink`、`ok_ink`。确认主按钮采用主题危险动作色，普通下载/安装采用主题主操作色。图标使用 currentColor；不把 Sauber 色值、白色文字、警告底色或阴影写进组件。

HTML 复用 `theme-tokens.css` 和 `shared/global-background.js`，可切换所有现有内置主题；Dark/Light/Sauber 为必验主题。透明度、模糊与浮层角色复用全局材质，背景只画一次。原生使用 `ui.widgets.*`、主题发布及现有 styles/recipes 更新；切换主题保留当前计划、进度、焦点与任务计数。辅助程序为独立系统窗口，接收受限主题 token 快照；缺失时采用系统外观，不能固定浅色或照搬主程序节点。

设置面板标准 900×640；更新弹窗宽 520、最大宽为容器减 32，圆角 14；标题 16/22、正文 12/18、按钮 32 高，文本动作按内容宽度加水平内边距。任务列表独立滚动，头部和底部动作固定；标准 1440×900 与最小 860×480 内容区均须可读可操作。Tab 限于弹窗，Esc 仅在允许阶段取消，确认默认焦点为取消；进行中用 aria-live 的阶段/计数更新，不能每帧播报。

## 7. 实施顺序与验收

属于 V0.3 现有两个实施阶段：先非 UI（发布契约、验证、更新计划、关闭协调器、辅助程序与恢复），后 UI（入口、状态消费、主题与可访问性），不单独建立 0.3.x 功能版本。本轮不得据此实现原生功能或改发布脚本。

建议模块边界如下，路径均为未来实施目标，不表示文件已经存在：

| 目标模块 | 职责与接口 |
| --- | --- |
| `src/update/manifest.zig` | 有界清单解码、Ed25519、版本比较、兼容性与附件约束，输出不可变已验证描述 |
| `src/update/controller.zig` | 应用级唯一 UpdatePlan；检查、下载、验证、安装意图与 generation；输出只读 Snapshot |
| `src/update/close_coordinator.zig` | 冻结 app scope 工作清单、建立门禁、统一请求关闭、推进 released/awaiting/unknown、取消更新 |
| `src/update/install_transaction.zig` 与独立 helper 入口 | 准备/提交/取消回执、启动门禁、持久恢复阶段、数据兼容与新版就绪回执 |
| `src/platform/macos_update_download.m` | 系统下载、进度与取消回调；只将 owned 数据发送给控制器，不持 UI 节点 |
| `src/ui/update_view.zig` 与对应 styles | 状态渲染、确认票据、用户动作、键盘与主题；复用现有设置和菜单入口 |
| 现有打包脚本的更新出口 | 从同一最终 App 生成 ZIP 与签名清单，校验附件完整性后允许发布 |

命令契约固定为 `check / download / cancel_download / request_install / confirm_close / cancel_install / retry_close`。`confirm_close` 必须带计划 ID、包摘要、inventory revision；Snapshot 含 phase、可用动作、下载字节、按稳定 ID 标识的工作及关闭回执、错误/恢复信息。下载与安装 worker 结果携带 plan/generation，由主线程拒绝过期结果；关闭批次回执按 batch/owner/operation 独立归档，取消安装后仍能更新释放状态。所有回调均不得直接改 Signal 或退出进程。

下载缓存通过系统缓存目录 API 定位 `com.zerowork.app/updates/<plan-id>`；可恢复事务记录放应用支持目录的更新子目录，0700 且不写凭据。最终替换暂存和备份位于目标卷，不能假设缓存目录与安装目录同卷。保留一份旧包和未完成事务；清理缓存不能顺带删除恢复依据或应用数据。

必要验收：版本与签名拒绝、包路径/大小/链接检查；多窗口/后台/retained/连接中清单覆盖；确认前无关闭副作用；一次确认结束全部对象；新增工作导致摘要失效；重复点击、取消更新、15 秒等待与 unknown；远端未知结果和本地 released 区分；无权限时不提前关闭；草稿未提交处理；辅助程序就绪前不退出；各替换阶段异常中止、恢复与启动失败；三主题/标准最小尺寸、主题切换保留进度、键盘与真实原生窗口。原型测试只验证本地模拟，不作为上述原生验收。

### 7.1 本轮补齐的必要场景

| 场景 | 必须保持的结果 |
| --- | --- |
| 取消先于 helper 提交 / 提交先于取消 / ACK 丢失 | 唯一持久决定；取消成功不替换，已提交不谎报取消，结果未知保持门禁并查询 |
| 快照失败、跨窗口草稿、无工作时新增任务 | 未授权关闭为零；无工作路径也复核门禁；布局取自结束前 |
| 部分关闭后取消、晚到 released、立刻再次更新 | 已发请求继续收尾，未发请求不新增，旧回执不安装，新计划不重复派发 |
| 旧包移走后中断、事务写盘失败、恢复再次失败 | 核实实际文件与身份；不删除唯一备份；失败界面独立于主 App |
| 新版未写数据 / 已写数据 / 兼容未知 / 新进程仍在 | 只有兼容证明和进程释放均满足才允许恢复旧版 |
| 安装期间重新启动、父进程退出超时后再退出 | 新实例不访问数据；撤销的旧退出授权不会再次生效 |
| 后台下载/校验与显式取消、晚到下载结果 | 隐藏不取消；显式取消清理未验证缓存；旧 generation 结果不进入 ready |

# V0.7.0 PATCH · 阶段 1：AI 宿主本地文件工具补全（删除、移动与编辑增强）

> 2026-11-16。本 PATCH 属于 V0.7.0 第一阶段新增批次，不改动 [V0.7 主链](V0.7_AI_AGENT_FLOW.md) 的批次划分与验收；继承 [V0.4.3 本地工作区契约](V0.4_PATCH_AI_LOCAL_WORKSPACE.md) 全部裁决——工作区是默认解析基准，不是访问沙箱，也不是本地工具的启用开关。

## 1. 用户裁决与本次范围

**三项裁决（2026-11-16 会话确认）：**

1. **本地工具的能力门禁与工作区无关**。工具加载开关 = 绑定内活跃 Local/SSH 终端成员（`workspaceScopeRevision`）＋权限策略＋父/子任务能力求交；不选工作区目录时工具照常加载，AI 依然可按授权操作本机绝对路径。本 PATCH 的新工具**不得**以工作区启用为加载或执行条件。
2. **新工具纯本地实现，不做远程执行代码**。`host.local_delete` / `host.local_move` 只在 Mac 本机执行，不进 `file.*` 终端栈、不扩展 `zw-file` 协议、不引入 SFTP 通道。远端删除/移动维持现状（PTY 显式命令＋用户在场）。
3. **描述必须写明 "on the Mac"**。SSH 对话中模型同时可见 `file.*`（远端）与 `host.local_*`（本机），delete 的误用后果最重，新工具描述与本机语义要显眼。

本次交付：`host.local_delete`、`host.local_move`、`host.local_write_text` 追加 `mode=append`、`host.local_edit_text` 的 `occurrence` 索引与行区间锚点。UI 仅复用既有变更折叠卡片与中文标题。

## 3. 工具契约

### 3.1 `host.local_delete`

- **参数**：`request_key`（必填）、`path`/`file_ref` 二选一、`base_directory`（可选）、`expected_version`（必填，来自当前本机读取）。
- **能力/审批**：`authority=local_files`、`effect=resource_write`、`approval_policy=confirm`、能力档 `LocalFiles.write`。
- **审批证据**：删除前完整文件内容作为 detail（这是用户批准的唯一依据）；evidence_hash 绑定解析后的真实绝对路径＋版本。
- **执行**：解析路径（复用 `paths.resolve`，`.file` 模式）→ 快照原文件并校验版本 → 审批 → 原子删除：先把目标 rename 进本操作恢复暂存目录（`.zerowork-file-<op>.tmp/entry`），暂存保留到恢复配额过期，与现有 replace 的保留协议一致 → 回执 committed/verified。
- **约束**：仅常规文件；硬链接（nlink>1）与特殊权限位文件拒绝（沿用 `checkOriginal`）；NotesBoundary 对 delete 生效；`..`/符号链接按真实解析后目标处理。

### 3.2 `host.local_move`

- **参数**：`request_key`、`source_path`/`source_file_ref` 二选一、`target_path`（必填）、`base_directory`（可选，同时作用于两个相对路径）、`expected_version`（必填）。
- **执行**：解析源（`.file`）与目标（`.create`，缺省不覆盖）→ 校验源版本 → 审批（detail 为"源路径 → 目标路径"＋内容摘要）→ 源 rename 进暂存（`entry`）→ 从暂存 rename 发布到目标（独占 create 语义，同设备）→ 回执。
- **跨卷**：`renameatx_np` 返回 `XDEV`/`OPNOTSUPP` 等即拒绝（`AtomicReplaceUnsupported` 系），**不做 copy+delete 退化**——两步失去原子性与版本保护，宁可让模型显式分两次操作。
- **仅文件**：本版不支持移动目录；目标是目录或已存在路径返回 `PathAlreadyExists`。目标父目录必须已存在（**首版不支持 `create_parents`**，双目标父链发布留待后续批次，见 §7 设计修正）。
- **`file_ref` 失效语义**：移动后旧引用按 `SourceChanged` 拒绝（引用绑定的 inode 身份已不在原路径），不静默跟随。

### 3.3 `host.local_write_text` 增加 `mode=append`

- `mode` 枚举扩展为 `create | replace | append`；append 要求 `expected_version`（同 replace），内容追加到现有文件末尾；与 `create_parents` 互斥。
- 审批 diff 为现有尾部行＋新增行；回执 `submitted_after_version` 描述追加后内容。

### 3.4 `host.local_edit_text` 锚点增强

- **`occurrence`**（可选整数，默认 1）：`old_text` 存在多处时不再直接拒绝 `AmbiguousMatch`，按第 N 处（1 起）定位；超出实际出现次数返回 `MatchNotFound`。多次编辑同一 `occurrence` 目标时仍拒绝重叠。
- **行区间模式**（可选 `line_start`/`line_end`，1 起含端点，与 `old_text` 互斥）：整行替换锚点。行号按 CRLF/LF 统一计数，区间越界返回 `LineRangeOutOfRange`；区间内旧内容进入审批 diff。
- **结构化错误载荷**：`AmbiguousMatch` 错误正文附出现次数与建议（传 occurrence 或扩大上下文），延续 §3.5（V0.7 主链）"错误教恢复"基调。

### 3.5 不变式（逐条保留）

- 幂等：同一 `request_key` 重复派发返回原回执，不重放副作用。
- 版本门禁：delete/move/append 全部要求 `expected_version`；auto 模式保留版本拒绝。
- 工作区 revision 依赖复验：使用 preferred base 的请求在审批等待与派发前复验；`WorkspaceChanged` 拒绝旧依赖请求。
- 恢复暂存配额（`RecoveryQuotaExceeded`）、私有目录校验、最后校验后外部变化保留协议（committed_unverified/conflict）全部沿用。
- `NotesBoundary`、恢复路径名保护（`isRecoveryPath`）、拒绝 `~user`/环境变量展开——全部不变。
- 描述开头写 "on the Mac"；相对路径规则与既有工具一致，不新增工作区启用条件。

## 4. Journal 与投影

- `local_file_tool_id` 保持 `host.local_file_mutation`（delete/move/write/edit 同一家族，共用 journal schema），Evidence 增加 `source_target: ?[]const u8`（move 的目标路径），`Kind` 序列化为新枚举值；旧记录读到未知 kind 返回可辨识错误而不是崩溃。
- `local_get_changes` 投影：delete 显示"已删除 · 原路径"＋有界删除前 diff（全 remove 行）；move 显示"源 → 目标"；`verify=true` 的只读核验按各自语义（delete：目标不存在且暂存保留即一致；move：目标匹配提交候选）。
- 变更卡片：状态行按 kind 中文提示（"文件已删除，可在恢复引用中找回"、"文件已移动"）。

## 6. 明确不做（本 PATCH）

- 远端（SSH）删除/移动的结构化工具、`zw-file` 协议扩展、SFTP 文件通道。
- 目录删除/移动/递归操作；glob 批量删除。
- 工作区作为权限开关或加载条件的任何改动。
- 回收站/时间机器式恢复 UI；恢复仍按既有恢复引用机制只读核验。

## 7. 实施与验收记录

2026-11-16 实施完成（阶段 1 全量，含一次设计修正）：

- **实现范围**：`local_file_commit.zig` 的 `Kind` 扩展为 `{create, replace, edit, append, delete, move, overwrite}`（`overwrite` 为 syscall 层内部值，工具不可提交）；delete 采用"暂存覆盖 + 目标名消失"两步模型；move 采用"源 → 暂存 → 目标"两段 rename，崩溃时原件留在暂存可经 `observe` 核验；renameatx_np 增加无标志（plain overwrite）路径。新增 `prepareMove` 双目标入口；`Evidence.destination` 持久化 move 目标（journal schema 兼容，可选字段）。
- **设计修正**（相对 §3.2 原稿）：move 首版**不支持 `create_parents`**——目标父目录必须已存在。理由：`ParentChain` 发布链按单一目标设计，move 的双目标接入需要独立批次；工具 schema 已移除该参数并写入描述。
- **工具面**：`host.local_delete` / `host.local_move` 进入 `host_local_file_mutation` 家族与审批白名单（`host_approval`、`mutationResult`）；提示词补 "host.local_* tools act on the Mac itself" 防远端误用。
- **UI**：中文标题（删除文件/移动文件）、变更卡片按 kind 显示"文件已删除/已移动"状态行；`local_get_changes` 投影新增 `destination` 字段。
- **验收**：新增 4 项 commit 单测（delete 原子性与暂存保留、move 源消失/目标发布/独占拒绝、append 版本门禁、occurrence 定位与行区间替换与越界拒绝）；全量 `zig build test` 2784 passed / 0 failed / 11 skipped（11 项为环境相关 SKIP）。构建仅余 2 条既有 leak 报告，来自本日另一 V0.7 批次（`child_gateway.authorizedSessionsPayload`，非本 PATCH 引入）。

# AI 会话效率修复：Local / SSH / KVM

日期：2026-11-04。本文记录本次分批修复的契约、覆盖范围与真实验收结果；不将计划当作已完成。沿用 V0.1.7、V0.2.6、V0.2.3 和插件 API 2 的所有权、权限、录制与重试边界。

## 范围与边界

- 修复目标信息、读取来源、模型结果、输出预算、语义等待和图片复用。保留既有工具身份及兼容默认值。
- 聊天只访问当前绑定及合法历史；目标不跟随 activeTab。派发前仍复验 scope、generation、权限、参数和输入状态。
- 创建、Shell 接入、执行、图像观察保持独立真实动作；handler 不隐含跨路由执行。停止与接管不依赖模型再次调用。
- 不新增 OCR、云端服务、自动录屏、磁盘图片归档、跨界面盲操作；不自动提交。

## 第一批契约

1. 本次请求表提供一致的合法目标提示；实时目标提示不取消合法 recording_ref 读取，也不成为授权。
2. 初始/工具观察带来源、观察时间、revision 和范围；需要操作时才附带对应控制状态，观察本身不授予输入权。
3. 完整回执继续由结果存储/UI消费，模型结果可精简，但保留证据来源、未知、输出归属/缺口、稳定引用及恢复路径。
4. 默认输出量保持兼容；显式较大读取受完整 JSON 结果与上下文预算约束，UTF-8/游标不得断裂。
5. 图像内容与观察记录分离。相同合法来源、尺寸/变换的相同像素在一次请求中只携带一份；保留各次观察事实。跨请求仍携带当前所需原图，不假定服务商记忆。
6. 复用 image.read 和既有卸载链路。预算计算以最终发送内容为准；不能卸载必要新像素后假称观察成功。历史读取不续期输入授权。
7. 未知模型的图片预留不是实际 usage；无真实渠道测量不伪造 Grok 公式或任意调低值。上下文、传输、图片内存分别受限。

## 第二批契约

- 保留 revision 等待；增加等待真实结果/明确输入/失败/未知的语义，普通阶段变化不必回到模型。
- 短执行可同调用有界等待；等待超时不代表命令失败，也不重发。总回合/网络预算继续生效；仅用户决策等待暂停自动时间预算。
- 已受理 run 的同调用等待被取消、容量拒绝或关闭中断时，返回原 execution_ref、最后已知状态与 wait_interrupted，而不是沿用 CancelledBeforeDispatch 把已发送的命令标成未执行。复制原回执失败仍归未知，不允许按“未派发”重放；停止/接管仍由原 Driver 独立推进。
- SSH 观察与 Shell 状态必须同源并受 freshness fence 约束；接入只初始化已确认 Shell，不发送业务命令。
- KVM screenshot 可等待精确操作和后续合格帧，图像外发独立授权；相同像素不等于操作成功，不能拿旧图替代新帧。
- 后台等待不持 UI 锁，取消/接管/关闭后不发布旧结果。复用现有步骤、结果和状态组件，不重画界面。

## 第三批契约

- 文本扩容同时约束长度类型、事件批次、期限、取消和人工接管；保持 ASCII、Enter 独立，部分发送不重放。
- KVM 继续读取最新完整远程 CPU 帧。缓存有界且与会话代次/图像变换绑定；像素复用不复用观察授权。
- 内部生成图像可复用已验证像素，外部附件仍完整解码验证。取消/关闭释放原图、编码缓存和帧租约；不产生悬空引用。
- 生产 Runtime 每会话最多一个编码任务；后台线程仅消费不可变远程帧租约和冻结的图像变换，不接触 UI/连接/权限。工作内存先占用共享帧预算；编码完成后释放原帧，宿主再次核对输入 epoch、传输/控制/几何代次再发布观察。取消后的结果只回收；Runtime 关闭回执必须等编码任务完成回收，不能提前销毁 framebuffer/budget。准备阶段在同一已批准观察调用内有界等待，不产生模型轮询或新的副作用。
- 新 sequence 的精确像素比较也在后台执行；同 sequence 直接复用。未缩放区域按行比较，缩放区域仍比较实际映射像素。后台任务冻结原输入 operation_id，期间发生另一输入操作时不能把旧编码当作操作后画面发布。

## Grok 渠道标定

使用当前 App 已配置的本地 Magpie 网关与 `grok/grok-4.7@500k`，同一文本提示、合成测试图、`detail=high`，真实返回的 prompt_tokens 为：纯文本 1259；1024×640 单图 1938（图片增量 679）；1920×1200 单图 3578（增量 2319）；两张 1920×1200 图 5897（增量 4638）。这是本次渠道观测，不能推出所有 Grok 接口或后续路由的通用公式。

模型配置支持下面的有界预留。8192 是覆盖该次 1920×1200 增量约 3.5 倍的保守配置值；超出尺寸范围自动回退未知模型预留 131072。现有无尺寸配置的 reservation 仍按旧语义兼容。两项尺寸必须成对且与 reservation 同时配置；修改会失效上下文估算缓存。没有静默修改用户现有模型配置，也不把本地估算显示成服务商实际 usage。

```toml
# 放在经过标定的 [[ai.providers.models]] 中；需要本次新版本支持。
image_token_reservation = 8192
image_token_max_width = 1920
image_token_max_height = 1200
```


## 回归问题的修复结论

| 问题 | 确定原因与处理 |
| --- | --- |
| Local TaskFinish 的 UserInputNotAccepted | 夹具只 pump 旧模式快照，缺少正常渲染循环的 refresh。重试前刷新同一 owner；输入仍只 queue 一次，原 deadline 和门禁保留。修改前产品副本仅修正夹具也通过。 |
| Local takeover 的 LengthMismatch | Shell Notice 紧凑字符串与内部固定 256 字节缓冲的默认解析不配对。补齐有界 jsonParse/jsonParseFromValue，保留 wire 格式，拒绝超长/无效 UTF-8。 |
| help/catalogue 数量不一致 | 旧测试写死目录数量，帮助文本漏列已有命令；后续 @dots 增项又使面板旧 16 项预期失效。帮助和面板测试按权威目录校验，计数及实际绘制一致；保留几何、边界和不省略断言。 |
| 输入审批的 UnexpectedSuccess | 另一条输入受理后，原 grant/wait/文案可能不变，旧批准仍通过。宿主 evidence_hash 绑定 execution、grant、wait 与上一输入序号；不进入模型或 UI，不因普通输出或同一输入消费进展额外触发审批。 |
| 模型缺少输入消费事实 | 精简投影曾漏掉 input_receipt；已补回，并核对原 host 回执与模型投影。grant 和内部派发计数仍不外发。 |
| 等待夹具与实际契约不一致 | 分别验证独立 wait 超时与已受理 run 的中断回执。SSH 夹具准确预期 ShellPromptNotObserved；一次 50 ms 观察繁忙耗尽后，仅在原 10 秒总期限内重试读取，不重发命令或延长超时。 |

历史搜索“单项通过、全量失败”已确认是**源码快照与测试产物不一致**。从保留的旧完整 ReleaseFast 二进制中只运行目标、完全不执行前序用例仍失败。LLDB 确认搜索命中、新阅读模型及 history_reading_top 均有效，但旧指令实际读取 history_search_top 的 optional presence 字节；该旧字段在新流程中应为空。调试器显示磁盘当前源码，不能证明旧产物编译时使用了该源码。

用当前源码重新构建完整二进制后，同一产物的目标和完整套件均通过；历史搜索实现与现有断言未改动。不能将这次差异归结为前序状态污染或优化器错误。后续记录绑定源码及二进制指纹，并确认过滤运行确实执行目标。旧失败快照、重复构建 hash 和逐轮临时记录已收拢，不再作为当前发布结论。

## 2. 逐入口UI与状态

### 2.1 独立SFTP创建与能力门控

从`+`选择已保存SFTP直接开文件连接；新配置由720宽三步连接卡标题SSH↔SFTP切换。保地址、用户、认证、route和协议私有草稿，SSH启动命令保留在SSH草稿但SFTP绝不执行。增加远程起始目录字段，默认未填时由服务器`.`求绝对目录。SFTP无交互shell、VT输入、终端网格、SOCKS或默认终端助手，不放空TerminalService迎合旧接口。

**当前原型明确独立SFTP创建入口的跳板不可用**：`342:1207116`保留route、允许仅保存，检测与“保存并浏览”禁用并显ProxyJumpTransportUnavailable；用户在路径步骤明确改直连后才可检测/浏览，禁止自动删route、借同名SSH或先连目标试探。正式SSH有多跳transport不能作为此SFTP工作区入口已支持的证据。

**SSH来源的文件工具与任务是另一条必交付路径**：`transfer-upload/download`、三种scope的running/taskdetail明确包含“经Bastion-01”的原会话与运行任务。本版必须让SSH来源的transfer_binding按冻结完整route建立独立传输连接，逐跳执行同V0.1.3认证/密钥核对，目标只开SFTP、上游只开隧道，不先开新shell/终端页签。`transfer-route-unavailable`是实际建立该独立文件连接失败/不支持组合时的分支，不是将全部SSH跳板任务长期禁用的依据；不能以现代码拒route代替这些正常状态。SFTP工作区创建的禁用策略与SSH文件工具的route能力按`purpose/entry_kind`区分，不能把其中一个入口的可用或禁用直接推给另一个入口。

### 2.3 双卡拖放、核对与冲突

拖动期间高亮候选目录，进入目录只浏览。松开冻结源endpoint/路径清单、目标endpoint/绝对目录、owner generation和选项；在**目标卡底部**显示核对。目录拖放/背景投放明确目标是目录项还是当前resolved_path，不把文件项当目录。核对显示来源、数量、目标、续传、MD5默认关、同名先询问；导航或切tab不改冻结快照，改目标需取消重发。目标不可写保源/目标快照和Permission denied，取消不删除源文件。确认后入队回执清本次核对态，保浏览状态；失败保原intent。

同名冲突卡宽620，当前树代表高409（旧metadata532非固定目标）；显示上传/下载方向、原owner、完整目标、源/目标大小与修改时间。四选初始无默认批准：“跳过”“另存为”“双方保留”“覆盖”；应用按钮随选择变化。批量勾选只作用本队列剩余冲突，不改变全局默认、不追溯已处理项。暂不处理只暂停，真取消走影响确认。

| 决策 | 执行与回执 |
| --- | --- |
| 跳过 | 当前文件标skip并继续其余项，不能将其字节伪记传输成功；批次摘要显示跳过数 |
| 另存为 | 单文件名校验空/分隔符/`.`/`..`/NUL及实际重复目标，输入保留；与源路径分开 |
| 双方保留 | 给建议名如`release (1).tar.gz`，实际创建必须避免竞态；回执显示最终创建名，不预报成功 |
| 覆盖 | 再弹明确方向/完整目标/原owner的危险确认；执行前重新stat并核对冲突版本，目标变化重新提示 |

远端覆盖卡460×276、本地覆盖480×228；取消返回原冲突等待，不删源或先删目标。节点`223:330800`、`236:475949/477759/481403`、`321:911916`。下载最终文件仅在临时数据全部完成、close/校验/落位通过后替换，失败不能损坏既有最终文件。

“仅对本队列剩余”只保存该Intent剩余冲突项的**策略**，不是全局默认，也不扩大到未来追加的Intent。另存为的具体名字只属当前entry，后续同名项仍需各自合法新名，不能把同一字面名字用于多个文件；双方保留逐项生成不冲突名，`.tar.gz`按原型作为整体扩展保留。覆盖的二次批准若批量应用，确认中须列冻结剩余集合的数量/方向/路径与版本，批准仅覆盖这批可核对项；后来新发现/目标变化的项另行确认，不套当前单文件批准。该集合/命名规则是原型四选和队列范围的实施补充。

全局Manager唯一分配JobId、FIFO、去重、重试/通知和并发预算；其engine接owner/endpoint路由适配。具体引擎局部EngineJobId映射含binding和attempt，不能直接当全局ID；切tab不能给全局引擎换attachSession后继续旧job。相同未终结intent去重须含owner、endpoint、路径与选项，不能合并不同session同名文件。

每个独立SSH Session有唯一IO执行者，串行访问该Session及其SFTP/channel。多个running job各有文件句柄/offset和操作状态，最多32KiB一次IO片轮转，在片边界处理目录/取消；IO片只是公平粒度，不覆盖用户逻辑chunk_kb/window_chunks，较大逻辑块分多次IO。不同binding可并行，同owner仍须支持原型多个任务运行；临时退回单任务只能标未完成并发缺口。元信息预计算、认证、stat/open/flush/close/rename都在IO侧，UI不调用阻塞远端API或join活动线程。

**同线程不等于可重入**：vendored libssh2的SFTP `read_state/write_state`属于SFTP上下文（`vendor/libssh2/src/sftp.h:172/178`），EAGAIN期间须固定原API调用、文件handle、offset、参数及buffer，直到该调用完成/失败/清理，不能在同上下文直接换另一Job的handle继续同一API。为满足同owner多个running任务、目录和校验不饥饿，使用有界独立SFTP上下文/channel保存各操作流状态，仍由同一个Session IO执行者轮转；上下文懒创建并计入并发/通道/内存预算，不能一任务一线程直接借Session。Session级channel-open/sftp-init/认证等内部状态也按其实际共享范围仲裁。通道上限/拒绝时保原Job排队或给真实能力原因，不并发踩状态、不静默退成单任务后标完成。ACK窗口使用统一的实际协议实现或库管线，不在同channel叠加第二个不知原request ID的解析器。

FileRead在同一IO执行者上按有界片读取，先realpath/stat并确认普通文件；symlink仅在解析为普通文件后读取并返回实际路径，目录/设备/未知类型、路径NUL、无权访问和不支持编码均为独立错误。读取片段含NUL或非法UTF-8则返回unsupported_binary/encoding，不静默替换成成功文本；仅因max_bytes预算切断且确认尚有后续字节时裁掉UTF-8尾部半码点并标truncated，真实EOF残缺码点仍为编码错误。读取前后核对可取得的size/mtime/版本，发现变化返回source_changed并保来源，不能声称一致快照；max_bytes不是完整文件大小，原大小未知与0B区分。每请求冻结30s预算，超时/断线/取消后关闭该请求句柄并回实际cleanup，不留无界buffer。SSH owner按其FileRead能力和ssh_file_tool目的建立本owner独立文件binding、保完整route，无需先开SFTP页签；不能误套独立SFTP工作区创建的route禁用策略。实际连接失败/不支持组合按本版不可用原因拒绝，不能借另一owner或用shell替代。Local由宿主明确选取后消费local_fs能力，remote-files调用只能使用远端endpoint；保留任务owner只供原Job恢复/校验，不成为AI读取已关闭会话的授权入口。`ai_file_reference_cache`（`236:488030`）及`ai_tool_read_remote_file`（`236:474813`）在V0.1.7接UI，服务与取消/截断契约须在v0.1.4.1冻结。

## 4. 引擎、窗口、恢复与校验算法

### 4.1 有界滑动窗口与真实进度

默认逻辑CHUNK=64KiB、WIN=16，使用Job创建时的有效配置快照；请求保存`request_id,offset,requested_len,acknowledged_len,attempt`。上传按offset读本机、WRITE收到对应STATUS OK才确认区间；下载READ收到DATA后按offset写本机，短DATA只确认实收区间并补余量。EOF/STATUS错误分正常文件尾与失败，乱序按request ID归位，重复/过期包不重复计数，未知ID/越界/区间回退为protocol错误。

完成需已确认区间覆盖实际预期长度、无在飞请求，再flush/close、可选全文件校验、落位回执。总量未知不除零/造ETA；0B文件真实创建/关闭后可完成。速度来自实际确认字节与单调时间，平滑窗口实现需有界；不以原型静态8.2MiB/s或固定6s倒计时作运行数据。

并发/窗口/块大小乘法先检查溢出与内存预算，不能因输入域允许255/65535就分配不可承受的窗口。服务发布可应用上限；超预算组合字段原位报错并保draft，不静默裁值。共享通道IO仍受该Session串行访问与公平预算；专用/共享模式的真实接线是本版实施要求，现有引擎未接入只登记实现缺口，不能把设置长期禁用视为完成。

### 4.2 续传、重试与目录批次

源与目标fingerprint至少含endpoint身份、原始绝对路径、kind、size、可取得mtime/其他版本信息；只有大小相近不能证明前缀一致。上传/下载都重新stat；源变化、目标大于源、目录目标、不可证明前缀兼容或binding失效不能盲append，保留原型续传/重新传输选择、原因与确认。批准绑定job/attempt/这次stat版本，执行前再次核对；重连后不重放旧handle请求。

网络超时先区分请求未发、已确认与结果unknown；只有证明可重试范围才自动恢复，同目标区间不能出现第二次业务副作用。Manager已有退避策略可复用，但界面显示真实等待与attempt，不把旧10s/3次示例当固定产品值。手动重试终态失败保JobId与原路径、重新执行尝试号；原endpoint不可用保持等待恢复，不默取新同名session。

递归复制先形成计划，保源root及相对目录、真实文件、空目录、symlink政策、不可读项和已知/未知总量；用目标root组合相对路径并验证不越界。批次保逐项成功/失败/跳过，部分失败不能汇总全成功。目录进入是浏览，新建目录只是mkdir，都不能误入传输队列。

### 4.3 完整MD5与安全落位

MD5默认关；打开则比较完整源/目标摘要，未知/缺工具/不一致均不显示校验通过。Checksum服务以同IO执行者上的有界流式读取和本机MD5累积为必需基础；SFTP-only可通过该owner远端READ读回目标/源计算全文件摘要，不能因没有Exec或远端`md5sum`就删掉已画的MD5能力。目录/传输/哈希共享公平预算，不把整文件读进内存。远端显式Checksum/Exec可作为已公布能力的优化，需独立channel、正确引用路径，不能裸拼`md5sum path`、假定安装命令、借另一SSH或模拟shell输入。实际权限拒绝读取、连接中断或远端不能提供摘要时，保已传字节并显示校验不可用/未完成，不伪成功。

首次完整MD5不一致后，按`transfer-manager-*-checksumfail`确认的要求，在源/目标fingerprint仍匹配、目标仍属该Job且覆盖批准有效时**只修复最后一个逻辑块一次**：范围为`floor((size-1)/CHUNK)×CHUNK.. size`，零文件无最后块直接报完整性失败；记录checksum_repair_count=1和实际范围，随后重新计算完整源/目标MD5，不能只比较末块。仍不一致进入checksum_failed并显示“末块重传一次后仍不一致”；源变化/目标被替换/权限或连接失败分别报实际原因，不伪造“已修复一次”。此自动修复不保证能修复中段损坏，也不无限循环。用户重新传输需重新核fingerprint/覆盖影响，从0新attempt，不把原型已失败的任务直接标成功。

校验失败保原source/target、实际digest/原因及可用重新传输。下载写job专属同目录临时路径，暂停保留记录/offset；完成flush/close/校验后按已批准策略落位，rename失败显示落位失败与临时路径。目标自批准后变化重新确认，不预先删旧最终文件。

### 4.4 0不限速与设置快照

用户明确`shared_pacing_kbps=0`表示**不施加额外吞吐限速**，仍有公平IO轮转、全局并发和内存预算；不能把0传旧Pacer后忽略InvalidRate。正值沿现有运算每单位1024B/s，UI目前写KB/s，持久化仍是原字段/原数值；不是kbit/s，不另造bytes_per_second字段。默认2048不变。

共享路径启动时选择unlimited或limited分支；limited按单调时间/实际确认字节发放有界额度，等待不能占住UI或饿死其他job/目录，参数乘法用检查/饱和保护。`dedicated_connection=false`仅对能由同一IO执行者安全复用的原SSH owner/route开放共享SFTP通道；冻结原binding并显示“共享通道”及实际限速状态，不共享到后来active tab。当前实现不支持的组合显示原因并记未完成缺口；共享调度与设置接线本身仍属V0.1.4交付。独立SFTP文件插件没有附着的终端transport，不能为满足“共享”而借任意SSH会话。

**与历史SPEC的差异和优先级**：旧`OVERALL_ARCHITECTURE §5.4`要求第二连接因服务端限制失败就自动共享；当前`transfer-route-unavailable`（`236:489061`）明确经Bastion的独立文件连接不可建立、保留选择且开始上传禁用，`342:1207116`也明确SFTP route仅保存、检测/打开禁用。本版优先这些确认原型，不对该失败场景偷偷共享、降直连或自动换owner。显式共享配置仅在原owner、完整route与服务能力确实支持时可用；无法证明安全共享则保草稿/暂停并说明，不把历史“自动降级”写成已交付，也不据当前route限制删掉其他合法配置的共享能力。此处为明确差异登记，不以所有独立连接失败都触发共享作为验收条件。

## 5. 暂停、取消、关闭与错误结果

queued可立即暂停/取消；running先pausing/cancelling，门控新请求、收敛在飞IO、关闭所属文件/校验channel，停写和清理回执后才paused/cancelled。清理未知保诊断/实际路径并禁替代attempt；cancel函数接收只是accepted。重复请求幂等，不能重复释放其他job句柄。

暂停保可续传临时数据；恢复重新核源/目标及原endpoint。取消上传保本地源，远端已写部分可能保留；取消下载只清该job可证明拥有的临时文件，不删用户最终文件或恰好同名.part。清理失败逐项呈残留路径/原因，不把“取消”误写“全部删除”。取消确认430宽、当前代表256高，显示文件、done/total、原会话/方向/完整目标与影响；取消返回传输继续。节点`236:483135`。

关闭/Esc隐藏管理器浮层不影响任务；关session按确认顺序暂停并保续传数据→停止AI→释放SOCKS→关闭，逐项等回执。暂停回执后Manager将原Job集合转由独立RetainedTransferOwnerId持有，保原SessionHandle为来源标识；关闭使原session的Terminal/Exec/Auth和文件binding全部失效，不能为续传延长其生命周期。用户显式恢复任务时，命令owner为`transfer_owner(id,original_handle)`，从原冻结快照重新认证，为该保留owner建独立transfer binding并增加binding generation；操作/事件使用保留owner+JobId+新binding generation，不向已关闭SessionRuntime发请求、不复活原shell、不换新同名页签、不重放批准。所有原任务终结/释放且新binding清理完成才结束保留owner；原资产被编辑/删除不替换冻结来源，凭据引用失效则提示原身份重新提供。仅保留不等于后台继续传输。应用退出若没有持久恢复实现，明确说明未完成任务范围，不能因运行期保留记录就承诺重启自动恢复。

错误必须含`job/attempt/owner,domain,code,stage?,retryable,effect(none/partial/unknown),cleanup`：invalid_request/not_found/permission/conflict/connection/timeout/checksum/protocol/io分别回原表单/卡/任务。源不可读、目标不可写、SFTP subsystem拒绝、目录读取失败、校验不可用、清理待核实不共用“认证失败”。批次部分错误保成功项和失败清单，旧generation/attempt只清理，不覆盖新UI。

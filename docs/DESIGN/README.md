## 1. 版本顺序与交付边界

**[V0.2.6 PATCH · AI 会话执行、统一记录与全局历史回看](V0.2.6_AI_SESSION_EXECUTION.md)** 属于当前 0.2 系列基线。当前源码已包含 host 查询/生命周期工具、稳定 ConversationId 与转组 handoff、独立 exec/交互 PTY、输入控制和记录关联，不能再统称“新增能力全部待实施”。具体支持条件、权限修订与验证范围仍以其当前正文和对应源码为准，本轮不追认未经运行验证的完整交付。它不包含 V0.4 子智能体、SKILLS 或 MCP 增量。

V0.4 按 2026-11-05 用户裁决重写为[附着式 Agent、子智能体、SKILLS 与 MCP](V0.4_AI_AGENT_CLUSTER.md)：组助手承担组内协调，子 Agent 默认独立上下文、可继承／复用，解绑后销毁 Worker，只保存配置／上下文及必要事实。增加顶部数量入口／列表／可继续交互的子弹窗，以及子智能体、技能、MCP 设置；技能仅本地导入，所有能力只作用于当前附着范围。移除独立 AI 页面、集群转换／纳管和 API 3 前置；当前源码已接入子 Agent、技能和 MCP 的基础链路及原生设置；外部服务兼容性与权限边界仍按正文逐项验收。

V0.6 的[网页连接设计](V0.6_WEB_CONNECTION.md) 作为当前实施依据，接入标准连接插件与真实 WKWebView 内容槽。预设网址自动打开，手动模式输入网址或点击书签后建链，两种模式均支持直连和多跳 SSH。每连接最多 16 个书签，单项最大 104 点，书签区最大 328 点并支持横向滚动。可编辑 SVG 已完成静态渲染核对，原生与网络验收待实施。

V0.6.1 的[AI 浏览器交互](V0.6.1_WEB_AI_CONTROL.md) 标记为可选、非必要，覆盖在当前网页会话观察和操作页面的独立交付。V0.6 可先行发布，本扩展不作为必要依赖。

设计版本按功能里程碑归档：0.1.0–0.1.8 属于 0.1 系列，0.2 为插件宿主，0.3 包含 BMC iKVM、应用内更新、菜单栏会话活动及 [AI 会话与消息调度 PATCH](V0.3_PATCH_AI_CONVERSATION_INPUT.md)，0.4 为附着式 Agent、子智能体、SKILLS 与 MCP，网页连接当前设计为 0.6，0.6.1 为可选 AI 浏览器交互。当前目录从 0.1.1 基础宿主开始，未单独建立 0.1.0 文档。既有 V0.1–V0.4 文档在设计版本后追加一位表示实施阶段：`.1` 为非 UI，`.2` 为 UI；例如 v0.1.7.1 → v0.1.7.2、v0.2.1 → v0.2.2、v0.3.1 → v0.3.2。其中 v0.2.1/v0.2.2 仅表示 V0.2 的实施阶段，不再作为独立设计版本。V0.6 改用阶段 A/B/C，避免将可选功能版本 V0.6.1 误读为非 UI 阶段。实际构建版本读取 `build.zig.zon`（本轮为 `0.3.0-rc11`），插件版本读取清单，不从设计阶段编号推导。

## 2. 非UI与UI如何避免冲突

按职责划分，不按目录名划分：位于src/ui的纯模型、controller、队列和校验仍可属于非UI；平台能力可由非UI适配器实现，再由UI接入。非UI负责实体/生命周期/状态机/服务/线程/持久化，UI负责视图/样式/焦点/键鼠/几何/可访问性及调用已定义命令。

每个v0.x.1交付固定的请求/结果结构、owner/generation/revision、错误/取消/清理语义、字段/单位/生效策略及可控验证场景；这些内容写在同一版本正文。v0.x.2只消费该契约，不直接操作PTY/libssh2、不重选当前active目标、不重新定义审批或保存事务。发现契约缺失先回到该版本非UI章节修正，并做受影响的必要回归，不能在另一文档追加相反规则。

同一子版本内部可并发处理职责独立、文件边界清晰的工作；共享接口/配置schema/命令目录/宿主状态由一个写入任务统一修改，其他任务消费已冻结版本。代码修改尽量分离纯服务与视图；共用文件必须先明确编辑区和单一写入者，不能仅以“一个非UI、一个UI”就假定无冲突。文档并发迁移不代表实现可以绕过上述前置门槛。

### 设计就绪的判断

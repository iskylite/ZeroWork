# ZeroWork V0.8.1 · Agent 本地沙箱

> **状态：设计，未实施。** 本版只覆盖 Agent 在这台 Mac 上使用所选文件与工作区、启动本机 MCP 进程、以及向配置好的 HTTP MCP 发送请求。默认值、界面和拒绝行为是实施合同，不是当前版本已生效的保护。

## 1. 产品边界

用户选一个目录，请助手「看代码、跑检查、把要改的地方列出来」，授权的是这个目录及这次工作，不是把自己的 Mac 账号交给助手。用户绑定一个 MCP，授权的是具体服务和工具，不等于允许它读项目，也不等于从对话里挑数据发给它。

| 场景 | 必须限制的操作 | 不作的承诺 |
| --- | --- | --- |
| 本地工作区 | 助手能读哪些文件；本地命令能在哪运行、改哪份文件；变更如何写回 | 不限制用户手动操作；不把原工作区默认交给任意程序 |
| 本地 MCP（stdio） | 启动前约束该程序、子进程、文件、环境和网络 | 会话绑定、MCP Roots、模板、只读提示或 JSON Schema 都不能代替进程隔离 |
| HTTP MCP | 宿主能连哪个端点、发哪个方法、把哪些数据和凭据发给谁 | 不控制服务端进程、文件、后续转发或实际动作；不显示「服务端已被沙箱隔离」 |

宿主、macOS 和用户明确安装的签名 App 属于受信任一侧；模型输出、项目内文件、第三方 MCP 程序、其返回的内容和链接不默认可信。已送给模型的内容可能被复述，不能依赖模型的来源标注或字符串扫描防止外发。已有应用外的用户程序或管理员不在 ZeroWork 能约束的范围。

**不做**：远程 SSH 命令、SFTP、KVM、网页页签、模型提供商传输以及内置 `fetch_url` 的重构。人工终端与现有正常 SSH 操作不变。在附着 SSH 的 AI 对话里调用本机文件工具时，当前本机调用仍受本文规则；不能偷偷改走 SSH、既有人工终端或另一个插件。

## 3. 谁决定，怎样生效

1. 用户通过目录选择器或 MCP 设置挑范围。会话工作区默认只读；stdio 默认看不到该工作区。调用工具、拿到文件路径、绑定 MCP、允许读取和允许把内容发送给 MCP，是几种不同的授权。
2. 模型只提出工具、参数与任务请求，不提供权限字段。宿主取「产品硬限制 ∩ 全局设置 ∩ 会话/任务权限 ∩ 工具和服务权限」；子 Agent 只能继承相同或更窄范围。不能强制的约束不从配置中剔除，而是停止该执行通道。
3. 宿主在派发前冻结对话、任务、执行方式、工具、规范化参数摘要、策略修订和工作区身份；MCP 再绑定服务、端点/程序指纹和对应工具 schema。预览、用户确认、派发使用同一份材料。等待审批或重连后重新校验；换目录、改策略、禁服务、替换程序或更新工具定义都会使相应批准失效。
4. 结构化读写走文件网关；本地命令及 stdio 走已验证的运行器；HTTP MCP 走宿主专用传输。`confirm/auto` 只影响询问频率，越权仍拒绝。政策收紧后阻止新派发，取消受影响的本地运行器；HTTP 已发送的请求只能标记服务端结果未知，不能说远端已停止。用已有 request key 避免副作用重放。
5. 回执分清「未派发、运行中、待审阅、已写回、已取消、结果未知」。仅记录执行通道、策略修订、任务/服务 ID、必要相对路径或摘要；不持久化完整环境、授权头、令牌、业务请求原文或未授权正文。

**例：检查项目，再把摘要发给 MCP。** 用户选择项目目录、开启可用的本地命令并允许运行预检。Agent 先读取获准文件，调用已支持的检查程序；程序只看到该任务的副本，日志写到私有临时区。用户如果把权限改成「写入待审阅」，程序可修副本，原项目仍没变，须在变更卡上确认才写回。用户随后要求将摘要发给 HTTP MCP，宿主显示实际接收端与这一次要发的参数；确认前未发。前面的本机读写批准不能代替这一次外发批准。

## 4. 本机工作区

### 4.1 文件工具

- 默认没有目录授权。用户明确选择一个文件可单次只读；选择目录后按「根目录身份 + 只读／写入待审阅」授权。未选目录不能从 Home、当前终端 cwd 或其他对话借权。老引用绑定原文件和原授权，失效后只保留历史显示。
- 用已有句柄和原子写模块实现：打开受信根，从该句柄逐段定位（保留诊断路径用于显示，不用它重新开文件）；检查文件类型、真实归属、目录/文件身份及写入版本。拒绝越界链接、未授权挂载点、设备、FIFO、socket；拒绝对多硬链接原件就地写。不能用字符串前缀证明归属。目录和文件替换、卷改变或无法确权时停止。
- App 私有数据、笔记后台存储、会话历史、SSH 文件/代理、钥匙串、Git 配置与钩子不属于隐式授权；默认不读 Git 元数据。用户选整块卷、整个 Home 或能囊括 App 私有数据的范围时要求缩到项目。经批准文件本身仍可能有业务秘密，不宣称自动识别所有秘密。
- 读取继续复用分页/大小上限和现有版本证据。用户人工浏览和预览不为 Agent 借权；引用、预览转附件或进入模型前，由实际读取入口按同一范围查验。修改过程不把原件直接交给第三方进程；结构化路径由受信宿主管控，不称为整个 App 在内核沙箱里。

### 4.2 本地命令与写回

- 首次默认关闭本地命令；开启也须通过真实运行器能力检查。启用后只为当前任务物化已批准普通文件到单独工作副本，不挂载真实工作区、主目录、App 数据、宿主 socket 或软/硬链接到宿主的入口。只读档只允许把临时产物放在专属临时区；写入待审阅档可改工作副本，不能直接改原件。
- 首版仅运行明确支持的固定参数程序。路径、运行时、参数和环境独立配置，不默认加载用户登录 shell、用户 PATH、安全代理或凭据。任意脚本和专属 PTY 与 batch 应用同一隔离；签名宿主样机没有验收的运行形态不开放。不可向既有人工本地 PTY 降级。
- 结果和差异是候选。原文件在提交前身份、版本或者范围有变化，报告冲突而不覆盖。复用原子提交与恢复凭据；多文件不承诺跨文件事务，逐项显示已应用、冲突、未应用。取消、超时或失败不会自动写回。结构化写和运行器建议统一走同一审阅卡。
- 一个任务一个临时视图，完成立即回收可回收内容；审阅期间只保留有上限的候选。并发、时限、数据量和进程树生命周期都有可验收上限。进程组只是回收手段之一，不能作为子进程被完全约束的证据。

## 5. 本地 MCP 与 HTTP MCP

### 5.1 本机进程

「测试连接」就会执行配置程序，启动前检查与正式调用同等严格。预检解析并复核规范化程序路径、文件身份、摘要，脚本还需绑定解释器和经过批准的入口与运行时。不得从当前工作区或用户 PATH 自动寻找已批准程序；路径相同而文件已换也要重新确认。程序或能力变化、策略变更、重新连接均按新范围检查，旧实例不做备用。仅开放可以证明隔离的程序形态；普通用户安装的工具如需要沙箱以外的访问，应显示不可用并说明所缺条件。

- 默认无工作区、无凭据、直连网络关闭；给程序的只有固定运行时与私有临时目录。用户可给这个服务选只读输入和输出暂存，不能让它继承会话工作区。只返回该运行器当前可见的 `roots/list` 路径；不泄漏原始项目路径。文件/目录内容进入第三方本机程序前明确许可，且不靠其 `readOnlyHint` 限制读写。
- 环境用最小允许名单。服务确实需令牌时只允许单项服务凭据引用，经用户批准后仅给该实例；默认让宿主代签请求，不向进程提供钥匙串、SSH agent、其他 MCP 或模型的凭据。秘密不进入诊断、日志或回复。一旦显式给程序一个秘密，不能承诺它不会通过其他已准许的渠道传给对方。
- 本期不开放自由出站；未来「仅经受控代理」须同时证明 OS 禁直连、代理可审计且只通该服务获准端点，不能用环境变量冒充。未实施时显示不可用。连接按会话、服务配置修订、程序身份和权限摘要分配，不能跨会话复用授权；收紧权限后关闭旧连接再建新连接。

### 5.2 HTTP MCP

1. **要连谁**：用用户选定的规范化「协议、主机、端口、MCP 路径」做精确匹配。默认 HTTPS 且校验证书，不跟随重定向、不采用环境代理。直连时在发包前校验解析到的地址、只用被批准的路由并保留 TLS 原主机名验证。公网上是默认地址类别；私网、回环默认禁用，有需要时要为具体端点独立批准；链路本地/元数据服务不开放。仅回环测试可显式允许 HTTP，不带真实凭据。受管企业代理需单独验证预期路由、防未授权外发；缺验证时禁用该能力，不自动改用系统代理。
2. **发送什么**：发现/握手只送协议元数据，不送本机路径、文件正文、聊天、记忆、模型上下文或可解引用的本地引用。业务操作绑定服务、方法、工具和当前 schema；默认逐次显示目标及准确参数待确认，即使工具声明只读。免重复授权只可用于已审查的常量与窄枚举/数值模板；不含任意文本、动态附件、隐式引用或未知字段。这样即使模型把文件内容改写成普通文本，也不会因少了“文件”标志绕过审阅。
3. **凭据给谁**：专属的 Header/OAuth 值只在复核端点与批准的请求后，由传输层填入；凭据不交给模型、别的端点或日志。OAuth 元数据和令牌交换不是业务端点的豁免，需要按角色校验并显式绑定；新增认证端点先提示。HTTP 3xx 和第三方 URL 不得悄悄携带任何凭据或本地数据跳转。
4. **回包如何接**：HTTP `roots/list` 默认空；资源引用按所选服务权限处理，不解释为本机路径。订阅、采样、问询、续步等同样经对应方法的传输边界和用户确认；准许采样生成并不批准将生成内容发回。没有回包时记录已发送/未派发与远端未知，不盲目重试。
5. **准确提示**：界面告知「限制本机发送和数据范围；服务端执行由服务端控制」。发给当前模型与发给另一个 MCP 是两次不同的传输，分别说明；不依赖模型作敏感数据分类，也不说已经控制了另一端。

## 6. 原生实现与放行条件

先把策略决策收敛为一个宿主模块；三条路径只消费宿主签发的受限计划。以下是职责约定，不是现有函数名：

| 接缝 | 从谁拿什么 | 只能输出什么 |
| --- | --- | --- |
| 计算与复核 | 文件网关、执行路由或扩展网关提交受信调用身份；宿主核对当前授权和策略修订 | 拒绝原因，或当前单次执行所需的策略计划；不接受模型提供的“已批准”标志 |
| 文件网关 | 受信目录句柄＋已验证相对路径＋操作/版本 | 有界读取、待审阅变更或提交回执；不返回可供子程序打开的宿主文件句柄 |
| 本机进程运行器 | 运行形态、固定程序和参数、专属工作副本、最小环境、限额和生命周期 ID | 输出、退出状态与候选变更；不持有宿主凭据或决定写回 |
| HTTP 传输 | 服务绑定、规范端点、校验过的实际路由、规范化业务载荷摘要和该服务的凭据引用 | 同一端点的限制内响应、未发送或交付未知；调用方不能在签核后换正文、目的地或请求方法 |

| 候选 | 选择 | 原因 |
| --- | --- | --- |
| 现有 Zig/C 本地文件 API 和业务提交 | 优先复用 | 句柄、版本、原子提交适合受控结构化工具；不需要把操作转成任意命令 |
| macOS App Sandbox + 独立签名 XPC helper | 本机进程候选主路径 | 公共系统机制；Zig 通过小块 ObjC/C 接入。XPC 负责 IPC 和权限分离，实际约束由签名 entitlement 和系统实施；不让一个常驻可执行任意命令的 helper 累积不同任务的权限 |
| 动态 Seatbelt / `sandbox-exec` | 参考，不做默认或兜底 | Codex/Anthropic 的文件、网络、拒绝策略值得参考，但 `sandbox-exec` 和 `sandbox_init` 已标为弃用，不引入任意配置脚本 |
| Apple Containerization / Virtualization.framework | 本期不采用 | 官方 Containerization 要求 Apple silicon、macOS 26/Xcode 26，运行的是 Linux 工作负载，不可冒充 macOS 本机工具，不能替换 ZeroWork 的 macOS 14+ 基线 |

先做签名样机证明 XPC 对端身份、任务之间的工作视图、子进程继承的实际限制、终止、网络、文件句柄传递和钥匙串/代理不可访问。访问书签不是通用执行授权。只共享必要的只读文件、临时数据和最小 IPC；不要共享 App 私有容器、凭据或所有任务的输入输出。禁止以关掉系统保护、打开全盘访问或关闭钥匙串检查作为通过条件。

**本机隔离无法证明时拒绝启动**。若只验收了结构化文件以及 HTTP，其他本机命令、PTY、stdio 或解释器保持不可用，仍保留聊天、授权文件和已经验收的 HTTP。不能悄悄走旧 spawn、普通终端、SSH、虚拟机或仅代理变量路径。

## 7. 配置与交互

在现有「偏好设置 → AI」加「本地沙箱」，工作区选择器旁显示「本地工作区权限」；MCP 编辑器分别显示「本机进程」与「HTTP 连接」，草稿导入不等于启用。会话可见「本地工具受限」或「本地命令隔离不可用」，不显示「整个对话都在沙箱」。收紧权限和关闭服务影响后续与当前受影响调用，不改变旧的人工终端配置。

下例是实施合同，不表示已有 TOML 字段。用户通过界面设置即可；授权书签与秘密引用由宿主管理，不随配置导出。未知字段、无效枚举、超上限、不可能强制的规则或互斥字段提示具体错误；只阻止受影响的配置，不使用宽松的旧规则。部署者可收紧硬限，不开放“关闭内核隔离”的配置项。

```toml
[ai.sandbox]
local_commands = false
default_workspace_access = "read_only"
process_network = "deny"
stdio_mcp = "require_sandbox"
http_mcp = "review_payload"
max_parallel_runners = 2
command_timeout_sec = 120
max_working_copy_mib = 512
max_output_mib = 8

# 针对一个会话；未选择范围时任何本地目录都不授权。
[workspace]
scope = "selected-workspace-id"
access = "review_changes"  # read_only | review_changes

# 以下为两个独立服务。stdio 不自动继承工作区。
[mcp.stdio]
service_id = "local-example"
input_scopes = []
output = "private_temp"   # private_temp | review_changes
network = "deny"
secret_refs = []

[mcp.http]
service_id = "http-example"
endpoint = "https://mcp.example.com/tools"
address_class = "public"  # public | approved_private | explicit_loopback
allow_redirect = false    # 硬限制
tool_bindings = []
payload = "review"
auth_ref = ""
```

这里的资源数值是验证起点，不是吞吐承诺。保留现有 MCP 服务配置的参数、工具绑定及超时边界（默认 30 秒，合法区间 100 毫秒至 120 秒）；新配置增加授权范围，而不是改协议。stdio 从私有目录启动，不能把原配置的任意 cwd 当作授权；HTTP 保留订阅独立取消，时间预算应区分握手、调用及订阅。达到容量限制不截掉安全必需数据后继续派发，用户看到明确的额度名称和下一步。

硬拒绝原因应区分来源，禁止只显示内部错误或让用户猜测：

| 错误 | 用户能看懂的原因 | 后果 |
| --- | --- | --- |
| `SandboxUnavailable` | 本机隔离不可用，未启动命令或 MCP | 不回退；其他已支持能力继续 |
| `WorkspaceScopeDenied` | 这项操作不在获准的本地范围内 | 未读或写越界内容 |
| `WorkspaceChanged` / `PolicyChanged` | 位置或权限已变，请重新发起 | 旧批准作废，不重放 |
| `McpProgramChanged` | 本机 MCP 程序已变化，请重新确认 | 不启动、不复用旧连接 |
| `McpEndpointDenied` | 不允许连这个地址 | 未发送业务内容和凭据 |
| `McpPayloadReviewRequired` | 此请求会向该 MCP 发送以下数据 | 预览目标与完整业务载荷，确认前不发 |
| `WorkspaceWriteConflict` | 原文件已变化，未覆盖 | 分项显示，并可重新审阅 |
| `McpDeliveryUnknown` | 请求已交给服务，但无法确认结果 | 不自动重放有副作用调用 |

诊断输出阶段、能力、策略修订、错误原因与请求 ID，不记录内容或完整敏感路径。配置内「测试连接」只做能力和握手检查，不执行任何业务工具或发项目数据；隔离不可用的本机程序连握手也不启动。

## 8. 原型和验收

- 设置：[本地沙箱](../UI_V4/ai/local-sandbox-settings.svg)；会话：[本地工作区权限](../UI_V4/ai/ai-workspace-permissions.svg)。
- MCP：[本机进程](../UI_V4/ai/mcp-stdio-sandbox.svg)、[无法安全启动](../UI_V4/ai/mcp-stdio-blocked.svg)、[HTTP 连接与数据](../UI_V4/ai/mcp-http-scope.svg)。

| 批次 | 场景 | 通过证据 |
| --- | --- | --- |
| A · 本地结构化 | 从真实 App 入口选目录/单文件，合法形态通过；无授权、跨会话、并行、越界、目录换名/替换、软/硬链接、重新打开及结构化写回冲突均覆盖 | 明确有无调用，实际文件和最小回执相符；只读场景磁盘原件没变 |
| B · 本地运行器 | 签名分发形态、基线 macOS 与一个当前支持版本、Apple silicon；合法工作副本与临时区可用，未知权限/未授权目录/真实凭据/直连不可用；检查子进程、限额、取消、失败平台与并行互不影响 | 记录签名、系统、已验证具体程序形态；能力不足时没有启动替代进程 |
| C · 本地 stdio | 首次测试连接、发现、业务、重连、换程序、缩权、Roots、采样、关闭；可控程序只见其授权视图，不读会话/项目 | 测试服务收据、实际权限观测和正常握手；只用自有夹具、凭据替身 |
| D · HTTP | 合法 HTTPS、证书失败、禁重定向、真实地址变化、内网/回环例外、代理、认证和回调。握手不送项目；自由文本/引用要审阅；取消、重连不重放 | 回环和可控 HTTPS 服务实际记录所收头与载荷；没有批准前发出的业务数据 |
| E · 共用回归 | 人工终端、正常 SSH、用户已有配置不变；Agent 无人工 PTY／SSH 等自动降级；隔离验证不影响正在运行的安装版 | 实际入口而不只 mock；精确记录未验收项，不把不能验证的情况算通过 |

A/D 可并行；B 是开启本地运行的门槛，C 按每种程序形态以前置 B 结果放行。原型和文字只验证产品合同；不替代签名样机真实边界验收。

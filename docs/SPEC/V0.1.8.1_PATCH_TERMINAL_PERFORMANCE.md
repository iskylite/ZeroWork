# V0.1.8.1 PATCH：终端交互延迟与资源占用

日期：2026-10-22；最终验收：2026-10-23。基于当前工作区 V0.1.1–V0.1.8 实现；不改变视觉规范、权限、会话所有权和录制保留语义。状态：本轮性能修复及Zenit升级兼容验收完成；完整UI保留9项升级前既有失败，见下文对照。

## 1. 开源参考与适配结论

- [Ghostty termio mailbox](https://github.com/ghostty-org/ghostty/blob/main/src/termio/mailbox.zig)：有界消息队列配合异步通知唤醒 I/O；本项目沿用现有队列，增加非阻塞唤醒管道，不引入新的运行时。
- [Ghostty renderer thread](https://github.com/ghostty-org/ghostty/blob/main/src/renderer/Thread.zig)：渲染通知与线程生命周期分离；本项目用进程级合并通知，主线程独占 Zenit Cx 和节点。
- [Alacritty event loop](https://github.com/alacritty/alacritty/blob/master/alacritty_terminal/src/event_loop.rs)：PTY readiness、输入消息、输出后的 Wakeup 分离，批量读写；本项目保留 VT 即时解析和 8ms 连续输出发布合并。
- [WezTerm scrollback](https://wezterm.org/scrollback.html)：缓存有明确上限，多会话需计入累计内存。本 PATCH 保留用户的录制容量，先消除可避免的重复驻留，不通过缩短历史冒充优化。

上述资料查阅于 2026-10-22，是架构参考；本项目源码和实际依赖 API 是实现依据，不复制产品性能数字。

## 2. 已确认的问题

0. core 模块未显式继承 build 的 optimize，发布构建需统一优化模式。
1. SSH 输入入队不能唤醒阻塞中的 kqueue，空闲输入可能增加接近 50ms 的发送前等待。
2. 本地 worker 固定休眠 10ms；PTY 回显及输入排队均受影响。元数据查询因输入反复提前。
3. 本地会话持续安排 33ms UI 刷新，SSH 持续安排 8ms 刷新；实际使用 MultiWindowApp，还需处理外层事件泵边界。
4. 录制线程无数据时每 2ms 唤醒。原始输出同时保留于内存 tap、磁盘 ring 与 Timeline。
5. Local Surface 复制 TextSlot 文本后仅使用 generation，再复制结构化快照；额外常驻 1MiB scratch。
6. 光标/时间戳刷新时重复构建正文 document；隐藏 Local 页仍执行展示刷新。
7. 采样发现主线程在空闲时持续渲染：refreshAppearance 重复传入相同终端主题，setTerminalTheme 无条件 requestRedraw，形成自激刷新循环。值未变化必须早退；不能关闭真实动画来掩盖问题。

这些是源码事实，不是已测得的 CPU 百分比、RSS 或端到端延迟。

## 4. 明确不纳入此 PATCH 的后续方向

逐字符节点替换为批量终端绘制、跨会话共享分块 Timeline 与全局缓存预算、完全重构快照所有权：涉及更大兼容面，先完成本 PATCH 的实测，再独立定义后续补丁。当前仍有主 VT、录制 VT、Timeline 与完整快照等真实成本，不宣称所有资源问题已经解决。

### 指标口径与剩余预算

- CPU：隔离测试进程的 CPU time 增量 / 8秒真实墙钟；单核心满载记100%。采样期间不发 Harness RPC，不并行编译或运行其他验证实例。
- RSS：`ps` 的 KiB；不能把释放64MiB逻辑分配直接写成RSS下降64MiB。未触页的预分配、allocator与GPU缓存会影响驻留量。
- 输入：当前自动化记录“发送命令到查询见到结果”的总耗时，包含多次RPC。只用于同脚本对比，不证明50ms key-to-photon预算或物理输入p95。
- 录制：每个启用磁盘ring的会话不再重复持有默认64MiB tap载荷；Local Surface减少1MiB scratch。SSH检查点写盘仍位于SSH worker，慢磁盘停顿尚需后续异步化验证；Timeline、录制VT和主VT仍各有职责，内存120MiB旧预算尚不能仅凭此声明达标。
- UI输出通知目前按进程合并，再由主线程请求各窗口刷新；多窗口精细路由以及更低的事件泵空闲唤醒留作后续测量优化。纯metadata和生命周期变化的通知已在下述深查中补齐。

## 6. 2026-10-23 深查与补漏

本轮复查没有把上一轮的构建通过视为性能验收。保留现有会话、历史容量、权限和样式，修复以下已确认问题：

- 隐藏的认证、连接进度、连接详情、AI附件预览反复执行关闭操作；传输面板重复设置相同锚点。这些操作每帧都请求下一帧。现在仅在状态真正变化时更新，认证首次关闭仍清空敏感输入。
- 渲染缓存快路不能跳过交互几何等待处理工作；部分交互索引重建也必须清理其他分支中残留的几何标记。否则 `wantsFrame()` 持续返回真，静态画面仍按显示刷新率生成帧。两个独立框架回归均在对应修复前失败、修复后通过，同时检查实际命中位置。
- Local Surface 消费版本后若获取快照遇到 `WorkerBusy` 或 `SnapshotUnavailable`，安排8ms重试；SSH确认后的分块粘贴在队列满且远端不回显时也自主重试，避免等待250ms生命周期兜底。
- FeedBridge 在最终展示收据提交后补合并通知；SSH EOF、断线、清理收据和重连ready更新后通知主线程。相同状态的重复清理不通知。
- Local无输出的cwd/前台进程变化、exec状态及输出变化、EOF/退出/错误/主题/几何变化，以及录制首次异步失败都通知展示端。采样时间戳变化不会单独触发重绘；过期会话关闭立即唤醒worker。
- 磁盘ring写失败保留首错、回退内存chronology并停止后续raw/checkpoint提交，避免缺口被标成完整历史；启用磁盘存储失败仍保留内存fallback。录制阻塞等待、关闭排空、ANSI/中文和resize导出有真实线程测试覆盖。

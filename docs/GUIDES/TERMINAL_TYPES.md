# 内置终端类型与兼容规则

设置中的 `xterm-256color`、`xterm`、`vt100` 均通过同一个 Ghostty VT 解析器、`TerminalService` 和原生 `TerminalSurface`。类型名称由 `src/vt/terminal_type.zig` 统一列举，设置下拉框和编辑器直接消费这个列表。SSH 的 PTY 请求使用所选名称；本地产品默认仍为 `xterm-256color`，不让 SSH 设置隐式改变本地会话。

`TERM` 声明影响远端程序读取的 terminfo 能力。验证时从实际 PTY 进程读取 `TERM` 并加载运行端的 terminfo，使用该条目自身的序列，不为没有声明的能力套用 xterm 序列。SSH peer 记录真正收到的 PTY 类型，并用其启动真实 ZSH。

| 类别 | xterm-256color | xterm | vt100 |

## 类型差异与兼容处理

修复前，实际 `TERM=vt100` 的 SSH 进程对 F5 读到 `ESC [ 15 ~`，而其 terminfo `kf5` 要求 `ESC O t`。仅对精确匹配的内置 `vt100` 增加以下旧式功能键别名：

| 物理功能键 | vt100 输入 | xterm 家族输入 |
| --- | --- | --- |
| F5 | `ESC O t` | `ESC [ 15 ~` |
| F6 | `ESC O u` | `ESC [ 17 ~` |
| F7 | `ESC O v` | `ESC [ 18 ~` |
| F8 | `ESC O l` | `ESC [ 19 ~` |
| F9 | `ESC O w` | `ESC [ 20 ~` |
| F10 | `ESC O x` | `ESC [ 21 ~` |

处理由共用编码入口执行，Local/SSH 使用同一份规则；不改变绘制器，不限制引擎可解析的颜色。修饰键、释放事件和 Kitty 协商协议继续由 Ghostty 处理，RIS 重置保留所选类型。`vt100-custom`、`screen-256color` 等自定义名称不会通过前缀推断成内置 VT100。

VT100 的 `kf0` 是旧式数字键盘 9 的别名。它没有对应的 F0 物理按键，原生 UI 矩阵明确保留 `declared_not_exercised`；另由真实 Local PTY 数字键盘服务测试覆盖对应 `ESC O y` 字节。不能把这一层测试混称为原生物理 F0 测试。

## 自定义声明

“自定义 TERM 声明…”只把用户输入的名称用于后续 SSH 连接与重连，不承诺实现任意同名硬件或软件终端。设置帮助与编辑器说明这一边界，远端必须提供对应的 terminfo。自定义值按原文保存，取消编辑不会改变当前值。

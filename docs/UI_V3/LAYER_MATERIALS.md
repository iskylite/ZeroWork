# 图层透明度与浮层设计合同

**主背景与四大卡片规则（2026-11-03）**：设置中的透明度 T 与模糊 B 控制最底层画布。先以 100% 不透明绘制画布底色及顶栏、主机栏、主内容区、状态栏的背景填充，再将这组背景作为一个整体，以不透明度 `1−T` 合成到共享图片上；不能在已调透明的画布上再次给卡片设置 `1−T`。四块前景容器本身不再重复填背景，文字、图标、控件及其输入命中保持原样。背景图片只按 B 模糊一次，B=0 时关闭；AI 助手三点入口一并纳入这组背景。主机列表卡片、AI 助手及设置窗口在 L0 上，均为 L1；内部卡片与后续菜单按实际承载关系逐层增加。原生使用独立 `composited_group` 背景节点，HTML 使用独立背景组；整机嵌入页将四块背景区域同步至父画布。

记录日期：2026-10-29。本文直接记录最终设计数值，原生实现与HTML基准使用相同参数。通用规则以[设计指南§3.3](../DESIGN/DESIGN_STANDARDS.md#33-阴影与背景能力)为准，实现入口为[app_theme.zig](../../src/ui/app_theme.zig)。

## 设计要求与术语

四块主卡片的背景透明程度直接由设置决定；内部填充和上层浮窗、气泡继续按实际角色与层级计算透明程度。只改变背景 RGBA，不降低文字、图标或整棵控件树的透明度。所有图层透出同一个窗口内背景，不重复绘制图片；本规则不表示窗口能透出 macOS 桌面。

本文的“透明度”均指透明程度 P，0% 为完全不透明、100% 为完全透明。代码 alpha 表示不透明度，方向相反：alpha=1−P。基础值取全局透明度滑块 0；已有滑块配置仍参与最终计算。

## 当前参数

工作区最终几何：外边距5pt，卡片间距8pt，顶栏36pt，底栏26pt，页签30pt。原生与HTML共用此组数值。

| 角色 | 用途 | 最终基础透明度 P0 | 滑块全程增量 D | 最大透明度 M |
| --- | --- | ---: | ---: | ---: |
| surface-1 | 主卡片、侧栏、顶栏、底栏 | 0.000000000 | 1.000000000 | 1.00 |
| surface-2 | 内部卡片 | 0.720000000 | 0.180000000 | 0.9 |
| well | 输入区、凹槽 | 0.640000000 | 0.200000000 | 0.84 |
| overlay | 首层浮层底色 | 0.000000000 | 0.500000000 | 0.5 |
| hover | 悬停表面 | 0.820000000 | 0.080000000 | 0.9 |
| tab-on | 活跃页签 | 0.680000000 | 0.140000000 | 0.82 |

**视觉层级（2026-11-03）**

L0 是最底层画布与四大卡片。实际绘制在 L0 上的主机列表卡片、AI 助手、设置窗口均为 L1；在 L1 卡片上的结果卡片或菜单为 L2；其内部命令／输出卡片以及菜单触发的 Tooltip 为 L3。每个实际卡片或独立浮层边界增加一层，透明布局容器、标题、工具栏不增加层级。菜单和 Tooltip 沿触发控件的实际所属卡片回溯，不能只计算浮窗深度。

浮层之间依靠背景实度、间距及必要的柔和投影区分，不追加整圈 border、outline 或描边式阴影。输入与键盘焦点同样遵循§3.2：使用底色、文字/图标与 caret/IME 表达状态，不以焦点 ring 补框。虚线空槽和组页签标记保留各自语义。

临时表面的透明度由其所在的视觉层级决定，不由 Tooltip、Popover、Modal、卡片等组件类型决定。`overlay` 只提供主题底色和首层的兼容参数；`well`、`surface-2` 等内部填充角色不能用于决定新浮层的透明度。实际卡片增加一层，输入内容及 hover 行反馈不单独增加卡片层级；纯布局节点的嵌套不计层。

| 实际浮层层级 | 最终透明程度 P（T=0） | 最终透明程度 P（T=1） | 最终不透明度 alpha8（T=0 → 1） |
| --- | ---: | ---: | ---: |
| L1：画布上的卡片／首层浮窗 | 0% | 80% | 255 → 51 |
| L2：L1 上的卡片／子菜单 | 0% | 60% | 255 → 102 |
| L3：L2 上的卡片／说明气泡 | 0% | 40% | 255 → 153 |
| L4 及以上 | 0% | 20% | 255 → 204 |

`T=clamp(background_transparency/100,0,1)`；最终透光率 `P(L)=T×Q(L)`，`Q(L)=(5−min(L,4))/5`，最终不透明度为 `1−P(L)`。在直接父表面上绘制时，实际填充 alpha 为 `1−Q(L)/Q(L−1)`（T=0 时用不透明填充），不能把最终不透明度再当作每层填充 alpha。L4+ 保留 20% 的设置透光率，不再强制全不透明。文字和图标保持独立。

浮窗按实际覆盖区域补偿：若该区域下方实际最高表面为 K，则所需填充为 `max(0,1−Q(L)/Q(K))`。超出父卡片、圆角之外或完全落在画布上的部分分别计算；同层浮窗重叠不再次累加实度。已更实的下层保持其现有透光率，避免用新的浅层窗口继续加实。原生在背景专用绘制节点中按窗口坐标分区，HTML 使用同坐标圆角 SVG 遮罩；都不降低前景透明度，不复制背景图片。背景补偿不改变浮窗的布局、排序、输入或局部模糊设置。

### 透明度与可读性（2026-11-03）

材质层级严格遵循设置透明度，图片开关、主题或可读性补偿不得把首层卡片自动加实。各层只修改背景 alpha，文字与图标保持独立；消息气泡使用所属 AI 助手之上的 L2 材质及匹配前景色。局部 hover／选中反馈仍按控件语义绘制，不把状态变化算成新的卡片层。普通卡片继承下层已模糊的背景，独立浮层的局部模糊为 `max(12,B)`。

父层按触发控件实际所在表面确定；原生 portal 浮层沿 OverlayStack 的存活 trigger 引用回溯父表面，手工定位的现有浮窗以其 overlay 材质边界识别。HTML 中普通嵌套沿表面边界回溯，脱离父 DOM 的弹层通过 `V3Materials.setOwner(surface, anchor)` 声明实际锚点。组件种类、DOM 深度、浮层 tier 和原始 z-index 均不直接选择透明度百分比；它们的排序、定位和交互职责保留。同层的独立浮窗共享 L1，不能按当前已打开窗口的数量升级透明度。

模型示例：工作区 → AI 浮窗 L1 → 模型选择 L2 → 模型说明 L3。同一个 Tooltip 直接由工作区触发时是 L1，放在模型菜单里时是 L3。移动父表面、关闭重开、切换主题或全局材质参数后须重新解析；气泡伸出父浮窗边界也使用同一层级底色。L2/L3 与 L1 同步局部背景模糊 `max(12,B)`，不模糊自身文字。

实现入口：`src/ui/app_theme.zig` 的 `layerAlpha/layerBackground` 和 `src/ui/layer_materials.zig`；原生主窗口与辅助窗口安装同一策略。HTML 对应 `shared/global-background.js`、`theme-tokens.css` 与 `theme-presets.json.materialProjection.floatingLevels`。

基础曲线数值（全局滑块 T=0；卡片最终 alpha 按实际层级覆盖这些角色的默认值，文字和图标不受影响）：

| 表面角色 | 最终基础透明程度 P（量化前） | 实际背景 alpha8 | 实际不透明度 |
| --- | ---: | ---: | ---: |
| surface-1 | 0.00000000% | 255/255 | 100.000000% |
| surface-2 | 72.00000000% | 71/255 | 27.843137% |
| well | 64.00000000% | 92/255 | 36.078431% |
| overlay | 0.00000000% | 255/255 | 100.000000% |
| hover | 82.00000000% | 46/255 | 18.039216% |
| tab-on | 68.00000000% | 82/255 | 32.156863% |

`T=clamp(background_transparency/100,0,1)`，`P=min(M,P0+D×T)`，`alpha8=round(255×(1−P))`。`P0`为代码直接使用的最终基础透明度，`D`为当前滑块全程增量，达到角色上限`M`后保持不变；不存在历史调节倍率。此表达保持当前滑块响应与各角色上限。

角色上限避免极端滑块值产生负 alpha，并保留上层可读底色。最终采用 8 位 alpha，表中未量化值与截图实际值存在约 0.2 个百分点以内的舍入差异。图片 alpha 为 T（0% 隐藏图片，100% 完整显示图片），与角色表面计算分开；图片关闭不关闭 UI 分层透明度。

浮层背景模糊为 max(12, blur_px) 逻辑 px。即使配置为 0，浮层仍有最低 12px，防止背景终端文字重影；根背景图使用用户配置的 blur_px，文字与控件自身不模糊。浮层采样已绘制的窗口内容，不采样桌面。

## 组件接入与更新

全局通知横幅与提醒列表是独立的最高材质层，固定使用 L4 的透明度上限，不沿工作区、AI 助手或触发按钮的承载关系计算等级。最终透明程度为 `P=0.2×T`（T=0/50%/75%/100% 时分别为 0/10%/15%/20%）；背景填充仍按实际覆盖区域补偿，文字与图标保持不透明。绘制顺序与该材质等级分别管理，控件旁的局部反馈不适用此规则。

会话关闭、SSH主机密钥确认、页签重命名、页签颜色选择、长名称提示及快捷键录制弹窗使用overlay；组终端标题栏使用surface-1，快捷键录制内部凹槽使用well。保留节点通过主题发布同步背景与blur，不降低前景透明度。

通知历史浮窗同步统一背景模糊，单独修改blur时保留节点身份与通知内容；通知底栏使用surface-2。通知、快速连接和传输空态的具体布局由各模块实现维护。

## 验证方式与边界

通用资源与性能基准以[设计指南](../DESIGN/DESIGN_STANDARDS.md)§7.4、§9.1 为准；本节记录材质实现与针对性回归入口，运行耗时不作为跨设备性能保证。

材质更新以表面边界索引为单位：仅在节点结构、声明、portal 锚点或绘制排序变化时重建索引；滚动只读取可见表面及其真实祖先裁剪。被父卡片裁剪的内部卡片直接使用所属层级填充，伸出父卡片或与同层表面交叠的区域才计算补偿。补偿分区按相对几何缓存，使用可保留的普通绘制节点；参数未变化时不得反复写样式或触发布局，源节点销毁后释放补偿记录。背景组也只在资源、参数或几何变化时更新。上述调度不改变最终透光率、圆角与模糊规则。

HTML 将滚动、尺寸和 DOM 更新合并到一次 RAF，缓存表面集合、遮罩及嵌入页几何消息，忽略自身样式写入产生的 MutationObserver 通知；已移除的表面解除 ResizeObserver 监听。只更新文字不重查整棵材质树。AI 历史估算按不可变对话版本及模型参数缓存，隐藏和滚出视口的视觉计时不持续请求重绘，实际后台任务继续运行。

## 控件与浮层内容的层级补充（2026-11-03）

输入内容、次级操作和浮层内的摘要卡片属于轻量内嵌卡片。RGB 继续按原语义派生，背景 alpha 同步相应材质角色：

- `popupInset`：先将不透明 overlay 与 well 按 70:30 混合；若与 overlay 的明暗对比小于 1.1:1，则使用该主题的不透明 well，RGB 保留静止输入区的色调差异，作为局部控件底色时 alpha 取 well；作为实际卡片时 alpha 由承载层级确定。用于输入、列表凹槽与详情内容，所有主题采用同一规则。
- `popupAction`：不透明 overlay 与 fg_2 按 88:12 混合，用于次操作；作为实际摘要卡片时 alpha 由承载层级确定。
- 输入静止态不画边框，以稳定底色与父表面的明暗差区分；聚焦使用独立的 popupSelection 底色、caret 与 IME 标记，出错使用 danger tint 和已有说明，不添加 border、outline 或 ring。
- `popupSelection`：在不透明 overlay 上混合强调色，深色 16%、浅色 10%；最终 alpha 取 tab-on；仅用于界面选择，不替换终端文本选择色或 ANSI 颜色。
- 浮层不统一添加轮廓，沿用圆角、底色、阴影与留白分层；模糊仍为 max(12, blur_px)。

共享 Input 的底色与必要的焦点反馈、次级按钮和未选复选框由同一主题发布提供这些颜色。显式覆盖样式的终端搜索、资产表单、页签筛选、传输确认、AI 菜单、连接与 SOCKS 详情同步采用相同语义。保留节点重绘同时更新派生内容底色，保留文本、选择、焦点和业务状态。HTML 对应 `theme-tokens.css` 的 `--control-bg`、`--popup-action`、`--popup-selected`。

本轮实际层级、覆盖范围及截图的可复现入口见上述验证方式；原生脚本为 `e2e/layer_materials_native.ts`，中间截图保存于运行时指定的仓库外目录。


## 保留面板与内部卡片回归（2026-11-05）

收起后从窗口树摘除的面板，在重新挂载时按错过的 theme version 重放当前主题，只更新原节点，不重建草稿或业务状态。通过 `Cx.replaySubtreeTheme` 使用与 `setTheme` 相同的主题钩子，且不再次发布整窗主题信号。材质边界不以背景 RGB 是否等于当前调色板判断；窗口背景 capture/blur 节点不计浮层，自定义视频进度表面保留其显式色调。

AI Textarea 的内部文本、光标和选区使用独立的 tokens 快照，因此另外订阅主题发布并刷新原文档的渲染，保证隐藏期间切换主题后草稿颜色同步。

恢复卡、会话清单授权卡、答复图片卡、代码块、传输任务卡、连接节点卡、关闭风险摘要和历史回溯条均声明实际材质边界。审批卡内部命令／详情视口继续递增一层。原始连接诊断由 portal chrome 独占背景，内容容器透明；快速连接选中行使用共享 popupSelection 状态材质。

`zig build test-ui -Dui-test-filter=material -j2` 覆盖生产组件层级、隐藏主题切换和草稿保留。构建 test-mode 后运行 `node e2e/layer_regressions_native.ts /absolute/test-binary /tmp/zw-layer-regressions`，通过真实设置保存主题，检查首次打开及反复收起重开、三主题和 860×480 截图；同目录的 pixel-report.json 检查空白外壳区域确实透出背景，并且重复重开不累加背景实度。输入为 Harness 合成事件，不代表物理键盘或 IME 验收。

## KVM 视频与 HUD 的原生分层验收（2026-11-05）

KVM 预览窗口挂载与主应用相同的 `layer_materials.Policy`，使用生产 BMC View、原始 typed services 和真实 Metal FrameSink。视频像素及黑色留白保持独立，不跟随 UI 透明度改变。FPS 保留视频专用背景 `rgba(18,20,24,199/255)`，输入错误提示保留黑色 65% 底色，两者不拦截视频输入。

进度卡的内容实际挂在玻璃表面之内，外层仅负责尺寸和阴影；路由摘要及展开的步骤诊断按实际父表面进入 L2。玻璃表面显式采样当前视频合成层（`capture_current_target=true`），避免在 `composited_group` 内采到窗口底图而变灰白。电源／启动摘要、连接日志的路由、列表和底栏补齐 L2 声明。

关闭的 KVM 菜单和弹窗订阅主题发布，重放其保留内容；BMC Select 适配层同步内部 palette、当前标签和重建后的选项文字，保留值、键盘高亮和滚动。提示气泡的可见性检查通过当前 registry 中的稳定节点 ID 确认控件存活，避免父菜单摘除重开后因旧输入 generation 误关气泡；气泡自己的 Scope 同步脱离节点树后的背景与文字颜色，实际输入事件的 generation 校验不变。

```sh
node e2e/bmc_kvm_video_frames_native.ts --binary /tmp/zw-kvm-material-build/bin/bmc-kvm-preview --out /tmp/zw-kvm-continuous-frames
```

原生矩阵在同一窗口中切换 Dark／Light／Sauber，覆盖 1440×900 与 860×480、T=0/75/100、黑白视频及 FPS、输入提示、五类菜单、嵌套下拉框、FPS 说明、启动顺序、断开确认、只读、无信号、中断旧帧、连接阶段、证书／凭据等待和失败。每次保存截图、实际背景／文字颜色、玻璃采样配置及层级补偿信息；`bmc_material_pixels.py` 检查原始视频、HUD 混色和进度卡采样，区分中断后仍显示的旧帧与无画面时的等待底色。截图仍需查看，不以样式数值代替 Metal 结果。此入口不建立 BMC 连接，不执行电源或启动写入，不代表真实设备连接、物理输入或 macOS 全屏验收。

本轮最终矩阵通过 156 个截图状态、102 项像素断言及气泡／选项文字颜色检查，分层异常为零；另有 24 次连续视频呈现、每次三点的像素检查通过。生产组件回归覆盖真实父表面、原节点保留、提示三次重开与三主题切换，以及既有视频、滚动和输入行为。

# 全局通知收口设计

日期：2026-10-29。HTML 策略与整机交互是设计基准；2026-10-29 已接入原生准入、来源、聚合、待处理及历史行为，验证范围见文末。原生视觉组件继续沿用已验收的 V3 样式。

入口：[现有整机中的全局通知验证](../app/index.html?notification-review=1) · [同一整机中的提醒列表](../app/index.html?notification-review=1&notification-center=1)。原 `notifications/index.html` 与 `history.html` 都进入同一整机服务，不再各自维护一份假通知队列。

## 决策

全局通知用于值得用户现在转移注意力的事。来源局部状态是事实的主要承载位置，通知只提供必要的及时提醒与定位。跨页面、后台运行、warning／failure 本身均不构成升级理由。

同时满足以下条件才升级：事件属于允许的业务类型；存在需要用户处理的实际影响；晚些处理会导致损失或使已委托的工作持续阻塞；用户没有在关注原位置。应用级持续保存风险是明确例外，即使用户正在当前工作区也需保持可见。

用户显式开启的后台完成提醒是另一独立例外，只在离开应用后通知。默认关闭；应用前台完成只更新原来源状态。

## 全产品事件归属

| 事件 | 默认位置 | 何时全局提醒 |
| --- | --- | --- |
| AI 思考、工具进度、回合结束、普通请求失败、主动停止、回退 | transcript／原工具卡／composer；必要时原会话状态 | 不升级；最终任务完成仅走显式订阅的后台完成提醒 |
| AI 审批、必要输入 | 原审批／输入卡 | 离开原位置且已委托任务因此持续阻塞时提醒一次；横幅不能直接批准 |
| 工具结果未知 | 原执行卡，保留已派发与未知部分 | 已产生副作用且需要及时介入核查时；普通读取失败不升级 |
| 用户主动连接失败、密码／指纹输入、连接测试 | 当前连接面板或会话状态 | 当场发生的失败不额外全局提醒 |
| 短暂断线、自动重连、正常恢复 | 对应会话状态 | 不逐次弹出；恢复更新原事项，不再追加成功横幅 |
| 持续连接故障 | 会话／链路状态 | 自动恢复停止、影响实际工作且用户不在原处时提醒一次 |
| 单文件失败、冲突、暂停、取消 | 原传输任务／冲突操作 | 不升级；后台整个批次停止且需要介入时才提醒 |
| 转发、SOCKS、KVM 等后台能力意外停止 | 原功能状态 | 实际影响正在进行的工作、需要及时处理且未查看时升级；正常启停不升级 |
| 复制、保存成功、刷新、普通配置校验、权限被拒绝 | 触发控件／字段／当前设置页 | 不进入全局历史；权限状态不因每次打开设置而重复警报 |
| 应用无法继续保存工作记录、持续的数据丢失风险 | 原来源说明与全局持续提醒 | 立即可见；关闭横幅不解除风险，来源恢复后解除 |
| 普通后台输出、终端 Bell／OSC 消息 | 页签状态／独立声音偏好 | 输出和文本内容不能直接获得全局提醒资格 |

## 全局层的交互

- 默认只呈现一条重要提醒。多个独立事项保留在列表，正常事项不形成一串补发弹窗；持续应用风险优先。重要性已消失的事件不能在稍后补弹。
- 一条提醒包含问题、真实来源、必要原因和一个“查看来源”动作。不在横幅中放批准、重试有副作用的命令、认证或清理操作。
- 同一宿主确认的共享链路故障合并为一项，保留受影响来源。按稳定 incident/operation ID 合并，禁止按相似文案或会话名称猜测同源。
- 同一事件以稳定 key 和单调 revision 去重；修改偏好、权限、窗口焦点或切换页面不补发旧事件。后续证据更新原记录。
- 应用前台使用应用内提醒，离开应用时才选择系统渠道；同一事件不会先系统通知、返回应用后再弹一份。系统授权、勿扰与平台提交结果仍单独建模，本原型不实际发送系统通知。
- 普通需要介入的横幅可超时收起，待处理项保留；应用级持续风险使用持久横幅。关闭横幅只关闭展示；定位来源只执行导航，不等于处理完成。
- 打开提醒列表后收起同一横幅，避免同时重复展示。列表入口沿用现有顶栏，普通业务事件不会让铃铛不断积累未读数。

## 提醒列表

入口名称为“提醒”，两种视图共用同一事实集合：

| 视图 | 收录内容 | 解除方式 |
| --- | --- | --- |
| 待处理 | 已升级且确实尚未解决的事项 | 对应业务的恢复／处理结果更新原记录；不能通过打开列表、关闭横幅或清空历史解除 |
| 最近提醒 | 曾经通过升级规则的重要提醒及其最终状态；不含全部运行日志 | 可清除已结束记录；活动事项不会被清空操作删除 |

角标优先显示待处理事项数，同源聚合算一项；已读与已解决独立。打开列表将重要提醒标为已查看，但待处理计数保留。无待处理时，如存在尚未查看的重要完成提醒，使用一个安静的圆点，不累计普通成功／失败数量。

历史只保留最近 100 条已结束提醒，未处理事项不为满足历史上限被丢弃。完整 AI 过程、命令错误、连接日志及传输明细仍在原模块。

## 主题与协作边界

已与「优化快速连接的主题层次感」及「优化 AI 助手预览与错误状态」对齐：

- 本会话唯一负责 `shared/notification-policy.js`、`notification-policy.css`、`notification-integration.js`、`notifications/review.js` 和整机挂载入口。共享卡片 renderer、原生 styles 及其 metadata 转发保留视觉会话的结果。
- 重要提醒横幅调用现有 `V3Feedback.show`，不复制一份卡片。列表外壳使用 `overlay` 与允许的柔和投影；内部条目用 `control-bg / popupInset`、9px 圆角、68px 最小折叠高度、6px 间距，无整圈描边、条目阴影或分隔线。
- 次操作与选择分别使用 `popupAction`、`popupSelection`；图标与文本使用现有 `danger-ink / warn-ink / ok-ink / accent-ink / fg / muted`。文字不随背景透明度变化，不设置整棵树 opacity。
- popupInset／`--control-bg` 默认采用不透明 overlay/well 70:30；当与 overlay 的对比不足 1.1:1 时，回退到该主题完整不透明 well，由共享 `--control-inset-well-strength` 的 30%／100% 决定。popupAction 为 overlay/fg₂ 88:12，选中态沿用当前主题定义，不自行增加调色板。17 个内置主题的 UI 角色已补全，`--sel` 统一映射 UI 的 `--popup-selected`，终端 `--sel-bg`／ANSI 保持独立。主题会话已完成全 17 主题原生组件、浮层及对比度回归和修后独立复核；覆盖与边界以[主题最终验证记录](../verification/theme-completion-20261029.md)为准，不将其扩大为本次通知策略在全部业务状态的验收。

## 实现位置与原生差距

`shared/notification-policy.js` 是本次唯一的升级规则与重要记录集合；`notification-integration.js` 为现有 HTML 文档宿主接入适配，直接组合已有 workspace/connection/settings 等模块。普通 `show()` 回执留在来源模块；结构化 `publish()` 才可申请全局提醒，业务文本不能决定渠道。公开通道只给定位意图。

整机预览外的验证控件提供 11 类本地事件，以及“正在看原位置／离开应用／完成偏好／勿扰”的组合；不执行真实连接、命令、保存或系统通知。模块的真实业务控制器仍需逐一提供结构化影响与时效事实，不能把旧 `toast(text)` 自动当成重要事件。

原生后续必须同步的边界：

1. `notification_host.zig`：停止以 warning／failure 直接升级；检查全部结果的已呈现状态，按真实影响选渠道。
2. `notification_coordinator.zig`：普通局部事件不创建全局历史未读；升级记录的已读、待处理、横幅显隐及系统投递独立；支持稳定事件／同源聚合。
3. `notification_presenter.zig` 和 `notification_history.zig`：默认一个横幅，列表分待处理／最近提醒，关闭与查看不代替业务处理；过期、已恢复、失效 owner 不补弹、不重建同名会话。
4. 设置与来源服务：后台完成新默认关闭；既有保存偏好须明确迁移，不静默覆盖。持续故障和任务阻塞提供宿主确证，不从重绘或语言模型正文推断。

本次不修改原生渠道策略或用户配置，不把原型中的验证通过当成正式 App 已完成全链路。

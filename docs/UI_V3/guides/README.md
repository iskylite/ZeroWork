# V3 设计指南

[返回设计中心](../index.html#guides)

## 目录组织

- `index.html`：统一设计门户，按大模块效果图、公共组件、说明文档、设计指南分区。
- `settings/`、`connection/`：产品大模块。各自维护交互原稿、资源及模块说明；未找回的稿件明确标注状态。
- `components/`：公共组件目录、示例与复用约定。
- `README.md`、模块 README：范围、行为与交付说明；`SCREENS.md` 索引状态图。
- `guides/`：跨模块设计规则与交付流程。


统一使用 V3。独立状态图不作为独立模块计数；旧 V2 保留历史身份。门户负责发现与导航，模块交互稿负责呈现产品界面。

## 视觉与交互

精确尺寸、字体、颜色及约束取自对应 HTML/CSS 和浏览器计算样式，不能单凭截图推断。设置稿标准面板为 1080×790 逻辑像素上限，按视口收缩；不能把该尺寸套给所有模块。

同类选择器保持同一组件与反馈规则。卡片、标题和悬浮层的圆角、裁切、焦点需覆盖默认、悬浮与点击状态。折叠仅改变布局；开关改变功能启用状态。列表有界滚动，固定行不得因 flex 压缩导致滚动失效。

公共组件在 `components/index.html` 独立绘制和操作；模块展示其业务用法。独立展板与业务模块保持一致。接口缺失的数据保持未知，演示结果明确标注模拟，不冒充真实验证。

## 确认与落地

先完成并确认 HTML 可交互原稿，再进行原生 Zenit 实现。HTML 本身承担原型职责，无需默认重复维护 Figma。原生控件与状态必须实际实现，不能用 WebView 或整页截图替代。

原生验收对齐内容区、逻辑尺寸、像素比例和状态，检查真实窗口截图及相关交互。浏览器演示不能代替原生输入法、焦点、滚动、文件选择与真实接口验证。

## 完整落地基准（本轮补全）

按功能族管理入口、状态、事件结果和组件映射；不能用总页数替代逐项覆盖。实现负责人应从模块 README 和实际 HTML 读取契约，待核对或限制项不能自行认作已通过。

- 默认整机1440×900，最小窗口860×480，设置为独立受控面板；评审尺寸切换不属于产品工具栏。
- AI 为当前 pane 顶部三点入口和默认600×456浮窗；保留只读归属、会话列表/新建、收起/最大/关闭、内容区与90px输入区。不能改成普通常驻右侧栏。
- 模型条常态一行：名称、上下文/能力、测试状态、操作；长名称省略可查看全名，详细错误按需展开，不撑高每一行。
- Tooltip/Popover/Menu/Modal均夹取在所属APP内，距边至少8px；底栏浮卡优先向上，锚点指向实际触发控件。不能使用浏览器viewport替代APP矩形。
- 新建连接统一消费连接模块向导，工作区嵌入方式是HTML原型的复用手段；原生实现映射同一个ConnectionEditor/Modal，不能把iframe方案照搬为WebView。
- 内置命令与输出留在终端文档流，有特殊背景/色彩/标记；pending更新原记录，错误包含原因和恢复入口。不能让连接过程覆盖原会话终端。
- 所有跨模块动作保留草稿，取消不执行；笔记命令只准备、不自动执行，AI附件先预览、不自动发送；广播/审批冻结目标，异步结果不跟随新active目标。
- 未来协议的功能设计可完整表达，界面标注模拟；没有真实权限、后端或系统能力时不显示“已真实完成”。插件能力不足时使用明确门控，同时保留规划状态可评审。

## 细粒度组件与融合（当前规则）

以[组件组合合同](../COMPONENT_MAP.md)为当前组织规则：通用组件→功能组件→模块→整机。功能组件目录挂载来源模块实际renderer/controller；页签与基础控件由共享源生成，不在不同页独立复刻。目录入口分别位于components/、features/、功能模块、app/。相似外观但不同owner或能力的组件通过明确变体组合。

当前预览只含本地、SSH、SFTP、KVM连接；VNC/RDP/FTP单独进入future/并标记未来，不通过默认导航混入。该规则替代上述允许未来协议出现在默认预览的历史描述。

Tab/Host/Terminal菜单遵循现有APP；终端右键粘贴、中键菜单；链路浮层在壳重绘后按稳定身份重锚。共享样式必须连同语义、状态和行为合同一起复用。通用方法已同步到zenit-html-ui skill的component-composition参考。

# AI 提示设计契约

日期：2026-10-29。状态：可交互 HTML 设计基准，原生通知路由与生命周期尚未按本契约实现。

入口：[交互预览](notifications.html)。全局升级、聚合和提醒列表以[全局通知收口设计](../notifications/README.md)为唯一规则，本页只定义 AI 原位置反馈。沿用「修复回退提示的 transcript 显示」已经完成的中性反馈、transcript 滚动承载和固定 composer；本次补齐不同提示的归属、操作、保留及提醒条件，不重做 AI 外壳或其他模块的通知。

## 归属与组件

| 内容 | 位置与组件 | 操作及保留 | 全局渠道 |
| --- | --- | --- | --- |
| 回退完成 | 回退位置的 `V3AI.localNotice`，中性图标、短正文及次级影响说明 | 可关闭；关闭不改变回退结果；重新发送、切换对话后清除 | 不弹窗、不制造全局历史未读 |
| 发送前校验 | composer 的 `V3AI.composerIssue`，关联附件、模型或输入 | 给出就地恢复动作；条件变化重新校验；仅编辑草稿不能清除仍存在的阻塞 | 不提醒 |
| 请求失败 | 原回合 `V3AI.recoveryCard` | 默认显示原因、保留内容和恢复操作；技术详情展开；重试不重放已执行工具 | 不重复升级；未查看状态归属此对话 |
| 工具失败、结果未知 | 原工具卡及其状态 | 明确是否派发、已知影响、未知部分与核查入口；持续保留并原位更新 | 仅需要及时介入且未查看时升级；普通读取错误不升级 |
| 等待审批、必要输入 | 原工具／审批卡 | 显示实际目标、操作和影响；处理后原位更新；禁止在全局横幅直接批准 | 用户离开且任务确实被阻塞时，允许提醒一次 |
| 用户接管、绑定变化 | 相邻执行步骤的 `V3AI.localNotice(kind=host)`，透明底轻量行 | 宿主事实，随相关执行记录保留；可定位真实对象；不伪造模型答复 | 通常不提醒 |
| 主动停止、正常结束 | 原回合状态行和现有结果 | 不追加重复“已停止／已完成”提示；停止不证明远端进程结束 | 停止不提醒；后台完成仅用户明确开启且离开应用时通知 |

共享 renderer、样式分别位于 `shared/ai-assistant.js` 和 `shared/ai-assistant.css`。本预览和 `ai/conversation.html` 使用同一 `localNotice`；原工作区等既有消费者通过同一 `V3AI.composer` 获得校验反馈。请求失败复用原恢复卡；升级提醒复用 `shared/feedback.js`，不另造通知栈。

## 视觉与布局

- 中性操作反馈保留 8px × 10px 内边距、8px 间距和圆角、11px / 18px 文字、14px 图标及 22px 关闭控件。颜色使用 `well / muted / warn-ink / accent-ink`，不用整块红黄底；正文与影响分层，必要信息不删。
- 宿主事实去掉卡片底色，4px 垂直间距、无横向内边距，与执行内容对齐。不能通过颜色判断状态，保留明确文字。
- 长路径、技术堆栈放在原卡可展开详情中，使用 `overflow-wrap:anywhere`。短原因和恢复入口默认可见，不将关键内容仅放在 tooltip。
- header 和 composer 不收缩；transcript 使用独立 `min-height:0` 的滚动区。局部操作提示出入只改变滚动内容，不移动输入框、发送按钮或状态工具行。
- composer 校验位于输入组件内部，允许内容高度随校验文案变化，向 transcript 申请空间；输入区不被压缩，最小尺寸仍保留可滚动记录与发送入口。校验修复后恢复正常高度。
- 保留现有按钮、字体与 AI 外壳，不新增常驻顶部通知栏、通知按钮或重复成功卡。轻量提示只有 140ms 淡入，尊重 `prefers-reduced-motion`；待处理状态不闪烁。
- 基准尺寸为 600 × 456 CSS px；紧凑尺寸为 600 × 358，额外压力检查为 360 × 456。三主题沿用 V3 tokens。浏览器截图和实测值存于仓库外，不在设计目录保存效果图。

## 提醒路由

先判断事件是否需要用户介入，再判断关注位置；`warning / failure` 只决定表达语义，不能直接决定全局渠道。

| 关注位置 | 常规结束、失败、回退 | 必须介入且当前未处理 |
| --- | --- | --- |
| 正在查看对应内容 | 原位反馈；结果在可见阅读范围才视作已查看 | 原位待处理卡，不重复提醒 |
| 应用内其他位置 | 对话入口已有状态可表达新结果；局部事件不灌入全局历史 | 应用内提醒一次，点击定位原卡 |
| 离开应用 | 默认不通知；已开启后台完成提醒时，仅最终完成通知一次 | 按用户通知偏好、系统权限和勿扰策略通知一次；回到应用不再重复弹一份 |

同一 `conversation_id + operation_id + event_revision` 最多提醒一次；关注位置、设置、权限变化不补发已消费的旧事件。新工具输出或轮询不能伪造新 revision。等待多个相关决策时按同一任务聚合，不逐条连发。

“已读”“已处理”“已关闭横幅”分别建模：关闭提醒不能解除审批或未知状态；定位原对话不能自动批准或重试。普通失败既不丢失记录，也不自动成为全局未读。处理完成后，原任务和入口状态同步解除；长期日志仍由 transcript／任务记录承载。

仅打开 AI 面板不能证明用户已经看到新内容；用户在读历史时保持当前位置，不强制滚到底、不抢焦点。采用已有会话入口状态提示待处理项；用户主动定位后再滚到对应项。必要时由无障碍 `status / polite` 宣告状态，不逐 token 重复宣告。

宿主提示分两类：回退等短暂 UI 回执不写入模型历史；绑定、控制权等事实按原生命周期记录。确实影响模型执行上下文的事实仍由既有 `host_notice` 在合法请求边界注入，不能因“UI 提示不入模型”而漏掉必要事实。

## 交互预览与原生映射

预览顶部可切换九种状态、三种尺寸、三种主题。右侧“触发此事件”检查提醒门槛、一次消费和定位；改变关注位置不自动触发事件。所有成功、审批和核查结果是明确的本地 fixture，不是实际工具执行。

| HTML | 原生映射／后续改动边界 |
| --- | --- |
| `localNotice(kind=rollback)` | 复用 `ai_feedback_view.zig` 的 transcript 节点和 `Button`；保存原回退语义、草稿、附件和几何约束 |
| `localNotice(kind=host)` | 对应执行／对话的宿主记录投影，不能复用短暂回执的单一生命周期 |
| `composerIssue` | composer 内的校验状态与已有模型／附件控件，重新计算可发送条件；原生组件不直接运行 HTML JS |
| `recoveryCard` | 既有 `ai_recovery_view.zig`，重试、编辑意图仍绑定原 owner／turn |
| 原工具／审批卡 | 既有 `ai_step_view.zig`、`ai_tool_results_view.zig`、`ai_tool_approval_view.zig`；本次未重设计审批结构 |
| `V3Feedback.show` | 通知 host 的渠道路由需单独接入上述规则；不能只隐藏 presenter 而继续累计全局未读 |

本次交付不修改原生代码、配置默认值或真实系统通知偏好；原生仍需后续按 owner／turn／revision 接线，并验证实际窗口。

## 定向验收

1. 关闭回退提示后，草稿不丢失，输入区和发送按钮坐标不变；重新发送不重新出现欢迎页或旧提示。
2. 模型与图片不兼容时不能发送；编辑草稿仍阻塞；切换兼容模型或移除图片后恢复发送，草稿保留。
3. 请求失败仅显示一张恢复卡，可展开详情并重试；长路径只在原卡展开、可完整查看，最小尺寸无横向溢出。
4. 正在看对话时触发审批事件不产生全局横幅；切换位置不补发；新审批事件在未查看时提醒一次，点击仅定位。
5. 未知执行核查后仍区分“当前服务状态已知”和“原命令退出状态未知”，不能伪称原命令执行成功。
6. 正常完成默认不提醒；只有离开应用并开启后台完成提醒后，新完成事件才通知一次。

浏览器实测与交互结果见本次任务交付说明；这些检查不代替原生窗口、VoiceOver、真实通知权限或模型执行验证。

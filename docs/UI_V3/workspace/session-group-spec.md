# v0.3 · 混合会话组与分隔线

2026-11-02：本项原生 APP 已落地，效果稿同步当前实现。默认入口：[一上两下混合会话组](index.html?mode=group)。

## 默认效果稿

上方 SFTP 占整宽，内容仍为左本地文件／右远端文件；下方是左侧本地终端（约 60%）和右侧 SSH 远程终端（约 40%）。上下高度初始约 55%／45%，比例可调。整宽横线与下方竖线形成 T 形边界，表达同组可混合上下、左右分割。上方 SFTP 自身的文件双栏属于该会话内部界面，不计作两个组成员。

```text
上下分割（55% / 45%）
├── SFTP（整宽；内部为本地 / 远端文件）
└── 左右分割（60% / 40%）
    ├── 本地终端
    └── SSH 远程终端
```

复用工作区现有 `terminalPane`、`fileColumn`、标题栏及主题，新增 `group-preview.js` 只处理布局树、分隔线和演示布局保存。卡片样式同时遵循既有 Refactoring UI 规范；本次不另建卡片视觉体系。

## 外观与交互

视觉基准复用当前 [index.html](index.html)、[styles.css](styles.css) 与实际原生组卡片。
保留 `group_workspace_styles.zig` 的卡片、标题栏、圆角、颜色和现有控件；
不建立另一套卡片设计。SFTP 与 KVM 直接使用各自现有 renderer。
原有 4pt 卡片间隙是可交互分隔线，空闲时露出底层画布，悬停时提供反馈。组容器不铺整块工作区底色，每张成员卡片单独绘制圆角底色；背景图仍使用统一窗口坐标与一次透明度合成。

- 原生会话内容节点直接挂载在卡片内，组模型只保存会话身份；不按协议枚举限制入组。
- 页签左右各 25% 边缘落点用于拖动排序，中央 50% 落点用于将独立会话加入已有组，或放到另一独立会话上建立新组；拖放区域不触发原生拖窗。拖放反馈区分排序与分组；拖动期间保持目标位置稳定，松开后提交排序或分组，Esc 取消不改变成员。
- 纯页签排序不更换 SessionId、ConversationId 或工具 sessionRef，助手通过稳定引用与查询获取会话，不注入排序通知。拖入已有组时保留组助手，刷新成员范围；拖到另一独立会话建组时，目标会话的活动助手以原 ConversationId 迁到新组，保留历史、草稿、模型与权限。两种入组都结束来源会话的活动助手并取消未完成操作、释放控制，保留来源历史和终端；来源历史不合并到目标助手，没有活动助手时不自动启动任务。成员更新在下一安全工具轮边界生效，历史工具结果仍属于原调用范围。
- 页签菜单「加入会话组…」仍可选择现有组或输入名称创建组；指令 `@grp` 继续可用。组页签右键提供重命名、页签颜色、整组左右／上下排列与断开关闭组。
- 所有会话和组页签左侧常驻 2.5×18pt 身份色条；只有活动页签显示底侧选中线。选择页签颜色同时修改这两条线，不染标题文字，不改变协议／系统图标颜色。
- 广播仅显示于终端成员；文件操作、KVM 视频与输入由原 renderer 处理。每张卡片右上角按钮只控制自身参与状态，底栏成员勾选、计数和按钮共用该状态；当前输入成员同样可取消。
- 任一已开启的成员可将普通 Shell 输入同步至其他已开启且在线可写的成员，来源不重复接收。单成员可独立开启，此时没有其他同步目标。底栏「全部开启／全部关闭」只执行批量控制，收起浮卡不改变参与状态。
- `@sync on` 幂等开启执行指令的当前会话，`@sync off` 仅关闭当前会话，其他成员状态不变，不额外确认；底栏入口仅打开状态与成员控制。
- 新增、重连和移出后重新加入的成员不自动获得旧资格；用户可直接用该成员卡片按钮或浮卡勾选开启，不需要重启整组或另做一次全局确认。离线输入不补发，内置指令不广播。
- `@new` 沿用当前主机；`@new --pick` 选择本地终端或已保存的主机；`@new <主机名>` 精确匹配配置名，含空格可加配对引号，重名时用选择器区分。组内创建保留来源组，`@dup` 继续复制当前会话配置与可信目录。
- 内置指令候选浮卡支持鼠标滚轮／触控板查看完整列表，滚动只改变候选阅读位置，不执行或采纳命令；到边界不穿透滚动背后终端，键盘选中项仍能滚入可见。
- 同一组内可嵌套左右和上下分割。拖动现有卡片标题／拖动柄，放到另一张卡片的上、下、左、右边缘即可组合布局；拖动期间仅显示落点边缘提示。
- 卡片菜单的新建左右／上下分栏只分割当前卡片；「全部改为左右／上下排列」是整组重排预设。
- 竖向分隔线调整左右分支宽度；横向分隔线只调整所属分支高度，允许左右两列的横线错位。
  横向拖动最小宽度 160pt，纵向最小高度 100pt；可用空间不足时以相邻空间的一半为限。
- 分割结构以会话身份为叶子，保存每个分支的方向和比例；切换页签、改变窗口大小后保留。
  拖动取消恢复起始比例；结束后原子写入 hosts.toml 同级的 session-group-layouts。
- 跨启动保存的是同名组的分割结构、每个分支的方向与比例，叶子按组成员顺序恢复。重建同名组、加入相同数量成员后恢复；
  不自动重连或恢复运行会话。布局文件不含连接凭证或会话内容。

## 效果稿与原生的边界

- 默认可编辑效果稿只展示 SFTP／本地终端／SSH 三张卡片。原生同时支持 KVM 和其他会话内容挂载；KVM 已验证离线内容保留与焦点切换，真实设备视频在线与输入不在本次验收结论内。
- 浏览器用 localStorage 存储演示分割树；原生使用上述 JSON 文件。两者均按组名与成员顺序恢复布局，不能将保存比例理解为自动恢复连接。
- `group-preview.js` 的分隔线支持鼠标拖动、Esc 取消、键盘方向键每次 2% 调整；预览的最小尺寸与原生一致（叶子宽 160、高 100，子树累计）。
- 原生单卡片「新建左右／上下分栏」仍复用现有新建会话入口；本次 HTML 默认稿通过标题拖放演示嵌套分割，不增加虚构的原生控件。

## 2026-11-04 修订与验证口径

本次修订以以上页签、逐成员广播、主机选择和候选滚动行为为当前契约。此前“单一固定来源＋整组重新确认”“仅组页签有色条”“标题文字改色”均已被替代。既有布局验收不等于本次新增交互已通过；本轮实际构建、交互和截图结果以任务交付记录为准。

页签误跳排查发现：组内卡片曾被排除在可见会话的已读确认之外，旧输出因此持续保持未读，并被周期动画重复播放。这不是新 Shell 活动的证据。当前要求可见卡片的活动按实际呈现状态确认已读；普通刷新、布局、光标闪烁及已读旧输出不能触发新活动提醒，组页签应汇总真实成员活动。本轮修复与原生验收结果单独报告。

候选列表的既有 ScrollArea 已挂载完整条目，本轮补充实际 Cx 滚轮／触控板、底部不穿透、重绘保留阅读偏移及滚后正确采纳验证，34／34 通过。画布定向测试29／29通过，覆盖组整块底色隐藏、各卡片在同一透明度层绘制、间隙无卡片底色及退组恢复；这些结果不替代最终窗口截图检查。
